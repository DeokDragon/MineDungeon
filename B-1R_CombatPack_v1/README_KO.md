# B-1R 전투 그래픽 시범 패키지 v1

첨부된 Idle v2 첫 프레임을 기준으로 원본 돌 픽셀을 재사용했습니다. 캐릭터 6종, 이펙트 6종과 검토용 GIF/WebP를 포함합니다. 새 몬스터 생성, Unity 프로젝트 수정, Git 작업은 수행하지 않았습니다. 숨겨진 관절 연결은 인접한 원본 돌 색으로 최소 보완했습니다.

모든 PNG는 실제 투명 RGBA이며 가로 한 줄입니다. 캐릭터 프레임은 64×64, 모든 리소스의 Pivot 제안은 중앙 (0.5, 0.5), PPU 제안은 64입니다. PNG에는 Pivot/PPU가 저장되지 않으므로 나중에 Unity에서 지정해야 합니다. 시트 전체가 아닌 개별 프레임 중심을 Pivot으로 사용합니다. VFX 해상도·프레임 수는 이번 시범 제안이며 공식 아트 규격이 아닙니다.

PNG 원본에는 제목·프레임선·체크무늬·캐릭터 그림자가 없습니다. Death 최종 프레임과 VFX 최종 프레임은 의도적으로 완전 투명합니다. Hit의 첫/마지막 프레임은 의도적으로 동일합니다.

## 동작 및 기존 외형

- Windup: 발바닥 고정, 허벅지 굽힘, 팔을 안쪽으로 모음, 상체 최대 5px 하강. 눈과 둥근 몸통을 늘리거나 확대하지 않았습니다.
- Jump: 팔·다리를 모으는 자세 변화만 포함합니다. 공중 높이/도약 거리/궤적은 시트에 포함하지 않았습니다.
- Landing: 접촉→최대 압축→충격 흡수. 추가 피해나 이벤트가 없습니다.
- Recovery: Landing 마지막 프레임과 첫 프레임 동일, 끝은 첨부 Idle v2 첫 프레임과 완전히 동일합니다.
- Hit: 1px의 제한적인 상체/어깨 반응만 포함하며 플래시·색변화·몸통 스케일 변형은 넣지 않았습니다.
- Death: 기존 돌 그룹을 따라 분리/붕괴/잔해/소멸. 사망 보상이나 처리 완료 시점과 독립적인 시각 자료입니다.

기본 자세·눈·주요 균열과 몸통 색은 원본을 재사용했습니다. intact 프레임의 얼굴은 몸통 이동량을 보정한 뒤 픽셀 동일성을 검사했습니다. 접지 동작의 두 발 영역은 원본과 픽셀 단위로 동일합니다. 다리의 굽힘과 팔 회전으로 자세를 바꾸었으므로 모든 프레임을 전체 상하 이동으로 만들지 않았습니다.

## 효과 분리와 크기 제안

- JumpDust: 작은 발밑 먼지와 소량의 돌 조각. 64px 셀 / 5f / 0.20초.
- LandingShockwave: 채워진 위험 장판이 아닌 얇은 원형 충격파. 128px 셀 / 6f / 0.25초.
- LandingDust: 착지 먼지만 분리. 128px 셀 / 6f / 0.25초.
- StoneFragments: 착지 시 돌 조각만 분리. 96px 셀 / 6f / 0.30초.
- HitFragments: 작은 파편 4개 중심의 절제된 피격 이펙트. 32px 셀 / 4f / 0.18초.
- DeathBurst: 붕괴에 겹쳐 쓰는 짧은 파편/먼지. 96px 셀 / 7f / 0.45초.

모두 단발 재생용입니다. GIF/WebP는 검토 편의를 위해 반복됩니다. 이펙트에 캐릭터 본체나 그림자가 없으며 각각 독립적으로 사용할 수 있습니다. 먼지/파편은 피해 범위를 표시하는 자료가 아닙니다.

충격파 최대 원본 반경은 57.6px 이하이며 PPU64·배율1에서 약 0.9 world unit입니다. 픽셀 중심 기준 측정값은 manifest.json에 기록했습니다. 실제 Transform 배율, 부모 배율, 카메라와 공격 위치를 포함한 씬 합성은 아직 검증하지 않았습니다. 실제 0.9 반경을 바꾸는 기준으로 이 PNG를 사용하면 안 됩니다.

## 예고 장판은 기존 기능 재사용

읽기 전용으로 확인한 StoneGolemTelegraph.cs는 radius로 Mesh/LineRenderer 경계를 만들고 진행률만 받아 표시합니다. StoneMonsterAI는 attackRadius=0.9를 전달합니다. 기존 예고 장판이 범위와 진행률을 처리하므로 신규 경고 PNG를 중복 제작하지 않았습니다. 착지 충격파 PNG는 착지 이후의 장식 자료이며 예고 장판을 대체하지 않습니다.

## Unity 적용 전에 확인할 사항

1. 현재 StoneMonsterSpriteAnimation은 Idle/Move 배열만 사용하며 전투 중 Idle 첫 프레임을 표시합니다. 새 전투 시트는 자동 연결되지 않습니다. 이번 작업에는 코드 변경이나 Animator 연결이 포함되지 않습니다.
2. 제안 Import: Sprite (2D and UI), Multiple, 프레임별 Grid By Cell Size, 중앙 Pivot, Point 필터, 무손실/압축 없음, PPU64. 알파가 있으며 배경 제거는 추가로 필요하지 않습니다. 이는 적용 참고이며 프로젝트 설정을 바꾼 기록이 아닙니다.
3. Windup 0.65초, Jump 0.35초, Recovery 1.0초, 공격 간격 2.8초와 실제 착지 반경 0.9를 그대로 유지해야 합니다. 애니메이션에서 피해/보상 이벤트를 추가하지 않습니다.
4. Landing 0.18초를 별도 후딜로 더하지 않습니다. 기존 1.0초 Recovery 창 안에서 착지 시각과 회복 시각을 배치하거나 겹쳐 사용합니다. Recovery 시트 단독 GIF는 1.0초 제안으로 작성했습니다. 둘을 단순 직렬 재생해 1.18초로 만들면 안 됩니다.
5. 도약의 실제 높이/이동은 기존 JumpVisual이 처리합니다. 스프라이트 도약을 추가로 크게 이동시키지 않습니다.
6. StoneHitFeedback의 플래시/변형과 함께 Hit 자세가 과해지지 않는지 실제 합성 확인이 필요합니다. Hit는 현재 이동/공격을 중단하는 기능이 없습니다.
7. 현재 LandingEffect에도 Mesh 착지 pulse와 돌출 dust가 있습니다. 기존 pulse와 새 shockwave를 동시에 켜면 중복 표현이므로 나중에 표현 하나를 선택해야 합니다. 기존 dust는 본체 스프라이트를 재사용하고 있어 새 먼지로 자동 교체되는 구조가 아닙니다.
8. StoneCombatBurst는 단일 chipSprite/dustSprite를 개별 입자로 쓰는 구조입니다. 이번 VFX 시트는 여러 프레임의 독립 효과 자료이므로 시트 전체를 단일 sprite 슬롯에 넣으면 안 됩니다. 실제 연결은 별도 통합 작업입니다.
9. Death는 기존 약 0.45초 연출 안에서 별도 시각 오브젝트에 사용할 수 있습니다. 보상/방 클리어를 마지막 투명 프레임까지 기다리게 만들지 않습니다.

## 검증 결과와 남은 한계

- PNG 12개 전부 재열기: 실제 크기, RGBA, 투명 픽셀, 셀 크기, 프레임 수와 셀 픽셀 일치 확인.
- 준비/착지/회복의 발 위치 고정, Landing→Recovery 및 Recovery→Idle 연결 확인.
- GIF 12개: 프레임 수/재생시간/투명성 재검사. 완전 투명한 종료 프레임도 보존했습니다.
- WebP 12개: 모든 프레임의 보이는 RGBA 픽셀이 PNG 확대 프레임과 같은지 확인. 반투명 PNG 원본 판단에는 WebP가 더 정확합니다.
- GIF는 256색·이진 투명 형식이라 반투명 먼지를 미세 점 패턴으로 근사합니다. PNG/WebP에는 이 근사 패턴이 없습니다.
- 기존 첨부 파일, 기존 생성 Idle/Move 파일과 읽은 프로젝트 소스의 SHA-256 변경 없음 확인.
- 프레임 접촉 시트를 정적으로 확인했습니다. Unity Import/실시간 재생/실제 카메라에서의 범위 합성/충돌 또는 피해 판정 검증은 수행하지 않았습니다. 이번 작업에는 코드 변경이 없으므로 컴파일·게임 테스트를 실행하지 않았습니다.
- 단일 정지 원본으로 보이지 않는 관절/파단면을 복원할 수 없어 원본 인접 픽셀로 보완한 시범 리소스입니다. Death의 조각 분할은 보이는 암석 그룹을 따른 근사이며 정밀 수작업 파단면은 아닙니다. 새로운 캐릭터를 생성하지 않았습니다.
- 현재 파일 생성 실패는 없습니다. 보행과 구별되는 자세 변화는 프레임 비교로 확인했지만, 묵직함·전환 자연스러움의 최종 승인은 실제 게임 배경과 타이밍에서 검토해야 합니다.

Documentation/manifest.json에 파일별 프레임 시간, Pivot/PPU 제안, 크기, 해시, 프레임 불투명 경계와 검증 항목을 기록했습니다. Documentation/*_contact.png는 검토용 프레임 모음이며 게임에 넣을 시트는 Animations/와 VFX/ 폴더의 PNG입니다.
