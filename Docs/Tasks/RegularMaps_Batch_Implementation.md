> **권장 Unity 프로젝트 저장 경로:** `Docs/Tasks/RegularMaps_Batch_Implementation.md`  
> **문서 상태:** 사용자 승인 하에 독립 프로토타입 제작을 요청하는 작업 지시서. 공식 랜덤 후보·최종 밸런스 확정 문서가 아님.

## 1. 목적

기존 프로토타입 5종을 보존하면서, 서로 다른 이동 구조를 지닌 신규 일반 맵 5종을 **각각 독립 씬/프리팹/시험 데이터**로 제작한다. 사용자가 Unity에서 직접 맵을 선택하여 Play 테스트하고 비교할 수 있게 한다. **공식 일반 맵 7종 후보의 교체·추가와 정규 던전 등록은 하지 않는다.**

신규 5종의 핵심 차이는 다음과 같다.

| 후보 | 구분 | 구조 핵심 | 시험 몬스터 |
|---|---|---|---|
| Map04 | ㄱ자 채굴갱 | 하단에서 왼쪽으로 크게 이동한 뒤 상단에서 오른쪽으로 전환 | A 6 + B 4 |
| Map07 | 3단 공동 | 서로 엇갈린 3개의 전투 공동을 차례로 돌파 | A 3 + B 4 + C 3 |
| Map08 | 우회 선택 | 중앙 암괴의 좌·우 경로 중 **한쪽만 지나도** 상단 공동 도착 | 하단 4 + 상단 6 |
| Map09 | 엇갈린 채굴실 | 메인 갱도의 서로 다른 높이에 좌측·우측 채굴 공동 | 중앙 4 + 왼쪽 3 + 오른쪽 3 |
| Map10 | 광산 교차로 | 같은 중앙 교차 공동에서 좌·우 채굴 공간과 상단 진로 분기 | 중앙 4 + 왼쪽 2 + 오른쪽 2 + 상단 2 |

## 3. 공통 제작 규격

### 3.1 좌표·바닥·통로

- **로컬 좌표**: 맵 캔버스 좌하단 `(0,0)`, 오른쪽 +X, 위쪽 +Y. 프로젝트의 월드 원점이 다르면 기존 프로토타입 방식으로 변환.
- **전체 캔버스**: X 0~28, Y 0~36 (28×36 유닛).
- **외곽**: 직사각형. 실제 이동 가능한 바닥만 개별 동굴 모양으로 개방; 나머지는 충돌 가능한 암석/암벽.
- **기본 주 통로 폭**: 5유닛. 아래에서 상단 출구로 진행하며 전투 공동은 각 맵에 맞춰 확장.
- 아래의 **구역 범위는 바닥 도형의 기준 외접 영역/연결 의도**다. 모든 사각 구역을 독립 방으로 절단하거나, 겹치는 사각형의 경계에 가짜 벽을 생성하면 안 된다. 인접 구역은 반드시 겹치거나 개방된 포털로 연속 연결한다.
- 자연스러운 모서리 다듬기, 플레이어 및 몬스터 충돌 여유를 위한 **최소 보정**만 허용. 핵심 동선·지형별 차별성 임의 변경 금지. 보정 좌표와 이유를 결과에 보고.
- 기존 플레이어 이동·회피/몬스터 반경을 고려한 실질 통과 폭을 확인한다. 몬스터 네비게이션 시험 반경 0.65 기준으로 정적 연결성 검사.

### 3.2 입구·출구·몬스터

- 입구·출구 좌표는 아래의 맵별 명세를 따른다. 출구까지 이동 가능한 바닥 및 끝단 여유를 확보한다.
- 총 **10마리 시험 배치**: 기존 몬스터 5종(돌/철/수정/석탄/자철석) 각 2마리.
- 모든 몬스터는 방 입장 시 생성. 추가 웨이브·트리거 스폰 도입 금지.
- 아래 몬스터 좌표는 **초기 후보 좌표**: 벽/진입구/지형 모서리/동종 중첩에 걸릴 경우 최소 조정 후 보고. 구역별 수량 보존.
- 종별 정확한 좌표 배분은 기존 종류별 인식 반경·공격 특성 및 위치 안전성을 검토해 결정하되, 개체 수 2마리씩 유지. 특정 좌표의 종류를 최종 확정한 것으로 간주하지 않는다.
- 최초 인식은 기존 **거리 + 장애물에 가리지 않은 시야** 또는 실제 피격에 따르며, 한 번 인식한 개체는 도주/벽 차단으로 자동 해제되지 않는다. 인식·추적·패턴 변경 금지.
- **입장 직후 즉시 공격받지 않을 것**: 특히 Map04/07/08/09/10의 하단 전투 공동 배치와 진입 시야를 확인한다. 초기 후보와 거리/LOS가 충돌하면 몬스터·공동 위치 또는 진입 갱도의 굴곡을 최소 수정하되 기존 AI 수치 변경 금지. 안전 구간 확보가 불가능하면 해당 맵을 미완료로 보고한다.
- 생존 대상 몬스터 전멸 시 기존 출구 개방 규칙 사용. 의도하지 않은 미탐색 몬스터가 숨겨지는 구조는 플레이테스트 위험으로 명시.

### 3.3 카메라

- 기존 `CameraFollow`, SmoothDamp 및 **Orthographic Size 4.5** 유지.
- 전체 직사각형 캔버스 기준으로 클램프. 16:9 한 화면은 약 16×9유닛이고, 캔버스 원점이 `(0,0)`일 때 카메라 중심 X 8~20, Y 4.5~31.5.
- 내부 암벽을 카메라 경계로 취급하지 않는다. 정규 맵/기존 프로토타입 카메라 설정 변경 금지.
- 기존 화면비 변경 후 Ortho Size 복원 오류는 이번 작업 범위 밖이며 별도로 보고.

### 3.4 개별 테스트 실행

기존 Editor 실행 메뉴를 재사용한다. 다음 메뉴를 추가한다.

- `Tools > MineDungeon > Prototypes > Open Cave 07`
- `Tools > MineDungeon > Prototypes > Open Cave 08`
- `Tools > MineDungeon > Prototypes > Open Cave 09`

기존 Cave01 V2/Cave02/Cave03/Cave05/Cave06 메뉴와 테스트 세션은 변경하지 않는다. 임시 저장은 프로젝트 기존의 **세션별 격리 경로**를 재사용해 실제 사용자 저장·백업을 건드리지 않는다.

## 4. 맵별 상세 제작 명세

### 4.1 Map04 — ㄱ자 채굴갱형

**동선**: 하단 입구 → 왼쪽 이동 → 좌측 수직 갱도와 A 공동 → 상단에서 오른쪽 전환 → B 공동 → 상단 출구. Cave02의 반복 좌·우 S자 이동과 구별.

| 요소 | 로컬 좌표 / 영역 |
|---|---|
| 캔버스 | X 0~28, Y 0~36 |
| 입구 | **(18.5, 2)** |
| 하단 접근 통로 | X 16~21, Y 1~7 |
| 좌측 이동 연결 | X 9~21, Y 6~11 |
| 좌측 세로 갱도 | X 7~12, Y 9~25 |
| A 공동 | X 4~13, Y 11~20 |
| 상단 가로 통로 | X 9~20, Y 23~28 |
| B 공동 | X 14~24, Y 24~32 |
| 출구 연결 | X 16~21, Y 30~35 |
| 출구 | **(18.5, 34)** |

**몬스터 시험 좌표**

- A 6: `(6,13)`, `(10,13)`, `(6,17)`, `(10,17)`, `(8,19)`, `(11,15)`
- B 4: `(16,26)`, `(21,26)`, `(16,30)`, `(21,30)`

**필수 검증 및 잠재 충돌**

- 하단 접근 통로와 좌측 연결, 좌측 세로 갱도와 상단 가로 통로가 실제 바닥으로 연결될 것.
- A의 `(11,15)` 등은 세로 갱도와 겹칠 수 있으나 벽 배치나 다른 몬스터와 충돌하면 조정.
- 하단 공동의 최초 가시·거리 인식을 확인. 안전한 굴곡 통로가 충분치 않으면 진입 구조를 보완하되 A/B 및 큰 방향 전환 유지.

### 4.2 Map07 — 3단 공동형

**동선**: 하단 안전 진입 → A 하단 공동 → 오른쪽으로 중심이 이동한 B 중단 공동 → 왼쪽으로 중심이 이동한 C 상단 공동 → 출구. 전투 공동 세 개의 공간감/리듬 변화가 핵심.

| 요소 | 로컬 좌표 / 영역 |
|---|---|
| 캔버스 | X 0~28, Y 0~36 |
| 입구 | **(14, 2)** |
| 하단 통로 | X 11.5~16.5, Y 1~7 |
| A 공동 | X 8~20, Y 6~14 |
| 연결 A→B | X 14~19, Y 12~18 |
| B 공동 | X 12~25, Y 17~25 |
| 연결 B→C | X 9~16, Y 23~29 |
| C 공동 | X 5~17, Y 27~33 |
| 출구 연결 | X 11.5~16.5, Y 32~35 |
| 출구 | **(14, 34)** |

**몬스터 시험 좌표**

- A 3: `(10,11)`, `(15,11)`, `(18,9)`
- B 4: `(15,19)`, `(20,19)`, `(16,23)`, `(22,23)`
- C 3: `(8,29)`, `(13,29)`, `(11,32)`

**필수 검증 및 잠재 충돌**

- A→B와 B→C 연결부의 **사각 구간 접촉 폭**이 반경 0.65 길찾기에도 충분해야 한다.
- C의 `(11,32)`와 상단 출구 연결 통로 간격을 확인.
- A 공동이 입구로부터 가까움: 입구 즉시 어그로 가능성 높음. 진입 갱도 LOS 차단 및 실제 거리 검사 필수. 크기·구성상 불가능하면 보고하고 AI는 변경하지 않음.

- A 하단 배치가 입구와 가까움. 안전 접근 굴곡/LOS 차단이 안 되면 최소 보정 후 보고.

- 중앙 갱도에서 첫 몬스터를 입구에서 바로 볼 수 있는지 LOS 검사; 필요하면 하단 진입 굴곡 등 최소 보정.
- 양쪽 채굴실에 접근 가능한지 정적 연결성 확인.
