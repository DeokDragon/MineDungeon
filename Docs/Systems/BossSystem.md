## 1. 시스템 개요

### 1.1 목적

보스 시스템은 광산던전의 보스 몬스터에 대한 전투 행동, 고유 공격 패턴, 공격 예고, 피해 판정, 체력 표시, 사망 및 던전 클리어 연동을 관리한다.

보스 전투는 던전 진행의 마지막 전투 단계로 구성하며, 플레이어가 공격 예고를 파악하고 적절하게 대응하는 액션 전투를 지향한다.

### 1.2 주요 기능

- 보스 체력 및 피해 처리
- 보스 공격 패턴
- 공격 예고와 실제 판정 연동
- 공격 후딜레이 및 쿨타임
- 보스 전용 HP바
- 무거운 공격의 화면 흔들림
- 사망 시 공격 및 예고 정리
- 보스 처치에 따른 던전 클리어 처리
- 클리어 보상 및 결과창 연동

### 1.3 현재 보스

현재 인수인계 문서에서 확인된 보스는 **돌골렘**이다.

기존 대화에서 사용된 '돌 보스'는 돌골렘을 의미한다.

돌골렘은 기존 5개 공격 패턴을 기준으로 구현 작업을 진행했다.

**구현 상태:** 5종 패턴 구현 후 정상적으로 구현되었다는 사용자 보고가 존재한다. 실제 Unity 코드와 플레이 결과는 아직 직접 검증하지 않았다.

## 2. 보스 전투 기본 구조

### 2.1 보스 방

플레이어는 일반 전투 방을 진행한 뒤 보스 방에 도달한다.

보스 방 연결 및 진행 기능은 구현·동작 확인 보고가 있다.

정확한 일반 방 개수와 보스 방의 맵 구조는 `DungeonSystem.md` 및 `MapSystem.md`에서 관리한다.

### 2.1.1 BossRoom24x22 정규 보스 아레나

| 항목 | 사용자 승인 규격 |
|---|---|
| 전체 캔버스 | 24×22 Unity 유닛 |
| 형태 | 단일 동굴형 보스 아레나 |
| 이동 가능 전투 바닥 | 대략X2~22/Y3~20 |
| 플레이어 입장/부활 | 방 로컬(12,2), 현재 보스 방 입구 |
| 돌골렘 초기 위치 | 방 로컬(12,14) |
| 내부 장애물 | 없음 |
| 출구 오브젝트 | 없음 |
| 카메라 | Orthographic Size4.5,16:9 중심X8~16/Y4.5~17.5 |

좌표는 보스 방 로컬 원점 기준이며 입구 바닥은 전투 바닥 개략 범위와 구분한다. 출구 문·방벽·불필요한 충돌체를 제거하고 외곽 암벽·입구/부활 위치는 유지한다. 일반 방의 벽/충돌·출구는 제거하지 않는다. 보스 처치 시 기존 클리어·결과 정산으로 연결하며 출구 통과를 요구하지 않는다. 던전당 부활2회·현재 방 입구 복귀를 유지하고 부활을 이유로 보스 위치를(12,14)로 강제 재설정하지 않는다.

1층 쉬움 정규 보스 참조 교체는 Codex 보고, 정상 적용은 사용자 확인이다. 프리팹 경로와5패턴/보상 보존·미검증은 §14의 구현 보고를 따른다.

### 2.2 전투 시작

보스룸 최초 진입 시 등장 연출 후 돌골렘과 전투한다. BossRoom24x22의 초기 배치/입장 위치는 §2.1.1을 유지한다. 등장 중 행동·피해 차단/전투 쿨타임 정지와 정상 완료·스킵의 종료 처리는 §4.12~4.15의 최신 승인 규칙이다. 같은 보스전 부활 시 완료된 등장을 반복하지 않는다.

실제 활성화 연결·첫 공격의 구체 선택·등장 리소스/시간/카메라 경로는 구현 전 확인 대상이다. 승인된 행동 제한이나 초기 위치 자체를 미확정으로 되돌리지 않으며 이번 신규 연출을 구현 완료로 표시하지 않는다.

### 2.3 보스 공격 흐름

기존 공격 명세와 공통 전투 원칙을 기준으로 다음 단계를 구분한다.

1. 공격 패턴 선택
2. 해당 패턴의 공격 예고
3. 공격 실행 및 피해 판정
4. 공격 종료
5. 다음 행동

위 단계는 문서 정리를 위한 논리적 구분이며, 실제 보스 AI의 상태 머신이나 코드 구조를 확정하는 것은 아니다.

공격 선택/전환/연계 쿨타임의 승인 규칙은 §4.8~4.16을 따른다. 실제 코드와의 연결·미명시 거리 경계와 최종 후딜/쿨타임 수치는 별도 확인한다.

## 3. 돌골렘 기본 능력치

### 3.1 능력치 항목

기존 보스 구현에 대해 확인할 주요 항목은 다음과 같다.

| 항목 | 현재 상태 |
|---|---|
| 최대 체력 | 수치 확인 필요 |
| 이동 속도 | 수치 확인 필요 |
| 기본 공격력 | 패턴별 확인 필요 |
| 패턴별 피해량 | 수치 확인 필요 |
| 공격 시작 거리 | 패턴별 확인 필요 |
| 공격 예고 시간 | 패턴별 확인 필요 |
| 공격 범위 | 패턴별 확인 필요 |
| 공격 쿨타임 | 패턴별 확인 필요 |
| 공격 후딜레이 | 패턴별 확인 필요 |
| 경직 시간 | 실제 적용 여부 및 수치 확인 필요 |

### 3.2 수치 관리 원칙

일반 몬스터의 HP, 공격력, 공격 범위 또는 쿨타임을 돌골렘의 능력치로 대신 사용하지 않는다.

기존 프로젝트에 돌골렘의 능력치 데이터가 존재한다면 해당 값을 먼저 확인한다.

새로운 수치가 필요할 경우 사용자 승인 후 공식 명세에 반영한다.

### 3.3 난이도와의 연동

던전 선택창에는 4가지 난이도가 존재한다.

보스의 정확한 난이도별 능력치 차이와 패턴 변화는 현재 자료에서 확정되지 않았다.

난이도별 보스 수치와 등장 조건은 실제 프로젝트 데이터를 확인한다.

## 4. 돌골렘 공격 패턴

**최신 승인·플레이테스트 반영:** 돌골렘1차 구현과2·3차·후딜/최종연계A 수정의 Codex 완료 보고가 있다(§14). 사용자는 최종 수정 뒤 현재 전투에 만족한다고 확인했다. 실제 등장/변신 아트·카메라 시네마틱/스킵UI·자동 설정은 후속 작업이다. 이번 문서 갱신은 코드/프리팹 읽기 확인과 기존 기록 대조이며 새Play 검증이 아니다. 최종 밸런스/연출 완성을 선언하지 않는다.

§4.2~4.7의 기존 기본형·미확인 수치는 보존하되 새 승인으로 결정된 낙석/페이즈/연계 규칙은 §4.8~4.16을 우선한다. 기본5종의 핵심 이동·피해 판정·예고·벽 충돌은 가능한 한 유지하며 과거 임시값을 개편 후 최종 밸런스로 승격하지 않는다.

### 4.1 공격 패턴 구성

기존 인수인계에서 확인되는 공격 패턴 계열은 총 5종이다.

| 번호 | 패턴 계열 | 세부 명세 상태 |
|---|---|---|
| 1 | 도약 내려찍기 | 패턴 계열 확인, 개별 수치 미확인 |
| 2 | 주변 강타 | 패턴 계열 확인, 개별 수치 미확인 |
| 3 | 바위 돌진 | 패턴 계열 확인, 개별 수치 미확인 |
| 4 | 부채꼴 돌 파편 | 패턴 계열 확인, 개별 수치 미확인 |
| 5 | 낙석 (과거 메테오 명칭) | B안 배치/회차 규칙 승인, 구체 피해·반경·시간 미확정 |

이 명칭은 인수인계에서 사용된 패턴 설명이며, 현재 Unity 코드에 적용된 정확한 패턴명과 반드시 일치한다고 단정하지 않는다.

### 4.2 패턴 1 — 도약 내려찍기

**기존 확인 내용**

- 돌골렘의 공격 패턴 계열 중 하나이다.
- 도약 후 내려찍는 형태의 공격으로 논의되었다.
- 일반 돌 몬스터의 점프 공격은 보스 도약 내려찍기의 기초 버전으로 설명되었다.

**확인 필요**

- 공격 시작 조건
- 도약 예고 중 추적/발동0.2초 전 고정과 기존 유효 착지·경로 검사 (§4.17)
- 도약 거리와 이동 시간
- 공격 예고 형태와 시간
- 착지 범위와 피해량
- 벽 및 충돌 처리
- 후딜레이와 쿨타임
- 화면 흔들림의 실제 적용 여부

일반 돌 몬스터의 능력치를 보스 패턴에 그대로 적용하지 않는다.

### 4.3 패턴 2 — 주변 강타

**기존 확인 내용**

- 돌골렘의 공격 패턴 계열 중 하나이다.
- 보스 주변을 공격하는 강타 계열로 논의되었다.

**확인 필요**

- 강타 위치와 범위
- 공격 예고 형태
- 피해량 및 판정 시점
- 플레이어 위치 추적 여부
- 후딜레이 및 쿨타임
- 충격 연출과 화면 흔들림 적용 여부

### 4.4 패턴 3 — 바위 돌진

**기존 확인 내용**

- 돌골렘의 공격 패턴 계열 중 하나이다.
- 돌진형 공격으로 논의되었다.

**확인 필요**

- 돌진 예고 중 추적/발동0.2초 전 방향 고정·발동 후 재추적 없음 (§4.17)
- 돌진 속도와 이동 거리
- 예고 범위 및 시간
- 벽 충돌 시 처리
- 플레이어 충돌 시 처리
- 피해량 및 후딜레이
- 실제 화면 흔들림 적용 시점

철 몬스터의 돌진 세부 수치를 보스에 그대로 적용하지 않는다.

### 4.5 패턴 4 — 부채꼴 돌 파편

**기존 확인 내용**

- 돌골렘의 공격 패턴 계열 중 하나이다.
- 부채꼴 형태의 돌 파편 공격으로 논의되었다.

**확인 필요**

- 파편 개수
- 발사 방향과 부채꼴 각도
- 투사체 속도 및 사거리
- 공격 예고 형태
- 피해량 및 중복 피격 처리
- 벽 충돌 및 소멸 조건
- 후딜레이와 쿨타임

정확한 파편 개수나 발사 각도는 임의로 정하지 않는다.

### 4.6 패턴 5 — 낙석 (기존 메테오 계열)

**기존 확인 내용**

- 메테오 또는 낙석 계열 공격이다.
- 공격 예고의 남은 시간이 채워지는 형태로 표시되도록 작업했다.
- 이 예고 방식은 이후 다른 보스 패턴에도 적용을 요청했다.

**확인 필요**

- B안의 실제 이동 가능 바닥 조회와 플레이어 주변 가중치 구현 일치
- 승인된 회차당7~8개/페이즈별 반복 횟수 적용
- 예고 범위와 시간
- 실제 낙하 시간 및 피해 판정 시점
- 피해량과 공격 반경
- 회차 독립 재추첨·동시 낙하와 동일 회차 피해 최대1회 적용
- 화면 흔들림의 적용 시점
- 후딜레이와 쿨타임

낙석 위치·개수·회차는 §4.10의 최신 승인으로 결정됐다. 정확한 원 반경·예고 시간·피해량·가중치는 미확정으로 유지한다. 공격 종료 뒤 지속 피해 장판은 생성하지 않는다.

### 4.7 공통 패턴 유지 원칙

기존5개 패턴을 기본형으로 보존하고2페이즈의 승인된 강화형/기본형 연계만 추가 기획으로 구분한다.

§4.8~4.16 승인 범위 밖의 패턴 교체·추가 효과·새 조건은 임의로 확정하지 않는다.

각 패턴의 전투 방식과 능력치는 `CombatSystem.md`, 실제 보스 코드 및 관련 데이터를 확인한 후 보완한다.

### 4.8 2페이즈 구조와 공격 선택

| 상태 | 승인 규칙 |
|---|---|
| 1페이즈 | 보스HP50% 초과, 기본 공격5종 사용 |
| 2페이즈 전환 조건 | 보스HP50% 이하에서 전환 예약 (§4.13) |
| 2페이즈 전투 | 전환 완료/스킵 후 강화 단일5종·기본형2개 연계2종 사용 |

HP50%는 확정 전환 조건이다.2페이즈 선택은 강화 단일70%/연계30%를 **초기 테스트 비율**로 사용한다. 최종 밸런스가 아니며 개편 구현 후1층 쉬움에서 조정한다. 최대HP·피해·범위·속도·쿨타임 최종값은 미확정이다. 사용 불가능한 연계의 재선택은 §4.11을 따른다.

### 4.9 2페이즈 강화 단일5종 — 최신 테스트 상태

| 패턴 | 현행 승인/적용 보고 |
|---|---|
| 도약 | 기존 착지 뒤 별도 충격파/예고 유지. 현재 초기 반경3.3(기본2.2×1.5), 착지 후 기존1.3초 대기+추가 예고0.8초=2.1초 뒤 충격파 보고. 추가 피해/시간은 기존 구현용 값이며 최종 미확정 |

### 4.10 낙석 B안 — 배치·회차·피해

보스룸의 **실제 이동 가능한 바닥**을 쓰는 B안을 유지하되 매 회차 시작에75% 확률로 직접 조준 여부를 결정한다. 성공 시 그 순간 플레이어 위치에1개만 배치하고 나머지는 전체 유효 바닥 랜덤, 실패 시 모두 랜덤이다.75%는 개별 원마다가 아닌 회차 전체에서 직접 조준1개를 고르는 초기 테스트 확률이다. 일반 랜덤이 우연히 플레이어 근처에 떨어지는 것은 허용한다. 위치 확정 뒤 추적하지 않으며 회차마다 새 위치/직접 조준을 추첨한다. 무효 목표는 기존 바닥/벽 검사 및 유효 바닥 대체 추첨을 유지한다는 구현 보고다. 암벽 내부는 유효 중심이 아니다. 한 회차당 위험 원7~8개가 동시에 낙하하며 회차마다 독립적으로 새 위치를 추첨한다. 같은 회차의 원 접촉/일부 겹침을 허용하고 플레이어 현재 위치·보스 발밑에도 생성할 수 있다. 인위적인 안전 위치를 항상 보장하지 않는다. 낙하 후 지속 피해 장판은 없다.

| 2페이즈 낙하 횟수 | 초기 테스트 확률 |
|---|---:|
| 1회 | 20% |
| 2회 | 45% |
| 3회 | 35% |

반경1.8·기존 예고0.9초 뒤 낙하 연출0.55초·충돌 종료→다음 회차 예고0.3초가 최신 테스트값이다. 모든 회차 위치를 미리 고정하거나 앞 회차 위치를 반복하지 않는다.75%/20·45·35%와 반경/시간/피해의 최종 튜닝은 후속 밸런싱 대상이다.

**추가 최종 승인:** 같은 회차의 여러 위험 원이 겹쳐도 동일 플레이어에게 최대1회만 피해를 적용한다. 다른 회차의 피격은 기존 플레이어 피격 무적 규칙을 따른다. 같은 회차 제한을 공격 전체1회 제한이나 새 무적 시간으로 확대하지 않는다.

### 4.11 2페이즈 연계2종과 개별 쿨타임

| 연계 | 기본형 순서 |
|---|---|
| A | 기본 도약 내려찍기 → 기본 주변 강타 |
| B | 기본 바위 돌진 → 기본 부채꼴 돌 파편 |

연계는2페이즈 전용이며 **강화형끼리 연결하지 않는다.** 낙석은 연계에서 제외한다. 시작 시 두 패턴이 모두 사용 가능해야 하고 기존 개별 패턴 쿨타임을 공유한다. 첫/둘째 실행 상태를 구분하며 연계 중 독립 공격을 중복 시작하지 않는다. 연계B 돌진에서 벽 충돌하면 둘째 파편은 취소하고 기존 돌진 벽 후딜을 적용한다.

**추가 최종 승인 — 대체 선택:** 연계를 선택했으나 사용할 수 없으면 현재 사용 가능한 단일 공격을 다시 선택한다. 연계 불가능만으로 선택 상태가 무한 대기/정지해서는 안 된다. 기존 쿨타임/행동 조건을 존중한다. 현재 사용 가능한 공격이 없으면 기존 추적 행동을 유지한다. 연계 불가 시 사용 가능한 강화 단일을 재선택하며 기존 쿨타임/상태 조건은 유지한다.

**추가 최종 승인 — 쿨타임:** 각 패턴이 실제로 예고를 시작할 때 해당 패턴의 쿨타임을 개별 시작한다. 연계 선택 시 두 쿨타임을 미리 소모하지 않는다. 둘째 패턴이 예고/실행을 시작하기 전에 취소되면 그 취소만으로 새 쿨타임을 만들지 않는다. 쿨타임 만료도 현재 공격·후딜 중첩 실행을 허용하지 않는다. 현재1차 구현 보고는 둘째 직전 신규 거리 제한을 추가하지 않았다. 미승인 조건은 추가하지 않는다. 최신A/B의 후속 예고/발사 타이밍은 아래처럼 구분한다.

#### 연계 A/B의 서로 다른 후속 절차 — 최신 승인

- **A:** 기본 도약 착지/피해→0.2초 대기→기본 강타 예고1.2초→피해→최종 강타 후딜0.8초. 착지→예고0.199999/예고→피해1.200001/총1.400000초의 Codex 실측 보고다.0.2초는 피해까지가 아니라 예고 시작까지다. 중간 도약 후딜/공통 대기는 없다. 예고 시작 때 강타 쿨타임 소모, 예고 전 취소는 미소모·후 취소는 시작한 쿨타임 유지다.
- **B:** 기본 돌진 정상 종료→약0.2초에 기본 파편 **실제 발사**(실측0.200001초). 중간 일반 후딜/공통 대기는 없고 마지막 후딜을 적용한다. 벽 충돌은 후속 취소/벽 후딜이다. A의1.2초 예고 복구를 B에 자동 적용하지 않는다. 실제 짧은 후속 준비/예고 시작에 패턴 쿨타임을 적용하며 미실행 취소는 신규 미소모다.

과거A의 착지→0.2초 짧은 예고→피해는 최신0.2초 대기+1.2초 예고로 대체됐다. 실패/중간검증 기록은 삭제하지 않는다.

### 4.12 보스 최초 등장 연출

보스룸 최초 진입 시 카메라 이동·보스 등장 애니메이션과 전투 제한을 적용한다. 수동 스킵 가능, 향후 설정의 자동 스킵 지원 방향이다. 같은 보스전 부활 시 이미 완료한 등장은 반복하지 않는다. 애니메이션/VFX·카메라 경로·효과음·시간·스킵UI 세부는 별도 아트/연출 기획으로 정하며 이번에 리소스나 수치를 확정하지 않는다.

### 4.13 HP50% 전환 예약과 변신

HP50% 이하가 되면2페이즈 전환을 예약한다. 현재 공격은 임의 중단하지 않고 해당 패턴 종료 후 변신 연출을 시작한다. 예약 중 새1페이즈 공격은 시작하지 않는다. 보스전당 전환 연출1회이며 수동 스킵/향후 자동 스킵을 지원한다. 정상 완료/스킵 뒤2페이즈 공격을 시작한다. HP0이면 전환보다 사망·클리어를 우선한다.

예약은 현재 공격 실행 상태와 구분해 관리한다. 공격 정리나 플레이어 사망으로 예약이 잘못 소실되지 않게 하며 예약 중 사망/부활은 §4.16을 따른다.

### 4.14 등장·변신 중 전투 제한과 쿨타임 정지

- 플레이어 이동·회피·기본 공격·E/R 스킬·물약 사용 금지.
- 보스 이동·공격, 양측 신규 피해, 새 예고·예약 공격 시작 차단.
- 기존 잔여 공격/투사체는 연출 중 피해가 발생하지 않도록 정리.
- 카메라 이동·애니메이션·연출·스킵 입력은 정상 동작.

**추가 최종 승인:** 플레이어와 보스의 전투 관련 쿨타임을 모두 정지한다. 기존 전투 쿨타임·회피·스킬·물약 재사용 제한을 포함하며 연출 시간만큼 감소시키지 않는다. 완료/스킵 시 이전 잔여 시간부터 정상 재개하고 초기화/즉시 만료시키지 않는다.

전체 게임 일시정지와 구분한다. 무조건적인Time.timeScale=0을 요구하지 않으며 기존 인벤토리 비정지·ESC 퍼즈·Unity 시간 관리와 충돌하지 않아야 한다. 연출/카메라는 계속 진행한다. 시간 관리/ESC의 구체 결합 방식은 구현 전 검토 대상으로 남긴다.

### 4.15 정상 완료와 스킵의 공통 종료

수동/향후 자동 스킵과 정상 완료는 동일한 최종 종료 처리를 한 번만 실행한다. 보스 최종 외형/해당 페이즈 적용, 카메라 정상 추적 복귀, 양측 행동 제한 해제, 전투 쿨타임 재개, 정상 공격 선택 복귀, 연출 중복 방지, 예약/잔여 피해의 잘못된 재개 방지를 포함한다. 스킵으로 쿨타임을 초기화/즉시 완료하지 않는다. 자동 스킵 설정UI·옵션 저장 방식은 이번 범위가 아니다.

### 4.16 사망·부활·클리어와 예약 보존

기존 던전당 부활2회·현재BossRoom24x22 입구(12,2) 복귀를 유지한다. **보스 남은HP·현재 페이즈·현재 위치를 유지**하며 초기(12,14)로 강제 이동하지 않는다. 플레이어 사망 시 진행 중 공격·연계 예약·낙석/투사체/예고/잔여 판정은 정리하고 취소된 연계는 부활 후 재개하지 않는다. 완료된 등장/변신은 다시 재생하지 않는다.

HP50% 이하 전환 예약 중 플레이어가 사망하면: 공격/잔여 판정 정리 → 기존 사망/부활 → 전환 예약 유지 → 부활 후 변신 연출 → 종료 후2페이즈 전투 순서다. 최종 사망/실패 확정이면 기존 실패를 우선한다. 보스HP0은 전환보다 사망·클리어 우선이며 낙석/투사체/연계 예약을 정리하고 기존 클리어·보상·저장으로 연결한다. 동일 프레임 양측 사망의 기존 클리어 우선과 중복 보상 방지도 유지한다.

## 5. 공격 예고 시스템

### 5.1 목적

공격 예고는 플레이어가 보스의 위험 범위와 공격 발동까지 남은 시간을 인식하도록 하는 전투 정보이다.

### 5.2 예고 정보

기존 보스 공격 예고 방향은 다음과 같다.

- 공격 위험 범위를 표시한다.
- 공격 발동까지 남은 시간을 채워지는 형태로 표시한다.
- 공격이 발동되는 시점에 예고가 완료되어야 한다.

### 5.3 채움 연출

기존 메테오 공격에서 사용한 채움형 공격 예고를 다른 패턴에도 적용하도록 요청한 기록이 있다.

따라서 보스의 공격 예고를 확인할 때 메테오 외 패턴에도 발동 시간 표시가 반영되었는지 확인해야 한다.

**구현 확인 필요**

- 실제 적용된 패턴 목록
- 채워지는 방향과 형태
- 패턴별 예고 시간
- 예고 완료와 실제 피해 판정의 동기화
- 예고 취소 시 표시 정리

### 5.4 공격 범위

각 패턴의 공격 예고 범위와 실제 판정 범위는 기존 개별 패턴 명세 및 실제 구현을 따른다.

모든 공격의 실제 범위를 예고보다 일괄적으로 작게 만드는 변경안은 적용하지 않는다.

일반 몬스터의 개별 명세에 존재하는 예고·실제 반경 차이를 돌골렘에 자동 적용하지 않는다.

### 5.5 예고와 공격 일치

플레이어가 화면에서 확인한 공격 예고와 실제 공격 시점이 불일치하지 않도록 한다.

공격 예고가 끝나기 전 피해가 발생하거나, 예고가 완료된 뒤 실제 공격이 부자연스럽게 지연되는 문제가 없는지 검증한다.

## 6. 공격 판정 및 전투 피드백

### 6.1 보스 공격 판정

각 공격은 해당 패턴의 피해량과 공격 범위에 따라 플레이어에게 피해를 준다.

개별 패턴의 판정 형태, 피해 횟수 및 중복 피해 방지 방식은 실제 구현 확인이 필요하다.

### 6.2 시각적 타격감

기존 기획에서는 사운드보다 시각적 타격감과 피격감을 우선 개발하는 방향을 선택했다.

검토 대상:

- 보스 피격 플래시
- 공격 적중 이펙트
- 피해량 표시
- 피격 반응
- 사망 연출
- 무거운 공격의 화면 흔들림

모든 효과가 구현 완료된 것으로 단정하지 않는다.

### 6.3 화면 흔들림 원칙

**기존 확정 방향**

화면 흔들림은 무거운 공격의 충격을 강조할 때 사용한다.

단순 공격 준비나 투사체 발사보다 실제 충격이 발생하는 시점을 우선한다.

대표적인 충격 시점:

- 착지
- 충돌
- 폭발

위 항목은 화면 흔들림의 우선 적용 방향이며, 각 패턴에 모두 적용되었다는 의미는 아니다.

### 6.4 화면 흔들림 중복 방지

발사와 낙하 타격이 거의 동시에 발생하는 상황에서는 양쪽에 과도한 화면 흔들림이 중복되지 않도록 한다.

공격 하나의 효과를 여러 단계에서 중복 적용하여 화면을 지나치게 흔들지 않는다.

### 6.5 적용 강도

패턴별 화면 흔들림 강도와 지속 시간은 현재 인수인계 자료에 확정 수치가 없다.

실제 Unity 구현을 확인한 뒤 기존 값을 기록한다.

## 7. 보스 체력 시스템

### 7.1 기본 체력

돌골렘은 체력을 보유하며 플레이어의 공격으로 피해를 받는다.

현재 보스 최대 체력의 정확한 값은 확인되지 않았다.

### 7.2 피해 처리

플레이어의 곡괭이 공격 및 스킬로 보스에게 피해를 입힐 수 있다.

개별 공격의 피해 계산 방식은 `CombatSystem.md`와 `EquipmentSkillSystem.md`의 규칙을 따른다.

### 7.3 사망

보스 체력이 소진되면 사망 처리한다.

사망 확정 후에는 남아 있는 공격과 예고를 정리하고 던전 클리어 처리에 연결한다.

사망 연출의 세부 지속 시간과 HP바 종료 시점은 기존 구현 확인이 필요하다.

---

## 8. 보스 HP바

### 8.1 표시 위치

보스 HP바는 플레이어 HUD의 상단 중앙에 표시한다.

일반 몬스터 HP바와 구분되는 보스 전용 UI이다.

### 8.2 기본 표시 방식

보스의 현재 체력을 표시한다.

플레이어가 보스에게 피해를 입히면 현재 체력 표시가 즉시 감소한다.

### 8.3 지연 피해 표시

기존 기획에 포함된 지연 피해 표시 방식은 다음과 같다.

1. 보스가 피해를 받는다.
2. 현재 체력 표시가 즉시 감소한다.
3. 감소 전 체력 구간이 밝은 주황색 계열로 남는다.
4. 일정 시간 공격받지 않으면 주황색 구간이 현재 체력까지 감소한다.

이 방식은 플레이어가 자신이 입힌 피해량을 시각적으로 인식하도록 하기 위한 것이다.

### 8.4 연속 공격 표시

플레이어가 연속해서 보스에게 피해를 입히는 경우 누적 피해량을 인식할 수 있어야 한다.

세부 지연 방식과 감소 애니메이션은 현재 구현을 확인한다.

### 8.5 미확정 수치

- HP바 크기
- 정확한 색상값
- 주황색 잔상 대기 시간
- 잔상 감소 속도
- 보스 사망 시 HP바 종료 시점

위 항목의 실제 적용값은 Unity 프로젝트 확인이 필요하다.

### 8.6 적용하지 않는 변경안

과거 Gemini 정리 과정에서 보스 사망 연출 이후가 아닌 사망 즉시 HP바를 숨기는 변경안이 제시되었으나, 사용자가 해당 변경안을 무시하도록 요청했다.

따라서 HP바를 사망 즉시 숨기도록 강제 변경하지 않는다.

기존 구현의 표시 종료 시점을 확인한 후 유지한다.

## 9. 보스 사망과 던전 클리어

### 9.1 클리어 조건

**보스를 처치하면 던전 클리어로 처리한다.**

별도의 보상 상자를 생성하고 T 키로 상호작용하는 기존 기획은 폐기되었다.

### 9.2 사망 후 처리

보스 사망이 확정되면 다음 처리가 필요하다.

- 보스 공격 중단
- 진행 중인 공격 예고 정리
- 남아 있는 공격 판정 정리
- 활성화된 보스 공격 관련 오브젝트 정리
- 던전 클리어 처리 연동

구체적인 처리 순서는 현재 Unity 이벤트 구조와 `DungeonSystem.md`를 기준으로 검증한다.

### 9.3 보상 지급

클리어 전용 보상은 최초 결과 진입 시점에 지급하고 저장한다.

보스 사망 이벤트와 결과창 열기 동작이 중복 실행되더라도 보상을 여러 번 지급하지 않아야 한다.

### 9.4 결과창

보스 처치 후 던전 클리어 결과창이 표시된다.

결과창에는 획득한 보상과 해당 런의 전투 기록을 표시한다.

클리어 상태에서는 결과창이 열려 있어도 플레이어가 이동할 수 있다.

결과창을 닫고 주변을 돌아볼 수 있으며, 우측 하단 버튼으로 같은 결과창을 다시 열 수 있다.

결과창을 다시 열더라도 새로운 보상을 지급하지 않는다.

### 9.5 로비 복귀

결과창에서 로비로 이동하면 던전 진행을 종료한다.

이미 획득하고 저장한 보상은 유지한다.

## 10. 플레이어 사망 및 부활 연동

### 10.1 부활 규칙

플레이어의 부활 가능 횟수는 2회이다.

부활 시 현재 방 입구에서 다시 시작한다.

### 10.2 보스 방에서 사망

보스 방에서 사망하여 부활 기회가 남아 있다면 현재 보스 방의 입구에서 부활한다.

처음 입장했던 던전의 첫 방으로 돌아가지 않는다.

### 10.3 공격 정리

플레이어 사망 또는 부활 과정에서 이전 보스 공격의 잔여 판정이 문제를 일으키지 않도록 한다.

정리할 대상:

- 진행 중인 공격
- 예고 범위
- 투사체 또는 낙하 공격 관련 오브젝트
- 남은 피해 판정

### 10.4 보스 위치 유지

사용자가 적용하지 않도록 요청한 변경안 중에는 부활 시 보스 위치를 강제로 조정하는 내용이 있다.

따라서 부활을 이유로 보스 위치를 강제 변경하는 새로운 규칙은 추가하지 않는다.

### 10.5 확인 필요 사항

최신 승인으로 부활 시 보스 남은HP·현재 페이즈·현재 위치 유지가 확정됐다. 아래는 구현 일치와 미명시 재개 세부의 확인 목록이며 유지 여부를 다시 미확정으로 두지 않는다.

- 부활 시 보스 남은HP 유지의 실제 구현 일치
- 부활 시 보스 공격 상태 복구 방식
- 현재 페이즈/현재 위치·전환 예약 보존의 실제 구현 일치
- 부활 직후 전투 재개 시점
- 부활 중 입력 및 공격 판정 처리

현재 자료에 없는 규칙을 임의로 확정하지 않는다.

## 11. 맵 시스템 연동

### 11.1 보스 방

보스는 일반 방 진행 이후 연결되는 보스 방에서 전투한다.

보스 방의 최종 크기, 구조 및 카메라 경계는 `MapSystem.md`에서 관리한다.

### 11.2 벽 및 충돌

보스 이동 공격과 투사체가 내부 벽이나 맵 경계와 어떻게 상호작용하는지 확인해야 한다.

특히 다음 항목이 중요하다.

- 도약 공격과 벽
- 돌진 공격과 벽
- 돌 파편과 벽
- 낙하 공격의 타겟 위치
- 플레이어가 도달할 수 없는 공간에서의 공격

각 패턴의 실제 충돌 규칙은 현재 구현 확인이 필요하다.

### 11.3 카메라와 화면 흔들림

무거운 공격의 화면 흔들림이 발생하더라도 카메라가 맵 외부의 불필요한 빈 공간을 노출하지 않도록 검증한다.

이 규칙은 현재 검토 중인 직사각형 전체 맵 방식과도 연관된다.

### 11.4 맵 개편 시 유지 조건

맵을 변경하더라도 다음 기능을 유지해야 한다.

- 보스 공격 패턴
- 공격 예고
- 피해 판정
- 플레이어 부활
- 보스 사망 판정
- 던전 클리어 연결
- 보상 지급 및 저장

맵 구조 문제를 해결하기 위해 기존 보스 패턴을 임의로 전면 재작성하지 않는다.

## 12. 보상 시스템 연동

### 12.1 보스 처치와 보상

보스 처치는 던전 클리어 조건이며, 클리어 보상 처리와 연결된다.

정확한 보스 전용 보상 및 클리어 전용 보상 데이터는 현재 프로젝트 확인이 필요하다.

### 12.2 돈과 경험치

별도의 던전 클리어 돈 보너스와 경험치 보너스는 존재하지 않는다.

보스 자체의 처치 보상이 있다면 기존 몬스터 보상과 클리어 보상을 구분하여 확인한다.

보스의 돈·경험치 지급 여부와 정확한 수치는 현재 자료에서 확정하지 않는다.

### 12.3 보상 중복 방지

한 번의 클리어로 보상이 의도치 않게 중복 지급되지 않도록 한다.

다음 이벤트를 구분해야 한다.

- 보스 사망
- 던전 클리어 확정
- 보상 지급 및 저장
- 결과창 표시
- 결과창 재열기

실제 이벤트 구조는 Unity 코드를 확인하여 검증한다.

- 보상이 결과 진입 시 지급 및 저장되는가?
- 결과창을 닫고 다시 열어도 보상 중복 지급이 없는가?
- 클리어 결과창이 떠 있어도 이동 가능한가?
- 로비로 이동한 뒤에도 획득 보상이 유지되는가?

## 17. 문서 관리

본 문서는 돌골렘 보스의 전투 및 클리어 연동 규칙을 관리한다.

전투 공통 판정은 `CombatSystem.md`, 던전 진행은 `DungeonSystem.md`, 보상 지급은 `RewardSystem.md`, UI 세부 배치는 `UISystem.md`에서 관리한다.

새로운 보스 패턴이나 능력치 변경을 진행할 때는 다음 사항을 확인한다.

1. 기존 보스 공격 방식과의 충돌
2. 일반 몬스터 및 플레이어 시스템에 미치는 영향
3. 맵과 카메라 시스템의 영향
4. 보상 및 던전 클리어 처리 영향
5. 사용자 최종 승인 여부
6. 공식 GDD 및 관련 Systems 문서 반영
7. CHANGELOG 변경 기록

사용자 승인 없이 새로운 패턴과 수치를 확정하지 않는다.
