## 1. 시스템 개요

### 1.1 목적

던전 시스템은 플레이어의 던전 입장부터 방 진행, 보스 처치, 클리어 및 실패, 재도전과 로비 복귀까지의 흐름을 관리한다.

각 전투 방에서 몬스터를 처치하여 다음 방으로 진행하고 마지막 보스를 처치하는 구조를 기본으로 한다.

### 1.2 주요 기능

- 던전 층 및 난이도 선택
- 던전 입장 조건 검사
- 던전 플레이 시작 및 초기화
- 일반 전투 방 진행
- 몬스터 전멸 시 출구 개방
- 다음 방 이동
- 런 내부 상태 유지
- 보스 처치에 따른 클리어 처리
- 최종 사망에 따른 실패 처리
- 던전 결과 및 재도전
- 로비 복귀

## 2. 던전 선택 및 입장

### 2.1 입장 위치

플레이어는 광산 입구가 존재하는 메인 씬에서 던전에 입장한다.

입장 흐름:

1. 플레이어가 광산 입구에 접근한다.
2. T 키를 입력하여 광산 입구와 상호작용한다.
3. 던전 선택창이 열린다.
4. 입장할 층과 난이도를 선택한다.
5. 입장 조건을 만족하면 던전을 시작한다.

기존 인벤토리에서 게임 시작 버튼을 누르던 임시 입장 방식은 최신 기획에서 대체되었다.

### 2.2 층 선택

던전 선택창에서 입장할 층을 선택할 수 있다.

선택한 층에 따라 다음 정보를 갱신한다.

- 층 이름
- 선택 가능한 난이도와 관련 정보
- 입장 필요 레벨
- 대표 이미지
- 클리어 보상 정보

전체 층 수 및 층별 정확한 설정값은 확인이 필요하다.

### 2.3 난이도 선택

각 던전의 선택 화면에는 4가지 난이도가 존재한다.

난이도를 변경하면 관련 정보를 갱신한다.

- 선택한 난이도 표시
- 입장 필요 레벨
- 던전 표시 정보
- 획득 가능한 클리어 보상

**확인 필요**

- 난이도별 명칭
- 난이도별 레벨 제한
- 몬스터 능력치 차이
- 몬스터 등장 구성 차이
- 보스 구성 및 능력치 차이
- 난이도별 보상 차이

이 항목은 기존 프로젝트 설정을 확인하기 전까지 새로운 수치를 확정하지 않는다.

### 2.3.1 1층 입장 레벨·성장 초기 제안 — 미적용

쉬움Lv.1/보통Lv.3/어려움Lv.5/악몽Lv.8을 초기 밸런스 제안으로 기록한다. 1층 악몽까지 약12판·Lv.10~12 도달은 목표이며 실제 달성 테스트 결과가 아니다. 기존 레벨 조건·미설정 밸런스/배치 차단·콘텐츠 구현 여부 검사와 Editor 예외는 유지하고 실제 입장 레벨 에셋은 변경하지 않는다. 과거1층1/2/3/5 구현 기록과 구분하며 Lv.50 전체 경험치표·2층 이후는 미확정이다. 상세 초기표/검증 한계는 ProgressionSystem §3.3.1을 따른다.

### 2.4 정규 던전 입장 조건 — 최신 승인 반영

기존 콘텐츠 구현 여부와 필요 레벨 검사를 유지한다. 이전 층/던전 클리어 기록을 새 입장 조건으로 도입하지 않는다.

`현재 플레이어 레벨 ≥ 선택 던전의 입장 필요 레벨`

레벨을 충족하지 못하면 기존 부족 레벨 안내를 표시한다. 입장 불가 버튼도 안내를 표시할 수 있도록 기존 규칙을 유지한다.

여기에 2026-10-22 최신 기준으로 **데이터 준비 검사**를 추가한다. 선택 층 밸런스·선택 난이도 밸런스·해당 런의 각 후보 맵 독립 배치가 미설정/무효이면 일반 던전 입장을 차단한다. 프로필을 작성해도 콘텐츠 구현 플래그·후보·보스·필요 레벨이 자동 활성화/변경되지 않는다.

미설정 프로필과 설정 완료된 0마리는 다르다. configured=true의 빈 배치는 유효하며 방 시작 시 전멸/출구 개방으로 처리할 수 있다는 구현 보고다. HP·공격력 계산 및 유효 범위는 [MonsterSystem.md](MonsterSystem.md) §2, 배치 검증은 [MapSystem.md](MapSystem.md) §12를 따른다.

WORK_STATUS 4차는 데이터 준비 검사를 저장 Flush/런 시작 전에 수행한다고 기록한다. 이는 기존 ‘레벨만’이라는 설명에 안전 검사를 보완한 것이며, 레벨 조건을 제거하거나 클리어 해금을 되살린 것이 아니다. Editor 선택 맵 테스트 예외는 §12의 개발 전용 경로에만 적용한다.

## 3. 던전 플레이 흐름

### 3.1 기본 진행

1. 기존 입장 조건과 밸런스/독립 배치 준비 검사를 통과한 층·난이도로 던전에 입장한다.
2. 일반 전투 방에 플레이어와 몬스터를 배치한다.
3. 플레이어가 몬스터와 전투한다.
4. 모든 대상 몬스터를 처치한다.
5. 방 출구가 개방된다.
6. 출구를 이용하여 다음 방으로 이동한다.
7. 정규 진행은 일반 방 3개 → 보스 방을 유지한다.
8. 보스 처치 시 던전을 클리어한다.
9. 던전 결과를 표시한다.

### 3.2 일반 전투 방

일반 방에는 해당 방의 전투 대상 몬스터가 배치된다.

방 진행 규칙:

- 전투 대상 몬스터가 남아 있는 동안 출구를 사용할 수 없다.
- 모든 대상 몬스터가 사망하면 출구가 열린다.
- 출구를 이용하여 다음 방으로 진행한다.
- 방 이동으로 인해 진행 중인 런의 주요 데이터가 초기화되어서는 안 된다.

### 3.3 일반 방 랜덤 후보 — 정규10종

최신 사용자 승인으로1층 쉬움의 일반 후보를 기존7종에서Map01~10/Cave01 V2~Cave10의10종으로 교체한다. 전체 캔버스28×36, 세부 특징은 [MapSystem](MapSystem.md) §10.1을 따른다. 다른 층/난이도에는 동일 등록을 임의 확대하지 않는다.10종은 후보 종류 수이며 **일반3방→보스 방→결과 정산**을 유지한다.

가중치·중복 허용·선택 알고리즘은 변경하지 않는다. 이전7종·테스트맵 제외/A의맵5 편입과 과거9종 설계는 이력으로 보존하며 현행 후보에 합산하지 않는다. 일반 방은 전멸→출구 개방→다음 방, 보스 방은 출구 없이 처치→클리어/정산이다. 현재 방 입구 부활·런 상태/보상 보존과 층/난이도별 독립 배치 정책은 유지한다.

### 3.4 방 이동

방 출구를 이용하면 다음 방으로 진행한다.

방 이동 과정에서는 다음을 보장해야 한다.

- 플레이어를 다음 방의 입장 위치로 이동
- 해당 방의 몬스터 및 출구 상태 적용
- 이전 방에서 남은 공격 판정 정리
- 새로운 방의 카메라 제한 영역 적용
- 런 내부 플레이어 상태 유지

몬스터 생성 위치, 카메라 처리 및 상세 방 교체 방식은 맵 시스템과 연동한다.

---

### 3.5 1층 쉬움 1차 플레이 시간 목표와 검증 계획

사용자 승인 테스트 목표는 입장부터 돌골렘 처치까지300~360초, 중앙330초다. 일반3방 각각55초(50~60), 보스150초(120~180), 이동/전환15초로 합계330초다. 로비 준비/결과창 읽기는 제외한다. 퍼즈·변신 연출·부활 대기는 가능한 별도 기록하되 전체에서 자동 제외하는 새 규칙은 만들지 않는다. 일반 전투의 빠른 처치/속도감과 보스 예고→회피→반격의 재미를 확인한다.

후속 Codex는 현재 플레이어/공용 무기·물약·일반5종 원본/층·난이도 프로필·10맵 배치/좌표·보스 피해 필드·EXP 연결/기존 검증 도구를 읽기 전용 조사한다. 공용 영향은 [PlayerSystem](PlayerSystem.md) §2.4의 사전 보고/별도 승인 조건을 따른다. 현재값이 같으면 불필요하게 변경하지 않고 기존 구조를 재사용한다.

전체/일반1~3/보스P1·P2/종류별 처치시간·가한/받은 피해·물약/부활·실패/획득EXP·추적/공격불능/대기·프레임 저하·가능한 시간 하위 구간을 기록한다. API 강제 처치·무적 런은 사람 전투 소요시간으로 쓰지 않는다. 일반 방이 길면 AI/동선/배치를 먼저 분석하고 수량1마리 단위 조정을 검토한다. 보스120초 미만/180초 초과는HP 상향/하향 검토 기준이며 최초약10% 이내 단계적 조정과 공격 기회/대기를 함께 제안한다. 이는 측정 후 사용자 승인용 기준으로 자동 변경 권한이 아니다. 여러 조합/사용자 플레이에서 목표 미달이면 차이와 원인을 기록한다. 초기 생존 관찰은 부활0~1회·물약1~2개, 패턴 대응 시 클리어/무시 시 사망 위험이며 최종 난이도 지표가 아니다.

WORK_STATUS의25일 초기 수치 적용 보고는 정상 자동2회 모두 실패·사람 클리어0회다. 무적 기능런은 진행/정산용이며 목표 달성 증거가 아니다. 이번에 적용·Play·실측을 하지 않았고 최종 밸런스는 미확정이다.

## 4. 런(Run) 상태 관리

### 4.1 런의 범위

한 번의 런은 선택한 던전과 난이도에 입장하여 클리어 또는 실패 결과에 도달하는 던전 플레이 단위를 의미한다.

결과창을 닫거나 다시 여는 행위는 새로운 런의 시작이 아니다.

### 4.2 방 이동 시 유지할 정보

| 정보 | 방 이동 시 처리 |
|---|---|
| 현재 체력 | 유지 |
| 남은 물약 | 유지 |
| 남은 부활 횟수 | 유지 |
| 획득한 돈 | 유지 |
| 획득한 경험치 | 유지 |
| 획득한 아이템 및 재료 | 유지 |
| 전투 기록 | 누적 유지 |

방 이동만을 이유로 체력, 물약, 부활 횟수 또는 전투 기록을 초기화하지 않는다.

### 4.3 영구 데이터와 런 데이터

던전 시스템은 런 내부에서 관리하는 상태와 영구 보유 데이터를 구분한다.

**런 내부 데이터**

- 현재 진행 중인 던전 및 난이도
- 현재 방 진행 상태
- 현재 체력
- 남은 물약
- 남은 부활 횟수
- 해당 런의 전투 기록

**영구 유지 대상**

- 돈과 경험치
- 레벨 및 성장 정보
- 획득 재료·아이템
- 스킬 보유 및 장착 정보
- 곡괭이·장비 정보

던전 보상은 저장 시스템과 연동한다.

획득한 보상은 방 이동 또는 결과창 전환 과정에서 사라지지 않아야 한다.

### 4.4 성장 구성 고정과 패시브의 방 전환 — 2026-10-22 승인 기획

던전 입장 시 성장 구성을 고정한다. 던전 내부 인벤토리는 장비·스킬·스탯·패시브 열람만 허용하고 장비/스킬 교체·스탯 투자/초기화는 불가하다. 메인에서만 투자 및 골드 초기화가 가능하다. 인벤토리 시간 계속 진행, 기존 입력 제한·일반3방→보스→정산·부활2회/현재 방 입구·물약·보상/저장 규칙을 유지한다.

신규 패시브는 일반 방 클리어 시 최대HP10% 회복, 재생의 방 클리어 즉시 중단/방 이동·부활 한도 초기화, 물리 강화 충전의 방 이동 유지/사망·부활 초기화라는 별도 규칙을 따른다. 이는 방 이동 자체가 체력/물약/생명을 전부 초기화한다는 뜻이 아니다. 구체 효과·해금은 ProgressionSystem §4와 PlayerSystem을 참조한다.

던전 중 획득EXP·레벨·미사용P의 영구 보존은 계속 유지한다. 자동 레벨 상승과 고정 성장 구성의 세부 적용 범위는 구현 전에 검토한다. 이번 신규 기획은 구현 완료 보고가 아니며 기존 Editor 선택 맵 테스트에 새 성장/장비 선택 기능이 이미 생겼다고 표시하지 않는다.

## 5. 부활 및 던전 실패

### 5.1 부활 횟수

확정된 규칙은 다음과 같다.

- 최초 생명을 포함한 총 생명: 3개
- 부활 가능 횟수: 2회

| 사망 횟수 | 남은 생명 | 처리 |
|---|---:|---|
| 0회 | 3 | 정상 플레이 |
| 1회 | 2 | 부활 |
| 2회 | 1 | 부활 |
| 3회 | 0 | 던전 실패 |

기존의 부활 3회 규칙은 폐기되었다.

### 5.2 부활 위치

플레이어는 현재 진행 중인 방의 입구에서 부활한다.

처음 던전에 입장했던 방으로 돌아가지 않는다.

보스 위치를 강제로 변경하는 추가 규칙은 적용하지 않는다.

### 5.3 던전 실패

부활 2회를 모두 사용한 뒤 다시 사망하면 던전 실패로 처리한다.

실패 시 다음 규칙을 적용한다.

- 플레이어는 사망 상태를 유지한다.
- 결과창을 닫더라도 이동 가능 상태로 복구하지 않는다.
- 이미 획득한 보상은 유지한다.
- 아직 획득하지 않은 클리어 보상은 지급하지 않는다.

플레이어 부활 동작과 생명 HUD의 상세 사항은 `PlayerSystem.md`에서 관리한다.

## 6. 보스 방 및 던전 클리어

### 6.1 보스 방

일반 방을 진행한 뒤 보스 방에 도달한다.

현재 확인된 보스는 돌골렘이다.

돌골렘은 5종 공격 패턴을 기준으로 개발이 진행되었다.

정확한 보스 능력치 및 개별 공격 규칙은 `BossSystem.md`에서 관리한다.1층 쉬움 정규 보스 방은BossRoom24x22로 교체 승인/구현 보고가 있다. 출구 문/방벽/불필요한 충돌체가 없고 보스 처치로 기존 클리어/정산에 연결한다. 일반 방 출구 규칙은 유지한다. 입장/부활은 현재 보스 방 입구(12,2), 부활2회·보스 위치 강제 초기화 금지를 유지한다. 다른 층/난이도는 별도 확인 대상이다.

### 6.1.1 보스 최초 등장·페이즈·부활 연결 — 신규 승인

보스1차 구현과후속 집중검증 보고가 있다. 전체 반복/빌드·실제 등장/변신 아트는27일 부분 완료 보고이며 카메라 가시성/스킵UI는 후속이다(BossSystem §4.19). 일반3방→BossRoom24x22→결과 정산과1층 쉬움 정규 등록·출구 없는 보스 클리어는 유지한다. 첫 진입은 등장 연출, 같은 보스전 부활은 완료된 등장을 반복하지 않는다.

HP50% 이하에서 전환을 예약하고 진행 중 공격 종료 뒤 변신한다. 예약 중 새1페이즈 공격을 시작하지 않고 정상 종료/스킵 후2페이즈로 진행한다. 플레이어 사망은 공격/연계·잔여 판정을 취소하지만 전환 예약은 보존한다. 부활 후 예약 변신을 수행하며 완료된 변신은 재생하지 않는다. 취소된 연계를 재개하지 않는다. 부활2회/현재 입구(12,2), 보스HP·페이즈·현재위치 유지를 따른다.

최종 사망/실패는 기존 실패 우선, 보스HP0은 변신보다 사망/클리어 우선이다. 보스 사망 시 낙석·투사체·연계 예약 정리 후 기존 클리어·보상·정산·저장으로 연결하고 동일 프레임 클리어 우선/중복 보상 방지·다시하기/로비 복귀 흐름을 유지한다. 수동/향후 자동 스킵은 정상 완료와 같은 최종 상태로 한 번만 종료하고 쿨타임을 초기화하지 않는다. 상세는 [BossSystem](BossSystem.md) §4.8~4.16이다.

### 6.2 클리어 조건

**보스를 처치하면 해당 던전을 클리어한다.**

보스 처치 후 기존의 보상 상자 상호작용을 요구하지 않는다.

최신 보상 처리 방향:

1. 보스 처치
2. 던전 클리어 처리
3. 클리어 보상 지급 및 저장
4. 던전 결과창 표시

보상 확정은 최초 결과 표시 시점에 수행하며 결과창의 열기·닫기 동작과 분리한다.

### 6.3 클리어 이후 상태

클리어 결과창이 표시되어도 플레이어는 이동할 수 있다.

결과창을 닫고 주변을 돌아볼 수 있다.

닫힌 결과창은 별도의 버튼을 통해 다시 열 수 있다.

결과창을 다시 열어도 보상이 중복 지급되거나 새 런이 시작되지 않는다.

이동 외 공격과 스킬 사용 가능 범위는 현재 구현 확인이 필요하다.

## 7. 던전 보상 연동

### 7.1 몬스터 처치 보상

몬스터를 처치하면 돈과 경험치를 즉시 획득한다. 같은 층·난이도·몬스터 종류는 어느 맵에서도 동일EXP를 지급하고 맵 총EXP는 실제 종류·수량에 따라 달라진다. 방·던전 클리어EXP 보너스는 없으며 실패해도 이미 획득한EXP는 유지한다.

일반 몬스터 재료 드롭은 다음 공통 명세를 따른다.

- 드롭 성공 확률: 50%
- 성공 시 수량: 1~2개

자세한 드롭 처리 및 개별 보상은 `RewardSystem.md`에서 관리한다.

### 7.2 클리어 보상

던전 클리어 시 클리어 전용 아이템 보상을 지급한다.

별도의 클리어 돈·경험치 보너스는 없다.

이미 획득한 몬스터 처치 보상을 결과창에서 다시 지급하지 않는다.

### 7.3 실패 보상

던전 실패 시 이미 획득한 보상을 100% 유지한다.

- 돈
- 경험치
- 재료
- 이미 획득한 아이템

아직 획득하지 않은 보스 및 클리어 전용 보상은 지급하지 않는다.

### 7.4 보상 지급과 저장

클리어 보상은 결과창 최초 진입 시점에 지급하고 저장한다.

다음 행동으로 인해 보상이 손실되거나 중복 지급되어서는 안 된다.

- 결과창 닫기
- 결과창 다시 열기
- 결과창에서 로비로 이동
- 퍼즈 메뉴에서 로비로 이동
- 게임 종료 및 재실행

정확한 저장 처리 방식은 `SaveSystem.md`에 따른다.

### 7.5 1층 쉬움 완주 EXP 예상 — 초기안 계산값

> 아래7맵 예상EXP/완주187~216·평균약199.71은 과거7종/당시 배치 계산 자료다. 현재10종에 적용하지 않는다.27일 승인10맵 배치의 별도 산술 예상은 RewardSystem §2.7을 따른다.

1마리 EXP 초기안은 돌4/철5/수정5/석탄4/자철석6/돌골렘45다. Map_01~07의 일반 방 예상EXP는47/57/52/48/57/52/48이다. 일반3방+보스 완주 최소187·최대216·평균약199.71EXP는 당시 사용자 제공 배치·선택 알고리즘 기준 계산이며 실제 적용·실행 검증 완료가 아니다.

기존 맵 후보/선택·독립 몬스터 배치·일반3방→보스→정산·부활·획득 보상 유지 규칙을 바꾸지 않는다. 보스45EXP를 클리어 보너스로 중복 지급하지 않는다. 배치/후보 변화 시 예상값을 재계산하고 상위 난도·2층 이후 지급량은 미확정으로 남긴다. 상세 표/계산 전제는 [RewardSystem](RewardSystem.md) §2.5~2.6을 따른다.

## 8. 던전 결과 처리

### 8.1 결과 유형

결과 유형은 클리어와 실패로 구분한다.

**클리어**

- 보스 처치 시 발생
- 클리어 전용 보상 지급 대상
- 플레이어 이동 가능

**실패**

- 부활 2회 소모 후 최종 사망 시 발생
- 이미 획득한 보상 유지
- 플레이어 이동 불가

### 8.2 결과창 기능

결과창은 획득 보상과 전투 기록을 표시한다.

주요 기록:

1. 클리어 시간 또는 진행 시간
2. 넣은 데미지
3. 받은 피해량
4. 회복량
5. 처치한 몬스터 수
6. 사용한 부활 횟수

전투 기록은 해당 런 전체를 기준으로 유지한다.

### 8.3 결과창 닫기 및 재열기

- 결과창을 닫을 수 있다.
- 닫힌 상태에서 우측 하단에 다시 열기 버튼을 표시한다.
- 다시 열면 동일한 런의 결과를 표시한다.
- 결과 확인으로 보상이 다시 지급되지 않는다.
- 결과창을 닫는 것만으로 새 런이 시작되지 않는다.

결과창의 레이아웃, 색상, 연출 및 상세 UI는 `UISystem.md`에서 관리한다.

### 8.4 전투 기록의 미확정 계산 규칙

다음 사항은 기존 구현 확인이 필요하다.

- 초과 피해를 총 피해량에 포함하는지
- 최대 체력을 초과하는 회복량을 제외하는지
- 부활 시 체력 복원을 회복량에 포함하는지
- 퍼즈 시간 및 로딩 시간을 진행 시간에서 제외하는지

---

### 8.5 Tab 지도와 방/런 상태 — 신규 승인

방 이동 시작/사망·부활/보스 등장·변신/주요UI 열림에는 즉시 지도를 숨긴다. 이전 방 지형/몬스터/출구 표시를 새 방에 남기지 않고 부활 후 실제 몬스터/보스 위치·생존 상태를 읽는다. 보스HP·페이즈·위치를 초기화하지 않는다. 각 차단 종료 후 정상 상태에서 Tab을 놓고 다시 눌러야 하며 남은 홀드로 자동 복귀하지 않는다.

일반 출구 잠김/개방을 표시하고 출구 없는 보스룸에는 아이콘을 두지 않는다. 클리어 결과창은 열림/재열기 시 숨김, 닫고 기존 이동이 허용되면 새 Tab 입력으로 현재 보스 방 지도를 허용한다. 기존 공격/스킬/물약 제한은 확대하지 않는다. 실패는 창을 닫아도 사망 상태라 지도 금지다. 부활2회·현재 입구·런 데이터/보상/정산/저장·결과 재열기를 보존한다. 상세는 [UISystem](UISystem.md) §3.6/[MapSystem](MapSystem.md) §16.6이며 지도 구현/회귀는 미검증이다.

일반 방 파괴 장식8개는 전멸/출구 개방·클리어 조건에서 제외한다. 출구 시각/VFX 종료를 이동 조건에 추가하지 않는다([MapSystem](MapSystem.md) §7.6/11.9).

## 9. 다시 시작 및 로비 복귀

### 9.1 다시 시작

결과창의 다시 시작 버튼을 선택하면 동일한 층과 난이도로 새로운 런을 시작한다.

**확정 초기화 규칙**

- 첫 번째 방부터 시작
- 플레이어 체력 초기화
- 물약 3개로 초기화
- 부활 가능 횟수 2회로 초기화

기존 영구 성장 및 획득 보상은 유지한다.

새 런에서 이전 결과창의 결과나 보상 지급 상태를 재사용하여 중복 지급이 발생해서는 안 된다.

### 9.1.1 다시하기 로비 지형 중첩 수정 — 구현 이력

WORK_STATUS는 다시하기 후MainMineEntrance/MainGround가 새 던전과 겹치던 비활성화 누락과 DungeonRunSettlement.cs/MineEntranceUI.cs 수정을 보고한다. 새 던전 시작 성공 시 기존 로비 비활성화를 적용하고 실패 시 로비를 유지한다. 사용자 직접 플레이의 개선 확인과 제한된 수동 확인 기록은 있으나 여러 차례 다시하기/로비 재입장 전체 회귀 완료가 아니다. 기존 같은 층/난이도·새 방·자원 초기화·영구 데이터 보존 흐름을 변경하는 신규 기획이 아니다.

### 9.2 로비로 이동

로비로 이동하면 현재 던전 진행을 종료하고 메인 로비로 돌아간다.

이미 획득하고 저장한 보상은 유지한다.

로비 복귀를 위해 결과창의 보상 지급 버튼이나 별도의 보상 상자 상호작용을 요구하지 않는다.

### 9.3 퍼즈 메뉴와 로비 이동

퍼즈 메뉴를 통해 로비로 이동하더라도 이미 획득한 보상은 사라지지 않아야 한다.

단, 클리어·실패가 확정되기 전 자발적으로 던전을 종료하는 행위의 상세 종료 규칙은 현재 자료만으로 확정할 수 없다.

해당 부분은 기존 구현 확인 및 별도 검토 대상으로 남긴다.

### 10.1 맵 변경 시 유의사항

2026-10-21 승인된 맵 구조·후보 개편을 적용하더라도 다음 기존 기능을 유지한다.

- 방 전멸 판정
- 출구 개방
- 다음 방 진행
- 현재 방 입구 부활
- 플레이어 런 데이터 유지
- 보상 지급 및 저장

### 10.2 몬스터 확장 시 유의사항

돌 몬스터뿐 아니라 철, 수정, 석탄, 자철석 몬스터도 방 전멸 판정에 정상적으로 연결되어야 한다.

몬스터 종류에 따라 출구 개방 판정이 누락되지 않도록 한다.

### 10.3 결과 및 저장 연동 주의사항

결과창을 닫거나 로비로 이동할 때 보상이 사라지지 않아야 한다.

동일한 런의 결과를 다시 확인하는 것만으로 보상이 반복 지급되어서는 안 된다.
