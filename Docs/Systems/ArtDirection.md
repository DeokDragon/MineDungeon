## 1. 문서 개요

### 1.1 목적

본 문서는 광산던전의 캐릭터, 몬스터, 배경, 장비, UI 및 전투 시각 효과의 제작·적용 방향을 관리한다.

현재 사용 중인 Unity 그래픽과 기존 UI를 존중하면서 향후 외부 아트 리소스의 도입과 교체 작업을 위한 기준을 마련한다.

### 1.2 프로젝트 기본 정보

- 게임 장르: 2D 탑뷰 싱글플레이 액션 던전
- 개발 엔진: Unity 6000.3.12f1 LTS
- 기준 해상도: 1920 × 1080
- 핵심 소재: 광산, 광물 몬스터, 곡괭이, 던전 탐험
- 아트 방향: 도트 느낌 검토 중
- 최종 픽셀 아트 규격: 미확정

### 1.3 문서 관리 범위

- 전체적인 그래픽 방향
- 캐릭터와 몬스터 시각적 구분
- 배경 및 지형 아트
- 장비와 아이템 아이콘
- UI 스타일 및 레퍼런스 사용
- 전투 시각 효과
- 외부 아트 리소스 도입
- Unity 적용 및 검증 원칙

본 문서는 전투 피해량, 몬스터 AI, 맵 진행 규칙 또는 아이템 보상 자체를 변경하지 않는다.

## 2. 전체 아트 방향

### 2.1 기본 방향

광산던전은 간단한 2D 그래픽을 기반으로 제작하고 있다.

광산 탐험과 광물 몬스터의 특징이 시각적으로 구분되는 게임을 지향한다.

도트 느낌의 그래픽을 고려하고 있으나 최종 스타일은 확정되지 않았다.

### 2.2 검토 중인 도트 아트

현재 기획 자료에는 다음 사실이 기록되어 있다.

- 도트 느낌을 고려 중이다.
- 최종 타일 크기는 정해지지 않았다.
- 캐릭터 해상도는 정해지지 않았다.
- 색상 팔레트는 정해지지 않았다.
- 모든 UI를 픽셀 규격으로 제작한다고 확정하지 않았다.

따라서 도트 아트 검토를 전체 그래픽의 픽셀 아트 전환 확정으로 해석하지 않는다.

### 2.3 아트 적용 원칙

- 현재 정상적으로 작동하는 게임 시스템을 우선 보존한다.
- 외형을 변경하더라도 충돌과 공격 판정이 불필요하게 변경되지 않도록 한다.
- 기존 UI와 새로운 아트 사이의 일관성을 검토한다.
- 실제 에셋과 현재 Unity 프리팹을 확인한 뒤 적용한다.
- 아직 정해지지 않은 아트 규격을 임의로 확정하지 않는다.

### 2.4 미확정 항목

| 항목 | 상태 |
|---|---|
| 최종 그래픽 스타일 | 검토 중 |
| 스프라이트 기본 크기 | 미확정 |
| 픽셀 퍼 유닛(PPU) | 미확정 |
| 타일 크기 | 미확정 |
| 색상 팔레트 | 미확정 |
| 픽셀 필터링 방식 | 미확정 |
| 조명 표현 방식 | 미확정 |
| 캐릭터 애니메이션 프레임 수 | 미확정 |
| UI의 픽셀 아트 적용 범위 | 미확정 |

## 3. 플레이어 캐릭터 아트

### 3.1 기본 콘셉트

플레이어는 광산을 탐험하며 곡괭이를 사용하는 캐릭터이다.

현재 인수인계 자료에는 플레이어 외형의 세부 디자인이나 최종 캐릭터 스프라이트가 명시되어 있지 않다.

### 3.2 제작 시 확인할 항목

- 캐릭터의 기본 외형
- 캐릭터 크기
- 탑뷰 이동 방향 표현
- 대기 및 이동 애니메이션
- 곡괭이 기본 공격 표현
- 회피 표현
- 피격 및 사망 표현
- 스킬 사용 표현

이 항목들은 아트 제작 시 검토할 대상으로, 모두 현재 구현되었다는 의미는 아니다.

### 3.3 공격 애니메이션 연동

곡괭이 공격 애니메이션은 기존 기본 공격 시스템과 연동되어야 한다.

다음 요소가 서로 불일치하지 않도록 검증한다.

- 곡괭이 스프라이트
- 공격 방향
- 공격 판정 위치
- 실제 공격 범위
- 공격 발생 시점

애니메이션 변경을 이유로 공격력이나 공격 범위를 임의로 변경하지 않는다.

### 3.4 이동 및 충돌

캐릭터 스프라이트를 교체하더라도 기존 이동과 벽 충돌이 정상적으로 작동해야 한다.

외형의 중심과 실제 캐릭터 위치가 어긋나는지 확인한다.

### 3.5 부활 및 사망

플레이어는 던전에서 2회 부활할 수 있으며 현재 방 입구에서 부활한다.

사망·부활 관련 그래픽을 적용할 때 이 기능을 변경하지 않는다.

사망 및 부활 애니메이션의 세부 규격은 현재 미확정이다.

## 4. 일반 몬스터 아트

### 4.1 기본 방향

일반 몬스터는 광물 소재별 특징을 가지는 적이다.

현재 일반 몬스터 상세 명세는 총 5종이다.

| 몬스터 | 소재 | 기존 공격 특성 |
|---|---|---|
| 돌 | 돌 | 도약 공격 |
| 철 | 철 | 직선 돌진 |
| 수정 | 수정 | 원거리 파편 |
| 석탄 | 석탄 | 근접 열기 폭발 |
| 자철석 | 자철석 | 자기장 및 감속 |

### 4.2 외형 차별화

몬스터의 실제 스프라이트를 선정하거나 제작할 때 각 몬스터 종류를 구분할 수 있는지 검토한다.

구체적인 실루엣, 크기 및 색상은 미확정이다.

개별 외형이 아직 제공되지 않았으므로 새로운 몬스터 디자인을 확정하지 않는다.

### 4.3 돌 몬스터

도약 공격을 사용하는 몬스터이다.

향후 아트를 적용할 때 이동, 도약, 착지 및 피격 표현이 기존 공격과 일치하는지 확인한다.

### 4.4 철 몬스터

직선 돌진 공격을 사용하는 몬스터이다.

돌진 방향과 실제 이동이 시각적으로 어긋나지 않는지 확인한다.

돌진 애니메이션 변경을 이유로 방향 고정 규칙을 변경하지 않는다.

### 4.5 수정 몬스터

직선 수정 파편을 발사한다.

투사체의 시각적 크기와 실제 판정이 일치하는지 검토한다.

스프라이트를 교체하더라도 투사체가 벽에 충돌하면 소멸하는 기존 규칙을 유지한다.

### 4.6 석탄 몬스터

몬스터 주변에 열기 폭발을 발생시킨다.

기존 기획에서 공격 예고 중 몸체가 달아오르는 표현이 논의되었다.

공격 후에도 생존하여 반복 공격하는 몬스터이며, 자폭형으로 변경하지 않는다.

### 4.7 자철석 몬스터

자기장 공격과 이동 속도 감소 효과를 사용한다.

자기장 예고는 고정된 위치에 표시되며, 감속 효과는 기존 수치를 따른다.

자기장 아트가 지속 피해를 발생시키는 새로운 게임 규칙으로 연결되어서는 안 된다.

### 4.8 공통 검증 사항

- 몬스터 외형과 충돌체의 정렬
- 공격 예고와 스프라이트 정렬
- 피격 플래시 표시
- 사망 연출
- 몬스터 HP바 위치
- 도약·돌진·투사체 효과
- 맵의 벽과 크기 비율

몬스터별 최종 스프라이트, 애니메이션 프레임 수 및 색상은 현재 미확정이다.

## 5. 보스 아트

### 5.1 현재 보스

현재 보스는 돌골렘이다.

돌골렘은 기존 5종 공격 패턴을 기준으로 개발되었다.

### 5.2 공격 패턴과 시각 효과

보스 패턴 계열:

1. 도약 내려찍기
2. 주변 강타
3. 바위 돌진
4. 부채꼴 돌 파편
5. 메테오 또는 낙석

세부 패턴명과 수치는 `BossSystem.md` 및 Unity 프로젝트를 확인한다.

### 5.3 공격 예고

보스 공격은 위험 범위와 공격 발동까지 남은 시간을 표시한다.

기존 메테오 패턴의 채움형 예고를 다른 패턴에도 적용하도록 작업을 요청한 기록이 있다.

공격 예고의 시각적 표현을 변경하더라도 실제 발동 시점과 일치해야 한다.

### 5.4 충격 연출

무거운 공격의 화면 흔들림은 실제 충격 시점을 중심으로 사용한다.

대표적인 검토 대상:

- 착지
- 충돌
- 폭발

모든 공격에 동일한 화면 흔들림을 적용하지 않는다.

### 5.5 보스 HP바

보스 HP바는 HUD 상단 중앙에 배치한다.

현재 체력은 즉시 감소하며 이전 체력 구간이 밝은 주황색으로 남아 있다가 지연 감소하는 구조이다.

보스 HP바의 정확한 색상값, 감소 속도 및 사망 시 종료 시점은 현재 구현 확인이 필요하다.

### 5.6 사망 연출

보스 사망은 던전 클리어 및 결과창 표시와 연동된다.

사망 연출을 변경하더라도 클리어 보상 지급·저장과 결과창 처리에 영향을 주지 않아야 한다.

보스 사망 즉시 HP바를 숨기도록 강제 변경하는 과거 제안은 적용하지 않는다.

## 6. 맵 및 배경 아트

### 6.1 기본 소재

게임의 주요 배경은 광산과 던전이다.

기존 일반 방 9종의 구조가 존재한다.

### 6.2 설계도와 실제 게임 아트

기존 맵 설계도에 사용한 색상과 도형은 제작용 구분 표기이다.

- 초록색 네모: 플레이어 입구
- 빨간색 네모: 출구
- 주황색 원: 몬스터 배치 영역
- 연보라색: 이동 가능한 바닥

위 색상과 도형을 실제 게임 아트로 그대로 구현해야 하는 것은 아니다.

### 6.3 바닥 및 벽

바닥은 플레이어가 이동 가능한 영역을 나타낸다.

벽은 플레이어와 몬스터의 이동을 막는다.

바닥과 벽의 최종 타일 그래픽, 소재 표현 및 크기는 현재 미확정이다.

### 6.4 최신 맵 개선안

**현재 재검토 중인 방향**

전체 맵을 직사각형 캔버스로 구성하고 실제 이동하지 않는 영역을 암석 또는 암벽으로 채우는 방식이다.

전체 캔버스가 직사각형이더라도 이동 가능한 공간의 실제 형태는 유지할 수 있다.

이 방식은 아직 최종 승인된 맵 구조가 아니다.

### 6.5 암석·암벽 표현

현재 논의된 암석·암벽은 이동 불가 공간을 채우는 지형 요소이다.

아트만 보고 다음 기능을 자동으로 추가하지 않는다.

- 채광
- 파괴
- 숨겨진 통로
- 상호작용

별도 기능은 사용자 승인이 필요하다.

### 6.6 카메라와 지형

내부 벽과 암석은 카메라 화면에 표시할 수 있는 지형이다.

카메라 제한 경계와 캐릭터 이동을 막는 벽은 구분한다.

배경 아트를 적용하더라도 카메라 경계, 화면 흔들림 및 기존 충돌 기능을 유지한다.

### 6.7 타일 및 스프라이트 규격

다음 사항은 미확정이다.

- 타일 해상도
- 타일의 Unity 월드 크기
- PPU
- 벽 스프라이트 높이
- 바닥과 벽의 표시 순서
- 반복 타일의 연결 방식
- 배경의 색상 팔레트
- 외곽 암석의 최종 디자인

맵의 실제 크기는 이미지 픽셀 크기만으로 결정하지 않는다.

## 7. 장비 및 아이템 아트

### 7.1 곡괭이

곡괭이는 플레이어의 주요 무기이다.

곡괭이 종류에 따라 공격력과 범위가 다를 수 있는 기존 기획을 유지한다.

### 7.2 곡괭이 그래픽

곡괭이 아트 제작 또는 교체 시 확인할 항목:

- 곡괭이 스프라이트
- 캐릭터와의 크기 비율
- 공격 동작에서의 배치
- 회전 중심과 피벗
- 공격 애니메이션과의 정렬
- 인벤토리 아이콘

곡괭이별 외형과 능력치를 아직 새로 확정하지 않는다.

### 7.3 제작 재료 아이콘

일반 몬스터의 재료 계열은 다음과 같다.

- 돌
- 철
- 수정
- 석탄
- 자철석

각 재료의 최종 아이콘 형태와 해상도는 확인이 필요하다.

### 7.4 아이템 희귀도

기존 UI에 적용되는 희귀도 색상 기준:

| 희귀도 | 색상 |
|---|---|
| 일반 | 회색 |
| 고급 | 초록 |
| 희귀 | 파랑 |
| 영웅 | 보라 |
| 전설 | 금색 |

희귀도 테두리는 아이템 분류 및 보유 상태와 구분하여 표시한다.

모든 장비와 스킬에 동일한 희귀도 단계가 존재하는지는 실제 데이터를 확인한다.

### 7.5 신규 무기 추가 제한

### 8.4 인벤토리

- 장착 표시
- 분류 탭
- 검색

- 아이템 툴팁

### 8.7 UI 시간 처리

인벤토리와 던전 선택창은 열려 있어도 게임 시간을 정지시키지 않는다.

## 10. 전투 이펙트

### 10.1 기본 방향

기존 기획에서는 시각적 타격감과 피격감 개선을 우선 진행하기로 했다.

사운드는 후속 작업 대상으로 검토했다.

### 10.2 타격 이펙트

공격이 적중했다는 사실을 시각적으로 전달하는 효과이다.

구체적인 형태, 크기, 색상 및 애니메이션은 미확정이다.

### 10.3 피격 플래시

몬스터가 피해를 받았음을 표현한다.

플래시의 정확한 색상과 지속 시간은 기존 구현 확인이 필요하다.

### 10.4 피해량 표시

피해량을 숫자 등으로 표시하는 기능이 검토되었다.

세부 항목:

- 표시 위치
- 글자 크기
- 색상
- 이동 애니메이션
- 사라지는 연출

현재 모든 세부 항목의 규격이 확정된 것은 아니다.

### 10.5 사망 연출

몬스터와 보스의 사망을 시각적으로 표현한다.

사망 연출과 실제 처치 이벤트를 구분하여 기존 보상 지급 및 방 진행 기능을 유지한다.

### 10.6 공격 예고

기존 몬스터와 보스의 공격 예고는 실제 공격 범위 및 발동 시점과 연동된다.

이펙트가 바뀌더라도 공격 판정을 임의로 확대하거나 축소하지 않는다.

### 10.7 화면 흔들림

화면 흔들림은 무거운 공격을 중심으로 사용한다.

착지·충돌·폭발과 같은 충격 시점을 우선한다.

모든 공격에 강한 화면 흔들림을 자동 적용하지 않는다.

## 11. 외부 아트 리소스 도입

### 11.1 도입 방향

사용자는 향후 몬스터와 맵 아트를 확보한 뒤 Unity 프로젝트에 넣고 Codex를 통해 배치 및 적용하는 흐름을 고려하고 있다.

현재 특정 아트 패키지가 최종 확정된 것은 아니다.

### 11.2 적용 전 확인 항목

| 항목 | 확인 내용 |
|---|---|
| 파일 구성 | 폴더와 개별 파일 구조 |
| 리소스 종류 | 스프라이트 또는 다른 모델 형식 |
| 크기 | 원본 이미지 및 실제 사용 크기 |
| 피벗 | 배치·회전 기준 위치 |
| 애니메이션 | 제공되는 동작과 프레임 |
| 충돌체 | 기존 이동 및 피격 판정과의 관계 |
| 공격 예고 | 시각적 범위와 실제 판정 정렬 |
| 라이선스 | 게임 프로젝트 사용 가능 범위 |

### 11.3 리소스 사용 권한

외부 리소스를 사용하기 전에 해당 라이선스와 사용 조건을 확인한다.

확인이 필요한 항목:

- 게임 사용 허용 여부
- 수정 허용 여부
- 배포 가능 여부
- 출처 표기 의무
- 유료·무료 사용 조건

특정 에셋의 라이선스가 확인되지 않았을 때 자유롭게 사용 가능하다고 단정하지 않는다.

### 11.4 Unity 기존 리소스 보존

아트 적용 과정에서 기존 정상 동작 기능이 손상되지 않아야 한다.

특히 다음 사항을 확인한다.

- 프리팹 참조
- 스크립트 참조
- 애니메이션 연결
- 충돌체
- 공격 판정
- 카메라
- 맵 출구 및 입구
- 몬스터 배치

### 11.5 메타데이터 보존

기존 Unity 에셋의 `.meta` 및 GUID를 불필요하게 변경하지 않는다.

기존 프리팹과 다른 오브젝트의 참조가 끊어지지 않도록 한다.

### 11.6 에셋 교체

스프라이트 교체만으로 해결할 수 있는 부분과 프리팹·애니메이션·충돌체 수정이 필요한 부분을 구분한다.

실제 구현 방식은 Codex가 Unity 프로젝트를 확인한 후 판단한다.

## 12. 아트와 맵 시스템의 관계

### 12.1 맵 변경

현재 일반 방 9종은 설계가 존재하지만 Unity 구현 결과 문제로 인해 재검토 중이다.

새로운 아트 작업이 기존 맵의 최종 구조 확정을 대신하지 않는다.

### 12.2 최신 개선 방향

직사각형 캔버스 및 암석·암벽 채움은 현재 맵 구조의 개선 제안이다.

실제 적용 여부와 규격은 맵 시스템에서 결정한다.

### 12.3 충돌과 시각 표현

지형 스프라이트의 형태와 실제 충돌 영역이 플레이어에게 혼란을 주지 않는지 확인한다.

단, 새로운 충돌 규칙은 아트 문서에서 임의로 확정하지 않는다.

### 12.4 카메라

내부 벽과 암석을 화면에 표시하는 기존 카메라 방향을 유지한다.

화면 흔들림과 맵 경계 처리도 함께 검증한다.

### 12.5 몬스터 가독성

맵 아트와 몬스터 아트를 함께 적용한 후 다음을 확인한다.

- 몬스터의 위치를 인식할 수 있는가?
- 공격 예고가 배경에 묻히지 않는가?
- 플레이어가 이동 가능 영역을 구분할 수 있는가?
- 출구를 확인할 수 있는가?

위 내용은 시각적 검증 항목이며 새로운 게임 규칙의 확정은 아니다.

**기록된 Unity MCP 테스트/시각 확인:** 분쇄·광선과 하단 스킬 HUD, 5종 색상/발밑 HP바, 인벤토리 툴팁/드롭다운 캡처, 1920×1080 패널 실측과 결과창 배치·스크롤 캡처가 보고됐다. 한글 누락 글리프 추가 후 HasCharacters 확인 기록이 있다. 캡처 경로의 과거 기록을 이번 작업에서 직접 이미지 검수한 사실로 취급하지 않는다.

**기획 대조 / 추가 확인:** 최종 도트 스타일·PPU·타일·팔레트·외부 패키지는 여전히 미확정이다. 현재 임시 그래픽/64px 재료 아이콘을 최종 아트로 승인하지 않는다. 기존 스프라이트·프리팹·GUID 참조 보존 원칙은 유지한다. 물약 HUD의 Q/E/R 재배치 보고와 금지된 중앙 하단 배치의 실제 관계, 화면비별 가독성·동시 공격 흔들림 체감·신규 맵 아트는 후속 검토 대상이다.

## 15. 시스템 연동 및 충돌 검토

| 관련 시스템 | 아트와의 관계 | 주요 위험 |
|---|---|---|
| PlayerSystem | 플레이어 스프라이트·애니메이션 | 위치·충돌 어긋남 |
| MonsterSystem | 몬스터 외형 및 공격 표현 | 공격 판정과 시각 효과 불일치 |
| BossSystem | 보스 패턴·HP바·사망 연출 | 클리어 처리 및 연출 충돌 |
| CombatSystem | 공격 예고·피격·타격 이펙트 | 피해 범위 오인 |
| MapSystem | 바닥·벽·암석·카메라 | 이동 가능 영역 혼동 |
| EquipmentSkillSystem | 곡괭이·스킬·아이템 아이콘 | 장비 및 스킬 표시 불일치 |
| RewardSystem | 보상 아이콘·희귀도 | 실제 보상과 표시 차이 |
| UISystem | 패널·타이틀·HUD | 기존 UI 일관성 손상 |

### 15.1 주요 주의사항

**아트와 전투**

스프라이트나 이펙트 변경으로 기존 공격 판정이 변경되지 않아야 한다.

**아트와 맵**

지형 아트가 이동할 수 있는 공간과 이동 불가 공간을 혼동시키지 않아야 한다.

**아트와 UI**

레퍼런스의 색상 및 문구를 무조건 복제하지 않는다.

**아트와 Unity 프로젝트**

기존 프리팹 및 파일 참조를 보존한다.

## 16. 검증 기준

### 16.1 전체 스타일

- 실제 사용 중인 그래픽과 새 아트가 시각적으로 어울리는가?
- 플레이어와 몬스터를 구분할 수 있는가?
- 배경과 공격 예고를 구분할 수 있는가?
- 픽셀 아트 규격이 미확정인 상태에서 임의 변경이 발생하지 않았는가?

### 16.2 캐릭터 및 몬스터

- 스프라이트와 충돌체가 정렬되는가?
- 공격 애니메이션과 실제 공격 판정이 일치하는가?
- 몬스터 HP바가 알맞은 위치에 표시되는가?
- 사망 연출이 기존 게임 진행을 방해하지 않는가?

### 16.3 보스

- 공격 예고가 정상적으로 보이는가?
- 실제 공격 발동 시점과 예고가 일치하는가?
- 화면 흔들림이 과도하게 중복되지 않는가?
- HP바 지연 피해 표시가 정상 동작하는가?
- 사망 연출 후 클리어 처리가 정상적인가?

### 16.4 맵

- 바닥과 벽을 구분할 수 있는가?
- 이동 불가 암석·암벽을 인지할 수 있는가?
- 카메라가 정상적으로 이동하는가?
- 화면 흔들림 시 불필요한 맵 외부 공간이 나타나지 않는가?

### 16.5 UI

- 기존 UI 레이아웃이 유지되는가?
- 참고 이미지를 그대로 복제하여 디자인이 어색해지지 않았는가?
- 아이콘·희귀도·수량 표시가 실제 정보와 일치하는가?
- 클리어·실패 결과창의 색상과 연출이 유지되는가?
- 아트 변경으로 기존 입력과 게임 시간 처리에 문제가 발생하지 않는가?

### 16.6 외부 리소스

- 라이선스와 사용 범위를 확인했는가?
- 파일 구조와 스프라이트 규격을 확인했는가?
- 기존 프리팹 참조가 유지되는가?
- `.meta` 및 GUID가 손상되지 않았는가?
- Unity에서 실제 플레이 테스트를 통과했는가?

- 무거운 충격 중심의 화면 흔들림
- 기존 희귀도 색상 및 결과창 시각 명세 유지
- 아트 교체 시 기존 게임 기능 유지

- 도트 느낌의 최종 그래픽

- 타일 규격
- PPU

- 보스 최종 외형

- 제작 UI의 최종 아트
