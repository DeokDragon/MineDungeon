## 1. 문서 개요

### 1.1 목적

본 문서는 광산던전의 캐릭터, 몬스터, 배경, 장비, UI 및 전투 시각 효과의 제작·적용 방향을 관리한다.

현재 사용 중인 Unity 그래픽과 기존 UI를 존중하면서 향후 외부 아트 리소스의 도입과 교체 작업을 위한 기준을 마련한다.

### 1.2 프로젝트 기본 정보

- 게임 장르: 2D 탑뷰 싱글플레이 액션 던전
- 개발 엔진: Unity 6000.3.12f1 LTS
- 기준 해상도: 1920 × 1080
- 핵심 소재: 광산, 광물 몬스터, 곡괭이, 던전 탐험
- 아트 방향: 도트 느낌 검토 중
- 최종 픽셀 아트 규격: 미확정

### 1.3 문서 관리 범위

- 전체적인 그래픽 방향
- 캐릭터와 몬스터 시각적 구분
- 배경 및 지형 아트
- 장비와 아이템 아이콘
- UI 스타일 및 레퍼런스 사용
- 전투 시각 효과
- 외부 아트 리소스 도입
- Unity 적용 및 검증 원칙

본 문서는 전투 피해량, 몬스터 AI, 맵 진행 규칙 또는 아이템 보상 자체를 변경하지 않는다.

## 2. 전체 아트 방향

### 2.1 기본 방향

광산던전은 간단한 2D 그래픽을 기반으로 제작하고 있다.

광산 탐험과 광물 몬스터의 특징이 시각적으로 구분되는 게임을 지향한다.

도트 느낌의 그래픽을 고려하고 있으나 최종 스타일은 확정되지 않았다.

### 2.2 검토 중인 도트 아트

현재 기획 자료에는 다음 사실이 기록되어 있다.

- 도트 느낌을 고려 중이다.
- 최종 타일 크기는 정해지지 않았다.
- 캐릭터 해상도는 정해지지 않았다.
- 색상 팔레트는 정해지지 않았다.
- 모든 UI를 픽셀 규격으로 제작한다고 확정하지 않았다.

따라서 도트 아트 검토를 전체 그래픽의 픽셀 아트 전환 확정으로 해석하지 않는다.

### 2.3 아트 적용 원칙

- 현재 정상적으로 작동하는 게임 시스템을 우선 보존한다.
- 외형을 변경하더라도 충돌과 공격 판정이 불필요하게 변경되지 않도록 한다.
- 기존 UI와 새로운 아트 사이의 일관성을 검토한다.
- 실제 에셋과 현재 Unity 프리팹을 확인한 뒤 적용한다.
- 아직 정해지지 않은 아트 규격을 임의로 확정하지 않는다.

### 2.4 미확정 항목

**적용 범위:** 아래는 게임 전체/공통 아트 규격의 미확정 상태다. 돌B-1R·철I-3R·수정C-2R·석탄C-1R·자철석M-1R은 §4.3~4.7의 개별 사용 기준을 채택했다. 개별 적용 규격을 플레이어·보스·맵·UI 또는 게임 공통 규격으로 확대하지 않는다.

| 항목 | 상태 |
|---|---|
| 최종 그래픽 스타일 | 검토 중 |
| 스프라이트 기본 크기 | 미확정 |
| 픽셀 퍼 유닛(PPU) | 미확정 |
| 타일 크기 | 미확정 |
| 색상 팔레트 | 미확정 |
| 픽셀 필터링 방식 | 미확정 |
| 조명 표현 방식 | 미확정 |
| 캐릭터 애니메이션 프레임 수 | 미확정 |
| UI의 픽셀 아트 적용 범위 | 미확정 |

## 3. 플레이어 캐릭터 아트

### 3.1 기본 콘셉트

플레이어는 광산을 탐험하며 곡괭이를 사용하는 캐릭터이다.

현재 인수인계 자료에는 플레이어 외형의 세부 디자인이나 최종 캐릭터 스프라이트가 명시되어 있지 않다.

### 3.2 제작 시 확인할 항목

- 캐릭터의 기본 외형
- 캐릭터 크기
- 탑뷰 이동 방향 표현
- 대기 및 이동 애니메이션
- 곡괭이 기본 공격 표현
- 회피 표현
- 피격 및 사망 표현
- 스킬 사용 표현

이 항목들은 아트 제작 시 검토할 대상으로, 모두 현재 구현되었다는 의미는 아니다.

### 3.3 공격 애니메이션 연동

곡괭이 공격 애니메이션은 기존 기본 공격 시스템과 연동되어야 한다.

다음 요소가 서로 불일치하지 않도록 검증한다.

- 곡괭이 스프라이트
- 공격 방향
- 공격 판정 위치
- 실제 공격 범위
- 공격 발생 시점

애니메이션 변경을 이유로 공격력이나 공격 범위를 임의로 변경하지 않는다.

### 3.4 이동 및 충돌

캐릭터 스프라이트를 교체하더라도 기존 이동과 벽 충돌이 정상적으로 작동해야 한다.

외형의 중심과 실제 캐릭터 위치가 어긋나는지 확인한다.

### 3.5 부활 및 사망

플레이어는 던전에서 2회 부활할 수 있으며 현재 방 입구에서 부활한다.

사망·부활 관련 그래픽을 적용할 때 이 기능을 변경하지 않는다.

사망 및 부활 애니메이션의 세부 규격은 현재 미확정이다.

## 4. 일반 몬스터 아트

### 4.1 기본 방향

일반 몬스터는 광물 소재별 특징을 가지는 적이다.

현재 일반 몬스터 상세 명세는 총 5종이다.

| 몬스터 | 소재 | 기존 공격 특성 |
|---|---|---|
| 돌 | 돌 | 도약 공격 |
| 철 | 철 | 직선 돌진 |
| 수정 | 수정 | 원거리 파편 |
| 석탄 | 석탄 | 근접 열기 폭발 |
| 자철석 | 자철석 | 자기장 및 감속 |

### 4.2 외형 차별화

**개별 채택 기준과 공통 미확정 구분:** 돌B-1R·철I-3R·수정C-2R·석탄C-1R은 아래 개별 외형을 현재 사용 기준으로 채택했다. 자철석M-1R도 §4.7에 새로 채택했다. 다음 공통 미확정 설명은5종의 개별 채택 기준을 제외한 게임 전체 아트 방향에 적용하며 보존한다.

몬스터의 실제 스프라이트를 선정하거나 제작할 때 각 몬스터 종류를 구분할 수 있는지 검토한다.

채택된5종 이외 대상과 게임 공통 실루엣·크기·색상은 미확정이다. 개별 외형이 제공되지 않은 대상에 새로운 디자인을 임의 확정하지 않는다.

### 4.3 돌 몬스터 B-1R — 현재 사용 기준

**2026-10-23 사용자 승인 완료.** 돌 몬스터는 도약 공격을 사용하는 몬스터이며 현재 사용 기준 그래픽은 B-1R이다. 당분간 전체 재제작은 진행하지 않는다. 플레이테스트에서 문제가 확인되면 개별 애니메이션의 개선을 검토할 수 있다.

#### 외형과 돌 몬스터 전용 제작 규격

둥글고 묵직한 암석 골렘, 짧고 굵은 팔·다리, 좁은 수평 눈 홈/호박색 눈빛, 몸체의 굵은 균열이 특징이다. 2D 탑뷰 기반 3/4 시점의 도트풍 그래픽을 사용한다.

| 항목 | 돌 몬스터 B-1R 본체 애니메이션 기준 |
|---|---|
| 프레임 | 64×64px |
| PPU | 64 |
| Pivot | 중앙 |
| 필터 | Point |
| 압축 | 무압축 |

이는 **현재 돌 몬스터 전용 규격**이며 다른 몬스터·플레이어·맵·UI와 게임 전체 공통 규격을 확정한 것이 아니다. 전투 VFX는 WORK_STATUS에 기록된 각 원본 규격을 보존하며 모든 VFX까지 본체64×64로 강제 변경하는 의미가 아니다.

#### 현재 애니메이션 8종

| 애니메이션 | 프레임 수 | 버전 |
|---|---:|---|
| Idle | 4 | v2 |
| Move | 6 | v2 |
| Wind-up | 6 | v1 |
| Jump | 4 | v2 |
| Landing | 3 | v2 |
| Recovery | 5 | v2 |
| Hit | 3 | v1 |
| Death | 7 | v1 |

위8종을 현재 사용 기준으로 삼는다. 과거 통합 보고의 Jump/Landing/Recovery v1은 후속v2 교체 전 이력으로 구분한다.

#### 현재 전투 이펙트 6종

| 이펙트 | 용도 |
|---|---|
| JumpDust | 도약 시작 |
| LandingShockwave | 착지 충격 표현 |
| LandingDust | 착지 먼지 |
| StoneFragments | 착지 돌 파편 |
| HitFragments | 피격 파편 |
| DeathBurst | 사망 파편·먼지 |

기존 Mesh·LineRenderer 기반 공격 예고 장판은 재사용한다. 기존 효과와 중복되지 않도록 하며 이펙트 자체에 새로운 공격 판정/피해를 발생시키지 않는다. **LandingShockwave는 돌 몬스터 착지VFX이고 플레이어 물리50P 패시브 충격파와 별개**다.

#### 방향 전환과 공격 중 피격

추적 중 플레이어의 좌우 위치에 따라 SpriteRenderer.flipX로 방향을 바꾸고 정지하면 마지막 방향을 유지한다. 공격 예고 시작 시 방향을 고정해 도약·착지·Recovery 동안 유지하고 공격 종료 후 추적에서 방향을 갱신한다. 이는 시각 표현이며 기존 이동 목표·공격 목표 위치·피해 판정을 바꾸지 않는다.

공격 중 피격은 Wind-up/Jump/Landing/Recovery의 공격 포즈를 우선한다. Hit 포즈로 공격 포즈를 덮지 않되 기존 피격 플래시·몸체 변형·HitFragments는 유지한다. 비공격 상태의 기존 Hit 표현도 유지한다. 새 피격 경직·공격 취소·시간 연장을 추가하지 않는다.

#### 기존 전투 타이밍과 즉시 처치 처리

Wind-up→Jump→Landing→Recovery를 기존 AI 상태에 연동한다. 예고0.65초·도약0.35초를 유지하고, 착지 후 기존 후딜레이1.0초 안에서 Landing약0.18초+Recovery약0.82초를 재생한다. 두 애니메이션을 이유로 후딜을 연장하지 않는다. HP30·속도2.6·최대도약3.2·착지반경0.9·피해12·공격간격2.8초 등 기존 기본 수치/판정은 [MonsterSystem](MonsterSystem.md) §4를 따른다. 기존 층/난이도 수치 적용 규칙도 변경하지 않는다.

Death/DeathBurst는 사망 시각 표현이다. 기존 사망 이벤트·EXP/재화 지급·몬스터 전멸·출구 개방을 연출 종료까지 지연시키지 않는다. 애니메이션/VFX가 기존 AI나 보상/방 진행의 새 실행 조건이 되어서는 안 된다.

### 4.4 철 몬스터 I-3R — 현재 사용 기준

사용자 채택 외형은 **I-3R**이다. I-3의 전방 중량감과 I-1의 간결한 금속판 구조를 결합하며 크고 각진 어깨·두껍고 무거운 주먹·청회색 금속판·어두운 관절·주황빛 눈·전방으로 무게가 실린 돌진형 실루엣을 유지한다.

기본 애니메이션은 Idle4프레임·Move6프레임이며 기존 실제 이동 속도에 보행FPS를 연동한다.

| 전투 애니메이션 | 프레임 |
|---|---:|
| Charge Wind-up | 6 |
| Charge | 4 |
| WallImpact | 4 |
| Recovery | 5 |
| Hit | 3 |
| Death | 7 |

| VFX | 용도 |
|---|---|
| ChargeDust | 돌진 시작 먼지 |
| ChargeTrail | 돌진 중 궤적 |
| WallImpact | 실제 벽 접촉 충격 |
| HitSparks | 피격 불꽃 |
| DeathFragments | 사망 금속 파편 |

직선 돌진과 시각 이동의 정렬을 확인한다. 예고 시작부터 돌진·후딜 종료까지 시각 방향을 고정하며 실제 돌진 방향 규칙은 바꾸지 않는다. 기존 예고선·본체 잔상을 유지하고 새 벽/피격/사망VFX와 기존 효과의 중복을 방지한다.

Wind-up은 기존 예고0.75초에 연동하고 일반 Recovery는 기존0.8초, 벽 충돌 시 WallImpact+Recovery는 기존1.5초 안에서 재생한다. Codex 보고의 벽 연출 분할은0.24초+1.26초다. 돌진거리6·피해15를 포함한 기존 수치는 [MonsterSystem](MonsterSystem.md) §5를 따른다. 기본·전투 아트 적용 및 관련 회귀 검증은 Codex 완료 보고이며 이번 문서 작업의 직접 Unity 검증이 아니다.

### 4.5 수정 몬스터 C-2R — 현재 사용 기준

사용자 채택 외형은 **C-2R Core Focus Fine-Tuned**다. 밝은 청록색 가슴 코어·양쪽 큰 어깨 수정·작은 머리와 청록 눈·코어 주변 보라 구조·어두운 청회색 몸체·수정 손을 유지한다. 큰 어깨 수정은 돌과 구분하는 핵심 요소다.

기본 Idle4프레임은 미세한 코어 맥동, Move6프레임은 양발 교대 보행을 표현한다.

| 전투 애니메이션 | 프레임 | 기존 전투 시간과 연동 |
|---|---:|---|
| Cast Wind-up | 6 | 예고0.75초 |
| Fire | 3 | 0.18초 |
| Recovery | 5 | 0.52초 |
| Hit | 3 | 기존 피격 표현 연동 |
| Death | 7 | 사망 처리와 분리한 시각 연출 |

| VFX | 용도 |
|---|---|
| CoreCharge | 가슴 코어 충전 |
| FireFlash | 실제 발사 순간 섬광 |
| ProjectileVisual | 기존 투사체의 수정 전용 시각 표현 |
| CrystalImpact | 명중·벽·최대거리 종료 충격 |
| CrystalDeathBurst | 사망 수정 파편 |

## 5. 보스 아트

### 5.1 현재 보스

현재 보스는 돌골렘이다.

돌골렘은 기존 5종 공격 패턴을 기준으로 개발되었다.

### 5.2 공격 패턴과 시각 효과

보스 패턴 계열:

1. 도약 내려찍기
2. 주변 강타
3. 바위 돌진
4. 부채꼴 돌 파편
5. 메테오 또는 낙석

세부 패턴명과 수치는 `BossSystem.md` 및 Unity 프로젝트를 확인한다.

### 5.3 공격 예고

보스 공격은 위험 범위와 공격 발동까지 남은 시간을 표시한다.

기존 메테오 패턴의 채움형 예고를 다른 패턴에도 적용하도록 작업을 요청한 기록이 있다.

공격 예고의 시각적 표현을 변경하더라도 실제 발동 시점과 일치해야 한다.

### 5.4 충격 연출

무거운 공격의 화면 흔들림은 실제 충격 시점을 중심으로 사용한다.

대표적인 검토 대상:

- 착지
- 충돌
- 폭발

모든 공격에 동일한 화면 흔들림을 적용하지 않는다.

### 5.5 보스 HP바

보스 HP바는 HUD 상단 중앙에 배치한다.

현재 체력은 즉시 감소하며 이전 체력 구간이 밝은 주황색으로 남아 있다가 지연 감소하는 구조이다.

보스 HP바의 정확한 색상값, 감소 속도 및 사망 시 종료 시점은 현재 구현 확인이 필요하다.

### 5.6 사망 연출

보스 사망은 던전 클리어 및 결과창 표시와 연동된다.

사망 연출을 변경하더라도 클리어 보상 지급·저장과 결과창 처리에 영향을 주지 않아야 한다.

보스 사망 즉시 HP바를 숨기도록 강제 변경하는 과거 제안은 적용하지 않는다.

## 6. 맵 및 배경 아트

### 6.1 기본 소재

게임의 주요 배경은 광산과 던전이다.

기존 일반 방 9종의 구조가 존재한다.

### 6.2 설계도와 실제 게임 아트

기존 맵 설계도에 사용한 색상과 도형은 제작용 구분 표기이다.

- 초록색 네모: 플레이어 입구
- 빨간색 네모: 출구
- 주황색 원: 몬스터 배치 영역
- 연보라색: 이동 가능한 바닥

위 색상과 도형을 실제 게임 아트로 그대로 구현해야 하는 것은 아니다.

### 6.3 바닥 및 벽

바닥은 플레이어가 이동 가능한 영역을 나타낸다.

벽은 플레이어와 몬스터의 이동을 막는다.

바닥과 벽의 최종 타일 그래픽, 소재 표현 및 크기는 현재 미확정이다.

### 6.4 최신 맵 개선안

**현재 재검토 중인 방향**

전체 맵을 직사각형 캔버스로 구성하고 실제 이동하지 않는 영역을 암석 또는 암벽으로 채우는 방식이다.

전체 캔버스가 직사각형이더라도 이동 가능한 공간의 실제 형태는 유지할 수 있다.

이 방식은 아직 최종 승인된 맵 구조가 아니다.

### 6.5 암석·암벽 표현

현재 논의된 암석·암벽은 이동 불가 공간을 채우는 지형 요소이다.

아트만 보고 다음 기능을 자동으로 추가하지 않는다.

- 채광
- 파괴
- 숨겨진 통로
- 상호작용

별도 기능은 사용자 승인이 필요하다.

### 6.6 카메라와 지형

내부 벽과 암석은 카메라 화면에 표시할 수 있는 지형이다.

카메라 제한 경계와 캐릭터 이동을 막는 벽은 구분한다.

배경 아트를 적용하더라도 카메라 경계, 화면 흔들림 및 기존 충돌 기능을 유지한다.

### 6.7 타일 및 스프라이트 규격

다음 사항은 미확정이다.

- 타일 해상도
- 타일의 Unity 월드 크기
- PPU
- 벽 스프라이트 높이
- 바닥과 벽의 표시 순서
- 반복 타일의 연결 방식
- 배경의 색상 팔레트
- 외곽 암석의 최종 디자인

맵의 실제 크기는 이미지 픽셀 크기만으로 결정하지 않는다.

곡괭이별 외형과 능력치를 아직 새로 확정하지 않는다.

### 7.3 제작 재료 아이콘

## 10. 전투 이펙트

### 10.1 기본 방향

기존 기획에서는 시각적 타격감과 피격감 개선을 우선 진행하기로 했다.

사운드는 후속 작업 대상으로 검토했다.

### 10.2 타격 이펙트

공격이 적중했다는 사실을 시각적으로 전달하는 효과이다.

곡괭이 3단 콤보는 §10.8의 물리적 무기 잔상형 표현을 승인했다. 그 외 효과의 미확정 형태·크기·색상·애니메이션을 일괄 확정하지 않는다.

### 10.3 피격 플래시

몬스터가 피해를 받았음을 표현한다.

플래시의 정확한 색상과 지속 시간은 기존 구현 확인이 필요하다.

### 10.4 피해량 표시

피해량을 숫자 등으로 표시하는 기능이 검토되었다.

세부 항목:

- 표시 위치
- 글자 크기
- 색상
- 이동 애니메이션
- 사라지는 연출

현재 모든 세부 항목의 규격이 확정된 것은 아니다.

### 10.5 사망 연출

몬스터와 보스의 사망을 시각적으로 표현한다.

사망 연출과 실제 처치 이벤트를 구분하여 기존 보상 지급 및 방 진행 기능을 유지한다.

### 10.6 공격 예고

기존 몬스터와 보스의 공격 예고는 실제 공격 범위 및 발동 시점과 연동된다.

이펙트가 바뀌더라도 공격 판정을 임의로 확대하거나 축소하지 않는다.

### 10.7 화면 흔들림

화면 흔들림은 무거운 공격을 중심으로 사용한다.

착지·충돌·폭발과 같은 충격 시점을 우선한다.

모든 공격에 강한 화면 흔들림을 자동 적용하지 않는다.

### 10.8 곡괭이 3단 콤보 — 물리적 무기 잔상형

**2026-10-25 사용자 승인:** 곡괭이 머리의 실제 이동 궤적, 타격 먼지와 소량의 돌 파편을 사용한다. 판타지 검기·에너지 파동으로 변경하지 않는다. 이 명세는 곡괭이 콤보 전용 표현 방향이며 게임 전체 공통 아트 규격·스프라이트 해상도·PPU·최종 팔레트를 확정하지 않는다.

| 단계 | 승인된 표현 |
|---|---|
| 1타 — 시계방향 휘두르기 | 머리를 따르는 짧고 얇은 곡선 잔상, 회색·갈색의 약한 표현으로 빠른 첫 공격 강조 |
| 2타 — 반시계방향 휘두르기 | 반대 방향 곡선 잔상, 1타보다 약간 선명하게 연속 공격 리듬 강조 |
| 3타 — 전방 파쇄 강타 | 전방으로 이동하는 짧은 집중형 잔상, 직접 적중 시 상대적으로 강한 먼지와 소량의 돌 파편 |

**초기 테스트값 — 최종 아트·연출 밸런스가 아니며 적용·테스트 완료 수치가 아니다.**

| 항목 | 1타 | 2타 | 3타 |
|---|---|---|---|
| 잔상 소멸 시간 | 0.10초 | 0.12초 | 0.15초 |
| 최대 불투명도 | 35% | 45% | 50% |
| 먼지 입자 | 2~3개 | 3~4개 | 5~7개 |
| 돌 파편 | 없음 | 없음 | 2~4개 |

잔상은 빗나가도 실제 무기 이동에 따라 표시한다. 먼지·파편은 실제 기본 공격 직접 피해 성공에만 발생하고, 물리50P 충격파 적중만으로 생성하지 않는다. 공격별 조준 방향 고정·360도 자유 조준과 무기 궤적을 유지하며, 실제 공격 취소 시 새 잔상 생성 중단/기존 잔상 정리·취소 후 새 직접 피해 및 적중 VFX 금지를 따른다. 이미 성립한 타격은 소급 취소하지 않는다.

곡괭이 잔상(무기 궤적)·직접 적중 먼지/파편·물리50P 독립 충격파·몬스터별 피격/사망 VFX의 역할을 분리한다. 기존 몬스터 VFX는 임의 제거·대체하지 않는다. 새 피해·경직·패시브 충전은 없고 3타 파쇄 자체에도 신규 광역 피해·추가 충격파가 없다. 다수 적중의 화면 중첩/성능을 검토하되 공격당 적중 VFX 최대 생성량·대표 위치 선정은 미확정이다. 위 입자 수를 공격 전체 최대 생성량으로 확정하지 않는다.

개발은 **2-1 잔상 우선 → 정상 작동 확인 후 2-2 먼지·파편 → 별도 상세 기획/사용자 승인 후 2-3 히트스톱·흔들림·사운드** 순서다. 연출 시간/흔들림/음향의 추가 수치는 미확정이다. 방향·취소/빗나감·가독성/성능·실제 적중 위치·복수 적중/몬스터 효과 중복·프레임 지연/GC는 후속 확인 대상이다. 이번 문서 작업에서 Unity 구현·Play 검증은 수행하지 않았다. 기존 콤보 기능의 구현·복구 보고와 신규 VFX를 구분하며 상세 발생·취소·전투 보존 규칙은 [CombatSystem](CombatSystem.md) §11.9를 따른다.

## 11. 외부 아트 리소스 도입

### 11.1 도입 방향

사용자는 향후 몬스터와 맵 아트를 확보한 뒤 Unity 프로젝트에 넣고 Codex를 통해 배치 및 적용하는 흐름을 고려하고 있다.

현재 특정 아트 패키지가 최종 확정된 것은 아니다.

### 11.2 적용 전 확인 항목

| 항목 | 확인 내용 |
|---|---|
| 파일 구성 | 폴더와 개별 파일 구조 |
| 리소스 종류 | 스프라이트 또는 다른 모델 형식 |
| 크기 | 원본 이미지 및 실제 사용 크기 |
| 피벗 | 배치·회전 기준 위치 |
| 애니메이션 | 제공되는 동작과 프레임 |
| 충돌체 | 기존 이동 및 피격 판정과의 관계 |
| 공격 예고 | 시각적 범위와 실제 판정 정렬 |
| 라이선스 | 게임 프로젝트 사용 가능 범위 |

### 11.3 리소스 사용 권한

외부 리소스를 사용하기 전에 해당 라이선스와 사용 조건을 확인한다.

확인이 필요한 항목:

- 게임 사용 허용 여부
- 수정 허용 여부
- 배포 가능 여부
- 출처 표기 의무
- 유료·무료 사용 조건

특정 에셋의 라이선스가 확인되지 않았을 때 자유롭게 사용 가능하다고 단정하지 않는다.

### 11.4 Unity 기존 리소스 보존

아트 적용 과정에서 기존 정상 동작 기능이 손상되지 않아야 한다.

특히 다음 사항을 확인한다.

- 프리팹 참조
- 스크립트 참조
- 애니메이션 연결
- 충돌체
- 공격 판정
- 카메라
- 맵 출구 및 입구
- 몬스터 배치

### 11.5 메타데이터 보존

기존 Unity 에셋의 `.meta` 및 GUID를 불필요하게 변경하지 않는다.

기존 프리팹과 다른 오브젝트의 참조가 끊어지지 않도록 한다.

### 11.6 에셋 교체

스프라이트 교체만으로 해결할 수 있는 부분과 프리팹·애니메이션·충돌체 수정이 필요한 부분을 구분한다.

실제 구현 방식은 Codex가 Unity 프로젝트를 확인한 후 판단한다.

## 12. 아트와 맵 시스템의 관계

### 12.1 맵 변경

현재 일반 방 9종은 설계가 존재하지만 Unity 구현 결과 문제로 인해 재검토 중이다.

## 15. 시스템 연동 및 충돌 검토

| 관련 시스템 | 아트와의 관계 | 주요 위험 |
|---|---|---|
| PlayerSystem | 플레이어 스프라이트·애니메이션 | 위치·충돌 어긋남 |
| MonsterSystem | 몬스터 외형 및 공격 표현 | 공격 판정과 시각 효과 불일치 |
| BossSystem | 보스 패턴·HP바·사망 연출 | 클리어 처리 및 연출 충돌 |
| CombatSystem | 공격 예고·피격·타격 이펙트 | 피해 범위 오인 |
| MapSystem | 바닥·벽·암석·카메라 | 이동 가능 영역 혼동 |
| EquipmentSkillSystem | 곡괭이·스킬·아이템 아이콘 | 장비 및 스킬 표시 불일치 |
| RewardSystem | 보상 아이콘·희귀도 | 실제 보상과 표시 차이 |
| UISystem | 패널·타이틀·HUD | 기존 UI 일관성 손상 |

### 15.1 주요 주의사항

**아트와 전투**

스프라이트나 이펙트 변경으로 기존 공격 판정이 변경되지 않아야 한다.

**아트와 맵**

지형 아트가 이동할 수 있는 공간과 이동 불가 공간을 혼동시키지 않아야 한다.

**아트와 UI**

레퍼런스의 색상 및 문구를 무조건 복제하지 않는다.

**아트와 Unity 프로젝트**

기존 프리팹 및 파일 참조를 보존한다.

## 16. 검증 기준

### 16.1 전체 스타일

- 실제 사용 중인 그래픽과 새 아트가 시각적으로 어울리는가?
- 플레이어와 몬스터를 구분할 수 있는가?
- 배경과 공격 예고를 구분할 수 있는가?
- 픽셀 아트 규격이 미확정인 상태에서 임의 변경이 발생하지 않았는가?

### 16.2 캐릭터 및 몬스터

- 스프라이트와 충돌체가 정렬되는가?
- 공격 애니메이션과 실제 공격 판정이 일치하는가?
- 몬스터 HP바가 알맞은 위치에 표시되는가?
- 사망 연출이 기존 게임 진행을 방해하지 않는가?

### 16.3 보스

- 공격 예고가 정상적으로 보이는가?
- 실제 공격 발동 시점과 예고가 일치하는가?
- 화면 흔들림이 과도하게 중복되지 않는가?
- HP바 지연 피해 표시가 정상 동작하는가?
- 사망 연출 후 클리어 처리가 정상적인가?

### 16.4 맵

- 바닥과 벽을 구분할 수 있는가?
- 이동 불가 암석·암벽을 인지할 수 있는가?
- 카메라가 정상적으로 이동하는가?
- 화면 흔들림 시 불필요한 맵 외부 공간이 나타나지 않는가?

### 16.5 UI

- 기존 UI 레이아웃이 유지되는가?
- 참고 이미지를 그대로 복제하여 디자인이 어색해지지 않았는가?
- 아이콘·희귀도·수량 표시가 실제 정보와 일치하는가?
- 클리어·실패 결과창의 색상과 연출이 유지되는가?
- 아트 변경으로 기존 입력과 게임 시간 처리에 문제가 발생하지 않는가?

### 16.6 외부 리소스

- 라이선스와 사용 범위를 확인했는가?
- 파일 구조와 스프라이트 규격을 확인했는가?
- 기존 프리팹 참조가 유지되는가?
- `.meta` 및 GUID가 손상되지 않았는가?
- Unity에서 실제 플레이 테스트를 통과했는가?

## 17. 기획 상태 정리

### 17.1 확정 또는 기존에 승인된 방향

- 2D 탑뷰 액션 던전
- 곡괭이를 사용하는 플레이어
- 광물 소재 일반 몬스터 5종
- 돌골렘 보스
- 기존 UI를 존중한 레퍼런스 적용
- Figma AI 레퍼런스의 배치·구성 중심 참고
- 전투 시각적 타격감·피격감 우선 개발
- 공격 예고와 실제 피해 판정의 정렬
- 무거운 충격 중심의 화면 흔들림
- 기존 희귀도 색상 및 결과창 시각 명세 유지
- 아트 교체 시 기존 게임 기능 유지
- 돌B-1R 기존 기준 유지, 철I-3R·수정C-2R·석탄C-1R 개별 외형/애니메이션/VFX 채택
- 자철석M-1R 채택·기본2종/전투5종/VFX4종 (§4.7)
- 5종 개별 본체 규격·시각 방향/피격우선·사망/보상 분리 (§4.3~4.8)

### 17.2 검토 중

- 도트 느낌의 최종 그래픽
- 전체 직사각형 맵 캔버스
- 이동 불가 영역의 암석·암벽 채움
- 외부 아트 패키지 도입
- 맵 4 수정 및 신규 맵 A의 실제 아트 구성

### 17.3 미확정

곡괭이 잔상·먼지·파편의 승인된 표현 방향과 초기 테스트값은 §10.8을 따른다. 아래는 전체 공통/다른 대상의 최종 아트 미확정 목록으로 보존한다. 돌·철·수정·석탄·자철석의 현재 채택 외형·프레임/버전·개별 제작 규격은 §4.3~4.7 예외이며 채택 대기로 해석하지 않는다. 석탄VFX v2는 교체/회귀 완료 보고가 있으며 이번 최신 실제 참조의 독립 확인과 구분한다.

- 최종 픽셀 아트 적용 여부
- 타일 규격
- PPU
- 캐릭터 스프라이트 해상도
- 몬스터별 최종 외형
- 보스 최종 외형
- 애니메이션 프레임 수
- 색상 팔레트
- 그림자 및 조명 스타일
- 이펙트별 최종 규격
- 특정 외부 에셋 패키지
- 에셋별 라이선스
- 제작 UI의 최종 아트

### 17.4 적용하지 않는 변경

- 모든 UI를 도트 아트로 강제 전환
- Figma 레퍼런스의 모든 색상과 문구 복제
- 해머·탐사봉의 신규 무기 추가
- 무너진 벽에 파괴 기능 자동 추가
- 모든 공격에 강한 화면 흔들림 일괄 적용
- 모든 공격의 실제 판정 범위를 일괄 축소
- 부활 시 보스 위치 강제 변경
- 보스 HP바 사망 즉시 숨김으로 강제 변경
