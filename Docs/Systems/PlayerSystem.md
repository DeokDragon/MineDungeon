## 1. 시스템 개요

### 1.1 목적

플레이어 시스템은 캐릭터의 이동, 생존, 체력, 사망, 부활, 물약 사용 및 기본적인 입력과 상태 관리를 담당한다.

플레이어가 던전 내에서 정상적으로 전투하고, 방 이동이나 사망·부활 과정에서 의도된 상태를 유지하도록 한다.

### 1.2 주요 기능

- 플레이어 이동
- 곡괭이를 이용한 기본 공격과 스킬 시스템 연동
- 회피 행동
- 체력 및 피해 처리
- 사망 판정
- 던전 내 부활
- 물약 보유 및 사용
- 생명 HUD 표시
- 월드 상호작용
- 던전 상태에 따른 조작 제한
- 성장 능력치 및 장비 능력치 연동

## 2. 플레이어 기본 능력치

### 2.1 능력치 구성

현재 기획에서 확인되는 플레이어 관련 능력치는 다음과 같다.

- 체력
- 이동 속도
- 공격 관련 능력치
- 경험치
- 레벨
- 스탯 포인트

장비 및 스킬에 따른 능력치 변화는 관련 시스템과 연동한다.

### 2.2 기존 밸런스 기준

일반 몬스터의 초기 밸런스를 설계할 당시 사용한 플레이어 기준값이다.

| 항목 | 설계 기준 |
|---|---|
| 체력 | 100 |
| 이동 속도 | 4.0 |
| 입문 무기 평타 피해량 | 10~15 |

**주의:** 위 수치는 1층 난이도 1의 일반 몬스터 밸런스 명세에서 사용한 가정값이다.

현재 Unity 프로젝트에 실제 적용된 플레이어 기본 능력치로 확정하지 않는다.

### 2.3 최신 투자 규칙과 남은 기본값 확인

2026-10-22 승인 투자 대상은 체력·물리·마법이며 각100P 상한이다. 체력1P는 최대HP+3, 물리/마법1P는 해당 공격 스탯+0.4다. 최종 공격 스탯은 기본+투자+장비 보너스로 구성한다. 방어력은 투자하지 않고 일부 상의·하의에서 얻는다.

§2.2의 체력100/속도4.0/평타10~15는 과거 설계 가정이고 신규 캐릭터 기본HP·기본 공격 스탯의 확정값이 아니다. 실제 기본HP/공격 스탯·이동/회피 수치·장비값과 DEF 감소 공식은 별도 확인한다. 공격 피해 공식은 CombatSystem §6.5를 따른다.

### 2.4 1층 쉬움 테스트 캐릭터와 공용 데이터 보호

신규Lv.1·초기3P 미사용·스킬 미장착·입문 곡괭이·추가 장비 보너스 없음이 승인된 테스트 조건이다. 최종 밸런스나 모든 난이도 영구 기본값이 아니다.

| 항목 | 초기 테스트값 |
|---|---:|
| 최대HP / 이동 속도 | 100 / 4.0 |
| 입문 곡괭이 기본 피해 | 12 |
| 기본 물리 / 마법 / DEF | 0 / 0 / 0 |
| 공격 시작 간격 | 0.6초 |
| 물약 보유 / 개당 회복 | 3개 / 35HP |
| 던전당 부활 | 2회 |

기존 체력/물리/마법 투자·패시브·레벨업3P·저장/초기화를 유지한다. Codex는 적용 전 현재값과 코드/SO/프리팹/저장·공유 범위를 읽기 전용 조사하고 사용자에게 보고한다. 같으면 재변경하지 않는다. 다른 층/난이도에 영향을 주는 전역 변경은 임의 적용하지 않고 기존 구조로 쉬움 전용 분리 가능한지 확인한다. 불가능하면 기술 대안/영향을 보고하며 공용 변경은 별도 사용자 승인 후 진행한다. 새 쉬움 스탯/아이템 구조를 이번에 확정하지 않는다.

WORK_STATUS의25일 보고는 공용HP100/이동4·피해10·물리7/마법6을 보존하고 격리 신규 저장 테스트에서만 피해12·공격스탯0/0을 썼다고 기록한다. DEF 시스템은 당시 미구현으로 새0스탯을 만들지 않았다. 시험 목표0과 실제 시스템 존재를 혼동하지 않는다. 이번에 코드/현재값을 독립 확인하거나 실제 저장/백업을 변경하지 않았다.

## 3. 플레이어 이동

### 3.1 기본 이동

플레이어는 2D 탑뷰 공간에서 이동한다.

현재 이동 기능은 구현 및 동작 확인이 보고되었다.

### 3.2 이동과 충돌

- 이동 가능한 바닥에서 정상적으로 움직인다.
- 이동을 차단하는 벽을 통과하지 않는다.
- 맵 외부의 이동 불가능 영역으로 진입하지 않는다.
- 방 이동 후 새로운 방의 유효한 입장 위치에서 플레이를 시작한다.

벽 및 이동 가능한 영역의 구체적인 설정은 `MapSystem.md`를 따른다.

### 3.3 카메라 연동

카메라는 플레이어를 부드럽게 따라가는 방식이다.

방 이동 시 새 방의 카메라 제한 영역이 적용되어야 한다.

카메라가 내부 벽이나 암석을 화면에 표시하는 것은 허용된다.

카메라 경계 및 흔들림 효과의 자세한 규칙은 맵·전투 시스템에서 관리한다.

### 3.4 이동 속도 변경

자철석 몬스터는 플레이어에게 이동 속도 감소 효과를 부여한다.

기존 제공 명세:

- 이동 속도 감소율: 30%
- 지속 시간: 1.5초

감속 종료 시 이동 속도를 임의의 고정 수치로 복구하지 않는다.

현재 플레이어의 기본 능력치 및 다른 적용 효과를 고려하여 원래 상태로 복구해야 한다.

**확인 필요:** 복수 감속 효과의 중첩 규칙과 실제 구현 방식.

## 4. 기본 공격과 회피

### 4.1 곡괭이 기본 공격 — 360도 3단 콤보 승인

주 무기는 곡괭이다.1타 시계방향/2타 반시계방향 휘두르기,3타 전방 파쇄이며 각 시작의 마우스 방향을 고정·다음 시작에 재조준한다. 원점은 플레이어를 따라 움직인다. 클릭1회는 현재 단계1회·연속 클릭1→2→3·홀드1→2→3→1, 빗맞혀도 연결 가능하다. 콤보 기능은 WORK_STATUS에 1단계 구현·복구 및 집중 검사 보고가 있으며 전체 수동 플레이/회귀 완료와 구분한다. 잔상·먼지·돌 파편은26일 적용/핵심Play 보고가 추가됐다(§13.1).

공격 중 클릭 예약은 최대1회, 홀드와 동시 요청이어도 같은 시점에 공격1개만 시작한다. 홀드 해제는 정상 클릭 예약을 지우지 않는다. 시작 간 최소0.6초/동작 종료 후 연결0.85초·전 단계50% 직접 판정은 초기 테스트 기준이며 실제 시작 조건으로 연결을 판단한다. 단계별 초기 수치·피해/패시브 공식은 [CombatSystem](CombatSystem.md) §3.5~3.9를 따른다.

실행된 회피·정상 E/R 스킬·물약/방 이동/사망·부활/연결 시간 초과는 콤보1타/예약 제거다. 거부된 입력으로 현재 공격 취소/초기화를 추가하지 않으며 일반 피격은 기존 취소 규칙을 따른다. 기존 이동·회피/스킬/물약 제한·인벤토리 전투 차단·부활2회를 유지한다. 물리100P 충전과 콤보는 별개이며 방 이동의 콤보 초기화가 패시브 충전 유지를 덮지 않는다. 새 영구 저장 필드를 추가하지 않는다.

### 4.1.1 무기 궤적·잔상과 공격 취소 — 2026-10-25 승인

물리적인 무기 잔상은 곡괭이 머리의 실제 이동 경로에 연동한다. 360도 자유 조준·각 공격 시작 방향 고정/다음 공격 재조준·플레이어를 따르는 원점을 유지한다. 정상 무기 이동이면 빗나가도 잔상을 표시하고 먼지·파편은 기본 공격 직접 피해 성공에만 생성한다. 물리50P 충격파만 적중한 경우 직접 적중 VFX를 만들지 않는다.

실행된 회피 등 기존 규칙에 따른 정상 공격 취소 시 새로운 잔상 생성을 중단하고 기존 잔상을 정리한다. 취소 이후 새 직접 피해/적중 VFX는 발생하지 않으며 이미 성립한 타격은 소급 취소하지 않는다. 거부 입력·일반 피격의 기존 취소 규칙을 변경하지 않는다. 기존 콤보 동작/입력·행동 제한·물리 패시브/전투 판정·저장을 유지한다. 발생·중복 방지·후속 단계는 [CombatSystem](CombatSystem.md) §11.9, 시각 스타일/초기 테스트값은 [ArtDirection](ArtDirection.md) §10.8을 따른다. 26일VFX 연결/핵심Play 보고와 전체검증을 구분하며 최신 현황은 §13.1을 따른다.

### 4.2 장비 능력치 연동

장착한 곡괭이는 플레이어의 공격 성능과 연관된다.

기존에는 곡괭이에 따른 공격력과 공격 범위 차이를 구상했다.

개별 곡괭이의 능력치와 공격 판정은 `EquipmentSkillSystem.md` 및 `CombatSystem.md`에서 관리한다.

### 4.3 회피

회피는 플레이어의 전투 행동에 포함된다.

회피 행동의 구체적인 수치는 현재 인수인계 문서만으로 확정할 수 없다.

**확인 필요**

- 회피 입력키
- 회피 이동거리
- 회피 속도 및 지속 시간
- 회피 쿨타임
- 회피 중 무적 적용 여부 및 시간
- 벽 충돌 처리
- 다른 행동과의 동시 사용 규칙

위 항목은 현재 Unity 구현을 확인한 후 상세화한다.

### 4.4 스킬 사용

플레이어는 획득한 스킬을 장착하여 전투에서 사용한다.

스킬 4종의 구현 완료 보고가 있다.

스킬의 실제 키 배치, 공격 판정, 쿨타임 및 장착 제한은 현재 프로젝트 확인이 필요하다.

스킬 획득 및 장착 규칙은 `EquipmentSkillSystem.md`를 따른다.

## 5. 체력 및 피해 처리

### 5.1 체력

플레이어는 현재 체력과 최대 체력을 가진다.

몬스터의 공격을 받으면 현재 체력이 감소한다.

최대 체력과 현재 체력은 별개의 상태로 관리한다.

### 5.1.1 최대 HP와 체력 패시브 — 승인 기획

최대HP 변경 시 현재HP 비율을 유지한다. 체력20P는 물약 회복량+20%, 50P는 **일반 방** 클리어 시 최대HP10% 회복, 100P는 생명력 재생이다. 기존 물약 수량/사용 제한·생명3/부활2·입장/재시작 초기화 규칙은 유지한다.

재생은 살아 있는 적이 존재하는 방에서 마지막 실제 HP 피해 후5초가 지나면 초당 최대HP1% 회복한다. 방당 누적 한도 최대HP20%, 방 클리어 즉시 중단, 방 이동·부활 시 한도 초기화다. 최대HP 변화 시 이미 사용한 회복 한도의 비율을 유지한다. 재생 한도와 현재HP 비율은 서로 구분한다. 실제HP 피해가 없는 거부/무효 타격을 피해로 확정하지 않는다.

회복량의 소수점·최대HP 상한에 걸린 회복의 한도 소모 방식, 부활 후 재생 대기시간 등 미명시 경계는 임의 결정하지 않는다. 상세 해금 기준은 ProgressionSystem §4다. 이는 새 승인 기획이며 재생/패시브 구현 완료 보고가 아니다.

### 5.2 피해 처리

몬스터 및 보스 공격이 플레이어에게 적중하면 해당 공격의 피해량을 적용한다.

공격 예고와 실제 피해 판정은 해당 몬스터 또는 보스 명세를 따른다.

피격 후 무적 시간, 넉백, 경직 및 기타 반응은 실제 구현 확인이 필요하다.

### 5.3 사망 판정

현재 체력이 소진되면 사망 처리한다.

사망 시 남은 부활 기회를 확인하여 다음 상태로 진행한다.

- 부활 기회가 남아 있으면 부활
- 모든 부활 기회를 소모했으면 던전 실패

### 5.4 사망 시 전투 상태 정리

플레이어 사망과 부활 과정에서는 이전 공격의 잔여 판정이 문제를 일으키지 않도록 해야 한다.

기존 몬스터 구현 명세의 연동 조건:

- 진행 중인 몬스터 공격 중단
- 공격 예고 장판 정리
- 잔여 투사체 정리
- 남아 있는 공격 판정 정리
- 부활 직후 이전 공격에 다시 피격되는 문제 방지

이 규칙의 구현 책임은 해당 몬스터, 전투 및 방 관리 시스템과 함께 검토한다.

## 6. 생명 및 부활 시스템

### 6.1 생명 규칙

**최신 확정 기획**

- 최초 생명: 3개
- 부활 가능 횟수: 2회
- 세 번째 사망 시 던전 실패

| 상황 | 남은 생명 | 처리 |
|---|---:|---|
| 던전 시작 | 3 | 정상 플레이 |
| 첫 번째 사망 | 2 | 부활 |
| 두 번째 사망 | 1 | 부활 |
| 세 번째 사망 | 0 | 던전 실패 |

기존 부활 3회 규칙은 적용하지 않는다.

### 6.2 부활 위치

플레이어는 현재 진행 중인 방의 입구에서 부활한다.

던전의 첫 번째 방 입구로 되돌아가지 않는다.

보스 방에서 사망한 경우에도 현재 방 입구 부활 원칙을 따른다.

부활 시 보스 위치를 강제로 이동시키는 변경안은 적용하지 않는다.

### 6.3 부활 시 상태 처리

부활 시 다음 사항을 유지하거나 확인해야 한다.

- 현재 진행 중인 방 유지
- 남은 부활 횟수 반영
- 해당 런에서 획득한 돈·경험치·아이템 유지
- 런 전투 기록 유지
- 남은 공격 판정 정리
- 카메라의 현재 방 설정 유지

**미확정 또는 구현 확인 필요**

- 부활 시 체력 회복량
- 부활 동작 또는 연출 시간
- 부활 직후 무적 시간
- 부활 중 입력 처리
- 부활 시 기존 상태 이상 효과 처리

현재 자료에 없는 수치를 새로 지정하지 않는다.

### 6.3.1 보스전 HP·페이즈·위치와 전환 예약

기존 부활2회·현재BossRoom24x22 입구(12,2) 복귀를 유지한다. 최신 승인으로 부활 시 보스 남은HP·현재 페이즈·현재 위치는 유지하며 초기 위치로 강제 이동하지 않는다. 플레이어 사망 시 공격·연계 예약·낙석/투사체/예고를 정리하고 취소된 연계는 재개하지 않는다. 이미 완료한 등장/변신은 반복하지 않는다.

HP50% 이하 전환 예약 중 사망은 공격 정리→기존 사망/부활→예약 유지→부활 후 변신→2페이즈 전투 순서다. 최종 사망/실패 확정은 기존 실패를 우선한다. 보스HP0/동일 프레임 양측 사망은 기존 클리어 우선·중복 보상 방지를 유지한다. 보스1차에서 관련 부활/예약 보존 검증 보고가 있지만 모든 상황의 전수 검증은 아니다. Player의 기존 부활HP/무적 등 미명시 수치는 바꾸지 않는다.

### 6.4 부활과 방 이동

방 이동 시 남은 부활 횟수는 유지한다.

다음 방으로 이동한다는 이유로 생명 3개를 다시 지급하지 않는다.

### 6.5 최종 사망

세 번째 사망 시 남은 생명이 0이 되고 던전 실패 상태가 된다.

실패 결과창을 닫아도 플레이어를 이동 가능 상태로 되돌리지 않는다.

자세한 실패 보상 및 결과 처리는 `DungeonSystem.md`, `RewardSystem.md`를 따른다.

## 7. 물약 시스템

### 7.1 기본 목적

물약은 플레이어의 체력을 회복하기 위한 소모 기능이다.

현재 플레이어에 물약 관련 스크립트를 연결하여 작업한 기록이 있다.

### 7.2 물약 수량

**확정 규칙**

던전을 다시 시작하면 물약 수량을 3개로 초기화한다.

한 런에서 방을 이동할 때 남은 물약 수량을 유지한다.

### 7.3 사용 관련 확인 사항

현재 자료에서 최종 명세가 확인되지 않은 내용:

- 물약 사용키
- 1회 회복량
- 사용 쿨타임
- 회복 적용 방식
- 최대 체력 상태에서의 사용 처리
- 사용 중 피격 처리
- 사망 또는 부활 시 물약 처리

해당 내용은 Unity 프로젝트 확인 후 확정 또는 보완한다.

### 7.4 결과창과 물약

던전 결과창의 회복량 기록은 실제 플레이 중 회복된 양과 연동한다.

부활 시 체력 복원을 회복량 통계에 포함할지는 별도 확인이 필요하다.

## 8. 월드 상호작용

### 8.1 상호작용 입력

확인된 월드 상호작용 키는 T이다.

현재 대표적인 상호작용 대상은 메인 씬의 광산 입구이다.

### 8.2 광산 입구

플레이어가 광산 입구 근처에서 T를 입력하면 던전 선택창을 연다.

기존의 임시 인벤토리 게임 시작 방식은 현재 기획에서 대체되었다.

### 8.3 상호작용 세부 규칙

다음 내용은 기존 구현 확인이 필요하다.

- 상호작용 거리
- 상호작용 가능 상태 표시
- 여러 대상이 가까이 있을 때의 선택 방식
- 상호작용 중 다른 행동 허용 여부

새로운 상호작용 시스템을 임의로 추가하지 않는다.

## 9. 플레이어와 UI 연동

### 9.1 확인된 입력

| 입력 | 기능 |
|---|---|
| T | 월드 상호작용 |
| I | 인벤토리 열기·닫기 |
| ESC | UI 닫기 또는 퍼즈 메뉴 |

공격, 회피, 물약, 스킬의 최종 키 배치는 현재 Unity 설정을 확인한다.

### 9.2 생명 HUD

생명은 부적 또는 유사한 아이콘 3개로 표시한다.

- 남은 생명에 해당하는 아이콘은 활성 상태로 표시한다.
- 소모된 아이콘은 어둡게 표시한다.
- 결과창의 부활 횟수 기록은 최대 2회를 기준으로 한다.

### 9.3 체력 HUD

플레이어의 현재 체력 상태를 HUD에 반영한다.

체력 표시의 구체적인 위치, 형태와 수치는 현재 구현 확인이 필요하다.

### 9.4 UI와 게임 시간

인벤토리와 던전 입장창이 열려 있어도 게임 시간은 흐른다.

ESC 퍼즈 메뉴는 일반적인 일시정지를 담당한다.

플레이어 입력과 UI 열기·닫기의 충돌은 현재 구현을 기준으로 검토한다.

---

### 9.5 Tab 지도 중 조작과 상태 보존

정상 플레이의 지도는 비정지·마우스 비차단이며 기존 이동·360도 조준/3단 콤보·E/R·회피·Q를 허용한다. 표시/숨김만으로 공격 취소·콤보/예약·스킬/패시브/물약 초기화를 만들지 않는다. 인벤토리 등 기존 조작 제한을 우회하지 않는다. 사망/부활 중 즉시 숨김/표시 금지, 완료 후 정상 상태에서 Tab을 놓고 새로 눌러야 한다. 연출/다른UI·클리어/실패 예외는 [UISystem](UISystem.md) §3.6을 따른다. 승인된 표시 기획을 유지하고28일 구현/아트·배경수정 핵심Play 보고와 남은 전체입력/상태 회귀는 UISystem §3.8에서 구분한다.

## 10. 던전 진행 상태와 플레이어 조작

### 10.1 정상 플레이

플레이어는 이동, 전투 및 상호작용 행동을 수행한다.

### 10.1.1 보스 등장·변신 연출 중 제한 — 신규 승인

보스1차 구현의 상태 제어/행동·쿨타임 정지에 Codex 집중검증 보고가 있다. 등장/변신 전용아트는27일 부분 완료 보고,카메라/스킵UI 미해결은 BossSystem §4.19를 우선하며 이번 재검증은 아니다. 보스 등장/변신 동안 이동·회피·기본 공격·E/R 스킬·물약을 금지하고 양측 신규 피해·공격 예고/예약을 차단하며 기존 잔여 공격을 정리한다. 플레이어/보스 전투 쿨타임과 회피·스킬·물약 재사용 제한은 정지한다. 연출 정상 종료/스킵 뒤 남은 쿨타임부터 재개하고 초기화/즉시 만료하지 않는다.

카메라·애니메이션·스킵 입력은 정상 동작하며 전체 게임 일시정지를 무조건 요구하지 않는다. 기존 인벤토리 비정지·전투 입력 차단·ESC 우선순위는 유지한다. 세부 스킵UI/ESC 결합은 별도 검토한다. 상세는 [BossSystem](BossSystem.md) §4.12~4.15를 따른다.

### 10.2 클리어 상태

보스를 처치하여 던전 클리어 결과창이 열리더라도 플레이어 이동은 가능하다.

결과창을 닫고 주변을 돌아볼 수 있다.

공격 및 스킬 사용 가능 범위는 구현 확인이 필요하다.

### 10.3 실패 상태

최종 사망으로 던전 실패 상태가 되면 플레이어는 이동할 수 없다.

실패 결과창을 닫아도 정상 플레이 상태로 복귀하지 않는다.

### 10.4 재시작

동일한 던전과 난이도로 다시 시작할 때 다음 항목을 초기화한다.

- 현재 체력
- 물약 수량: 3개
- 남은 부활 가능 횟수: 2회

기존 영구 성장 데이터는 유지한다.

## 11. 성장·장비·저장 연동

### 11.1 성장 시스템

몬스터를 처치하면 경험치를 즉시 획득한다.

Lv.1 미사용3P로 시작하고 레벨업당3P, 최대Lv.50까지 총150P를 획득한다. 기존1P 규칙은 이번 승인으로 대체한다.

성장에 따른 능력치 반영 규칙은 `ProgressionSystem.md`에서 관리한다.

### 11.2 장비 시스템

곡괭이의 능력치는 플레이어 공격 성능에 영향을 줄 수 있다.

개별 장비 및 스킬 수치는 장비·스킬 시스템 문서에서 관리한다.

### 11.3 영구 저장

저장 대상으로 관리해야 하는 플레이어 관련 정보는 다음과 같다.

- 경험치 및 레벨
- 영구 성장 능력치
- 사용·미사용 스탯 포인트
- 보유 장비
- 획득 및 장착 스킬

실제 저장 구현 범위는 코드 확인이 필요하다.

### 11.3.1 성장 구성과 기존 저장 이전

던전 입장 시 성장 구성을 고정하고 던전 내부에서는 장비·스킬·스탯·패시브 열람만 가능하다. 교체·투자·스탯 초기화는 불가하며 인벤토리 시간은 계속 흐른다. 방 이동에서도 구성과 기존 런 자원 보존 규칙을 유지한다. 물리 강화 충전은 방 이동 유지/사망·부활 초기화라는 별도 패시브 규칙을 따른다.

최신 승인 저장 이전은 기존 레벨·현재 레벨 진행EXP·투자 결과를 유지하고 레벨×3P에서 기존 투자P를 뺀 미사용P로 최초1회 보정한다. v1 투자0P 및 새 버전/이전 완료 보호의 조사·설계 범위는 SaveSystem §6을 따른다. v1만 지원하던 조사는 과거 상태이며 현재 v3 이전·보호 구현 보고는 SaveSystem §6을 따른다.

### 11.3.2 골드 스탯 초기화와 플레이어 상태

메인 로비에서 고정500G(초기 테스트값)를 소모하고 세 투자 전부를 반환한다. 미투자/골드 부족·던전에서는 거부한다. 최대HP 변경 시 현재HP 비율을 유지하며 레벨·EXP·아이템·장비·스킬 등 영구 정보는 보존한다. 파일 쓰기 실패 시 골드·투자·현재HP를 바꾸지 않는다.

성공 시 체력100P 재생 누계/대기·물리100P 충전·마법100P 폭발 대기 등 패시브 런타임만 정리하고 일반 스킬 쿨타임·물약·부활·런 보상은 보존한다. 잔류/예약 스킬이 있으면 실행을 거부한다. 현재HP 비율의 정수 변환은 현 구현에서 올림·사망0을 유지하며 이는 회복 이벤트/회복 통계에 합산하지 않는다는 Codex 보고다. 인라인2단계는 [UISystem](UISystem.md) §9.10.2, 저장은 [SaveSystem](SaveSystem.md) §6.6을 따른다.

### 11.4 런 내부 유지

현재 체력, 남은 물약, 부활 횟수는 던전 플레이 중 방을 이동하더라도 유지한다.

런 진행과 저장 데이터의 구분은 `DungeonSystem.md`, `SaveSystem.md`에서 관리한다.

## 12. 시스템 간 의존성

| 관련 시스템 | 연동 관계 |
|---|---|
| DungeonSystem | 부활, 실패, 재시작 및 런 상태 |
| MapSystem | 플레이어 위치, 벽 충돌, 방 입구, 카메라 |
| CombatSystem | 기본 공격, 회피, 피해 및 피격 |
| MonsterSystem | 공격 피해, 감속 및 사망 시 공격 정리 |
| BossSystem | 보스 공격, 예고, 부활 연동 |
| ProgressionSystem | 레벨, 스탯 및 능력치 |
| EquipmentSkillSystem | 곡괭이 능력치, 스킬 장착 |
| UISystem | 체력·생명·물약 HUD 및 입력 |
| SaveSystem | 영구 성장 및 획득 데이터 유지 |

### 12.1 변경 시 주의사항

- 맵 변경으로 현재 방 입구 부활이 손상되지 않아야 한다.
- 능력치 변경으로 감속 복구 규칙이 손상되지 않아야 한다.
- 방 교체로 체력과 물약 수량이 초기화되지 않아야 한다.
- 결과창 변경으로 클리어·실패 상태별 이동 허용 규칙이 바뀌지 않아야 한다.
- 몬스터 공격의 잔여 판정이 부활 직후 잘못 적용되지 않아야 한다.

## 13. 현재 구현 현황

**보스 최신 현황:** 2페이즈/강화·연계/낙석과 연출 상태 제어·전투 쿨타임 정지는1~3차 및후속 Codex 구현/집중검증 보고가 있다. 전용 연출 아트는27일 부분 완료 보고가 추가됐으며 카메라/스킵UI·자동 옵션은 후속이다(BossSystem §4.19). 전체 회귀/최종 밸런스 완료가 아니다. 이번 문서 작업에서 Play를 재실행하지 않았다. 최신 근거는 BossSystem §14, 기존 아래검사는 당시 이력이다. 곡괭이3단 콤보 기능은 WORK_STATUS의 1단계 구현·복구/집중 검사 보고가 있으며 잔상·먼지·파편은26일 적용/핵심Play 보고가 있다(§13.1). 이번에 재검증하지 않았다.

**2026-10-23 최신 사용자 승인 반영.** 승인 기획과 [WORK_STATUS.md](../WORK_STATUS.md)의 Codex 구현·검증 보고를 구분한다. 이번 작업은 문서 갱신과 관련 코드의 읽기 전용 확인이며 Unity 컴파일·Play·빌드 검증은 재실행하지 않았다. 아래 과거 구현 기록은 당시 이력으로 보존한다.

WORK_STATUS의 성장1~3차/성장4차D에는 Lv.50/3P·3스탯/9패시브·현재HP 비율·v3 이전·던전 투자 제한 및500G 초기화 구현 보고가 있다. 관련 코드에서도 초기화 비용·권한 재검사·저장 성공 후 적용을 읽기 전용 확인했다. 성장177개·초기화 서비스53개/UI57개 보고를 이번 테스트로 표현하지 않는다. 아래는 개편 이전 이력이다.

> **문서 갱신: 2026-10-21 / 승인 기획 v0.1 유지.** 구현 현황은 [WORK_STATUS.md](../WORK_STATUS.md)의 Codex 보고와 그 안에 기록된 Unity MCP 테스트(최종 기록일 2026-10-20)를 대조한 것이다. 이번 문서 작업에서 Unity 코드·씬·프리팹을 검사하거나 컴파일·플레이 테스트를 재실행하지 않았다. 아래의 ‘통과’·‘확인’은 당시 기록의 주장이다. 임시값은 최종 밸런스가 아니며 본문의 미확정 기획을 새로 확정하지 않는다. 기존 인수인계 및 확인 필요 목록은 보존하되 구현 사실의 근거와 시점은 최신 보충을 우선한다.

### 2026-10-21 구현 기록 대조

**Codex 구현 완료 보고:** 총 생명 3개 / 부활 2회를 유지한다. Q 물약과 E/R 스킬 입력, 스킬 4종의 행동 상태 제한 및 공격·회피·물약과의 상호 제한이 연결됐다. 기존 체력·이동·회피 명세를 변경하지 않는다.

- 방 이동 직전에 스킬을 취소하며 사망·부활·비활성화·결과 전환에서 소유 효과와 예약 피해, 행동 제한을 정리한 기록이다.
- 방 이동·부활에서는 스킬 쿨타임을 유지하고 새로운 런에서 초기화한다.
- 자철석 감속은 기본 이동 속도·스킬 배율에 0.7을 곱한다. 재적용은 감속을 중첩하지 않고 남은 시간을 갱신한다. 회피 속도는 기존 상태를 유지하며 사망·방 이동·결과·비활성화에서 ClearSlow로 정리한다.
- **당시 임시 구현 데이터:** 스킬용 물리 공격력 7 / 마법 공격력 6. 기존 평타 피해 10을 변경하지 않았다는 보고이며, §2의 설계 당시 플레이어 가정값이나 최종 능력치를 대체하지 않는다.

**기록된 Unity MCP 테스트:** 성장 통합 검증 37개에는 생명 3→2→1→0, 실제 부활 2회, 중복 사망 무소모와 새 도전 초기화가 포함된다. 별도 Q 입력 검증에서 HP 50→85, 물약 3→2, HUD 2/3을 확인했다는 기록이다. 스킬 60개 검증은 입력 우선순위·행동 제한·사망/부활/방 전환 예약 공격 취소를 포함한다. 몬스터 검증은 감속 0.7·비중첩 갱신·만료, 무적 중 피해/감속 없음, 사망 즉시 공격 취소와 부활을 보고한다.

**기획 대조 / 추가 확인:** 30% 감속 및 부활 규칙과 충돌하지 않는다. 비중첩·시간 갱신은 구현 보고로만 기록하며 미확정 중첩 기획을 새로 확정하지 않는다. Q 실험의 회복량은 테스트 관측값이며 최종 물약 수치가 아니다. 현재 플레이어 능력치·기존 이동/회피 수치와 최신 코드의 일치, 물리 입력 사용감·장시간 전투는 후속 확인 대상이다.

## 14. 기획 상태 정리

### 14.1 확정된 규칙

- 2D 탑뷰 플레이어 이동
- 곡괭이를 주요 무기로 사용
- 플레이어 체력 및 사망 시스템
- 부활 가능 횟수 2회
- 현재 방 입구에서 부활
- 방 이동 시 현재 체력, 물약, 부활 횟수 유지
- 다시 시작 시 물약 3개
- 최종 사망 시 던전 실패
- 클리어 결과창 중 이동 가능
- 실패 결과창 중 이동 불가
- Lv.1 초기3P·레벨업3P·Lv.50/총150P·3스탯 각100P 상한
- 자철석 몬스터의 30% 감속, 1.5초 지속

### 14.2 기존 기획에서 적용하지 않는 내용

- 부활 3회
- 부활 시 최초 던전 입구 복귀
- 부활 시 보스 위치 강제 변경
- 실패 결과창을 닫으면 플레이어 조작 복구
- 감속 해제 시 기본 이동 속도를 특정 고정값으로 강제 변경

### 14.3 미확정 또는 확인 필요

- 플레이어 실제 기본 능력치
- 기본 공격의 최종 입력 및 공격 속도
- 회피 세부 규칙
- 공격·스킬 단축키
- 물약 회복량 및 사용 조건
- 부활 시 체력 복원량
- 부활 무적 시간
- 피격 무적·경직·넉백
- 능력치 변경 및 상태 이상 중첩
- 개별 플레이어 HUD의 구체적 배치
