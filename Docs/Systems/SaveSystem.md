## 1. 시스템 개요

### 1.1 목적

저장 및 불러오기 시스템은 플레이어의 영구 성장 정보와 획득한 보상을 게임 종료 및 재실행 이후에도 유지하도록 관리한다.

특히 던전 진행 중 획득한 보상, 던전 클리어 보상, 장비 및 스킬 정보가 의도치 않게 소실되거나 중복 지급되지 않도록 하는 것을 목표로 한다.

### 1.2 주요 기능

- 플레이어 영구 데이터 저장
- 게임 시작 및 재실행 시 저장 데이터 불러오기
- 돈과 경험치 보존
- 레벨 및 스탯 포인트 보존
- 획득 아이템·재료·장비 보존
- 보유 및 장착 스킬 보존
- 던전 클리어 보상 저장
- 중복 보상 지급 방지
- 던전 재시작과 영구 데이터 분리
- 개발용 저장 데이터 초기화

### 1.3 기존 구현 현황

저장 및 불러오기 기능은 구현 완료 보고가 존재한다.

사용자는 Unity Play를 중지한 뒤 다시 실행해도 경험치와 돈 등이 유지되는 것을 확인했다고 보고했다.

다만 이는 사용자 보고 기준이며, 전체 데이터 항목과 저장 구조를 직접 검증한 것은 아니다.

## 2. 저장 데이터의 구분

### 2.1 영구 데이터

영구 데이터는 던전 클리어·실패·재시작 또는 게임 종료 이후에도 유지해야 하는 정보이다.

주요 대상:

- 돈
- 경험치
- 레벨
- 획득한 제작 재료
- 획득한 아이템
- 보유 곡괭이
- 제작한 곡괭이
- 장착 장비
- 보유 스킬
- 장착 스킬
- 성장 능력치
- 미사용 스탯 포인트
- 사용한 스탯 포인트

실제 현재 저장 시스템이 이 항목 전체를 지원하는지는 Unity 프로젝트 확인이 필요하다.

### 2.2 런 내부 데이터

런 내부 데이터는 한 번의 던전 플레이 과정에서 관리하는 상태이다.

| 데이터 | 방 이동 시 |
|---|---|
| 현재 체력 | 유지 |
| 남은 물약 | 유지 |
| 남은 부활 횟수 | 유지 |
| 현재 던전 및 난이도 | 유지 |
| 런 획득 보상 기록 | 유지 |
| 전투 기록 | 유지 |
| 현재 방 진행 상태 | 진행에 따라 갱신 |

런 데이터는 방을 이동한다고 초기화되지 않는다.

### 2.3 런 데이터와 영구 저장 구분

**런 데이터를 방 사이에서 유지하는 것과, 게임 종료 후에도 저장하는 것은 서로 다른 개념이다.**

현재 체력, 물약, 남은 부활 횟수 및 현재 방 진행 상태를 게임 종료 이후에도 복원하는지에 대한 규칙은 확정되지 않았다.

따라서 진행 중인 던전의 중단·재개 기능이 존재한다고 단정하지 않는다.

### 2.4 보상 데이터와 런 기록

돈, 경험치, 아이템 등 실제로 획득한 데이터와 결과창에 표시하는 런 기록을 구분한다.

런 기록은 해당 플레이에서 무엇을 얼마나 획득했는지 표시하기 위한 정보이다.

결과창을 표시하기 위해 런 기록을 읽는 행위가 보상 재지급으로 연결되어서는 안 된다.

## 3. 돈 및 경험치 저장

### 3.1 돈

몬스터 처치 시 돈을 즉시 획득한다.

획득한 돈은 영구 유지 대상이다.

던전에 실패하더라도 이미 획득한 돈을 회수하지 않는다.

### 3.2 경험치

몬스터 처치 시 경험치를 즉시 획득한다.

획득 경험치는 플레이어 레벨과 연동한다.

던전에 실패해도 이미 획득한 경험치를 유지한다.

### 3.3 레벨

현재 플레이어 레벨은 영구 저장 대상이다.

던전 재시작 또는 실패를 이유로 레벨을 초기화하지 않는다.

### 3.4 클리어 돈·경험치

**확정 규칙**

별도의 던전 클리어 돈·경험치 보너스는 없다.

결과창에 표시되는 돈과 경험치는 해당 런에서 이미 획득한 데이터를 기준으로 한다.

결과창을 열 때 돈이나 경험치를 다시 지급하지 않는다.

### 3.5 구현 확인 사항

- 돈 저장 및 복원
- 경험치 저장 및 복원
- 레벨 저장 및 복원
- 처치 보상과 저장 데이터의 일치
- 결과창 재열기에 따른 중복 지급 여부

## 4. 아이템 및 재료 저장

### 4.1 획득 재료

일반 몬스터는 기존 확정 드롭 규칙에 따라 재료를 지급한다.

- 드롭 성공 확률: 50%
- 성공 시 수량: 1~2개

획득한 재료는 영구 보유 데이터에 반영한다.

### 4.2 아이템 데이터

저장 대상에는 획득한 아이템이 포함된다.

정확한 아이템 ID, 데이터 구조 및 수량 보관 방식은 현재 프로젝트 확인이 필요하다.

### 4.3 인벤토리와의 연동

저장 데이터를 불러온 뒤 보유 아이템과 재료가 인벤토리에 정상적으로 표시되어야 한다.

인벤토리를 열거나 닫는 것만으로 보유 데이터가 변경되어서는 안 된다.

### 4.4 던전 실패

던전 실패 시 이미 획득한 재료와 아이템은 100% 유지한다.

실패했다고 기존 획득 재료를 회수하지 않는다.

### 4.5 확인 필요 사항

- 아이템 종류별 저장 방식
- 수량 데이터 저장
- 동일 아이템 중첩 보관
- 아이템 ID 변경 시 기존 데이터 처리
- 보유 아이템과 UI 표시의 일치

이 항목은 현재 구현 검증 대상이며 새로운 저장 방식을 확정하지 않는다.

## 5. 장비 및 스킬 저장

### 5.1 곡괭이

저장 대상으로 관리해야 하는 정보:

- 보유 곡괭이
- 제작한 곡괭이
- 장착한 곡괭이

곡괭이 제작 기능은 아직 구현 완료 보고가 없다.

따라서 제작한 곡괭이의 저장 기능까지 완료되었다고 단정하지 않는다.

### 5.2 다른 장비

기존 인벤토리 기획에는 상의, 하의, 악세서리 슬롯이 포함되어 있다.

장비 및 성장 관련 데이터는 영구 유지 대상이지만, 확장 장비의 실제 콘텐츠와 저장 지원 상태는 확인이 필요하다.

### 5.3 스킬

저장 대상:

- 획득한 스킬
- 장착한 스킬

기존 플레이어 스킬 4종의 구현 완료 보고가 있다.

정확한 스킬 ID, 장착 슬롯 및 저장 데이터 구조는 확인이 필요하다.

### 5.4 장착 상태 복원

저장한 장비와 스킬의 장착 상태는 불러오기 이후에도 유지되어야 한다.

장착 정보와 실제 전투에서 사용되는 장비·스킬이 일치하는지 검증한다.

### 5.5 제작 데이터 연동

향후 곡괭이 제작 기능이 구현되면 제작 과정의 돈·재료 사용과 곡괭이 획득 결과가 영구 데이터에 올바르게 반영되어야 한다.

구체적인 저장 시점과 방식은 제작 기능의 상세 구현을 확인하여 정한다.

## 6. 스탯 및 성장 데이터 저장

### 6.1 저장 대상

- 경험치
- 현재 레벨
- 미사용 스탯 포인트
- 사용한 스탯 포인트
- 스탯 투자 결과
- 영구 성장 관련 데이터

### 6.2 레벨업과 저장

레벨이 오르면 스탯 포인트 1개를 획득한다.

레벨업 결과와 획득한 스탯 포인트는 서로 일관되게 유지해야 한다.

### 6.3 스탯 투자

플레이어가 스탯 포인트를 투자하면 사용한 포인트와 투자 결과가 함께 관리되어야 한다.

스탯 투자 시스템의 실제 구현 완료 여부는 확인되지 않았다.

### 6.4 불러오기

저장 데이터를 불러올 때 다음 상태가 일치해야 한다.

- 레벨
- 경험치
- 보유 스탯 포인트
- 사용한 스탯 포인트
- 투자 결과로 반영된 능력치

기존 성장 결과가 중복 계산되거나 소실되지 않아야 한다.

---

## 7. 던전 클리어 보상 저장

### 7.1 클리어 조건

보스를 처치하면 던전 클리어 상태가 확정된다.

### 7.2 클리어 보상 지급 시점

**최신 확정 규칙**

클리어 보상은 결과창을 최초로 표시하는 과정에서 지급하고 저장한다.

결과창의 열기·닫기 상태와 보상 지급 및 저장은 분리한다.

### 7.3 클리어 처리 관계

기획상 필요한 처리 관계는 다음과 같다.

1. 보스 처치
2. 던전 클리어 상태 확정
3. 클리어 보상 결정 및 지급
4. 지급한 보상 저장
5. 결과창에 확정된 보상 표시

이 과정은 보상과 결과창의 관계를 설명한 것이며, 실제 코드 내부의 상세 이벤트 순서를 확정하는 것은 아니다.

### 7.4 결과창 닫기

결과창을 닫아도 이미 지급된 클리어 보상은 유지한다.

닫기 동작을 저장 완료의 필수 조건으로 사용하지 않는다.

### 7.5 결과창 재열기

결과창을 다시 열면 해당 런의 기존 보상 데이터를 표시한다.

새로운 보상 지급 및 저장 처리를 반복하지 않는다.

### 7.6 로비 복귀

결과창에서 로비로 이동하더라도 클리어 보상은 유지한다.

로비 이동 버튼을 눌러야만 클리어 보상이 저장되는 구조에 의존하지 않는다.

### 7.7 게임 종료

클리어 보상이 지급 및 저장된 뒤 게임을 종료하더라도 보상이 유지되어야 한다.

### 7.8 중복 지급 방지

동일한 런의 클리어 보상이 반복 지급되지 않아야 한다.

중복 지급 가능성이 있는 상황:

- 결과창 최초 표시 과정의 중복 실행
- 결과창 닫기 및 재열기
- 로비 이동
- 저장 처리 재호출
- 이미 처리한 결과에 대한 재진입

실제 구현에서 지급 완료 상태를 관리하는 방식은 기존 코드를 확인한다.

## 8. 던전 실패와 데이터 유지

### 8.1 실패 조건

부활 가능 횟수 2회를 모두 사용한 뒤 최종 사망하면 던전 실패가 발생한다.

### 8.2 획득 보상 유지

**확정 규칙**

던전 실패 시에도 이미 획득한 보상은 100% 유지한다.

유지 대상:

- 돈
- 경험치
- 재료
- 이미 획득한 아이템

### 8.3 미획득 보상

아직 획득하지 않은 보스 보상과 클리어 전용 보상은 지급하지 않는다.

### 8.4 엘리트 보상

엘리트 몬스터가 존재하고 이미 처치 보상을 지급받았다면 실패 시 해당 보상을 임의로 회수하지 않는다.

### 8.5 실패 결과창

실패 결과창은 실제로 획득한 보상을 표시한다.

결과창을 표시하거나 닫는 이유로 이미 획득한 보상을 회수하지 않는다.

### 8.6 저장 확인

던전 실패 및 로비 복귀 이후에도 기존 획득 보상이 유지되는지 확인한다.

경험치 획득으로 인한 레벨 상승 및 성장 결과도 영구 데이터로 유지한다.

## 9. 방 이동과 데이터 유지

### 9.1 방 이동

플레이어가 한 던전 내에서 다음 방으로 진행하면 런 데이터가 유지되어야 한다.

### 9.2 유지 대상

- 현재 체력
- 남은 물약
- 남은 부활 횟수
- 획득한 돈
- 획득한 경험치
- 획득한 아이템
- 획득한 재료
- 전투 기록

### 9.3 방 교체 시 주의사항

방이 교체된다는 이유로 플레이어의 영구 성장 데이터나 획득한 보상을 초기화하지 않는다.

이전 방의 공격 오브젝트를 정리하는 과정과 플레이어의 보유 데이터 관리는 구분한다.

### 9.4 게임 종료 시 런 복원

현재 진행 중인 방, 체력, 물약, 부활 횟수 등을 게임 종료 후 복원하는지 여부는 미확정이다.

새로운 중단·재개 기능을 임의로 추가하지 않는다.

## 10. 던전 다시 시작

### 10.1 기본 동작

결과창에서 다시 시작하면 동일한 층과 난이도로 새로운 런을 시작한다.

### 10.2 초기화 대상

확정된 초기화 규칙:

- 첫 번째 방부터 시작
- 플레이어 체력 초기화
- 물약 수량 3개
- 부활 가능 횟수 2회

### 10.3 유지 대상

새 런을 시작하더라도 다음 영구 정보는 유지한다.

- 돈
- 경험치
- 레벨
- 보유 아이템 및 재료
- 장비
- 스킬
- 영구 성장 데이터

### 10.4 런 기록

새로운 런은 이전 런의 결과를 그대로 재사용하지 않아야 한다.

해당 런의 전투 기록과 보상 기록은 새로운 플레이 단위로 관리한다.

단, 결과창을 닫았다가 다시 여는 것은 새로운 런이 아니다.

### 10.5 중복 보상

새 런 시작 과정에서 이전 런의 클리어 보상을 다시 지급하지 않아야 한다.

## 11. 로비 복귀

### 11.1 결과창에서 로비 복귀

결과창의 로비 이동 버튼을 통해 메인 로비로 복귀한다.

이미 획득하고 저장한 보상은 유지한다.

### 11.2 퍼즈 메뉴에서 로비 복귀

퍼즈 메뉴에서 로비로 이동하더라도 이미 획득한 보상은 유지되어야 한다.

### 11.3 중도 종료

클리어 또는 실패가 확정되기 전에 자발적으로 던전을 종료하는 경우의 전체 처리 규칙은 현재 자료에서 확정되지 않았다.

특히 다음 사항은 추가 확인이 필요하다.

- 진행 중인 런을 다시 이어서 플레이할 수 있는지
- 중도 종료 시 던전 진행 상태를 저장하는지
- 결과창을 표시하는지
- 전투 기록을 유지하는지

이미 획득한 보상을 유지한다는 확정 규칙과 중도 종료의 세부 흐름은 구분한다.

기존 Unity 프로젝트의 실제 저장 구조를 우선 확인한다.

새로운 저장 파일 형식이나 외부 저장 서비스를 임의로 도입하지 않는다.

곡괭이 제작 결과와 돈·재료 소모 결과가 일치하지 않을 수 있다.

**저장 ↔ 던전**

방 이동 및 새 런 초기화 과정에서 영구 데이터가 잘못 초기화될 수 있다.

## 16. 현재 구현 현황

> **문서 갱신: 2026-10-21 / 승인 기획 v0.1 유지.** 구현 현황은 [WORK_STATUS.md](../WORK_STATUS.md)의 Codex 보고와 그 안에 기록된 Unity MCP 테스트(최종 기록일 2026-10-20)를 대조한 것이다. 이번 문서 작업에서 Unity 코드·씬·프리팹을 검사하거나 컴파일·플레이 테스트를 재실행하지 않았다. 아래의 ‘통과’·‘확인’은 당시 기록의 주장이다. 임시값은 최종 밸런스가 아니며 본문의 미확정 기획을 새로 확정하지 않는다. 기존 인수인계 및 확인 필요 목록은 보존하되 구현 사실의 근거와 시점은 최신 보충을 우선한다.

### 2026-10-21 구현 기록 대조

**Codex 구현 완료 보고:** 기존 DungeonRunManager에 CharacterSaveService를 연결하고 CharacterSaveFile v1 JSON payload와 SHA256 체크섬을 사용한다. 임시 파일 Flush(true) 후 원본 교체, 정상 .bak 백업, 손상 주 파일 .corrupt-GUID 보존 후 백업 복구 방식이다.

- 주 파일/백업 모두 로드 실패 시 LoadBlocked로 자동 저장과 명시적 Flush를 차단한다. 일반 저장 실패는 오류 안내와 재시도를 제공하며 귀환·종료 및 결과의 귀환/재시작을 차단한다. 모든 일시적 쓰기 오류가 곧 LoadBlocked라는 의미로 확대하지 않는다.
- 저장 대상: 레벨·현재 경험치·미사용 스탯 포인트·돈·재료 수량/등록순서·보유 스킬 ID·E/R 장착·카메라 흔들림 배율. 알 수 없는 재료/스킬 ID는 경고와 함께 별도 보존한다. 전용 재료 추가 후 5종 카탈로그를 연결한 기록이다.
- 영구 변경 후 0.4초 unscaled 디바운스 자동 저장, 처치 보상 트랜잭션 중간 Flush 차단, 입장·귀환·종료 전 Flush와 정상 종료 마지막 시도를 사용한다.
- 결과 정산은 lastSettledPlayId와 보유 데이터를 같은 스냅샷으로 즉시 저장하며, 저장 실패 시 메모리 보상을 유지하고 재시도에 재추첨/재지급하지 않는다.
- 실제 장비 제작·분배 스탯은 당시 미구현으로 그 결과 데이터도 저장 대상에 없다. 진행 중 던전의 방·적·체력·물약·생명·쿨타임·UI를 저장하지 않고 중간 이어하기를 지원하지 않는 구현 기록이다. 승인된 미래 장비/성장 저장 방향을 삭제한 것이 아니다.

**당시 저장 경로:** 빌드는 `C:/Users/User/AppData/LocalLow/DefaultCompany/mineDungeon/character.json`, Editor는 같은 폴더 아래 `Editor/character.json`으로 분리한다. 이는 기록상의 경로이며 이번 작업에서 사용자 저장 파일에 접근하거나 초기화하지 않았다.

**개발용 초기화 구현 보고:** Play Mode의 Ctrl+Shift+F9 또는 Tools/Mine Dungeon/개발용/플레이어 진행 데이터 초기화 메뉴와 native 확인창을 사용한다. Editor/UNITY_EDITOR 전용이다. 저장·보상 트랜잭션·씬 재시작 중에는 거부하고 주 파일/.bak을 신규 스냅샷으로 교체한 뒤 메모리 성장/인벤토리/정산 ID와 런을 정리해 Main으로 돌아간다. 실패 시 LoadBlocked 및 재시도를 사용한다. 카메라 흔들림 설정과 무관한 데이터는 보존한다. 테스트 기본 스킬 4종은 확정 초기 지급으로 승인하지 않는다.

**기록된 Unity MCP 테스트:** 저장 17항목 + 별도 Play 재실행 5항목, 재연결 후 입력/unknown ID 8항목 및 선택 필드 누락 로드 검증을 구분한다. 손상 주 파일/정상 백업 복구와 둘 다 손상 시 쓰기 차단, 성장/보유/장착/설정 복원, 결과 정산 ID·재시도 중복 무지급, 재료 5종 저장 복원이 보고됐다. 개발 초기화는 격리 경로의 메서드 호출로 기본값·설정 유지·주/백업 일치·재진입·반복 초기화·실패/재시도를 확인한 기록이며 물리 단축키/native 확인창 클릭·ESC 자동 검증은 하지 않았다.

**기획 대조 / 추가 확인:** 영구 보유 유지·중복 방지 원칙과 부합한다. 장비/투자 저장은 구현 공백, 중간 이어하기 없음은 당시 구현 지원 범위이며 미확정 기획의 새 확정이 아니다. 최신 Unity 코드/데이터 구조와의 일치, 실제 배포 빌드 종료·재실행/플랫폼 파일 교체·강제 종료 직전 디바운스 보존은 후속 검증 대상이다. 2026-10-20 결과 입력 시험에서 실제 Editor 저장이 변경되어 직전 .bak으로 복구·SHA256 일치를 확인했다는 사고 기록이 있으므로, 기존 기록 전체를 ‘사용자 저장 무접근’으로 일반화하지 않는다.

**출처:** WORK_STATUS의 「2026-10-19 성장 자동 저장 / 퍼즈 귀환·종료」 및 재연결 후 최종 완료, 「2026-10-20 통합 클리어/실패 결과창」, 「일반 몬스터 전용 재료」, 「Editor 전용 진행 데이터 초기화」.

- 방 이동 시 체력과 물약이 유지되는가?
- 방 이동 시 남은 부활 횟수가 유지되는가?
- 획득 보상과 전투 기록이 방 이동 후에도 유지되는가?
- 방 전환으로 영구 데이터가 초기화되지 않는가?

### 17.3 클리어

- 보스 처치 후 최초 결과 진입 과정에서 보상이 지급되는가?
- 지급한 보상이 저장되는가?
- 결과창 닫기 및 재열기로 보상이 중복 지급되지 않는가?
- 로비 복귀 후에도 보상이 유지되는가?
- 게임 종료 후 재실행해도 보상이 유지되는가?

### 17.4 실패

- 최종 사망 이후에도 획득한 보상이 유지되는가?
- 미획득 클리어 보상이 지급되지 않는가?
- 실패 후 로비 복귀 시 돈·경험치·재료·아이템이 유지되는가?

### 17.5 다시 시작

- 같은 층과 난이도로 새 런을 시작하는가?
- 체력, 물약 3개, 부활 2회가 초기화되는가?
- 레벨, 경험치, 돈, 장비 및 스킬이 유지되는가?
- 이전 런의 보상을 중복 지급하지 않는가?

### 17.6 개발용 초기화

해당 기능이 구현된 경우 다음을 확인한다.

- 초기화 범위가 명확한가?
- 확인 절차 없이 저장 데이터가 삭제되지 않는가?
- 현재 메모리 상태와 저장 데이터가 일치하는가?
- 이전 데이터를 자동 저장하여 복원하지 않는가?
- 무관한 파일을 삭제하지 않는가?

## 18. 기획 상태 정리

### 18.1 확정된 규칙

- 영구 성장과 획득 보상 유지
- 돈과 경험치 저장
- 레벨 및 스탯 포인트 저장 대상 관리
- 아이템·재료·장비·스킬 저장 대상 관리
- 방 이동 시 런 데이터 유지
- 클리어 보상 최초 결과 진입 시 지급 및 저장
- 결과창 재열기 시 보상 중복 지급 금지
- 결과창 로비 복귀 후 획득 보상 유지
- 퍼즈 메뉴 로비 복귀 시 이미 획득한 보상 유지
- 실패 시 이미 획득한 보상 100% 유지
- 다시 시작 시 영구 성장 유지
- 결과창에 이미 지급한 경험치와 돈을 재지급하지 않음

### 18.2 폐기 또는 적용하지 않는 내용

- 던전 실패 시 획득한 돈·경험치·재료 회수
- 결과창 버튼을 눌러야 클리어 보상을 지급하는 구조
- 결과창 재열기 때 보상 재지급
- 다시 시작할 때 영구 성장 데이터 초기화
- 방 이동 때 체력과 부활 횟수 초기화
- 별도의 던전 클리어 돈·경험치 보너스 지급

### 18.3 미확정 또는 확인 필요

- 실제 저장 파일 형식
- 실제 저장 경로
- 자동 저장 조건 및 주기
- 저장 슬롯 개수
- 저장 데이터 버전 관리
- 저장 실패 대응 방식
- 데이터 손상 시 복원 방식
- 현재 런 중단·재개 지원 여부
- 세부 저장 데이터 구조
- 실제 장비·스킬·스탯 저장 지원 범위
- 개발용 저장 초기화 구현 여부
- 개발용 초기화 단축키 및 초기화 범위
- 중도 던전 이탈의 전체 데이터 처리 방식

## 19. 문서 관리

본 문서는 광산던전의 영구 데이터 저장, 불러오기, 런 상태와 영구 데이터의 구분 및 보상 중복 지급 방지 규칙을 관리한다.

관련 기준 문서는 다음과 같다.

- `DungeonSystem.md`: 던전 진행, 클리어·실패·재시작
- `RewardSystem.md`: 보상 획득과 지급 시점
- `ProgressionSystem.md`: 경험치, 레벨, 스탯 성장
- `EquipmentSkillSystem.md`: 장비, 스킬, 제작
- `PlayerSystem.md`: 체력, 물약 및 부활
- `UISystem.md`: 결과창, HUD, 인벤토리

저장 관련 기획을 변경할 때는 획득 보상, 성장, 장비 및 던전 진행 시스템에 미치는 영향을 먼저 검토한다.

사용자 승인 후 공식 문서 수정안을 작성하고 관련 변경 내역을 `CHANGELOG.md`에 기록한다.

실제 구현 작업에서는 기존 저장 구조를 먼저 확인하고, 저장 데이터를 임의로 삭제하거나 새로운 형식으로 교체하지 않는다.
