## 1. 시스템 개요

### 1.1 목적

맵 시스템은 던전의 일반 전투 방과 보스 방, 방 이동, 몬스터 배치, 벽 및 이동 가능 영역, 카메라 제한 영역을 관리한다.

플레이어가 일반 방에서 몬스터를 처치하고 다음 방으로 이동하여 최종적으로 보스 방에 도달하는 구조를 지원한다.

### 1.2 주요 기능

- 일반 전투 방 구성
- 보스 방 연결
- 준비된 방 후보의 랜덤 선택
- 플레이어 입장 위치
- 몬스터 배치 영역
- 몬스터 전멸에 따른 출구 개방
- 다음 방 전환
- 벽 및 장애물 충돌
- 카메라 추적 및 영역 제한
- 현재 방 입구에서 부활
- 방 전환 시 기존 시스템 연동

### 1.3 시스템 상태

기존 일반 방 9종에 대한 설계도가 제작되었다.

Codex를 통해 Unity에 신규 맵을 구현하는 작업을 진행했으나 결과에 문제가 있어 맵 구조를 재검토하고 있다.

전체 맵 캔버스를 직사각형으로 구성하고 이동하지 않는 공간을 암석·암벽으로 채우는 방향이 최신 개선안으로 제시되었다.

이 개선안은 현재 검토 단계이며 최종 적용 확정으로 기록하지 않는다.

## 2. 던전의 방 진행 구조

### 2.1 기본 흐름

1. 플레이어가 던전에 입장한다.
2. 일반 전투 방을 불러온다.
3. 해당 방에 몬스터를 배치한다.
4. 플레이어가 몬스터와 전투한다.
5. 모든 대상 몬스터를 처치한다.
6. 방의 출구가 개방된다.
7. 출구를 이용하여 다음 방으로 진행한다.
8. 일반 방 진행 후 보스 방에 도달한다.
9. 보스를 처치하면 던전을 클리어한다.

### 2.2 방의 종류

**일반 전투 방**

- 일반 몬스터와 전투하는 공간
- 몬스터 전멸 시 출구 개방
- 준비된 맵 후보 중 랜덤으로 호출하는 방향

**보스 방**

- 보스 몬스터와 전투하는 공간
- 현재 보스는 돌골렘
- 보스 처치 시 던전 클리어

### 2.3 방 개수

기존 기획에서는 일반 방 3개와 보스 방 1개로 구성하는 방식을 논의한 이력이 있다.

다만 최신 인수인계 자료에서는 한 런의 정확한 방 개수와 구성을 프로젝트 설정으로 확인하도록 명시했다.

따라서 현재 방 개수를 최종 확정 수치로 기록하지 않는다.

**확인 필요**

- 한 런의 일반 방 개수
- 보스 방 포함 전체 방 개수
- 층·난이도별 방 개수 차이
- 방 진행 순서
- 중복 맵 등장 허용 여부

## 3. 맵 설계도의 공통 표기

### 3.1 설계도 색상

기존 맵 설계도에서 사용한 표기는 다음과 같다.

| 표기 | 의미 |
|---|---|
| 초록색 네모 | 플레이어 입장 위치 |
| 빨간색 네모 | 몬스터 전멸 후 사용할 출구 |
| 주황색 원 | 몬스터 배치 영역 |
| 벽 표시 | 플레이어와 몬스터의 이동을 막는 벽 |
| 연보라색 | 이동 가능한 바닥 영역 |

### 3.2 설계도 표기와 실제 게임 아트

설계도의 색상은 제작자가 구조를 구분하기 위해 사용한 표시이다.

초록색 입구, 빨간색 출구, 주황색 몬스터 영역을 실제 게임에 같은 색의 도형으로 구현하라는 뜻이 아니다.

### 3.3 몬스터 배치 영역

주황색 원은 몬스터 한 마리의 정확한 생성 위치를 의미하지 않는다.

하나의 배치 영역에 여러 몬스터를 배치할 수 있다.

배치 영역의 수와 몬스터의 실제 등장 수는 구분한다.

### 3.4 바닥과 벽

연보라색 영역은 플레이어가 이동 가능한 바닥을 나타낸다.

벽으로 지정한 위치는 플레이어 및 몬스터의 이동을 막는다.

설계도에서 인접한 두 바닥 구역 사이에 표시된 도형 경계가 반드시 벽이라는 의미는 아니다.

## 4. 기존 일반 방 맵 9종

현재 문서의 맵 설명은 기존에 확인된 설계도의 특징을 기록한 것이다.

Gemini에서 개선한 최신 이미지와 실제 형태가 다를 수 있다.

### 4.1 맵 1

**기존 설계 특징**

- 직사각형 구조
- 좌우로 번갈아 뻗는 가로 벽
- 좌측 하단 입구
- 우측 상단 출구
- 몬스터 배치 영역 2개

내부 가로 벽에 의해 이동 경로가 제한되는 구조이다.

### 4.2 맵 2

**기존 설계 특징**

- 세로형 구조
- 중앙 상단 장애물
- 하단 중앙 입구
- 상단 출구 후보 2개
- 몬스터 배치 영역 4개

**기존 출구 규칙**

상단의 출구 후보 2개 중 하나만 실제 출구로 선택한다.

방이 생성될 때 출구를 한 번 결정한다.

선택되지 않은 위치를 실제 사용 가능한 출구로 남겨두지 않는다.

선택된 출구도 몬스터 전멸 전에는 사용할 수 없다.

### 4.3 맵 3

**기존 설계 특징**

- 세로형 구조
- 작은 장애물과 긴 가로 벽
- 우측 하단 입구
- 상단 중앙 출구
- 몬스터 배치 영역 3개

### 4.4 맵 4

**기존 설계 특징**

- 꺾인 외곽 형태
- 우측 아래로 확장된 구역
- 좌측 아래 입구
- 우측 아래 출구
- 몬스터 배치 영역 3개
- 무너진 벽 표시 존재

현재 최신 개선안에서 추가 수정이 필요하다고 지적된 맵이다.

최신 수정 방향은 별도의 재검토 항목으로 관리한다.

### 4.5 맵 5

**기존 설계 특징**

- 맵 1의 변형
- 좌우로 번갈아 배치한 가로 벽
- 좌측 아래 입구
- 우측 위 측면 출구
- 몬스터 배치 영역 3개

### 4.6 맵 6

**기존 설계 특징**

- 세로 중심 통로
- 좌측·우측 확장 구역
- 하단 입구
- 상단 출구
- 몬스터 배치 영역 4개

확장된 바닥 구역과 중앙 통로가 연결되는 구조이다.

설계도의 단순 도형 경계를 실제 벽으로 잘못 해석하여 연결 통로를 막지 않도록 주의한다.

### 4.7 맵 7

**기존 설계 특징**

- 하단 중앙 벽으로 좌우 구역이 나뉨
- 좌측 아래 입구
- 상단 출구
- 몬스터 배치 영역 4개

### 4.8 맵 8

**기존 설계 특징**

- 맵 7 계열의 반대 배치
- 우측 아래 입구
- 상단 출구
- 몬스터 배치 영역 4개

### 4.9 맵 9

**기존 설계 특징**

- 오른쪽 아래에서 시작하는 꺾인 구조
- 왼쪽 위 방향으로 진행
- 좌측 위 출구
- 몬스터 배치 영역 3개
- 무너진 벽 표시 존재

### 4.10 기존 설계 요약

| 맵 | 배치 영역 수 | 주요 특징 |
|---|---:|---|
| 1 | 2 | 번갈아 배치된 가로 벽 |
| 2 | 4 | 상단 출구 후보 2개 중 하나 선택 |
| 3 | 3 | 세로형 및 긴 가로 벽 |
| 4 | 3 | 꺾인 외곽과 우측 확장 |
| 5 | 3 | 맵 1 변형 |
| 6 | 4 | 중심 통로와 좌우 확장 |
| 7 | 4 | 하단 중앙 벽과 좌우 구역 |
| 8 | 4 | 맵 7의 반대 배치 |
| 9 | 3 | 꺾인 진행 동선 |

이 배치 영역 수는 몬스터의 실제 등장 마릿수가 아니다.

## 5. 무너진 벽 표시

### 5.1 대상

기존 맵 4와 맵 9에는 무너진 벽 표시가 존재한다.

### 5.2 현재 명세

무너진 벽은 기존 설계도에 표현된 지형 요소이다.

이 표시만으로 별도 상호작용 기능을 확정할 수 없다.

### 5.3 자동 추가하지 않는 기능

- 파괴 가능한 벽
- 숨겨진 방
- 추가 출입 경로
- 외부 탈출 경로
- 특수 상호작용

위 기능은 별도 기획과 사용자 승인 없이 추가하지 않는다.

## 6. 맵 크기 및 월드 영역

### 6.1 이전 테스트 크기

기존 테스트에서 바닥 크기를 25 × 20으로 설정한 이력이 있다.

하지만 이는 모든 신규 맵의 최종 크기 확정을 의미하지 않는다.

### 6.2 현재 상태

일반 방 9종과 신규 맵 A의 최종 Unity 월드 크기는 미확정이다.

### 6.3 크기 검토 요소

최종 맵 크기를 결정할 때 다음을 함께 검토해야 한다.

- 플레이어 크기
- 플레이어 이동 속도
- 카메라 표시 범위
- 일반 몬스터 공격 거리
- 보스 공격 범위
- 회피 가능한 공간
- 통로 폭
- 몬스터 등장 수
- 방 클리어 시간

### 6.4 이미지 크기와 Unity 크기

설계도 이미지의 픽셀 크기를 Unity 월드 크기로 그대로 사용하지 않는다.

실제 플레이어와 몬스터의 크기 및 이동·공격 성능을 기준으로 최종 크기를 결정한다.

## 7. 최신 맵 구조 재검토

### 7.1 기존 구현 시도

기존에는 비직사각형 이동 영역을 그대로 제작하는 방향을 검토했다.

기존 시도의 핵심 내용:

- 비직사각형 이동 공간 구성
- 내부 벽 위로 카메라가 지나가는 것 허용
- 맵 외곽 밖으로 카메라가 나가지 않도록 제한

이후 Codex를 통한 신규 맵 제작 결과에 여러 문제가 발생했다고 보고되었다.

### 7.2 최신 개선 제안

**상태: 재검토 중 — 최종 확정 전**

사용자가 Gemini에서 검토한 개선 방향은 다음과 같다.

> 전체 맵을 직사각형 안에 넣고, 실제 이동하지 않는 빈 공간을 암석이나 암벽으로 채운다.

### 7.3 전체 맵 캔버스

최신 제안에서는 전체 맵 캔버스를 직사각형으로 구성한다.

카메라가 사용할 외곽 제한 영역도 해당 직사각형을 기준으로 관리하는 방향이다.

### 7.4 실제 이동 영역

전체 맵이 직사각형이더라도 플레이어가 실제로 이동할 수 있는 공간까지 직사각형으로 바꾸는 것은 아니다.

이동 가능한 공간은 기존 설계처럼 다음 형태를 유지할 수 있다.

- 꺾인 동선
- 분리되어 보이는 확장 구역
- 좁은 연결 통로
- 내부 장애물에 따라 달라지는 이동 경로

### 7.5 이동 불가능한 공간

실제로 이동하지 않는 공간을 암석 또는 암벽으로 채우는 방향이다.

해당 공간은 플레이어 및 몬스터의 이동을 제한한다.

암석과 암벽의 구체적인 아트, 타일 및 충돌 설정은 최종 확정되지 않았다.

### 7.6 카메라 경계

최신 개선 제안은 전체 직사각형을 카메라 제한의 기준으로 사용한다.

내부 벽과 암석은 카메라가 화면에 담을 수 있다.

정확한 카메라 제한 계산 및 기존 구현과의 차이는 후속 검증이 필요하다.

### 7.7 현재 확정 상태

이번 문서는 최신 개선 방향을 기록하지만 이를 모든 맵에 적용할 최종 공식 규칙으로 확정하지 않는다.

맵 파트별 기획 검토와 사용자 최종 결정이 필요하다.

## 8. 맵 4 최신 수정 방향

### 8.1 문제 제기

사용자는 Gemini 개선안의 맵 4가 추가 수정이 필요하다고 판단했다.

### 8.2 요청 방향

- 맵 6처럼 남는 공간을 암벽 등으로 채우는 방향
- 전체 외형을 직사각형으로 정리
- 기존 실제 이동 경로는 유지

### 8.3 확인 사항

정확한 최신 맵 4의 형태는 이미지 확인이 필요하다.

기존 맵 4의 입구·출구와 몬스터 배치가 개선안에서 유지되었는지도 최신 설계도를 기준으로 확인한다.

### 8.4 상태

**현재 재검토 중이며 최종 맵 형태 미확정**

## 9. 신규 맵 A

### 9.1 현재 상태

사용자는 Gemini 개선안에 신규 맵 A를 추가했다.

### 9.2 확인되지 않은 사항

- 최신 실제 맵 이미지
- 이동 가능한 공간
- 내부 벽 구성
- 입구 위치
- 출구 위치
- 몬스터 배치 영역
- 맵 크기
- 기존 맵 대체 여부
- 기존 후보에 추가되는지 여부

### 9.3 관리 원칙

신규 맵 A의 구조를 추측하여 작성하지 않는다.

최신 설계도 확인 후 구체적인 명세를 추가한다.

기존 9종에 더해 총 10종으로 확정되었다고 단정하지 않는다.

## 10. 랜덤 방 선택

### 10.1 기본 방향

일반 방은 준비된 맵 후보 중에서 랜덤으로 불러오는 방식이다.

### 10.2 맵 후보

기존 설계된 일반 방은 9종이다.

신규 맵 A의 후보 포함 여부는 미확정이다.

### 10.3 확인 필요

- 랜덤 선택 시점
- 후보 맵 목록
- 동일 맵 중복 등장 가능 여부
- 맵 선택 가중치
- 층·난이도별 후보 차이
- 일반 방 개수
- 보스 방 연결 방식
- 실제 프리팹 로딩 구조

### 10.4 주의사항

랜덤 선택 과정에서 실제 생성한 맵과 플레이어 입장 위치, 출구 및 카메라 경계가 서로 불일치하지 않아야 한다.

방 교체 중 이전 방의 전투 데이터가 새로운 방에 잘못 영향을 주지 않아야 한다.

### 10.5 구현 상태

기존 방 진행 및 보스 방 연결은 동작 확인 보고가 있다.

신규 일반 방의 랜덤 호출 구조는 맵 개편 과정에서 재검토가 필요하다.

## 11. 플레이어 입구 및 출구

### 11.1 입구

각 방에는 플레이어가 해당 방에 진입하는 위치가 존재한다.

기존 설계도에서는 초록색 네모로 표시했다.

### 11.2 출구

기존 설계도에서는 출구를 빨간색 네모로 표시했다.

전투 대상 몬스터가 모두 사망하면 출구를 사용할 수 있다.

### 11.3 출구 개방

**확정 규칙**

방에서 처치해야 하는 모든 몬스터를 처치하면 출구가 개방된다.

### 11.4 출구와 다음 방

출구를 이용하면 다음 방으로 진행한다.

방 이동 시 플레이어를 다음 방의 입장 위치에 배치한다.

### 11.5 맵 2 예외

기존 맵 2는 출구 후보 2개 중 하나를 방 생성 시 한 번 선택하는 설계이다.

선택되지 않은 출구 후보는 실제로 사용할 수 있는 출구로 남지 않는다.

### 11.6 부활 위치

플레이어의 부활 위치는 현재 진행 중인 방의 입구이다.

던전 최초 시작 방의 입구로 되돌아가지 않는다.

## 12. 몬스터 배치 시스템

### 12.1 기본 개념

일반 방의 설계도에는 몬스터 배치 영역이 존재한다.

각 배치 영역은 여러 몬스터를 배치할 수 있는 공간을 의미한다.

### 12.2 배치 조건

몬스터를 배치할 때 다음 조건을 만족해야 한다.

- 벽 내부에 생성하지 않는다.
- 서로 완전히 겹쳐 생성하지 않는다.
- 플레이어 입구를 막지 않는다.
- 출구를 막지 않는다.
- 플레이어가 도달할 수 없는 공간에 생성하지 않는다.

### 12.3 몬스터 수

몬스터 배치 영역 개수와 실제 등장하는 몬스터 수는 별개이다.

기존 몬스터 수를 각 배치 영역마다 그대로 복제하여 전체 적 수가 의도치 않게 폭증하지 않도록 한다.

### 12.4 몬스터 종류

현재 일반 몬스터 명세는 다음 5종이다.

- 돌
- 철
- 수정
- 석탄
- 자철석

맵별 몬스터 종류와 등장 수의 상세 구성은 현재 데이터 확인이 필요하다.

### 12.5 난이도 연동

던전 난이도는 4종이다.

난이도에 따른 정확한 몬스터 종류 및 배치 수의 차이는 현재 자료에 확정되어 있지 않다.

새로운 난이도 배치 값을 임의로 작성하지 않는다.

## 13. 내부 벽 및 충돌

### 13.1 벽의 기본 역할

벽은 플레이어와 몬스터의 이동을 제한하는 장애물이다.

### 13.2 카메라와 벽

내부 벽은 카메라가 화면에 표시하거나 카메라 시야가 통과할 수 있는 지형이다.

카메라 자체의 제한 경계와 캐릭터 이동을 막는 벽은 구분한다.

### 13.3 연결 통로

설계도에서 서로 연결되어야 하는 바닥 구역을 잘못 벽으로 막지 않는다.

특히 맵 6처럼 확장된 이동 구역과 중심 통로가 연결되는 구조에서는 바닥 구역의 연결 관계를 확인해야 한다.

### 13.4 실제 충돌

벽은 플레이어와 몬스터의 이동을 막는다.

다만 몬스터의 고유 공격이 벽과 충돌하는 세부 규칙은 개별 몬스터 및 보스 명세를 따른다.

### 13.5 확인 필요

- 벽 충돌체 구조
- 플레이어와 몬스터의 충돌 레이어
- 내부 벽과 외곽 벽의 처리
- 좁은 통로 폭
- 맵 바닥 및 벽 타일 규격
- 이동 불가 암석·암벽의 충돌 범위

기존 Unity 충돌 설정을 불필요하게 전역 변경하지 않는다.

## 14. 몬스터 AI와 맵 구조

### 14.1 주요 문제

기존 직선 추적 방식의 몬스터 AI는 복잡한 내부 벽에 막힐 수 있다.

몬스터가 플레이어에게 접근하지 못하면 해당 방의 전멸 조건을 만족하기 어려워질 수 있다.

### 14.2 검토할 상황

- 몬스터가 벽에 계속 걸리는 상황
- 플레이어에게 접근하지 못하는 상황
- 몬스터가 이동 불가 영역에 생성되는 상황
- 플레이어가 몬스터에게 접근할 수 없는 상황
- 마지막 몬스터가 벽 뒤에 갇혀 방을 완료할 수 없는 상황

### 14.3 일반 이동과 공격 이동 구분

몬스터가 일반 이동으로 플레이어에게 접근하는 방식과 고유 공격 중 이동하는 방식은 구분한다.

일반 이동에 벽 우회가 필요하더라도 공격 패턴의 기존 고유 규칙까지 변경하지 않는다.

### 14.4 돌 몬스터

도약 공격 중 벽을 통과하거나 이동 불가 영역에 착지하는 문제가 없는지 검증한다.

### 14.5 철 몬스터

철 몬스터의 공격은 방향을 고정한 직선 돌진이다.

벽에 충돌하면 공격이 종료되어야 한다.

벽을 자동으로 우회하는 돌진 공격으로 바꾸지 않는다.

### 14.6 수정 몬스터

수정 파편은 벽에 충돌하면 소멸한다.

후퇴 행동 중 벽을 통과하지 않아야 한다.

### 14.7 석탄 몬스터

원형 폭발 공격과 내부 벽 사이의 실제 피해 처리 방식은 구현 확인이 필요하다.

### 14.8 자철석 몬스터

자기장 공격의 위치 고정 및 감속 처리를 유지한다.

벽 뒤의 대상에 대한 실제 범위 판정은 현재 구현을 확인한다.

### 14.9 보스

돌골렘의 도약·돌진·돌 파편·메테오 공격과 맵 충돌 관계는 실제 구현을 확인한다.

## 15. 카메라 시스템

### 15.1 기본 방향

기존 카메라는 플레이어를 부드럽게 따라가는 방식이다.

이동 및 추적 기능은 구현·동작 확인 보고가 있다.

### 15.2 기존 문제

비직사각형 맵의 외곽을 기준으로 카메라 이동을 제한하는 과정에서 문제가 발생했다.

### 15.3 최신 개선 방향

**재검토 중**

전체 맵을 직사각형 캔버스로 구성하고 카메라 제한도 해당 직사각형을 기준으로 적용하는 방향이다.

### 15.4 카메라 제한 고려 사항

- 카메라 중심점뿐 아니라 실제 화면 폭과 높이를 고려
- 화면 가장자리가 맵 밖으로 나가는 문제 확인
- 내부 벽과 암석을 화면에 표시할 수 있음
- 방 교체 시 새 방의 제한 영역 적용
- 입장 및 부활 시 현재 방 카메라 설정 사용

### 15.5 화면 흔들림

무거운 공격의 화면 흔들림이 발생할 때 맵 외부의 불필요한 빈 공간이 노출되는지 확인한다.

화면 흔들림의 세부 강도와 적용 패턴은 `CombatSystem.md`, `BossSystem.md`를 따른다.

### 15.6 맵 크기와 카메라

맵 크기는 카메라의 표시 범위를 고려하여 결정해야 한다.

작은 맵에서 카메라 화면이 맵 전체보다 커지는 경우의 처리 방식은 실제 구현 검증이 필요하다.

### 16.1 방 전환

### 16.2 유지 대상

- 남은 물약
- 남은 부활 횟수
- 획득한 돈
- 획득한 경험치
- 획득한 아이템과 재료
- 해당 런의 전투 기록

- 공격 예고
- 투사체
- 남은 공격 판정
- 이전 방의 전투 관련 참조

### 16.4 다음 방 초기화

새로 호출한 방은 해당 방의 입구, 몬스터 배치, 출구 및 카메라 정보를 사용한다.

### 16.5 주의사항

방 전환과 영구 플레이어 데이터 초기화를 혼동하지 않는다.

방 전환으로 인해 이전 방의 몬스터 보상이 중복 지급되어서는 안 된다.

## 17. 기존 Unity 맵 작업 상태

### 17.1 기존 작업

사용자는 일반 방 9종을 설계했고 Codex에 구현을 요청했다.

이후 구현 결과에 여러 문제가 있어 맵 구조를 재정리하기로 했다.

### 17.2 Git 되돌리기

문제가 발생한 맵 작업을 Fork의 Discard Changes로 되돌리는 방식을 논의했다.

실제로 되돌리기를 완료했는지는 확인되지 않았다.

### 17.3 되돌리기 시 주의사항

- 진행 중인 Codex 작업 상태 확인
- 되돌릴 변경 파일 확인
- 정상 구현된 다른 기능 보존
- 맵과 무관한 변경 내용 보존
- Unity 프리팹 참조 확인
- `.meta` 및 GUID 보존
- Missing Script 발생 여부 확인

### 17.4 현재 판단

맵 9종의 설계가 존재한다는 사실과 Unity 적용이 정상 완료되었다는 사실은 구분해야 한다.

현재 새 맵의 Unity 구현은 문제 발생 이후 재검토 대상으로 관리한다.

## 20. 시스템 간 의존 관계

| 관련 시스템 | 맵 시스템과의 관계 | 주요 검토 사항 |
|---|---|---|
| DungeonSystem | 방 진행, 출구, 보스 방 | 진행 불가 상황 |
| PlayerSystem | 이동, 벽 충돌, 부활 | 입구 및 부활 위치 |
| MonsterSystem | 몬스터 배치와 AI | 접근 불가·고립 |
| BossSystem | 보스 방과 공격 충돌 | 패턴 정상 동작 |
| CombatSystem | 이동 공격과 투사체 | 벽·장애물 충돌 |
| RewardSystem | 몬스터 처치 보상 | 보상 중복 처리 |
| UISystem | 던전 진행 관련 UI | 표시 데이터 연동 |
| SaveSystem | 런 상태 및 획득 데이터 | 방 전환 시 데이터 유지 |

### 20.1 주요 충돌 위험

**맵 ↔ 몬스터 AI**

복잡한 벽 때문에 몬스터가 플레이어에게 접근하지 못할 수 있다.

**맵 ↔ 카메라**

카메라 제한과 화면 크기 또는 화면 흔들림이 충돌할 수 있다.

**맵 ↔ 출구**

출구가 벽 또는 도달할 수 없는 위치에 배치되면 진행이 불가능해질 수 있다.

**맵 ↔ 부활**

현재 방 입구 정보가 잘못 적용되면 플레이어가 이전 방이나 벽 안에서 부활할 수 있다.

**맵 ↔ 방 전환**

방을 교체하면서 런 데이터나 공격 상태가 잘못 처리될 수 있다.
