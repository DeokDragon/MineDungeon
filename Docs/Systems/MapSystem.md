## 1. 시스템 개요

### 1.1 목적

맵 시스템은 던전의 일반 전투 방과 보스 방, 방 이동, 몬스터 배치, 벽 및 이동 가능 영역, 카메라 제한 영역을 관리한다.

플레이어가 일반 방에서 몬스터를 처치하고 다음 방으로 이동하여 최종적으로 보스 방에 도달하는 구조를 지원한다.

### 1.2 주요 기능

- 일반 전투 방 구성
- 보스 방 연결
- 준비된 방 후보의 랜덤 선택
- 플레이어 입장 위치
- 몬스터 배치 영역
- 몬스터 전멸에 따른 출구 개방
- 다음 방 전환
- 벽 및 장애물 충돌
- 카메라 추적 및 영역 제한
- 현재 방 입구에서 부활
- 방 전환 시 기존 시스템 연동

### 1.3 시스템 상태

**2026-10-21 — 일반 방 맵 구조 개편 확정 / 사용자 승인 완료.** 모든 일반 맵의 직사각형 전체 캔버스, 이동 불가 영역의 암석·암벽 채움, 직사각형 경계 기준 카메라 제한을 공식 기획으로 적용한다. 실제 이동 영역은 맵별 고유 형태를 유지한다.

현재 랜덤 후보는 신규 제작 일반 맵 7종이다. 기존 테스트 일반 맵은 후보에서 제외하고, 신규 맵 A는 맵 5로 편입한다. 과거 9종 설계는 §4에 보존하며 현재 후보와 합산하지 않는다. 맵 4의 좌측 상단 붕괴 암석 구역과 수정된 몬스터 배치를 적용한다.

승인된 기획과 Codex 구현·테스트 보고는 구분한다. 제공된 완료 보고와 이번 문서 작업에서 직접 확인한 범위는 §21, 남은 확인 사항은 §23에서 관리한다.

## 2. 던전의 방 진행 구조

### 2.1 기본 흐름

1. 플레이어가 던전에 입장한다.
2. 일반 전투 방을 불러온다.
3. 해당 방에 몬스터를 배치한다.
4. 플레이어가 몬스터와 전투한다.
5. 모든 대상 몬스터를 처치한다.
6. 방의 출구가 개방된다.
7. 출구를 이용하여 다음 방으로 진행한다.
8. 일반 방 진행 후 보스 방에 도달한다.
9. 보스를 처치하면 던전을 클리어한다.

### 2.2 방의 종류

**일반 전투 방**

- 일반 몬스터와 전투하는 공간
- 몬스터 전멸 시 출구 개방
- 신규 일반 맵 7종 중 랜덤으로 호출하며 기존 테스트 맵은 후보에서 제외

**보스 방**

- 보스 몬스터와 전투하는 공간
- 현재 보스는 돌골렘
- 보스 처치 시 던전 클리어

### 2.3 맵 종류 수와 진행 방 수

랜덤 후보 7종은 맵 종류 수이며 한 런에서 진행하는 방 수가 아니다. 제공된 Codex 완료 보고는 일반 방 3개 → 보스 방 → 결과 정산의 진행 검증을 포함한다. 이번 문서 작업에서 해당 진행을 직접 재검증하지 않았다.

층·난이도별 방 수·후보 목록 차이, 중복 등장 허용 여부, 선택 가중치와 구체적 알고리즘은 실제 구현 확인 대상으로 남긴다.

## 3. 맵 설계도의 공통 표기

### 3.1 설계도 색상

기존 맵 설계도에서 사용한 표기는 다음과 같다.

| 표기 | 의미 |
|---|---|
| 초록색 네모 | 플레이어 입장 위치 |
| 빨간색 네모 | 몬스터 전멸 후 사용할 출구 |
| 주황색 원 | 몬스터 배치 영역 |
| 벽 표시 | 플레이어와 몬스터의 이동을 막는 벽 |
| 연보라색 | 이동 가능한 바닥 영역 |

### 3.2 설계도 표기와 실제 게임 아트

설계도의 색상은 제작자가 구조를 구분하기 위해 사용한 표시이다.

초록색 입구, 빨간색 출구, 주황색 몬스터 영역을 실제 게임에 같은 색의 도형으로 구현하라는 뜻이 아니다.

### 3.3 몬스터 배치 영역

주황색 원은 몬스터 한 마리의 정확한 생성 위치를 의미하지 않는다.

하나의 배치 영역에 여러 몬스터를 배치할 수 있다.

배치 영역의 수와 몬스터의 실제 등장 수는 구분한다.

### 3.4 바닥과 벽

연보라색 영역은 플레이어가 이동 가능한 바닥을 나타낸다.

벽으로 지정한 위치는 플레이어 및 몬스터의 이동을 막는다.

설계도에서 인접한 두 바닥 구역 사이에 표시된 도형 경계가 반드시 벽이라는 의미는 아니다.

## 4. 기존 일반 방 맵 9종

> **과거 설계 자료:** 아래 9종의 설계 특징과 번호는 역사 기록이다. 현재 후보는 신규 7종이며 아래 목록과 합산하지 않는다. 특히 §4.5의 과거 맵 5는 신규 맵 A가 편입된 현재 맵 5의 명세가 아니다. 현재 공통 구조·맵 4·맵 5 기준은 §7~10을 따른다.

현재 문서의 맵 설명은 기존에 확인된 설계도의 특징을 기록한 것이다.

Gemini에서 개선한 최신 이미지와 실제 형태가 다를 수 있다.

### 4.1 맵 1

**기존 설계 특징**

- 직사각형 구조
- 좌우로 번갈아 뻗는 가로 벽
- 좌측 하단 입구
- 우측 상단 출구
- 몬스터 배치 영역 2개

내부 가로 벽에 의해 이동 경로가 제한되는 구조이다.

### 4.2 맵 2

**기존 설계 특징**

- 세로형 구조
- 중앙 상단 장애물
- 하단 중앙 입구
- 상단 출구 후보 2개
- 몬스터 배치 영역 4개

**기존 출구 규칙**

상단의 출구 후보 2개 중 하나만 실제 출구로 선택한다.

방이 생성될 때 출구를 한 번 결정한다.

선택되지 않은 위치를 실제 사용 가능한 출구로 남겨두지 않는다.

선택된 출구도 몬스터 전멸 전에는 사용할 수 없다.

### 4.3 맵 3

**기존 설계 특징**

- 세로형 구조
- 작은 장애물과 긴 가로 벽
- 우측 하단 입구
- 상단 중앙 출구
- 몬스터 배치 영역 3개

### 4.4 맵 4

**기존 설계 특징**

- 꺾인 외곽 형태

## 5. 무너진 벽 표시

### 5.1 대상

기존 맵 4와 맵 9에는 무너진 벽 표시가 존재한다.

### 5.2 현재 명세

무너진 벽은 기존 설계도에 표현된 지형 요소이다.

이 표시만으로 별도 상호작용 기능을 확정할 수 없다.

### 5.3 자동 추가하지 않는 기능

- 파괴 가능한 벽
- 숨겨진 방
- 추가 출입 경로
- 외부 탈출 경로
- 특수 상호작용

위 기능은 별도 기획과 사용자 승인 없이 추가하지 않는다.

## 6. 맵 크기 및 월드 영역

### 6.1 이전 테스트 크기

기존 테스트에서 바닥 크기를 25 × 20으로 설정한 이력이 있다.

하지만 이는 모든 신규 맵의 최종 크기 확정을 의미하지 않는다.

### 6.2 현재 상태

현재 후보인 신규 일반 맵 7종의 최종 Unity 월드 크기·배치 좌표는 실제 구현 자료 확인 대상으로 남긴다. 신규 맵 A는 별도 후보가 아니라 맵 5이며, 과거 9종 설계와 합산하지 않는다.

### 6.3 크기 검토 요소

최종 맵 크기를 결정할 때 다음을 함께 검토해야 한다.

- 플레이어 크기
- 플레이어 이동 속도
- 카메라 표시 범위
- 일반 몬스터 공격 거리
- 보스 공격 범위
- 회피 가능한 공간
- 통로 폭
- 몬스터 등장 수
- 방 클리어 시간

### 6.4 이미지 크기와 Unity 크기

설계도 이미지의 픽셀 크기를 Unity 월드 크기로 그대로 사용하지 않는다.

실제 플레이어와 몬스터의 크기 및 이동·공격 성능을 기준으로 최종 크기를 결정한다.

## 7. 확정된 맵 공통 구조

**기획 상태: 사용자 승인 완료 / 승인일: 2026-10-21.**

### 7.1 전체 맵 캔버스

모든 일반 맵은 직사각형 전체 캔버스를 사용한다. 직사각형은 전체 맵의 외곽 기준이며 모든 바닥을 이동 가능하게 만드는 규칙이 아니다.

### 7.2 실제 이동 영역

플레이어와 몬스터가 이동 가능한 공간은 각 맵 고유의 형태와 동선을 유지한다. 꺾인 동선·확장 구역·연결 통로·내부 장애물에 따른 경로를 전체 직사각형 바닥으로 대체하지 않는다.

### 7.3 이동 불가 공간

플레이어와 몬스터가 이동할 수 없는 공간은 암석 또는 암벽으로 채운다. 구체적인 아트·타일 규격·충돌 설정과 좌표는 승인된 구조 원칙과 구분하여 실제 구현 자료로 확인한다.

### 7.4 카메라 경계

카메라는 직사각형 전체 캔버스의 경계를 기준으로 이동을 제한한다. 내부 벽과 암석·암벽은 카메라 제한 경계와 구분한다. 세부 계산·화면비·흔들림 처리는 §15 및 검증 기록을 따른다.

### 7.5 승인 범위

기존의 ‘개선 제안·재검토 중·최종 확정 전’ 상태는 이번 사용자 승인으로 대체됐다. 본 변경은 맵 구조·후보 편성에 한정하며 다른 시스템의 확정 규칙과 전투 수치를 변경하지 않는다.

## 8. 맵 4 확정 수정 규칙

**기획 상태: 사용자 승인 완료 / 승인일: 2026-10-21.**

### 8.1 적용 구조

- 좌측 상단에 붕괴 암석 구역을 적용한다.
- 수정된 몬스터 배치를 적용한다.
- 전체 직사각형 캔버스와 이동 불가 공간의 암석·암벽 채움 규칙을 따른다.
- 기존 출구 개방·다음 방 이동·현재 방 입구 부활·런 데이터 유지·보스 진행과 정산을 유지한다.

### 8.2 기능 범위

붕괴 암석을 파괴 가능한 지형이나 신규 상호작용으로 해석하지 않는다. 구체적인 벽·바닥·몬스터 배치 좌표 및 프리팹 데이터는 실제 Unity 구현 자료를 기준으로 확인한다.

### 8.3 구현 보고

사용자가 전달한 Codex 완료 보고는 맵 4의 123개 검사 통과와 오류·Missing Script 0건을 포함한다. 이번 문서 작업에서 재실행한 테스트가 아니다. 상세 증거 수준과 남은 검증은 §21~23을 따른다.

## 9. 신규 맵 A의 맵 5 편입

**기획 상태: 사용자 승인 완료 / 승인일: 2026-10-21.**

### 9.1 현재 번호

## 11. 플레이어 입구 및 출구

### 11.1 입구

각 방에는 플레이어가 해당 방에 진입하는 위치가 존재한다.

기존 설계도에서는 초록색 네모로 표시했다.

### 11.2 출구

기존 설계도에서는 출구를 빨간색 네모로 표시했다.

### 11.3 출구 개방

방에서 처치해야 하는 모든 몬스터를 처치하면 출구가 개방된다.

### 11.4 출구와 다음 방

출구를 이용하면 다음 방으로 진행한다.

플레이어의 부활 위치는 현재 진행 중인 방의 입구이다.

던전 최초 시작 방의 입구로 되돌아가지 않는다.

## 12. 몬스터 배치 시스템

### 12.1 기본 개념

일반 방의 설계도에는 몬스터 배치 영역이 존재한다.

각 배치 영역은 여러 몬스터를 배치할 수 있는 공간을 의미한다.

### 12.2 배치 조건

몬스터를 배치할 때 다음 조건을 만족해야 한다.

- 벽 내부에 생성하지 않는다.
- 서로 완전히 겹쳐 생성하지 않는다.
- 플레이어 입구를 막지 않는다.
- 출구를 막지 않는다.
- 플레이어가 도달할 수 없는 공간에 생성하지 않는다.

### 12.3 몬스터 수

몬스터 배치 영역 개수와 실제 등장하는 몬스터 수는 별개이다.

기존 몬스터 수를 각 배치 영역마다 그대로 복제하여 전체 적 수가 의도치 않게 폭증하지 않도록 한다.

### 12.4 몬스터 종류

현재 일반 몬스터 명세는 다음 5종이다.

- 돌
- 철
- 수정
- 석탄
- 자철석

맵별 몬스터 종류와 등장 수의 상세 구성은 현재 데이터 확인이 필요하다.

### 12.5 난이도 연동

던전 난이도는 4종이다.

난이도에 따른 정확한 몬스터 종류 및 배치 수의 차이는 현재 자료에 확정되어 있지 않다.

새로운 난이도 배치 값을 임의로 작성하지 않는다.

## 13. 내부 벽 및 충돌

### 13.1 벽의 기본 역할

벽은 플레이어와 몬스터의 이동을 제한하는 장애물이다.

### 13.2 카메라와 벽

내부 벽은 카메라가 화면에 표시하거나 카메라 시야가 통과할 수 있는 지형이다.

카메라 자체의 제한 경계와 캐릭터 이동을 막는 벽은 구분한다.

### 13.3 연결 통로

설계도에서 서로 연결되어야 하는 바닥 구역을 잘못 벽으로 막지 않는다.

특히 맵 6처럼 확장된 이동 구역과 중심 통로가 연결되는 구조에서는 바닥 구역의 연결 관계를 확인해야 한다.

### 13.4 실제 충돌

벽은 플레이어와 몬스터의 이동을 막는다.

다만 몬스터의 고유 공격이 벽과 충돌하는 세부 규칙은 개별 몬스터 및 보스 명세를 따른다.

### 13.5 확인 필요

- 벽 충돌체 구조
- 플레이어와 몬스터의 충돌 레이어
- 내부 벽과 외곽 벽의 처리
- 좁은 통로 폭
- 맵 바닥 및 벽 타일 규격
- 이동 불가 암석·암벽의 충돌 범위

기존 Unity 충돌 설정을 불필요하게 전역 변경하지 않는다.

## 14. 몬스터 AI와 맵 구조

### 14.1 주요 문제

기존 직선 추적 방식의 몬스터 AI는 복잡한 내부 벽에 막힐 수 있다.

몬스터가 플레이어에게 접근하지 못하면 해당 방의 전멸 조건을 만족하기 어려워질 수 있다.

### 14.2 검토할 상황

- 몬스터가 벽에 계속 걸리는 상황
- 플레이어에게 접근하지 못하는 상황
- 몬스터가 이동 불가 영역에 생성되는 상황
- 플레이어가 몬스터에게 접근할 수 없는 상황
- 마지막 몬스터가 벽 뒤에 갇혀 방을 완료할 수 없는 상황

### 14.3 일반 이동과 공격 이동 구분

몬스터가 일반 이동으로 플레이어에게 접근하는 방식과 고유 공격 중 이동하는 방식은 구분한다.

일반 이동에 벽 우회가 필요하더라도 공격 패턴의 기존 고유 규칙까지 변경하지 않는다.

### 14.4 돌 몬스터

도약 공격 중 벽을 통과하거나 이동 불가 영역에 착지하는 문제가 없는지 검증한다.

### 14.5 철 몬스터

철 몬스터의 공격은 방향을 고정한 직선 돌진이다.

벽에 충돌하면 공격이 종료되어야 한다.

벽을 자동으로 우회하는 돌진 공격으로 바꾸지 않는다.

### 14.6 수정 몬스터

수정 파편은 벽에 충돌하면 소멸한다.

후퇴 행동 중 벽을 통과하지 않아야 한다.

### 14.7 석탄 몬스터

원형 폭발 공격과 내부 벽 사이의 실제 피해 처리 방식은 구현 확인이 필요하다.

### 14.8 자철석 몬스터

자기장 공격의 위치 고정 및 감속 처리를 유지한다.

벽 뒤의 대상에 대한 실제 범위 판정은 현재 구현을 확인한다.

### 14.9 보스

돌골렘의 도약·돌진·돌 파편·메테오 공격과 맵 충돌 관계는 실제 구현을 확인한다.

## 15. 카메라 시스템

### 15.1 기본 방향

기존 카메라는 플레이어를 부드럽게 따라가는 방식이다.

이동 및 추적 기능은 구현·동작 확인 보고가 있다.

### 15.2 기존 문제

비직사각형 맵의 외곽을 기준으로 카메라 이동을 제한하는 과정에서 문제가 발생했다.

### 15.3 확정된 카메라 경계

**2026-10-21 사용자 승인 완료.** 카메라는 직사각형 전체 캔버스 경계를 기준으로 이동을 제한한다. 내부 벽과 암석·암벽은 카메라 제한 경계와 구분한다.

### 15.4 카메라 제한 고려 사항

- 카메라 중심점뿐 아니라 실제 화면 폭과 높이를 고려
- 화면 가장자리가 맵 밖으로 나가는 문제 확인
- 내부 벽과 암석을 화면에 표시할 수 있음
- 방 교체 시 새 방의 제한 영역 적용
- 입장 및 부활 시 현재 방 카메라 설정 사용

### 15.5 화면 흔들림

무거운 공격의 화면 흔들림이 발생할 때 맵 외부의 불필요한 빈 공간이 노출되는지 확인한다.

화면 흔들림의 세부 강도와 적용 패턴은 `CombatSystem.md`, `BossSystem.md`를 따른다.

### 15.6 맵 크기와 카메라

맵 크기는 카메라의 표시 범위를 고려하여 결정해야 한다.

작은 맵에서 카메라 화면이 맵 전체보다 커지는 경우의 처리 방식은 실제 구현 검증이 필요하다.
