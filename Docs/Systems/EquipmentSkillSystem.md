## 1. 시스템 개요

### 1.1 목적

장비·스킬·제작 시스템은 플레이어가 던전에서 획득한 재료와 돈을 사용하여 곡괭이를 제작하고, 획득한 장비와 스킬을 관리·장착하는 성장 구조를 담당한다.

장비와 스킬은 캐릭터의 전투 능력 및 플레이 방식에 영향을 주는 요소이며, 플레이어의 레벨과 스탯 성장 시스템에 연결된다.

### 1.2 주요 기능

- 곡괭이 보유 및 장착
- 곡괭이 제작
- 제작 재료 및 돈의 사용
- 장비 정보 표시
- 인벤토리와 장비 슬롯 연동
- 스킬 획득 및 보관
- 스킬 장착 및 사용
- 장비·스킬의 전투 능력치 연동
- 제작 결과 안내
- 보유·장착 데이터 저장 및 복원

### 1.3 현재 기획 상태

| 구분 | 상태 |
|---|---|
| 곡괭이를 주요 무기로 사용 | 확정 |
| 돈과 재료를 사용한 곡괭이 제작 | 확정 |
| 메인 씬에서 곡괭이 제작 | 확정된 기획 방향 |
| 곡괭이 제작 기능 | 구현 완료 보고 없음 |
| 스킬의 던전 클리어 보상 획득 | 확정 |
| 획득한 스킬 장착 | 확정 |
| 플레이어 스킬 4종 | 구현 완료 보고 |
| 상의·하의·악세서리 장비 | 확장 구상, 상세 미확정 |
| 장비 강화·분해·판매 | 확정되지 않음 |

## 2. 장비 시스템

### 2.1 주요 무기

플레이어의 주요 무기는 곡괭이이다.

곡괭이는 플레이어의 기본 공격에 사용되는 장비이며, 기존 기획에서는 곡괭이 종류에 따라 공격력과 공격 범위에 차이를 두는 방향을 논의했다.

정확한 개별 곡괭이 능력치는 현재 자료에서 확인되지 않는다.

### 2.2 곡괭이 획득

현재 확정된 주요 곡괭이 획득 방식은 제작이다.

몬스터에게서 획득한 재료와 돈을 사용하여 곡괭이를 제작한다.

곡괭이가 몬스터나 보상 상자에서 직접 드롭되는 별도 규칙은 현재 자료로 확정할 수 없다.

### 2.3 곡괭이 능력치

기존 기획에서 곡괭이와 관련해 논의된 요소는 다음과 같다.

- 공격력
- 공격 범위
- 물리·마법 관련 능력치
- 희귀도

단, 모든 곡괭이가 위 능력치를 반드시 보유한다고 확정된 것은 아니다.

**확인 필요**

- 곡괭이 종류 및 이름
- 개별 공격력
- 공격 범위
- 공격 속도 관련 능력치 존재 여부
- 물리·마법 능력치 적용 여부
- 희귀도
- 착용 조건
- 곡괭이별 고유 효과 존재 여부

명세가 없는 새로운 곡괭이 효과를 추가하지 않는다.

### 2.4 장착

플레이어는 보유한 곡괭이를 장착하여 전투에 사용할 수 있는 구조이다.

장착된 곡괭이의 전투 성능은 플레이어 기본 공격 시스템과 연동한다.

**확인 필요**

- 최초 장착 곡괭이
- 장착 및 해제 방식
- 곡괭이 교체 조건
- 제작 직후 자동 장착 여부
- 장착 중인 곡괭이의 인벤토리 표시
- 동일 곡괭이 여러 개 보유 시 처리

### 2.5 다른 장비

기존 인벤토리 기획에는 다음 장비 분류가 포함되어 있다.

- 무기
- 상의
- 하의
- 악세서리

상의·하의·악세서리의 구체적인 품목·획득·능력치 값은 미확정이다. 다만 이번 승인에서는 방어력을 스탯 투자에서 제외하고 일부 상의·하의 장비에서 획득하는 방향을 확정한다. 실제 DEF와 피해 감소율은 구분하며 감소 공식/개별 장비 수치를 새로 정하지 않는다.

인벤토리 슬롯이 존재한다는 이유로 해당 장비의 실제 콘텐츠까지 구현 완료된 것으로 판단하지 않는다.

## 3. 곡괭이 제작 시스템

### 3.1 목적

곡괭이 제작은 던전에서 획득한 돈과 재료를 새로운 무기로 전환하여 플레이어의 성장을 돕는 시스템이다.

기존 몬스터 재료 드롭과 직접적으로 연결되는 후속 콘텐츠이다.

### 3.2 제작 위치

곡괭이 제작은 광산 입구가 존재하는 메인 씬에서 진행한다.

던전 전투 도중 곡괭이를 제작하는 구조가 아니다.

### 3.3 제작 재료 획득

제작에 활용할 재료는 일반 몬스터 처치 보상을 통해 획득하는 구조이다.

현재 재료 드롭 명세가 존재하는 몬스터 계열:

| 몬스터 | 재료 계열 |
|---|---|
| 돌 몬스터 | 돌 |
| 철 몬스터 | 철 |
| 수정 몬스터 | 수정 |
| 석탄 몬스터 | 석탄 |
| 자철석 몬스터 | 자철석 |

정확한 재료 아이템 이름과 ID는 현재 Unity 프로젝트 데이터를 확인한다.

### 3.4 제작 경제 구조

**확정된 경제 흐름**

몬스터 처치

→ 돈과 재료 획득

→ 메인 씬에서 곡괭이 제작

→ 곡괭이 장착

→ 던전 재도전

던전 클리어 시 별도의 돈·경험치 보너스를 지급하지 않는 기존 보상 규칙을 유지한다.

### 3.5 제작 비용

곡괭이 제작에는 돈과 필요한 제작 재료가 사용된다.

정확한 제작 비용과 요구 재료는 곡괭이별 상세 데이터 확인 또는 후속 기획이 필요하다.

현재 문서에서는 수치를 임의로 지정하지 않는다.

### 3.6 제작창 기본 구성

기존 기획에서 요청된 제작창 구성은 다음과 같다.

1. 제작 가능한 곡괭이 목록
2. 선택한 곡괭이의 정보
3. 필요한 제작 재료
4. 현재 보유 재료 수량
5. 필요한 돈
6. 제작 버튼
7. 제작 결과 안내

### 3.7 제작 과정

기획상 제작 과정은 다음과 같이 구분한다.

1. 메인 씬에서 곡괭이 제작 기능에 접근한다.
2. 제작 가능한 곡괭이 목록을 확인한다.
3. 제작할 곡괭이를 선택한다.
4. 필요한 돈과 재료를 확인한다.
5. 제작 기능을 이용한다.
6. 제작 결과를 확인한다.

이 과정은 기존에 요청된 UI 구성과 경제 관계를 정리한 것이다.

정확한 입력 흐름, 재료 부족 시 처리, 제작 성공 조건 및 버튼 동작은 아직 상세 확정되지 않았다.

### 3.8 제작 결과

제작을 통해 획득한 곡괭이는 플레이어가 보유·장착할 수 있는 장비이다.

다음 사항은 현재 미확정이다.

- 제작 성공 연출
- 제작 완료 안내 문구
- 제작 직후 자동 장착 여부
- 동일 곡괭이 중복 제작 처리
- 이미 보유한 곡괭이의 제작 가능 여부
- 제작 취소 및 확인 방식

### 3.9 제작 시 데이터 연동

제작은 돈·재료의 보유량 및 장비 획득과 관련된다.

구현 시 확인해야 할 항목:

- 현재 보유 돈과 재료를 올바르게 참조하는가?
- 제작 비용의 적용 결과가 일관적인가?
- 제작 결과 곡괭이가 정상적으로 보유 데이터에 반영되는가?
- 제작 과정에서 재료·돈 또는 장비가 의도치 않게 중복 처리되지 않는가?
- 제작 결과가 저장 및 불러오기와 연결되는가?

구체적인 처리 방식은 실제 구현 단계에서 프로젝트 구조를 확인하여 검증한다.

### 3.10 자동 추가하지 않을 기능

곡괭이 제작에 다음 기능을 자동으로 포함하지 않는다.

- 장비 강화
- 아이템 분해
- 아이템 판매
- 랜덤 옵션
- 별도 제작 성공 확률
- 제작 실패 시 재료 손실
- 무기 외 다른 장비 제작

새로운 제작 기능은 별도 기획과 사용자 승인이 필요하다.

## 4. 스킬 시스템

### 4.1 기본 구조

스킬은 플레이어가 획득하고 장착하여 전투에 사용하는 능력이다.

현재 플레이어 스킬 4종의 구현 완료 보고가 존재한다.

### 4.2 스킬 획득

**최신 확정 규칙**

스킬은 던전 클리어 보상으로 획득한다.

일반 몬스터가 스킬을 직접 드롭하지 않는다.

### 4.3 기존 인챈트 방식과의 관계

과거에는 곡괭이에 인챈트로 스킬을 부여하는 구조를 논의했다.

최신 기획에서는 던전 클리어 보상으로 스킬을 획득하고 장착하여 사용하는 방식이 주된 구조이다.

인챈트 중심 스킬 획득 방식을 별도의 확정 기능으로 복원하지 않는다.

### 4.4 스킬 장착

플레이어는 획득한 스킬을 장착하여 전투에서 사용한다.

기존 인벤토리 기획에는 스킬 보관과 장착 관련 기능이 포함되어 있다.

**확인 필요**

- 스킬 장착 가능 개수
- 스킬 장착 슬롯 구성
- 장착 및 해제 방법
- 이미 장착한 스킬의 교체 방식
- 장착 가능 조건
- 실제 장착 표시의 세부 표현 (임시 대기/펄스/취소는 §4.4.1 승인 기준 적용)

### 4.4.1 임시 장착 대기와 실제 E/R 장착 — UI-05/06 승인

**2026-10-24 사용자 최종 승인 / Unity 적용·회귀 검증 미진행.** 장착 가능한 스킬 선택은 임시 장착 대기다. 실제 E/R 장착·교환·사용과 영구 보유/장착 데이터는 기존 규칙을 따른다. 대기는 실제 장착 상태와 구분하며 새 저장 필드/스키마를 추가하는 승인이 아니다.

- 스킬 카드 클릭: 해당 스킬 대기 시작. 다른 스킬 클릭: 기존 임시 대기만 정리하고 새 스킬 대기 시작.
- E/R 슬롯 클릭: 해당 슬롯에 실제 장착 완료 후 대기 종료. 기존 장착 권한·교환·던전 제한을 유지한다.
- 다른 일반 아이템·인벤토리 빈 공간·다른 UI 탭·인벤토리 바깥 클릭, I/ESC에 의한 실제 닫기: 대기 취소.

장착 대기 중 선택 카드의 임시 강조와 E/R 슬롯 청록 테두리 펄스를 표시한다. 기존 슬롯 위치·크기·기능은 유지하며 테두리 밝기/투명도만 부드럽게 변화시킨다. 약0.8초는 초기 시각 테스트값이고 슬롯/아이콘 전체 점멸이나 새 스킬 효과가 아니다. 완료/취소 시 즉시 펄스를 종료한다.

취소는 임시 강조·펄스·대기 참조만 정리하며 **실제 장착된 E/R 스킬을 변경하지 않는다.** 장착 해제/저장 요청도 발생시키지 않는다. 바깥 클릭은 월드 공격/상호작용으로 전달하지 않고 기존 ESC 닫기/퍼즈 우선순위·비정지·전투 입력 차단을 유지한다. 장착 거부/실패 시 동작은 기존 API 확인 대상으로 남기며 성공을 가정해 실제 장착 데이터를 변경하지 않는다. 상세 입력 표는 [UISystem](UISystem.md) §9.13을 따른다.

### 4.4.2 분류 Hover와 실제 전환 — UI-08 충돌 방지

사용자 최종 승인된 UI-08 연동 규칙이다(2026-10-25 문서 반영). **분류 탭의 단순 Hover/툴팁 표시는 임시 장착 대기를 취소하지 않는다.** 실제 다른 분류로 전환할 때는 UI-06대로 임시 선택 강조·E/R 펄스·장착 대기 참조를 정리한다. 실제 E/R 장착 스킬·보유/저장 데이터는 유지하며 장착 저장/해제 요청을 발생시키지 않는다.

검색·분류·정렬·아이템 데이터와 기존 장착 로직은 바꾸지 않는다. 툴팁은 표시/입력 보호만 담당하며 표시/숨김이 필터 결과나 선택 상태를 바꾸지 않는다. 상세는 [UISystem](UISystem.md) §9.14를 따른다. 본 UI-07~08 신규 개선안의 Unity 구현은 미확인/별도 작업, 회귀 검증은 미진행이며 기존 장착 구현 보고와 구분한다.

### 4.5 스킬 사용

장착한 스킬은 전투 중 지정된 입력으로 사용한다.

기존 대화에서는 E 및 R 스킬 입력이 논의되었으나 현재 인수인계에서는 정확한 최종 키 배치 확인이 필요하다고 기록되어 있다.

따라서 E/R을 현재 확정 입력으로 자동 지정하지 않는다.

### 4.6 스킬 정보

개별 스킬의 상세 명세에는 실제 구현을 확인한 후 다음 내용을 기록할 수 있다.

- 스킬 이름
- 스킬 설명
- 피해량 또는 계수
- 공격 범위
- 사거리
- 쿨타임
- 효과 및 속성
- 사용 조건

이는 데이터 확인 항목이며, 현재 스킬 4종에 해당 정보가 모두 존재한다고 단정하지 않는다.

### 4.7 단일 유형 공격 스탯과 패시브 — 최신 승인

대지 분쇄(EarthSmash)·착암 돌격(DrillDash)은 물리, 청록 광선(TealBeam)·불안정 광석 발파(OreBlast)는 마법이다. 최종 물리/마법 공격 스탯=기본+해당 투자 보너스+장비 보너스를 사용한다. 곡괭이 기본 공격은 물리, 스킬은 해당 단일 유형 스탯으로 기본피해×(1+최종스탯/100)을 계산한다. 기존 혼합 계수 기획을 대체하며 패시브 후속 처리/최종 한 번 .5 올림은 CombatSystem §6.5를 따른다.

개별 스킬의 신규 기본 피해량은 미확정이다. 임시 물리7/마법6·스킬피해19/14/16/19 또는 혼합 계수를 신규 기본값으로 확정하지 않는다. 기존 시전·판정·기본 범위·쿨타임·행동 제한/장착 규칙은 명시된 투자 패시브 효과 외에 유지한다.

마법50P의 마법 스킬 쿨타임-15%는 장비 감소율과 합산하고 별도 밸런스 상한을 현재 두지 않는다. 합계100% 이상 처리는 미확정이다. 9패시브의 해금/효과는 ProgressionSystem §4, 실제 공격 적용은 CombatSystem §4를 참조한다. 투자 패시브를 신규 장비 옵션·스킬 레벨업 기능으로 바꾸지 않는다.

### 4.8 스킬 성장

현재 인수인계에는 별도의 스킬 레벨업이나 강화 규칙이 확정되어 있지 않다.

스킬 강화나 진화 기능을 임의로 추가하지 않는다.

## 5. 인벤토리 연동

### 5.1 보관 대상

기존 인벤토리 기획에서 확인되는 보관 대상은 다음과 같다.

- 스킬
- 재료
- 곡괭이
- 향후 확장 가능한 장비

인벤토리는 구현 완료 보고가 있다.

### 5.2 분류 탭

기존 기획의 기본 분류는 다음과 같다.

- 전체
- 무기
- 상의
- 하의
- 악세서리
- 재료

스킬을 표시하는 탭 또는 별도 화면의 실제 구성은 현재 구현 확인이 필요하다.

### 5.3 장비 및 캐릭터 영역

인벤토리 기획에는 다음 영역이 포함되어 있다.

- 캐릭터 표시
- 무기 슬롯
- 상의 슬롯
- 하의 슬롯
- 악세서리 슬롯
- 현재 스탯 표시

장비 분류와 슬롯의 존재가 모든 장비 콘텐츠의 구현 완료를 의미하지는 않는다.

### 5.3.1 인벤토리 성장 탭과 던전 제한

우측 아이템 목록과 기존 색상·배치·스타일을 유지하고 좌측은 캐릭터 정보/스탯 2탭으로 구성한다. 공통 하단 FINAL ATTRIBUTES와 미사용P 알림·×1/×5/×10 즉시 투자·패시브 상세·메인 전용 초기화 기획은 UISystem §9.10을 따른다.

던전 내부는 장비·스킬·스탯·패시브 열람만 가능하고 장비/스킬 교체·스탯 투자/초기화는 불가하다. 던전 입장 시 성장 구성을 고정한다. 인벤토리를 열어도 시간은 계속 흐르며 기존 전투 입력 차단·I/ESC 흐름은 유지한다. 새 UI/장비/패시브 구현 완료를 의미하지 않는다.

### 5.4 장착 표시

기존 인벤토리에서는 장착 중인 아이템을 표시하는 기능이 요청되었다.

장착 중인 아이템은 E 아이콘 등으로 구분하는 방향이 논의되었다.

장착 표시 문자와 스킬 사용 입력 E가 혼동되지 않도록 실제 UI를 확인한다.

### 5.5 희귀도

기존 인벤토리와 결과창에서는 아이템의 희귀도를 테두리 색상으로 구분하는 방식이다.

| 희귀도 | 색상 |
|---|---|
| 일반 | 회색 |
| 고급 | 초록 |
| 희귀 | 파랑 |
| 영웅 | 보라 |
| 전설 | 금색 |

이 표는 기존 결과창의 확정된 희귀도 색상 기준이다.

모든 곡괭이와 스킬에 동일한 희귀도 단계가 적용되어 있는지는 현재 아이템 데이터를 확인한다.

### 5.6 아이템 수량

기존 인벤토리 슬롯에서는 우측 상단에 아이템 수량을 표시한다.

재료와 장비의 중첩 보관 규칙은 현재 구현 확인이 필요하다.

### 5.7 검색 및 정렬

인벤토리에는 아이템 이름 검색 기능이 기획되어 있다.

기존에 제시된 정렬 예시:

- 희귀도
- 타입
- 마법력
- 물리 능력치

최종 적용된 정렬 목록과 우선순위는 현재 구현 확인이 필요하다.

### 5.8 아이템 툴팁

모든 아이템은 마우스 호버 시 설명창을 표시하는 방향이다.

아이템 종류에 따라 관련 정보를 표시한다.

주요 정보 항목:

- 이름
- 분류
- 희귀도
- 물리·마법 타입
- 관련 능력치
- 피해량
- 스킬 설명
- 쿨타임
- 장착 관련 안내

아이템 종류와 관련 없는 정보는 표시하지 않는다.

예를 들어 단순 제작 재료에 스킬 쿨타임을 표시하지 않는다.

## 6. 장비·스킬과 전투 연동

### 6.1 곡괭이와 기본 공격

장착 중인 곡괭이는 플레이어의 기본 공격과 연결된다.

곡괭이별 공격 성능 차이는 기존 기획에 포함되어 있다.

실제 피해 계산식과 범위 적용 방식은 `CombatSystem.md` 및 Unity 데이터를 확인한다.

### 6.2 스킬과 전투

장착한 스킬은 전투 중 사용한다.

공격 판정, 사거리, 피해 및 쿨타임은 개별 스킬 데이터에 따른다.

### 6.3 장비와 성장

플레이어는 레벨업으로 스탯 포인트를 획득하며, 장비를 통해 전투 성능을 변화시키는 구조를 가진다.

최종 물리·마법 공격 스탯은 기본+투자+장비 보너스로 합산한다. 투자1P당 해당 공격 스탯+0.4, 체력은 최대HP+3이다. 각 장비의 실제 보너스 값·DEF 감소 공식·미명시 계산 경계는 미확정이다.

### 6.4 상태 이상과 능력치

자철석 몬스터의 감속 등 일시적인 능력치 변화가 종료될 때 현재 플레이어 능력치에 맞게 복구해야 한다.

장비나 성장으로 변화한 능력치를 특정 기본값으로 덮어쓰지 않는다.

## 7. 보상 시스템 연동

### 7.1 제작 재료

일반 몬스터는 각 계열에 해당하는 제작 재료를 드롭한다.

기존 확정 드롭 규칙:

- 드롭 성공 확률: 50%
- 성공 시 수량: 1~2개

드롭 성공 시 해당 재료를 직접 획득한다.

### 7.2 제작용 돈

몬스터를 처치하면 돈을 즉시 획득한다.

곡괭이 제작에는 돈을 사용한다.

몬스터별 돈 지급량과 곡괭이별 제작 비용은 현재 데이터 확인이 필요하다.

### 7.3 스킬 보상

스킬은 던전 클리어 보상에 포함되는 획득 대상이다.

층과 난이도별 스킬 보상 구성 및 획득 확률은 현재 프로젝트 확인이 필요하다.

### 7.4 던전 실패 시 보상

던전에 실패하더라도 이미 획득한 아이템과 재료는 100% 유지한다.

획득하지 않은 클리어 전용 보상은 지급하지 않는다.

### 7.5 보상 중복 방지

결과창을 닫거나 다시 열어도 기존 스킬이나 아이템을 중복 지급하지 않는다.

보상 지급 및 저장은 `RewardSystem.md`, `SaveSystem.md`의 확정 규칙을 따른다.

## 8. 제작·장착 UI

### 8.1 제작 UI 방향

기존 제작 UI는 Gemini 및 Figma를 통해 레퍼런스를 준비할 계획이었다.

실제 최종 레이아웃은 아직 확정되지 않았다.

### 8.2 제작창 정보

제작창에는 다음 정보를 포함하는 방향이다.

- 제작할 곡괭이
- 곡괭이 정보
- 필요 재료
- 보유 재료 수량
- 제작 비용
- 제작 버튼
- 결과 안내

### 8.3 제작창 입력

다음 사항은 추가 확인이 필요하다.

- 제작 상호작용 오브젝트의 형태
- 제작창 열기·닫기 방법
- 선택 상태 표시
- 제작 불가 상태 표시
- 재료 부족 안내
- 제작 결과 연출

### 8.4 인벤토리 UI

인벤토리의 장비 영역과 아이템 슬롯은 현재 보유·장착 상태를 표시한다.

기존 기준1920×1080·인벤토리1440×810과 레이아웃은 유지한다. UI-02의 `현재 플레이어`, UI-03의 `스킬을 선택한 뒤 E/R 슬롯을 클릭하세요` 고정 문구는 제거하되 캐릭터 영역/장비 슬롯·선택/장착 기능은 보존한다. UI-04의 일반 아이템은 Hover/Pressed·희귀도/실제 장착 표시를 유지하고 불필요한 지속 청록 강조만 해제한다. 내부 선택에 의존하는 상세/기능은 구현 전에 확인하며 데이터를 무조건 삭제하지 않는다. 향후 장착 튜토리얼은 별도 검토이며 이번에 추가하지 않는다. 상세는 UISystem §9.13을 따른다.

### 8.5 게임 시간 처리

인벤토리를 열어도 게임 시간은 정지하지 않는다.

일반적인 시간 정지는 ESC 퍼즈 메뉴에서 처리한다.

곡괭이 제작창을 열었을 때 시간 정지 여부는 현재 자료에서 명확히 확정되지 않았다.

다른 UI의 규칙을 자동으로 확대 적용하지 않는다.

## 9. 저장 및 불러오기

### 9.1 저장 대상

기존 기획에서 영구 유지 대상으로 확인된 정보:

- 보유 곡괭이
- 제작한 곡괭이
- 획득한 장비 및 아이템
- 장착 장비
- 보유 스킬
- 장착 스킬
- 제작 재료
- 보유 돈

### 9.2 제작 데이터

곡괭이 제작 결과는 영구 성장 및 보유 장비 데이터와 연결된다.

게임을 종료하고 다시 실행하더라도 제작한 곡괭이를 유지해야 한다.

### 9.3 장착 정보

플레이어의 장비와 스킬 장착 상태는 저장 및 불러오기 대상이다.

실제 저장 데이터의 구조와 장착 상태 복원 방식은 Unity 프로젝트 확인이 필요하다.

임시 장착 대기/취소는 실제 장착 저장과 구분한다. UI-06 취소는 기존 장착 데이터·저장 상태를 보존하며 장착 저장/해제 요청을 만들지 않는다. UI-01 성공 메시지 제거도 저장 기능/이벤트 통지를 생략하는 규칙이 아니고 새 저장 필드/스키마를 요구하지 않는다.

### 9.4 중복 지급 및 소모 방지

제작과 보상 지급 과정에서 다음 문제가 발생하지 않아야 한다.

- 제작 재료가 의도치 않게 중복 소모됨
- 제작 비용이 의도치 않게 중복 차감됨
- 제작 결과 장비가 중복 지급됨
- 지급한 스킬이 결과창 재열기로 다시 지급됨
- 저장 및 복원 과정에서 장비나 스킬이 사라짐

### 9.5 저장 관련 구현 상태

저장 및 불러오기 기능의 구현 완료 보고가 있다.

그러나 곡괭이 제작 기능은 구현 완료 보고가 없으므로 제작 데이터의 저장까지 검증되었다고 단정할 수 없다.

## 10. 시스템 간 의존 관계

| 연관 시스템 | 연동 내용 | 주요 검토 사항 |
|---|---|---|
| RewardSystem | 돈·재료·스킬 획득 | 보상 중복 지급 방지 |
| MonsterSystem | 제작 재료 드롭 | 재료 종류·수량 연동 |
| PlayerSystem | 장비 장착 및 스킬 사용 | 플레이어 전투 상태 |
| CombatSystem | 곡괭이·스킬 피해 판정 | 공격력·범위 적용 |
| ProgressionSystem | 성장 능력치 | 장비와 스탯 계산 관계 |
| DungeonSystem | 클리어 보상과 재도전 | 획득 보상 유지 |
| UISystem | 제작창·인벤토리·툴팁 | 데이터와 UI 일치 |
| SaveSystem | 장비·스킬·재료 보존 | 제작 결과 영구 유지 |

### 10.1 주요 충돌 가능성

**제작 ↔ 보상**

몬스터가 지급하는 재료와 제작에 필요한 재료가 일치해야 한다.

**제작 ↔ 저장**

제작 과정의 재료·돈 소모와 장비 획득 결과가 저장 데이터에 올바르게 반영되어야 한다.

**장비 ↔ 전투**

곡괭이를 교체했을 때 공격력 및 공격 범위가 잘못 중복 반영되면 안 된다.

**스킬 ↔ 인벤토리**

스킬 보유 데이터와 장착 상태 및 실제 사용 가능한 스킬이 일치해야 한다.

**장비 ↔ 성장**

스탯 투자 효과와 장비 효과가 함께 적용될 때 능력치 계산이 일관되어야 한다.

## 11. 현재 구현 현황

### 2026-10-21 구현 기록 대조

**Codex 구현 완료 보고:** EarthSmash / DrillDash / TealBeam / OreBlast 4종을 Assets/Skills/*.asset의 SkillData에서 관리한다. 당시 기본 장착은 E EarthSmash / R TealBeam이며 인벤토리 준비 상태에서 스킬 장착·교환을 지원하고 전투 중 변경은 제한한다.

- 보유 스킬 ID와 E/R 장착 상태를 CharacterSaveService로 저장·복원한다. 방 이동·재도전에서도 세션의 선택을 유지한다.
- 스킬은 던전 클리어 보상으로 획득하는 확정 방향을 유지한다. 1층 쉬움의 자동 클리어 보상 연결과 보유 스킬 중복 제외는 RewardSystem의 구현 기록을 따른다.
- 테스트 시작 스킬 4종 각 1개는 테스트 설정이다. Editor 초기화도 실제 신규 지급 배열과 Main 기본 E/R을 읽는 구현이며, 일반 게임의 확정 초기 지급 4종으로 간주하지 않는다.
- WORK_STATUS 기준 곡괭이 제작 기능, 실제 상의·하의·악세서리 등 장비 콘텐츠와 분배 스탯 시스템은 미구현이다. 기존 곡괭이 기본 Player 상태를 사용한다. UI 슬롯/분류가 있다는 이유로 장비 콘텐츠 완료로 보지 않는다.

**기록된 Unity MCP 테스트:** 인벤토리 최종 통합 57개는 검색·분류·정렬·툴팁·장착/교환·E/R 실행 연결·전투 장착 금지·입력 누출 방지·방 이동·재도전 보유 유지를 보고한다. 이 검증 당시의 인벤토리 시간 정지는 2026-10-18 후속 비정지 14항목 검증으로 대체된다. 이후 저장 검증에서 보유/장착 복원과 스킬 4개 중복 없음이 보고됐다.

**기획 대조 / 추가 확인:** E/R 두 슬롯은 당시 구현 정보이며 최종 키 배치를 새로 승인한 것이 아니다. 제작·확장 장비 미구현은 계획과 구현의 차이로 남기고 제작 비용·품목·능력치를 임의로 채우지 않는다. 스킬 획득 확률과 중복 보상 정책의 최종 승인, 장비/제작 후 저장 확장은 별도 검토 대상이다.

## 12. 향후 구현 검증 기준

### 12.1 곡괭이 제작

- 제작창에서 기존 기획의 필수 정보를 표시하는가?
- 선택한 곡괭이의 제작 비용과 필요 재료가 올바른가?
- 보유 돈과 재료가 올바르게 표시되는가?
- 제작 결과가 실제 보유 장비에 반영되는가?
- 비용·재료가 중복 소모되지 않는가?
- 제작한 곡괭이가 저장 및 불러오기 후 유지되는가?

### 12.2 곡괭이 장착

- 보유한 곡괭이를 장착할 수 있는가?
- 현재 장착 상태가 인벤토리에 표시되는가?
- 장착한 곡괭이의 능력치가 전투에 정상 반영되는가?
- 장비 교체 후 이전 장비 효과가 잘못 남지 않는가?

### 12.3 스킬 획득

- 던전 클리어 보상으로 스킬을 획득하는가?
- 일반 몬스터가 별도 스킬을 드롭하지 않는가?
- 결과창을 다시 열어도 스킬이 중복 지급되지 않는가?
- 획득 스킬이 저장 및 불러오기 후 유지되는가?

### 12.4 스킬 장착 및 사용

- 보유 스킬을 장착할 수 있는가?
- 장착 상태가 UI에 올바르게 표시되는가?
- 장착한 스킬을 전투에서 사용할 수 있는가?
- 실제 쿨타임과 효과가 기존 구현에 맞게 적용되는가?
- 장착 변경 후 이전 스킬 상태가 잘못 남지 않는가?

### 12.5 인벤토리

- 재료·곡괭이·스킬이 정상적으로 표시되는가?
- 아이템 분류와 검색이 올바르게 동작하는가?
- 장착 아이콘이 스킬 입력 표시와 혼동되지 않는가?
- 툴팁에 아이템 종류와 관계없는 정보가 표시되지 않는가?

## 13. 기획 상태 정리

### 13.1 확정된 규칙

- 곡괭이를 주요 무기로 사용한다.
- 던전에서 획득한 돈과 재료로 곡괭이를 제작한다.
- 곡괭이 제작은 메인 씬에서 진행하는 방향이다.
- 제작한 곡괭이를 장착하여 던전에 도전한다.
- 스킬은 던전 클리어 보상으로 획득한다.
- 획득한 스킬은 장착하여 사용한다.
- 일반 몬스터는 스킬을 직접 드롭하지 않는다.
- 일반 몬스터 재료는 50% 확률로 드롭하며 성공 시 1~2개를 획득한다.
- 이미 획득한 장비와 재료는 던전 실패 후에도 유지한다.
- 획득 및 장착 장비·스킬 데이터는 영구 저장 대상이다.
- 기존 인벤토리의 기본 분류 및 아이템 표시 방향을 유지한다.

### 13.2 폐기 또는 적용하지 않는 기획

- 인챈트를 주된 스킬 획득 구조로 사용
- 일반 몬스터의 직접 스킬 드롭
- 곡괭이 외 해머·탐사봉을 신규 무기로 추가
- 확정되지 않은 강화·분해·판매·랜덤 옵션 추가
- 던전 클리어 시 별도 돈·경험치 보너스 지급
- 보스 처치 후 상자 상호작용으로 보상 획득

### 13.3 미확정 또는 확인 필요

- 곡괭이 이름과 종류
- 곡괭이별 능력치
- 곡괭이 희귀도
- 제작 재료별 요구량
- 제작 비용
- 제작창 최종 디자인
- 제작 상호작용 오브젝트
- 제작 후 자동 장착 여부
- 중복 제작 규칙
- 장비의 중첩 보관 방식
- 스킬 4종의 정확한 명세
- 스킬 장착 슬롯 개수
- 스킬 사용 단축키
- 스킬 획득 확률
- 상의·하의·악세서리의 실제 콘텐츠
- 실제 장비 보너스 값·DEF 감소 공식·쿨타임 합계100% 이상 처리 (공격 스탯 합산 관계는 확정)
- 곡괭이 제작 기능의 실제 구현 여부
