## 1. 시스템 개요

### 1.1 목적

성장 시스템은 플레이어가 던전 전투를 통해 경험치를 획득하고 레벨을 올리며, 레벨업으로 얻은 스탯 포인트를 활용하여 캐릭터를 성장시키는 구조를 관리한다.

성장 결과는 영구 데이터로 유지하여 반복적인 던전 플레이에 반영한다.

### 1.2 핵심 성장 방향

- 몬스터 처치를 통한 경험치 획득
- 누적 경험치에 따른 레벨 상승
- 레벨업 시 스탯 포인트 획득
- 획득한 스탯 포인트를 투자하는 성장 구조
- 레벨을 던전 입장 조건으로 활용
- 캐릭터 성장 정보를 저장하고 유지
- 곡괭이 제작 및 스킬 획득을 통한 전투 성장과 연계

### 1.3 성장 요소 구분

| 성장 요소 | 주요 역할 | 기준 문서 |
|---|---|---|
| 레벨·경험치 | 몬스터 처치에 따른 레벨 성장 | ProgressionSystem |
| 스탯 포인트 | 레벨업 보상 및 능력치 투자 | ProgressionSystem |
| 플레이어 능력치 | 이동·체력·전투 성능 | PlayerSystem |
| 곡괭이 | 장비를 통한 전투 성능 변화 | EquipmentSkillSystem |
| 스킬 | 획득 및 장착을 통한 전투 수단 확장 | EquipmentSkillSystem |
| 영구 데이터 | 성장 결과 저장 및 복원 | SaveSystem |

장비와 스킬은 성장 구조와 관련되지만, 레벨·스탯 성장과 같은 방식으로 관리한다고 확정하지 않는다.

## 2. 경험치 시스템

### 2.1 경험치 획득

**최신 확정 규칙**

플레이어는 몬스터를 처치하면 경험치를 즉시 획득한다.

경험치는 던전 결과창에서 일괄 지급하는 방식이 아니다.

### 2.2 몬스터별 경험치

각 몬스터에는 처치 시 지급할 경험치가 존재한다.

몬스터의 종류에 따라 지급량이 다를 수 있다.

정확한 몬스터별 경험치 값은 현재 인수인계 문서에 없으므로 Unity 프로젝트 데이터를 확인한다.

### 2.3 경험치 지급 흐름

1. 몬스터 처치가 확정된다.
2. 해당 몬스터의 경험치 보상을 확인한다.
3. 플레이어에게 경험치를 지급한다.
4. 현재 경험치 및 레벨 데이터에 반영한다.
5. 필요 경험치를 충족하면 레벨업을 처리한다.
6. 획득 경험치를 해당 런의 보상 기록에 반영한다.
7. HUD에 현재 성장 상태를 표시한다.

이 흐름은 기획상 처리 관계를 나타낸다. 실제 코드의 이벤트 실행 순서나 클래스 구조를 확정하는 것은 아니다.

### 2.4 던전 클리어 경험치

**별도의 던전 클리어 경험치 보너스는 지급하지 않는다.**

보스 처치 이후 결과창에 표시되는 획득 경험치는 해당 런에서 이미 지급된 경험치를 나타낸다.

결과창에서 동일한 경험치를 다시 지급하지 않는다.

### 2.5 던전 실패 시 경험치

던전에 실패해도 이미 획득한 경험치는 100% 유지한다.

실패했다고 해당 런에서 획득한 경험치를 차감하지 않는다.

경험치 획득으로 상승한 레벨 역시 영구 성장 데이터로 유지하는 구조를 따른다.

## 3. 레벨 시스템

### 3.1 레벨 상승

플레이어는 경험치를 누적하여 레벨을 올린다.

레벨 상승에 필요한 경험치 조건을 충족하면 레벨업한다.

### 3.2 레벨 관련 데이터

확인해야 할 항목은 다음과 같다.

- 현재 레벨
- 경험치
- 레벨별 필요 경험치
- 최대 레벨
- 레벨업 처리 방식

현재 경험치를 누적 총량으로 관리하는지, 레벨별 진행량으로 관리하는지는 실제 구현 확인이 필요하다.

### 3.3 경험치 테이블

레벨별 필요 경험치 수치는 현재 인수인계 자료에 없다.

따라서 새로운 경험치 공식이나 레벨 테이블을 작성하지 않는다.

기존 프로젝트에 경험치 테이블 또는 계산식이 있다면 해당 데이터를 우선 확인한다.

### 3.4 최대 레벨

최대 레벨은 미확정이다.

현재 구현에서 상한이 존재하는지 확인하고, 별도의 사용자 승인 없이 새로운 레벨 상한을 추가하지 않는다.

### 3.5 레벨업 관련 확인 사항

다음 내용은 현재 명세가 확인되지 않았다.

- 한 번의 경험치 지급으로 여러 레벨 상승이 가능한 경우의 처리
- 레벨업 시 체력 및 다른 능력치 변화 여부
- 레벨업 시 현재 체력 회복 여부
- 레벨업 시 별도 보상 지급 여부
- 레벨업 연출 및 알림

해당 기능이 이미 구현되어 있다면 기존 동작을 확인한다. 새로운 기능으로 임의 확정하지 않는다.

## 4. 스탯 포인트 시스템

### 4.1 기본 규칙

**최신 확정 규칙**

플레이어는 레벨이 오를 때마다 스탯 포인트 1개를 획득한다.

획득한 스탯 포인트를 투자하여 성장하는 구조를 사용한다.

### 4.2 스탯 포인트 획득

| 조건 | 획득량 |
|---|---:|
| 레벨 1회 상승 | 1포인트 |

레벨 상승과 스탯 포인트 획득은 연동되어야 한다.

### 4.3 스탯 포인트 데이터

성장 시스템은 다음 정보를 구분하여 관리하는 방향이다.

- 미사용 스탯 포인트
- 사용한 스탯 포인트
- 스탯 투자 결과

각 데이터는 영구 저장 대상이다.

### 4.4 스탯 포인트 투자

플레이어는 획득한 스탯 포인트를 능력치 성장에 사용할 수 있는 구조를 원한다.

단, 투자 가능한 능력치 종류와 각 포인트의 효과는 현재 자료에 최종 명세가 없다.

**미확정 항목**

- 투자 가능한 스탯 종류
- 스탯별 필요 포인트
- 1포인트당 능력치 증가량
- 스탯별 최대 투자 한도
- 스탯 투자 취소 및 초기화 가능 여부
- 스탯 투자 UI
- 최초 캐릭터의 미사용 포인트

### 4.5 중복 처리 방지

동일한 레벨 상승으로 스탯 포인트가 의도치 않게 중복 지급되어서는 안 된다.

또한 스탯 투자 과정에서 포인트 소모 및 능력치 반영이 불일치하지 않도록 검증해야 한다.

구체적인 구현 방식은 현재 Unity 데이터와 코드를 확인한다.

## 5. 플레이어 능력치 연동

### 5.1 능력치 관계

성장 시스템은 플레이어 능력치와 연동된다.

현재 기획 자료에서 확인되는 능력치 관련 요소는 다음과 같다.

- 체력
- 이동 속도
- 공격 관련 능력치
- 물리 관련 능력치
- 마법 관련 능력치

이는 기존 기획과 인벤토리 표시 항목에 등장한 개념이다.

모든 항목이 실제 투자 가능한 스탯으로 확정되었다는 의미는 아니다.

### 5.2 기존 밸런스 기준

일반 몬스터 5종의 초기 밸런스 설계 당시 사용한 플레이어 기준값은 다음과 같다.

| 항목 | 기준값 |
|---|---:|
| 체력 | 100 |
| 이동 속도 | 4.0 |
| 입문 무기 평타 피해량 | 10~15 |

이 값은 1층 난이도 1 몬스터 설계를 위한 기준이다.

현재 Unity 프로젝트의 실제 플레이어 기본 능력치 또는 레벨별 성장값으로 확정하지 않는다.

### 5.3 최종 능력치 계산

플레이어의 최종 능력치는 기본 능력치, 성장 결과 및 장비 등의 영향을 받을 수 있다.

정확한 계산식과 적용 순서는 현재 자료에서 확인되지 않는다.

따라서 다음 내용을 임의로 정하지 않는다.

- 기본 능력치와 스탯 증가량의 계산식
- 장비 능력치 적용 방식
- 비율형 효과와 고정 수치 효과의 적용 순서
- 능력치 상한
- 반올림 및 소수점 처리 방식

### 5.4 이동 속도 감소 효과

자철석 몬스터의 기존 명세에는 플레이어 이동 속도 30% 감소, 1.5초 지속 효과가 있다.

감속 종료 시 이동 속도를 특정 고정값으로 복구하지 않는다.

현재 능력치 및 적용된 효과에 맞춰 감속 효과를 제거해야 한다.

감속 중첩과 능력치 계산 방식은 실제 구현 확인이 필요하다.

## 6. 던전 입장 조건 연동

### 6.1 레벨 기반 입장

**최신 확정 규칙**

플레이어가 선택한 던전의 필요 레벨을 충족하면 입장할 수 있다.

이전 던전을 클리어했는지는 입장 조건으로 사용하지 않는다.

### 6.2 입장 판정

`현재 플레이어 레벨 ≥ 해당 던전의 입장 필요 레벨`

위 조건을 만족하면 해당 던전에 입장할 수 있다.

### 6.3 입장 불가 안내

필요 레벨이 부족한 경우 입장 불가 상태를 표시한다.

플레이어가 입장을 시도하면 레벨이 충족되지 않았다는 안내 메시지를 보여준다.

### 6.4 필요 레벨 데이터

층과 난이도별 정확한 필요 레벨은 현재 자료에서 확인되지 않았다.

해당 값은 실제 프로젝트 데이터 또는 향후 승인된 `DungeonSystem.md` 명세를 따른다.

### 6.5 이전 층 클리어 조건

기존에 논의되었던 이전 던전 클리어 기반 해금 규칙은 폐기되었다.

레벨 조건을 만족하더라도 이전 층을 클리어하지 않았다는 이유로 입장을 제한하는 규칙을 추가하지 않는다.

## 7. 장비 성장 연동

### 7.1 곡괭이 제작

곡괭이는 플레이어의 주요 무기이다.

기존 경제 구조:

몬스터 처치

→ 돈과 제작 재료 획득

→ 메인 씬에서 곡괭이 제작

→ 곡괭이 장착

→ 던전 재도전

### 7.2 장비 능력치

곡괭이별 공격력과 공격 범위 차이가 기존 기획에서 논의되었다.

개별 곡괭이의 능력치는 현재 자료에서 확정되지 않았다.

정확한 장비 수치와 제작 규칙은 `EquipmentSkillSystem.md`에서 관리한다.

### 7.3 장비와 스탯 성장

장비로 인한 능력치와 스탯 포인트 투자로 얻는 능력치의 관계는 현재 확인이 필요하다.

장비를 장착할 때 기본 스탯이 직접 변경되는지, 별도의 보정 수치가 적용되는지는 실제 구현을 확인한다.

### 7.4 미확정 장비 기능

다음 기능은 자동으로 추가하지 않는다.

- 강화
- 분해
- 판매
- 랜덤 옵션
- 별도 장비 레벨업

새로운 장비 성장 방식은 사용자 승인 후 기획한다.

---

## 8. 스킬 성장 연동

### 8.1 스킬 획득

스킬은 던전 클리어 보상으로 획득한다.

일반 몬스터가 스킬을 직접 드롭하는 구조는 적용하지 않는다.

### 8.2 스킬 장착

획득한 스킬을 장착하여 전투에서 사용하는 구조이다.

기존 스킬 4종의 구현 완료 보고가 존재한다.

### 8.3 스킬과 성장

스킬의 전투 성능은 플레이어 능력치 또는 장비와 연관될 수 있다.

그러나 구체적인 연동 공식은 현재 확인되지 않았다.

스킬 레벨업이나 별도 강화 시스템 역시 확정된 기획으로 간주하지 않는다.

### 8.4 확인 필요 사항

- 스킬별 능력치 참조 방식
- 공격력 및 피해 계산식
- 스킬 장착 제한
- 스킬 획득 데이터 저장
- 장착 상태 저장
- 스킬 강화 또는 레벨 개념의 실제 존재 여부

상세 내용은 `EquipmentSkillSystem.md`에서 관리한다.

## 9. 영구 성장 및 저장

### 9.1 영구 성장 원칙

플레이어가 획득한 성장 결과는 던전 클리어 또는 실패와 관계없이 유지한다.

던전 진행을 다시 시작해도 영구 성장 정보를 초기화하지 않는다.

### 9.2 저장 대상

| 데이터 | 유지 기준 |
|---|---|
| 레벨 | 영구 유지 |
| 경험치 | 영구 유지 |
| 미사용 스탯 포인트 | 영구 유지 |
| 사용한 스탯 포인트 | 영구 유지 |
| 스탯 투자 결과 | 영구 유지 |
| 획득 장비 | 영구 유지 |
| 보유 스킬 | 영구 유지 |
| 장착 스킬 | 영구 유지 |

실제 저장 지원 범위와 데이터 구조는 Unity 프로젝트 확인이 필요하다.

### 9.3 실패 시 성장 유지

던전 실패 시에도 획득한 경험치와 레벨 상승 결과는 유지한다.

실패했다는 이유로 해당 런에서 획득한 경험치를 회수하지 않는다.

### 9.4 다시 시작

던전 결과창에서 다시 시작하면 같은 층과 난이도로 새로운 런을 시작한다.

런 상태 중 체력, 물약, 부활 횟수 등은 초기화되지만 영구 성장 데이터는 유지한다.

### 9.5 저장 구현 현황

사용자는 Unity Play를 중지했다가 다시 시작해도 돈과 경험치 등이 유지되는 것을 확인했다고 보고했다.

다만 실제 저장 파일 구조와 모든 성장 항목의 저장 여부는 아직 직접 검증하지 않았다.

## 10. 성장 UI

### 10.1 HUD

기존 레벨·경험치 HUD는 구현 완료 보고가 있다.

플레이어의 현재 레벨과 경험치 진행 상태를 확인할 수 있도록 하는 구조이다.

### 10.2 인벤토리 능력치 영역

기존 인벤토리 기획에는 캐릭터와 현재 스탯을 표시하는 영역이 포함되어 있다.

확인할 사항:

- 표시되는 능력치 항목
- 실제 적용 능력치와 표시 수치의 일치
- 장비 능력치 반영 여부
- 투자한 스탯 반영 여부

### 10.3 스탯 투자 UI

스탯 포인트 투자 기능은 기획에 포함되지만 현재 구현 완료 여부는 확인되지 않았다.

투자 UI의 레이아웃, 버튼, 확인 절차 및 표시 방식은 미확정이다.

새로운 UI를 임의로 확정하지 않는다.

### 10.4 던전 결과창

결과창에는 해당 런에서 획득한 경험치와 플레이어의 현재 성장 상태를 표시한다.

기존 결과창 명세에 포함된 요소:

- 획득 경험치
- 현재 레벨
- 경험치 퍼센트
- 경험치 바

결과창의 경험치 카운트업은 표시용 연출이다.

카운트업 과정에서 경험치를 반복 지급하지 않는다.

## 11. 경험치 지급 및 성장 데이터의 중복 방지

### 11.1 몬스터 처치

하나의 몬스터 사망으로 경험치가 의도치 않게 여러 번 지급되지 않아야 한다.

기존 몬스터 사망 이벤트와 보상 지급 구조를 확인한다.

### 11.2 결과창

결과창을 열거나 다시 열어도 경험치를 추가 지급하지 않는다.

결과창에는 해당 런에서 이미 획득한 경험치를 표시한다.

### 11.3 저장 및 불러오기

저장 데이터를 불러올 때 동일한 경험치나 스탯 포인트가 중복 적용되지 않아야 한다.

### 11.4 스탯 포인트

레벨업 처리 및 저장 데이터 복원 과정에서 포인트가 잘못 중복 지급되거나 소실되지 않도록 확인한다.

## 12. 다른 시스템과의 의존 관계

| 관련 시스템 | 연동 내용 | 주요 주의사항 |
|---|---|---|
| DungeonSystem | 입장 레벨, 재시작, 실패 | 이전 층 클리어 조건 재도입 금지 |
| RewardSystem | 몬스터 경험치 지급 | 결과창 중복 지급 방지 |
| MonsterSystem | 처치 경험치 데이터 | 몬스터별 수치 확인 |
| PlayerSystem | 체력, 이동 속도 및 능력치 | 최종 능력치 반영 |
| CombatSystem | 공격 관련 성장 효과 | 피해 계산식 확인 |
| EquipmentSkillSystem | 곡괭이 및 스킬 | 성장 효과 중복 계산 주의 |
| UISystem | 경험치 HUD 및 스탯 표시 | 실제 값과 표시 값 일치 |
| SaveSystem | 레벨, 경험치, 스탯 저장 | 초기화 및 중복 적용 방지 |

### 12.1 주요 충돌 가능성

**성장 ↔ 던전 입장**

레벨만 충족하면 입장할 수 있다는 최신 규칙을 유지해야 한다.

**성장 ↔ 보상**

경험치를 처치 시 지급하고 결과창에서는 표시만 해야 한다.

**성장 ↔ 장비**

장비와 스탯 포인트가 같은 능력치에 영향을 준다면 중복 계산을 방지해야 한다.

**성장 ↔ 플레이어 상태 이상**

이동 속도가 변화하더라도 감속 종료 시 기존 능력치가 올바르게 복구되어야 한다.

**성장 ↔ 저장**

사용한 포인트와 미사용 포인트 및 투자 결과가 저장·불러오기 과정에서 일치해야 한다.

## 14. 시스템 검증 기준

### 14.1 경험치 획득

- 몬스터 처치 시 경험치가 즉시 지급되는가?
- 몬스터별 지급량이 실제 데이터와 일치하는가?
- 하나의 사망으로 경험치가 중복 지급되지 않는가?
- 결과창에서 경험치를 다시 지급하지 않는가?

### 14.2 레벨업

- 경험치가 레벨업 조건을 충족하면 레벨이 상승하는가?
- 레벨업당 스탯 포인트 1개가 지급되는가?
- 레벨과 경험치 데이터가 일관되게 유지되는가?
- 최대 레벨 관련 기존 구현이 있다면 정상 동작하는가?

### 14.3 스탯 포인트

- 미사용 포인트가 올바르게 표시되는가?
- 포인트 사용량과 투자 결과가 일치하는가?
- 포인트가 중복 지급되거나 소실되지 않는가?
- 저장 후에도 투자 결과가 유지되는가?

### 14.4 던전 입장

- 필요 레벨을 충족하면 입장할 수 있는가?
- 이전 층 클리어 여부가 입장을 제한하지 않는가?
- 필요 레벨 미충족 시 안내 메시지가 표시되는가?

### 14.5 능력치 연동

- 플레이어 능력치가 기존 성장 데이터와 일치하는가?
- 장비 능력치가 의도치 않게 중복 반영되지 않는가?
- 자철석 감속 종료 후 현재 능력치에 맞게 이동 속도가 복구되는가?

### 14.6 영구 저장

- 던전 실패 후에도 경험치가 유지되는가?
- 다시 시작해도 레벨과 투자 스탯이 유지되는가?
- 게임 종료 후 재실행해도 성장 데이터가 유지되는가?
- 결과창을 다시 열어도 경험치가 재지급되지 않는가?

## 15. 기획 상태 정리

### 15.1 확정된 규칙

- 몬스터 처치 시 경험치 즉시 획득
- 경험치 누적에 따른 레벨 상승
- 레벨업당 스탯 포인트 1개 획득
- 획득한 포인트를 투자하는 성장 방향
- 필요 레벨 충족 시 던전 입장 가능
- 이전 던전 클리어 여부는 입장 조건이 아님
- 던전 클리어 경험치 보너스 없음
- 실패해도 이미 획득한 경험치 유지
- 레벨·경험치 및 스탯 관련 데이터 영구 보존
- 결과창은 이미 획득한 경험치를 표시

### 15.2 폐기 또는 적용하지 않는 내용

- 이전 던전 클리어를 다음 던전 입장 조건으로 사용
- 클리어 시 별도 경험치 보너스 추가
- 실패 시 이미 획득한 경험치 회수
- 결과창 표시 과정에서 경험치 중복 지급
- 확정되지 않은 강화·분해·판매 시스템 자동 추가

### 15.3 미확정 또는 확인 필요

- 레벨별 필요 경험치
- 경험치 계산 방식
- 최대 레벨
- 몬스터별 경험치 지급량
- 스탯 종류
- 스탯 포인트당 증가량
- 스탯 투자 상한
- 스탯 초기화 가능 여부
- 스탯 투자 UI 구현 여부
- 레벨업 시 자동 능력치 상승 여부
- 장비와 스탯의 능력치 계산식
- 스킬과 스탯의 연동 공식
- 능력치 표시 및 반올림 규칙
- 실제 성장 데이터 저장 구조
