## 1. 시스템 개요

### 1.1 목적

성장 시스템은 플레이어가 던전 전투를 통해 경험치를 획득하고 레벨을 올리며, 레벨업으로 얻은 스탯 포인트를 활용하여 캐릭터를 성장시키는 구조를 관리한다.

성장 결과는 영구 데이터로 유지하여 반복적인 던전 플레이에 반영한다.

### 1.2 핵심 성장 방향

- 몬스터 처치를 통한 경험치 획득
- 누적 경험치에 따른 레벨 상승
- 레벨업 시 스탯 포인트 획득
- 획득한 스탯 포인트를 투자하는 성장 구조
- 레벨을 던전 입장 조건으로 활용
- 캐릭터 성장 정보를 저장하고 유지
- 곡괭이 제작 및 스킬 획득을 통한 전투 성장과 연계

### 1.3 성장 요소 구분

| 성장 요소 | 주요 역할 | 기준 문서 |
|---|---|---|
| 레벨·경험치 | 몬스터 처치에 따른 레벨 성장 | ProgressionSystem |
| 스탯 포인트 | 레벨업 보상 및 능력치 투자 | ProgressionSystem |
| 플레이어 능력치 | 이동·체력·전투 성능 | PlayerSystem |
| 곡괭이 | 장비를 통한 전투 성능 변화 | EquipmentSkillSystem |
| 스킬 | 획득 및 장착을 통한 전투 수단 확장 | EquipmentSkillSystem |
| 영구 데이터 | 성장 결과 저장 및 복원 | SaveSystem |

장비와 스킬은 성장 구조와 관련되지만, 레벨·스탯 성장과 같은 방식으로 관리한다고 확정하지 않는다.

## 2. 경험치 시스템

### 2.1 경험치 획득

**최신 확정 규칙**

플레이어는 몬스터를 처치하면 경험치를 즉시 획득한다.

경험치는 던전 결과창에서 일괄 지급하는 방식이 아니다.

### 2.2 몬스터별 경험치

각 몬스터에는 처치 시 지급할 경험치가 존재한다.

몬스터의 종류에 따라 지급량이 다를 수 있다.

같은 층·난이도·종류의 EXP는 맵과 무관하게 동일하고 맵 총량은 실제 종류·수량으로 달라진다. 1층 쉬움 초기안은 돌4/철5/수정5/석탄4/자철석6/돌골렘45 EXP이며 미적용 테스트 수치다. 맵별 값과 완주 최소187·최대216·평균약199.71 EXP는 [RewardSystem](RewardSystem.md) §2.5~2.6의 제공 계산값으로 실제 적용·Unity 테스트 결과가 아니다.

### 2.3 경험치 지급 흐름

1. 몬스터 처치가 확정된다.
2. 해당 몬스터의 경험치 보상을 확인한다.
3. 플레이어에게 경험치를 지급한다.
4. 현재 경험치 및 레벨 데이터에 반영한다.
5. 필요 경험치를 충족하면 레벨업을 처리한다.
6. 획득 경험치를 해당 런의 보상 기록에 반영한다.
7. HUD에 현재 성장 상태를 표시한다.

이 흐름은 기획상 처리 관계를 나타낸다. 실제 코드의 이벤트 실행 순서나 클래스 구조를 확정하는 것은 아니다.

### 2.4 던전 클리어 경험치

**방·던전 클리어 경험치 보너스는 지급하지 않는다.**

보스 처치 이후 결과창에 표시되는 획득 경험치는 해당 런에서 이미 지급된 경험치를 나타낸다.

결과창에서 동일한 경험치를 다시 지급하지 않는다.

### 2.5 던전 실패 시 경험치

던전에 실패해도 이미 획득한 경험치는 100% 유지한다.

실패했다고 해당 런에서 획득한 경험치를 차감하지 않는다.

경험치 획득으로 상승한 레벨 역시 영구 성장 데이터로 유지하는 구조를 따른다.

## 3. 레벨 시스템

### 3.1 레벨 상승

플레이어는 경험치를 누적하여 레벨을 올린다.

레벨 상승에 필요한 경험치 조건을 충족하면 레벨업한다.

### 3.2 레벨 관련 데이터

확인해야 할 항목은 다음과 같다.

- 현재 레벨
- 경험치
- 레벨별 필요 경험치
- 최대 레벨
- 레벨업 처리 방식

현재 경험치는 레벨별 진행량으로 저장한다는 Codex 보고가 있다. 누적 필요EXP 표의 총량으로 기존 진행EXP를 덮어쓰지 않는다.

### 3.3 성장 시스템 1차 경험치 테이블 — 초기 테스트값

**2026-10-22 승인 초기 테스트값 / 최종 밸런스 아님.** WORK_STATUS의 성장1차 이후 적용·검증 보고가 있으며 이번 문서 작업의 직접 Unity 검증은 아니다. 최대Lv.50을 기준으로 현재레벨1~49의 다음 레벨 필요EXP를 아래 식으로 정한다.

`다음 레벨 필요 EXP = 100 + 50 × (현재 레벨 - 1)`

Lv.1→50은49개 레벨업 구간이며 총 필요EXP는 **63,700**이다. 과거 임시Lv.5/100·150·200·250 기록은 구현 이력으로 보존하고 새 테스트 표의 적용 근거로 사용하지 않는다. 새 표의 적용 보고는 §13을 따른다. 최초11구간은 앞서 작성한 Lv.1→12 초기안과 동일하다.

### 3.4 시작·최대 레벨

2026-10-22 승인 기준은 Lv.1 시작·최대 Lv.50이다. Lv.1의 초기 미사용 포인트 3P와 Lv.2~50의 49회 레벨업당 3P를 합쳐 Lv.50까지 총 150P를 획득한다. Lv.50 이후 레벨 상승은 없다. 전체 경험치표는 §3.3.1의 1차 테스트값이며 최종 밸런스와 실제 구현 완료는 별개다.

### 3.5 레벨업 관련 확인 사항

다음 내용은 현재 명세가 확인되지 않았다.

- 한 번의 경험치 지급으로 여러 레벨 상승이 가능한 경우의 처리
- 레벨업 시 체력 및 다른 능력치 변화 여부
- 레벨업 시 현재 체력 회복 여부
- 레벨업 시 별도 보상 지급 여부
- 레벨업 연출 및 알림

해당 기능이 이미 구현되어 있다면 기존 동작을 확인한다. 새로운 기능으로 임의 확정하지 않는다.

## 4. 스탯 포인트 및 패시브 시스템

**2026-10-23 최신 사용자 승인 반영.** 승인 기획과 [WORK_STATUS.md](../WORK_STATUS.md)의 Codex 구현·검증 보고를 구분한다. 이번 작업은 문서 갱신과 관련 코드의 읽기 전용 확인이며 Unity 컴파일·Play·빌드 검증은 재실행하지 않았다. 아래 과거 구현 기록은 당시 이력으로 보존한다.

### 4.1 지급과 투자

| 항목 | 확정 규칙 |
|---|---|
| 초기 상태 | Lv.1, 미사용 3P |
| 레벨업 | 매회 3P |
| 최대 성장 | Lv.50, 총 획득 150P = 초기3 + 49×3 |
| 투자 대상 | 체력·물리·마법 3종 |
| 개별 상한 | 스탯별 100P |
| 체력 보너스 | 1P당 최대 HP +3 |
| 물리 보너스 | 1P당 물리 공격 스탯 +0.4 |
| 마법 보너스 | 1P당 마법 공격 스탯 +0.4 |

기존 레벨업당 1P 기획은 위 3P 규칙으로 대체한다. 방어력은 투자 대상이 아니며 일부 상의·하의 장비에서 획득한다. 체력·물리·마법 투자량과 미사용 포인트를 영구 데이터로 관리하고 중복 지급·중복 투자·포인트 소모/능력치 불일치를 방지해야 한다.

### 4.2 투자 조작과 던전 제한

메인 씬 인벤토리 스탯 탭에서 ×1/×5/×10을 선택하고 [+] 클릭 즉시 투자·저장한다.

`실제 투자량 = min(선택 배수, 보유 포인트, 100 - 해당 스탯 투자량)`

투자 후 능력치·패시브 해금 상태를 즉시 갱신한다. 던전에서는 장비·스킬·스탯·패시브 열람만 가능하고 장비/스킬 교체·스탯 투자·초기화는 불가하다. 던전 입장 시 성장 구성을 고정한다. 던전 중 획득 경험치/레벨·미사용 포인트 보존 규칙을 폐기하거나 입장 당시 레벨로 되돌리는 뜻이 아니다. 현재 구현 보고는 런 중 레벨·미사용P 상승을 유지하면서 투자 구성은 변경하지 않는다. 새 레벨이 투자 효과·패시브를 자동으로 다시 분배하는 규칙을 추가하지 않는다.

### 4.3 스탯 초기화 — 2026-10-23 승인

메인 로비 인벤토리 스탯 탭에서 **고정 500G(초기 밸런스 테스트값)**로 초기화한다. 레벨·투자량과 무관한 비용이며 최종 경제 밸런스가 아니다. 체력·물리·마법 투자P 전부를 기존 미사용P에 더하고 세 투자량을0으로 만든다. 투자량에 따라 해금된9패시브도 자동으로 잠긴다. 투자0P 또는500G 미만이면 실행하지 않는다.

별도 팝업 대신 같은 스탯 탭 안의 **인라인 2단계 확인**을 사용한다. 첫 클릭은 비용·반환P만 보여 주며 데이터는 바꾸지 않는다. 최종 확인에서 로비·보유 골드·투자량·실행 권한을 재검사한다. 취소·탭 전환·인벤토리 닫기로 확인 상태를 해제하며 중복 과금을 방지한다. 상세 UI는 [UISystem](UISystem.md) §9.10.2를 따른다.

레벨·현재 진행EXP·아이템·장비·스킬·설정 등 다른 영구 정보는 보존한다. 기존 v3 스냅샷에 골드 차감과 전체 포인트 반환을 함께 저장하고 **파일 저장 성공 후 두 메모리 값을 함께 확정**한다. 쓰기 실패 시 원래 골드·포인트를 유지하고 오류 안내/재시도를 제공한다. 개발용 전체 저장 초기화와 구분한다.

최대HP 변경 시 현재HP 비율을 유지한다. 초기화는100P 패시브의 재생·물리 충전·마법 폭발 대기 상태를 정리하지만 일반 스킬 쿨타임·물약·부활·런 보상은 보존한다. 예약·잔류 스킬 효과가 있으면 초기화를 거부한다. 던전에서는 열람만 허용한다. 저장/실패 경계는 [SaveSystem](SaveSystem.md) §6.6을 따른다.

### 4.4 패시브 해금과 수치 상태

각 스탯에 20P·50P·100P를 투자하면 해당 단계 패시브가 자동 해금되며 별도 포인트는 소모하지 않는다. 아래9종은 승인 기획이며 구현 보고는 §13에서 별도로 관리한다. 충격파 30%와 추가 폭발 40%는 **초기 밸런스값**으로 최종 튜닝값과 구분한다. 다른 승인 수치도 이후 변경은 별도 승인/밸런싱으로 관리한다.

### 4.5 체력 패시브 3종

| 투자 | 승인 효과 |
|---|---|
| 20P | 물약 회복량 +20%. 기존 물약 수량·사용/부활 규칙은 유지 |
| 50P | 일반 방 클리어 시 최대 HP의 10% 회복. 보스 방 보상으로 확대하지 않음 |
| 100P | 생명력 재생. 아래 조건 적용 |

생명력 재생은 살아 있는 적이 존재하는 방에서만 작동한다. 마지막 **실제 HP 피해** 후 5초가 지나면 초당 최대 HP 1%를 회복하고, 방당 누적 회복 한도는 최대 HP 20%다. 방 클리어 시 즉시 중단하며 방 이동·부활 시 회복 한도를 초기화한다. 최대 HP가 변하면 이미 사용한 회복 한도의 비율을 유지한다. 상세 체력 연동은 [PlayerSystem](PlayerSystem.md)을 따른다.

### 4.6 물리 패시브 3종

| 투자 | 승인 효과 |
|---|---|
| 20P | 곡괭이 기본 공격 사거리 +15% |
| 50P | 기본 공격 적중 시 플레이어 전방 부채꼴 충격파 1회. 직접 타격 대상도 범위 안이면 추가 피해 허용. 현재 사거리2.0 Unity 유닛·각도90°, 기본 공격 피해 기준 초기 비율30%. 물리20P의 기본 공격 범위 증가는 충격파에 미적용 |
| 100P | 직접 적중한 기본 공격 3회 후 다음 기본 공격 및 충격파 피해 +100%. 강화 준비 상태에서 빗나가도 강화 소모. 방 이동 시 충전 유지, 사망·부활 시 충전 초기화 |

현재 구현에서는 한 기본 공격이 여러 적을 직접 맞혀도 충전1회이며 충격파·강화 공격으로 재충전하지 않는다고 보고됐다. 직접 피해의 반올림 전 값×30%에 강화 배율을 적용하고 최종 반올림한다. 이 세부 처리는 구현 기록이며 별도 미명시 경계를 새 승인 기획으로 확대하지 않는다. 기존 일반 공격·스킬 사용 행동 제한을 무시하는 추가 입력 규칙을 만들지 않는다.

### 4.6.1 신규3단 콤보와 물리 패시브 — 승인 기획

기존3스탯/9패시브의 해금·성장·저장 규칙은 바꾸지 않는다. 콤보 구현/검증은 미완료다. 물리20P는 전 단계 사거리+15%만 적용한다(초기1.5/1.5/1.7→1.725/1.725/1.955). 각도/독립 충격파 범위에는 적용하지 않는다.

물리50P는1·2·3타 실제 직접 적중마다 공격당 최대1회, 다수 적도1회다. 독립2.0/90°·초기30%·중복 방지를 유지한다.3타는 **130% 단계 배율 적용 뒤 반올림 전 기본 직접 피해**를 기준으로 충격파를 계산하고100P 강화도 직접/충격파 각각에 적용한다. 중간 반올림 없이 각 최종 피해에서 한 번/.5 올림은 보존한다.

물리100P 충전은 단계별 유효 비강화 기본 직접 공격1회 단위/다수 적도 최대1회다. 충격파·강화 공격은 재충전하지 않는다. 어느 단계에서도 강화 가능하고 콤보3타와 별개다. 허용된 공격 시작 후 소비된 강화는 빗나감/취소로 복구하지 않고 시작 거부는 미소모다. 방 이동 충전 유지·사망/부활 초기화를 유지하며 콤보 단계/예약은 별도로 초기화한다. 정확한 계산은 [CombatSystem](CombatSystem.md) §3.8을 따른다.

### 4.7 마법 패시브 3종

| 투자 | 승인 효과 |
|---|---|
| 20P | 마법 스킬의 관련 공격 범위 치수 +20%. 부채꼴은 거리와 각도를 모두 확대 |
| 50P | 마법 스킬 쿨타임 -15%, 장비 쿨타임 감소율과 합산. 별도의 밸런스 상한은 현재 두지 않음 |
| 100P | 마법 스킬의 최초 유효 적중 몬스터 중심 추가 폭발. 최초 대상도 피해 적용. 초기 피해 비율40%, 반경1.5 Unity 유닛, 공유 내부 쿨타임1.5초. 마법20P 범위 확대 미적용·연쇄 폭발 금지 |

공유 내부 쿨타임은 마법 스킬 사이에 적용한다. 최초 적중 정렬·동률 처리와 감소율 합계100% 이상 처리의 현재 구현은 CombatSystem §4.6에 분리 기록한다. 해당 구현 세부를 최종 밸런스나 모든 미래 스킬의 규칙으로 확대하지 않는다. 피해 및 반올림 순서는 [CombatSystem](CombatSystem.md) §6.5를 따른다.

### 4.8 기존 저장 이전과 영구 보존

기존 캐릭터 레벨과 현재 레벨 진행 경험치·기존 투자 결과를 유지한다. 해당 레벨 총 획득 포인트는 `현재 레벨×3P`, 보정 후 미사용 포인트는 `총 획득 포인트-기존 투자 포인트`다. 정상 기존 v1은 투자 기능이 없으므로 투자0P로 이전 가능하며 최초 한 번만 보정해 중복 지급을 막는다.

이전 전 저장 파일과 백업을 별도 보호하고 이전 완료 상태를 관리한다. 재화·재료·보유/장착 스킬·설정 등 영구 정보는 보존한다. 현재 Codex 보고와 관련 코드에는 v3 투자 필드·v1/v2 이전·완료 표시·별도 보호본이 존재한다. 초기화는 이 v3를 재사용하며 신규 스키마를 요구하지 않는다. 구현·이상 데이터 차단 및 미검증은 SaveSystem §6을 따른다. 과거 Lv.5 상한에서 버려진 경험치는 복구할 수 없다는 사용자 제공 Codex 읽기 전용 분석을 구분한다. 상세 이전 기준은 [SaveSystem](SaveSystem.md) §6을 따른다.

## 5. 플레이어 능력치 연동

### 5.1 투자와 기타 능력치 구분

투자 스탯은 체력·물리·마법 3종뿐이다. 이동 속도·공격 간격·방어력은 표시/장비 등 다른 능력치이며 투자 대상에 자동 포함하지 않는다. 방어력은 일부 상의·하의에서 얻는 기획이고 개별 장비 콘텐츠 구현 완료를 뜻하지 않는다.

### 5.2 기존 밸런스 기준

일반 몬스터 5종의 초기 밸런스 설계 당시 사용한 플레이어 기준값은 다음과 같다.

| 항목 | 기준값 |
|---|---:|
| 체력 | 100 |
| 이동 속도 | 4.0 |
| 입문 무기 평타 피해량 | 10~15 |

이 값은 1층 난이도 1 몬스터 설계를 위한 기준이다.

현재 Unity 프로젝트의 실제 플레이어 기본 능력치 또는 레벨별 성장값으로 확정하지 않는다.

### 5.3 최종 능력치 계산

최종 물리·마법 공격 스탯은 각각 기본 공격 스탯+투자 보너스+장비 보너스다. 투자 보너스는 해당 스탯 투자P×0.4다. 체력 투자는 최대HP에 투자P×3을 더하며 최대HP 변경 시 현재HP 비율을 유지한다. 기본 공격 스탯/기본HP·장비 보너스의 구체적인 신규 수치는 확정하지 않는다.

곡괭이/단일 유형 스킬 피해와 최종 한 번 .5 올림, 패시브의 후속 처리 기준은 CombatSystem §6.5를 따른다. 방어력 피해 감소 공식·기타 능력치의 미명시 계산/표시 반올림은 별도 검토한다.

### 5.4 이동 속도 감소 효과

자철석 몬스터의 기존 명세에는 플레이어 이동 속도 30% 감소, 1.5초 지속 효과가 있다.

감속 종료 시 이동 속도를 특정 고정값으로 복구하지 않는다.

현재 능력치 및 적용된 효과에 맞춰 감속 효과를 제거해야 한다.

감속 중첩과 능력치 계산 방식은 실제 구현 확인이 필요하다.

## 6. 던전 입장 조건 연동

### 6.1 레벨 기반 입장

**최신 확정 규칙**

플레이어가 선택한 던전의 필요 레벨을 충족하면 입장할 수 있다.

이전 던전을 클리어했는지는 입장 조건으로 사용하지 않는다.

### 6.2 입장 판정

`현재 플레이어 레벨 ≥ 해당 던전의 입장 필요 레벨`

위 조건을 만족하면 해당 던전에 입장할 수 있다.

### 6.3 입장 불가 안내

필요 레벨이 부족한 경우 입장 불가 상태를 표시한다.

플레이어가 입장을 시도하면 레벨이 충족되지 않았다는 안내 메시지를 보여준다.

### 6.4 필요 레벨 데이터

1층 초기 입장 레벨 제안은 쉬움1/보통3/어려움5/악몽8이며 아직 적용·최종 확정된 조건이 아니다. 과거 구현 레벨1/2/3/5를 이번 문서만으로 덮어쓰지 않는다. 데이터 준비·콘텐츠 검사와 기존 레벨 조건은 유지한다.

해당 값은 실제 프로젝트 데이터 또는 향후 승인된 `DungeonSystem.md` 명세를 따른다.

### 6.5 이전 층 클리어 조건

기존에 논의되었던 이전 던전 클리어 기반 해금 규칙은 폐기되었다.

레벨 조건을 만족하더라도 이전 층을 클리어하지 않았다는 이유로 입장을 제한하는 규칙을 추가하지 않는다.

## 7. 장비 성장 연동

### 7.1 곡괭이 제작

곡괭이는 플레이어의 주요 무기이다.

기존 경제 구조:

몬스터 처치

→ 돈과 제작 재료 획득

→ 메인 씬에서 곡괭이 제작

→ 곡괭이 장착

→ 던전 재도전

### 7.2 장비 능력치

곡괭이별 공격력과 공격 범위 차이가 기존 기획에서 논의되었다.

개별 곡괭이의 능력치는 현재 자료에서 확정되지 않았다.

정확한 장비 수치와 제작 규칙은 `EquipmentSkillSystem.md`에서 관리한다.

### 7.3 장비와 스탯 성장

장비로 인한 능력치와 스탯 포인트 투자로 얻는 능력치의 관계는 현재 확인이 필요하다.

장비를 장착할 때 기본 스탯이 직접 변경되는지, 별도의 보정 수치가 적용되는지는 실제 구현을 확인한다.

### 7.4 미확정 장비 기능

다음 기능은 자동으로 추가하지 않는다.

- 강화
- 분해
- 판매
- 랜덤 옵션
- 별도 장비 레벨업

새로운 장비 성장 방식은 사용자 승인 후 기획한다.

## 8. 스킬 성장 연동

### 8.1 스킬 획득

스킬은 던전 클리어 보상으로 획득한다.

일반 몬스터가 스킬을 직접 드롭하는 구조는 적용하지 않는다.

### 8.2 스킬 장착

획득한 스킬을 장착하여 전투에서 사용하는 구조이다.

기존 스킬 4종의 구현 완료 보고가 존재한다.

### 8.3 스킬과 성장

대지 분쇄·착암 돌격은 물리, 청록 광선·불안정 광석 발파는 마법으로 분류한다. 해당 최종 공격 스탯을 참조하는 단일 유형 피해 공식으로 기존 혼합 계수 기획을 대체한다. 마법 범위/쿨타임/추가 폭발 등 투자 패시브와 기존 시전·판정·범위·쿨타임·행동 제한을 구분하며, 명시된 패시브 효과 외 기존 동작은 유지한다. 별도 스킬 레벨업/강화 시스템을 추가한 것이 아니다.

### 8.4 구현 전 확인

신규 스킬 기본 피해량, 패시브 추가 피해 비율의 참조 기준과 경계 판정, 장비 보너스 실제 데이터/쿨타임 감소100% 이상 처리와 새 공식 적용 검증이 필요하다. 보유/장착 스킬의 기존 저장/획득 규칙은 보존한다. 상세는 EquipmentSkillSystem·CombatSystem을 따른다.

## 9. 영구 성장 및 저장

### 9.1 영구 성장 원칙

플레이어가 획득한 성장 결과는 던전 클리어 또는 실패와 관계없이 유지한다.

던전 진행을 다시 시작해도 영구 성장 정보를 초기화하지 않는다.

### 9.2 저장 대상

| 데이터 | 유지 기준 |
|---|---|
| 레벨 | 영구 유지 |
| 경험치 | 영구 유지 |
| 미사용 스탯 포인트 | 영구 유지 |
| 사용한 스탯 포인트 | 영구 유지 |
| 스탯 투자 결과 | 영구 유지 |
| 획득 장비 | 영구 유지 |
| 보유 스킬 | 영구 유지 |
| 장착 스킬 | 영구 유지 |

실제 저장 지원 범위와 데이터 구조는 Unity 프로젝트 확인이 필요하다.

### 9.3 실패 시 성장 유지

던전 실패 시에도 획득한 경험치와 레벨 상승 결과는 유지한다.

실패했다는 이유로 해당 런에서 획득한 경험치를 회수하지 않는다.

### 9.4 다시 시작

던전 결과창에서 다시 시작하면 같은 층과 난이도로 새로운 런을 시작한다.

런 상태 중 체력, 물약, 부활 횟수 등은 초기화되지만 영구 성장 데이터는 유지한다.

### 9.5 저장 구현 현황

사용자는 Unity Play를 중지했다가 다시 시작해도 돈과 경험치 등이 유지되는 것을 확인했다고 보고했다.

다만 실제 저장 파일 구조와 모든 성장 항목의 저장 여부는 아직 직접 검증하지 않았다.

## 10. 성장 UI

### 10.1 HUD

기존 레벨·경험치 HUD는 구현 완료 보고가 있다.

플레이어의 현재 레벨과 경험치 진행 상태를 확인할 수 있도록 하는 구조이다.

### 10.2 인벤토리 능력치 영역

기존 인벤토리 기획에는 캐릭터와 현재 스탯을 표시하는 영역이 포함되어 있다.

확인할 사항:

- 표시되는 능력치 항목
- 실제 적용 능력치와 표시 수치의 일치
- 장비 능력치 반영 여부
- 투자한 스탯 반영 여부

### 10.3 스탯 투자 UI

기존 우측 아이템 영역을 유지하고 좌측 캐릭터 정보/스탯 2탭, 공통 하단 FINAL ATTRIBUTES, 미사용P 알림 점, ×1/×5/×10 및 즉시 투자/저장·한 번에 하나만 펼치는3카드 아코디언·9패시브 Hover 상세·500G 인라인 초기화를 사용한다. 세부 기획은 UISystem §9.10을 따른다. UI 승인과 구현 완료는 구분한다.

### 10.4 던전 결과창

결과창에는 해당 런에서 획득한 경험치와 플레이어의 현재 성장 상태를 표시한다.

기존 결과창 명세에 포함된 요소:

- 획득 경험치
- 현재 레벨
- 경험치 퍼센트
- 경험치 바

결과창의 경험치 카운트업은 표시용 연출이다.

카운트업 과정에서 경험치를 반복 지급하지 않는다.

## 11. 경험치 지급 및 성장 데이터의 중복 방지

### 11.1 몬스터 처치

하나의 몬스터 사망으로 경험치가 의도치 않게 여러 번 지급되지 않아야 한다.

기존 몬스터 사망 이벤트와 보상 지급 구조를 확인한다.

### 11.2 결과창

결과창을 열거나 다시 열어도 경험치를 추가 지급하지 않는다.

결과창에는 해당 런에서 이미 획득한 경험치를 표시한다.

### 11.3 저장 및 불러오기

저장 데이터를 불러올 때 동일한 경험치나 스탯 포인트가 중복 적용되지 않아야 한다.

### 11.4 스탯 포인트

레벨업 처리 및 저장 데이터 복원 과정에서 포인트가 잘못 중복 지급되거나 소실되지 않도록 확인한다.

## 12. 다른 시스템과의 의존 관계

| 관련 시스템 | 연동 내용 | 주요 주의사항 |
|---|---|---|

### 12.1 주요 충돌 가능성

**성장 ↔ 던전 입장**

레벨만 충족하면 입장할 수 있다는 최신 규칙을 유지해야 한다.

**성장 ↔ 보상**

경험치를 처치 시 지급하고 결과창에서는 표시만 해야 한다.

**성장 ↔ 장비**

장비와 스탯 포인트가 같은 능력치에 영향을 준다면 중복 계산을 방지해야 한다.

**성장 ↔ 플레이어 상태 이상**

이동 속도가 변화하더라도 감속 종료 시 기존 능력치가 올바르게 복구되어야 한다.

**성장 ↔ 저장**

사용한 포인트와 미사용 포인트 및 투자 결과가 저장·불러오기 과정에서 일치해야 한다.

## 14. 시스템 검증 기준

### 14.1 경험치 획득

- 몬스터 처치 시 경험치가 즉시 지급되는가?
- 몬스터별 지급량이 실제 데이터와 일치하는가?
- 하나의 사망으로 경험치가 중복 지급되지 않는가?
- 결과창에서 경험치를 다시 지급하지 않는가?

- 경험치가 레벨업 조건을 충족하면 레벨이 상승하는가?
- Lv.1 초기3P·레벨업3P·Lv.50 총150P 및 중복 지급 방지가 새 기획대로 동작하는가?
- 레벨과 경험치 데이터가 일관되게 유지되는가?
- 최대 레벨 관련 기존 구현이 있다면 정상 동작하는가?

### 14.3 스탯 포인트

- 미사용 포인트가 올바르게 표시되는가?
- 포인트 사용량과 투자 결과가 일치하는가?
- 포인트가 중복 지급되거나 소실되지 않는가?
- 저장 후에도 투자 결과가 유지되는가?

### 14.4 던전 입장

- 필요 레벨을 충족하면 입장할 수 있는가?
- 이전 층 클리어 여부가 입장을 제한하지 않는가?
- 필요 레벨 미충족 시 안내 메시지가 표시되는가?

### 14.5 능력치 연동

- 플레이어 능력치가 기존 성장 데이터와 일치하는가?
- 장비 능력치가 의도치 않게 중복 반영되지 않는가?
- 자철석 감속 종료 후 현재 능력치에 맞게 이동 속도가 복구되는가?

### 14.6 영구 저장

- 던전 실패 후에도 경험치가 유지되는가?
- 다시 시작해도 레벨과 투자 스탯이 유지되는가?
- 게임 종료 후 재실행해도 성장 데이터가 유지되는가?
- 결과창을 다시 열어도 경험치가 재지급되지 않는가?

- 메인 전용 투자/골드 초기화, 던전 구성 고정/열람만 허용
- 획득한 포인트를 투자하는 성장 방향
- 필요 레벨 충족 시 던전 입장 가능
- 이전 던전 클리어 여부는 입장 조건이 아님
- 던전 클리어 경험치 보너스 없음
- 실패해도 이미 획득한 경험치 유지
- 레벨·경험치 및 스탯 관련 데이터 영구 보존
- 결과창은 이미 획득한 경험치를 표시

### 15.2 폐기 또는 적용하지 않는 내용

- 이전 던전 클리어를 다음 던전 입장 조건으로 사용
- 클리어 시 별도 경험치 보너스 추가
- 실패 시 이미 획득한 경험치 회수
- 결과창 표시 과정에서 경험치 중복 지급
- 확정되지 않은 강화·분해·판매 시스템 자동 추가

### 15.3 미확정 또는 구현 전 확인

- Lv.1~49 전체 경험치 테스트 표의 최종 튜닝·Lv.50 도달 후 추가EXP 누적/표시/집계 정책
- 2층 이후 밸런스·몬스터별EXP 최종값과 1층 성장 목표 검증
- 기본 공격 스탯·신규 스킬 기본 피해량·장비별 보너스/DEF 감소 공식
- 초기화500G·충격파30%·폭발40%의 최종 밸런스 튜닝
- 최초 대상·다중 적중·쿨타임 합계100% 이상 처리의 현재 구현 세부에 대한 최종 정책 검토
- 회복/표시 소수점 및 패시브 경계의 전체 전투 회귀 (현재 구현은 Player/Combat 참조)
- v3 이전·보호/복구의 강제 장애 및 사용자 실데이터 전수 검증
- 던전 내 자동 레벨 상승과 입장 시 고정 구성의 구체적 적용 범위
- 실제 OS 입력·타 해상도·장시간·배포 빌드 회귀 검증

## 16. 문서 관리

본 문서는 플레이어의 경험치, 레벨, 스탯 포인트 및 영구 성장 규칙을 관리한다.

관련 상세 기획의 기준 문서는 다음과 같다.

- `DungeonSystem.md`: 던전 입장 조건과 런 진행
- `PlayerSystem.md`: 플레이어 기본 능력치 및 생존
- `RewardSystem.md`: 경험치 지급 조건
- `CombatSystem.md`: 피해 계산 및 전투 연동
- `EquipmentSkillSystem.md`: 곡괭이와 스킬
- `UISystem.md`: 경험치 HUD 및 스탯 표시
- `SaveSystem.md`: 영구 성장 데이터 저장

기획 변경 시 기존 GDD 및 관련 Systems 문서와의 충돌 여부를 검토한다.

사용자 승인 후 공식 문서 수정안을 작성하고 `CHANGELOG.md`에 확정 변경을 기록한다.

확인되지 않은 수치와 기능을 임의로 추가하지 않는다.
