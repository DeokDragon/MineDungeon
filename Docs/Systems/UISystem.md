## 1. 시스템 개요

### 1.1 목적

UI 시스템은 플레이어가 게임의 상태와 진행 정보를 확인하고, 던전 입장, 인벤토리 관리, 장비·스킬 확인, 전투 결과 확인 등의 기능을 이용할 수 있도록 한다.

기존 UI의 표시 방식과 입력 규칙을 유지하면서 각 게임 시스템에서 관리하는 데이터를 정확하게 표현하는 것을 목표로 한다.

### 1.2 UI 구성

| UI | 주요 역할 |
|---|---|
| 플레이어 HUD | 체력, 생명, 물약, 성장 상태 등 표시 |
| 일반 몬스터 HP바 | 몬스터 체력 표시 |
| 보스 HP바 | 보스 체력 및 지연 피해 표시 |
| 공격 예고 | 위험 범위 및 공격 발동 시점 안내 |
| 획득 알림 | 아이템·재료 획득 정보 |
| 인벤토리 | 아이템 분류, 검색, 정렬, 장착 정보 |
| 던전 입장창 | 층·난이도 선택, 입장 조건 및 보상 확인 |
| 던전 결과창 | 획득 보상, 전투 기록, 재시작 및 로비 복귀 |
| 퍼즈 메뉴 | 일반적인 일시정지와 메뉴 기능 |
| 곡괭이 제작창 | 제작할 곡괭이 및 필요 자원 확인 |

곡괭이 제작창은 기획 단계이며, 현재 모든 UI가 구현 완료되었다는 의미는 아니다.

## 2. UI 공통 규칙

### 2.1 기준 해상도

UI의 기준 해상도는 **1920 × 1080**이다.

실제 UI의 크기, 배치 및 스케일 설정은 기존 Unity 프로젝트 값을 확인한다.

### 2.2 UI 디자인 방향

UI는 정보를 쉽게 구분할 수 있도록 구성하며, 현재 개발된 UI와 시각적 일관성을 유지한다.

기존 Figma 레퍼런스는 주로 다음 요소를 참고하는 용도이다.

- 버튼 위치
- 정보 배치
- 패널 크기
- 선택 상태
- 화면 구성

레퍼런스의 모든 색상과 문구를 그대로 복제하지 않는다.

### 2.3 UI 크기

인벤토리와 던전 선택창은 기존에 화면을 지나치게 많이 차지하여 크기를 줄인 이력이 있다.

사용자는 수정된 크기가 적절하다고 보고했다.

따라서 새로운 UI 작업에서 기존 패널의 크기를 임의로 확대하거나 초기 레퍼런스 크기로 되돌리지 않는다.

### 2.4 UI 표시 데이터

UI는 관련 시스템의 실제 상태를 표시해야 한다.

예시:

- 체력 HUD: 플레이어 체력
- 생명 HUD: 남은 생명
- 인벤토리: 보유 아이템
- 던전 선택창: 입장 조건 및 보상
- 결과창: 해당 런에서 획득한 보상과 전투 기록

UI를 다시 표시한다는 이유로 보상을 지급하거나 영구 데이터를 변경하지 않는다.

## 3. UI 입력 및 시간 처리

### 3.1 확인된 입력

| 입력 | 기능 |
|---|---|
| T | 월드 상호작용 |
| I | 인벤토리 열기 및 닫기 |
| ESC | 열린 UI 닫기 또는 퍼즈 메뉴 |

공격, 회피, 물약 및 스킬의 최종 입력 배치는 Unity 프로젝트 확인이 필요하다.

### 3.2 게임 시간 처리

**확정 규칙**

- 인벤토리를 열어도 게임 시간이 멈추지 않는다.
- 던전 선택창을 열어도 게임 시간이 멈추지 않는다.
- 일반적인 일시정지는 ESC 퍼즈 메뉴에서 처리한다.

UI를 열 때마다 공통적으로 게임의 `timeScale`을 0으로 변경하는 구조를 적용하지 않는다.

### 3.3 ESC 입력

ESC는 열린 UI를 닫거나 퍼즈 메뉴를 이용하는 입력으로 사용한다.

다음 동작의 정확한 입력 우선순위는 기존 구현을 확인한다.

- 여러 UI가 열린 경우
- 결과창이 열린 경우
- 퍼즈 메뉴가 열린 경우
- UI 전환 도중 ESC를 누르는 경우

확정되지 않은 UI 입력 우선순위를 새로 지정하지 않는다.

### 3.4 인벤토리와 던전 선택창 전환

던전 선택창이 열린 상태에서 I를 누르면 다음 순서로 동작한다.

1. 던전 선택창을 닫는다.
2. 인벤토리를 연다.
3. 이후 인벤토리를 닫더라도 던전 선택창을 다시 열지 않는다.
4. 일반 게임 화면으로 돌아간다.

인벤토리를 닫았다는 이유로 이전 던전 선택창을 자동으로 다시 표시하지 않는다.

### 3.5 UI 중복 및 재열림

확정된 UI 전환 규칙을 유지한다.

다른 UI에도 불필요한 자동 재열림을 추가하지 않는다.

여러 UI의 동시 표시 허용 범위는 실제 구현 확인이 필요하다.

## 4. 플레이어 HUD

### 4.1 목적

플레이어 HUD는 전투 중 확인해야 하는 플레이어 상태를 표시한다.

### 4.2 체력

플레이어의 현재 체력과 최대 체력 관련 정보를 표시하는 영역이다.

정확한 표시 형태, 위치, 색상과 크기는 현재 구현을 확인한다.

### 4.3 생명 HUD

**확정 규칙**

- 최초 생명을 포함한 총 3개의 생명
- 부활 가능 횟수는 2회
- 부적 또는 유사한 아이콘 3개 사용
- 소모된 아이콘은 어둡게 표시

| 상황 | 활성 생명 아이콘 |
|---|---:|
| 던전 시작 | 3개 |
| 첫 번째 사망 후 | 2개 |
| 두 번째 사망 후 | 1개 |
| 세 번째 사망 후 | 0개 |

세 번째 사망 시 던전 실패가 발생한다.

### 4.4 물약 표시

물약은 플레이어의 회복 수단이다.

다시 시작하면 물약 3개로 초기화한다.

물약 HUD의 실제 배치, 표현 및 조작 방식은 기존 구현을 확인한다.

과거 제안 중 물약 HUD를 화면 중앙 하단으로 변경하는 안은 사용자가 적용하지 않도록 요청했다.

따라서 해당 배치를 자동 반영하지 않는다.

### 4.5 레벨 및 경험치

기존 레벨·경험치 HUD는 구현 완료 보고가 있다.

플레이어의 레벨 및 경험치 상태를 표시한다.

정확한 HUD 배치와 경험치 표시 방식은 기존 프로젝트를 확인한다.

### 4.6 스킬 표시

스킬 4종의 구현 완료 보고가 존재한다.

스킬 사용 UI의 최종 배치, 장착 슬롯 수 및 단축키는 현재 인수인계 자료에서 확인되지 않는다.

현재 구현 데이터를 확인한 뒤 상세 명세를 보완한다.

## 5. 일반 몬스터 HP바

### 5.1 표시 위치

일반 몬스터 HP바는 몬스터 캐릭터 아래쪽에 배치하는 방향이다.

몬스터가 이동하면 HP바도 함께 이동한다.

### 5.2 체력 표시

몬스터의 현재 체력 상태를 반영한다.

기존 피격 및 사망 처리와 연동한다.

### 5.3 엘리트 몬스터

기존 HP바 기획에는 일반 몬스터와 엘리트 몬스터가 함께 언급되었다.

다만 엘리트 몬스터의 실제 존재 여부, 별도 HP바 형태 및 차별화 규칙은 확인이 필요하다.

### 5.4 구현 확인 사항

- HP바의 최종 크기
- 표시 및 숨김 조건
- 체력 감소 애니메이션
- 몬스터 사망 시 표시 종료
- 몬스터와 HP바 위치 정렬
- 현재 구현 여부

## 6. 보스 HP바

### 6.1 표시 위치

보스 HP바는 **플레이어 HUD 상단 중앙**에 배치한다.

### 6.2 체력 감소

플레이어가 보스에게 피해를 입히면 현재 체력 표시가 즉시 감소한다.

### 6.3 지연 피해 표시

기존 확정된 표현 방식은 다음과 같다.

1. 보스가 피해를 받는다.
2. 현재 체력 표시가 즉시 감소한다.
3. 감소 전 체력 구간은 밝은 주황색 계열로 남는다.
4. 일정 시간 공격받지 않으면 주황색 구간이 현재 체력까지 감소한다.

### 6.4 연속 공격

연속으로 보스에게 피해를 입힐 때 누적된 피해량을 인지할 수 있어야 한다.

### 6.5 미확정 수치

- 지연 체력 표시 대기 시간
- 잔상 감소 속도
- 정확한 색상값
- HP바 크기
- 보스 사망 시 HP바 종료 시점

### 6.6 적용하지 않는 변경

보스 HP바를 사망 연출 후가 아니라 사망 즉시 숨기도록 변경하는 과거 제안은 적용하지 않는다.

현재 보스 구현과 연출을 확인하여 유지한다.

## 7. 공격 예고 UI

### 7.1 목적

공격 예고는 플레이어가 위험 범위와 공격 발동 시점을 확인할 수 있도록 한다.

### 7.2 일반 몬스터

공격 예고 형태는 몬스터의 공격 특성에 따라 구분한다.

| 몬스터 | 예고 형태 |
|---|---|
| 돌 | 목표 위치 고정 원형 |
| 철 | 방향 고정 직선 |
| 수정 | 발사 방향 고정 직선 |
| 석탄 | 몬스터 주변 원형 |
| 자철석 | 목표 위치 고정 원형 |

예고 시간과 실제 공격 범위는 `MonsterSystem.md`를 따른다.

### 7.3 보스 공격 예고

돌골렘 공격은 위험 범위와 발동까지 남은 시간을 표시한다.

기존 메테오에서 사용한 채움형 예고 연출을 다른 패턴에도 적용하도록 요청한 기록이 있다.

실제 적용 상태는 확인이 필요하다.

### 7.4 예고와 실제 공격

예고 완료 시점과 실제 공격 발동 시점이 일치하도록 한다.

모든 공격의 실제 범위를 예고보다 일괄적으로 작게 변경하지 않는다.

석탄과 자철석의 개별 예고·실제 범위 차이는 기존 확정 명세를 유지한다.

### 7.5 전투 종료 및 취소

플레이어 사망, 방 전환 또는 공격 중단 시 남아 있는 예고 장판을 정리해야 한다.

## 8. 아이템 획득 알림 UI

### 8.1 목적

플레이어가 새로운 아이템과 재료를 획득했음을 화면에 표시한다.

### 8.2 표시 위치

기존 기획:

- 화면 우측 중앙 부근
- 세로 방향으로 나열
- 최신 획득 알림이 위쪽
- 이전 알림이 아래로 이동

### 8.3 구성 요소

- 아이템 아이콘
- 아이템 이름
- 획득 수량

### 8.4 표시 대상

몬스터 재료 획득도 알림 대상이다.

재료는 별도의 바닥 상호작용 없이 직접 획득하는 방향이다.

### 8.5 표시 연출

알림 유지 시간, 최대 표시 개수 및 사라지는 연출은 현재 구현 확인이 필요하다.

알림의 표시·삭제는 실제 보상 보유 데이터와 분리한다.

---

## 9. 인벤토리 UI

### 9.1 목적

플레이어가 보유한 아이템을 확인하고 분류·검색하며, 장비 및 스킬 정보를 관리하는 화면이다.

### 9.2 구현 현황

인벤토리는 구현 완료 보고가 있다.

기존에 화면을 너무 많이 차지하던 크기를 축소했으며, 사용자는 수정된 크기가 적절하다고 보고했다.

실제 패널 크기는 Unity 프로젝트에서 확인한다.

### 9.3 보관 대상

기존 인벤토리 기획에서 확인되는 보관 대상:

- 곡괭이
- 스킬
- 제작 재료
- 향후 장비 확장 가능 항목

### 9.4 분류 탭

기존 기본 분류:

1. 전체
2. 무기
3. 상의
4. 하의
5. 악세서리
6. 재료

분류 탭은 아이콘으로 표시한다.

선택한 분류에 해당하는 아이템만 목록에 표시한다.

스킬의 최종 분류 탭 또는 별도 화면 방식은 실제 구현을 확인한다.

### 9.5 아이템 검색

아이템 이름을 검색할 수 있다.

검색어에 맞는 아이템을 목록에 표시한다.

검색 결과와 현재 분류 탭의 관계는 기존 구현 확인이 필요하다.

### 9.6 아이템 정렬

기존에 예시로 제시한 정렬 요소:

- 희귀도
- 타입
- 마법력
- 물리 능력치

최종 정렬 목록 및 정렬 방향은 확인이 필요하다.

위 항목을 모두 실제 구현 완료된 기능으로 판단하지 않는다.

### 9.7 아이템 슬롯

기존 인벤토리 슬롯 구성:

| 위치 | 표시 정보 |
|---|---|
| 중앙 | 아이템 아이콘 |
| 테두리 | 희귀도 색상 |
| 우측 상단 | 수량 |
| 좌측 상단 | 장착 여부 |

장착 중인 아이템은 E 아이콘 등의 방식으로 표시하는 요청이 있었다.

E 표시는 스킬 입력과 혼동되지 않도록 검토한다.

### 9.8 희귀도 표시

기존 결과창에 명시된 희귀도 색상 기준은 다음과 같다.

| 희귀도 | 색상 |
|---|---|
| 일반 | 회색 |
| 고급 | 초록 |
| 희귀 | 파랑 |
| 영웅 | 보라 |
| 전설 | 금색 |

인벤토리에서도 희귀도에 따른 슬롯 테두리 표현을 사용한다.

현재 인벤토리에 적용된 정확한 색상값은 확인이 필요하다.

### 9.9 아이템 툴팁

모든 아이템은 마우스 호버 시 설명창을 표시하는 방향이다.

아이템 종류에 따라 관련 정보를 표시한다.

- 이름
- 분류
- 희귀도
- 물리·마법 타입
- 관련 능력치
- 스킬 쿨타임
- 스킬 설명
- 피해량
- 장착 안내

아이템과 무관한 항목은 표시하지 않는다.

예를 들어 제작 재료에 스킬 쿨타임을 표시하지 않는다.

### 9.10 캐릭터 정보·스탯 2탭 — 2026-10-22 승인 기획

**2026-10-22 최신 사용자 승인 기획 / 구현 완료 아님.** 기존 WORK_STATUS의 임시 성장·전투 구현 보고와 이번 신규 규칙을 구분한다. 이번 작업은 문서 수정이며 Unity 코드·에셋·저장 파일·컴파일·플레이를 변경하거나 실행하지 않았다.

기존 우측 아이템 영역·분류·검색·정렬·툴팁과 UI 레퍼런스 색상·배치·스타일을 최대한 유지한다. 좌측을 **캐릭터 정보 / 스탯** 2탭으로 구성하고 필요한 부분만 수정한다. 기존 캐릭터/무기·상의·하의·악세서리 표시 방향을 유지하되 실제 장비 콘텐츠 구현 완료로 간주하지 않는다.

두 탭의 하단에 FINAL ATTRIBUTES를 공통 고정한다.

| 표시 항목 | 표시 기준 |
|---|---|
| 물리 공격력 | 기본+물리 투자 보너스+장비 보너스에 따른 최종 공격 스탯 |
| 마법 공격력 | 기본+마법 투자 보너스+장비 보너스에 따른 최종 공격 스탯 |
| 최대 체력 | 체력 투자1P당+3 등 실제 최종 최대HP |
| 방어력 | 실제 DEF와 피해 감소율을 구분해 표시. DEF 감소 공식은 미확정 |
| 공격 간격 | 기존 최종 공격 간격 |
| 이동 속도 | 기존 최종 이동 속도 |

방어력·공격 간격·이동 속도는 투자 스탯으로 자동 추가하지 않는다. 표시 자릿수/DEF 감소율 계산/미명시 표기 세부는 구현 전 검토한다.

### 9.10.1 스탯 투자와 패시브 카드

미사용 스탯 포인트가 있으면 스탯 탭에 알림 점을 표시한다. 체력·물리·마법 카드에서 현재 투자량·각100P 상한과 20P/50P/100P 패시브 상세/해금 상태를 확인한다. 패시브는 자동 해금이며 별도 포인트 소모 버튼을 추가하지 않는다.

×1/×5/×10 선택 후 [+] 클릭 즉시 투자하고 저장한다. `실제 투자량=min(선택 배수, 보유 포인트, 100-해당 스탯 투자량)`을 적용하고 능력치·해금 표시를 즉시 갱신한다. 일반 투자를 매번 확인창 대기 방식으로 바꾸지 않는다. 저장 실패 시 포인트/표시 일치와 복구 동선은 세부 구현 검토 대상이다.

### 9.10.2 스탯 초기화와 열람 제한

메인 씬 인벤토리 스탯 탭에 초기화 버튼을 둔다. 고정 골드를 소모해 모든 투자 포인트를 반환하며 비용·반환 포인트 확인창을 제공한다. 실제 비용은 미확정으로 임의 표시하지 않는다. 개발용 전체 저장 초기화와 구분한다.

던전에서는 인벤토리와 장비·스킬·스탯·패시브 정보를 열람할 수 있지만 장비/스킬 교체·투자·초기화는 불가하다. 입장 시 성장 구성 고정, 인벤토리 시간 계속 진행 및 기존 전투 입력 차단을 유지한다. 최대HP 변경 시 현재HP 비율을 유지하는 규칙은 PlayerSystem을 따른다. 기존 물약/부활·스킬 장착/저장 동작을 임의로 바꾸지 않는다.

### 9.11 인벤토리 닫기

다음 방법으로 인벤토리를 닫는다.

- 닫기 버튼
- I 키

### 9.12 인벤토리와 시간 처리

인벤토리를 열어도 게임 시간은 흐른다.

인벤토리 열기만으로 일반적인 퍼즈를 적용하지 않는다.

## 10. 던전 입장창

### 10.1 진입 방법

광산 입구가 존재하는 메인 씬에서 이용한다.

플레이어는 광산 입구에 접근하여 T 키로 상호작용한다.

### 10.2 기존 임시 방식 폐기

과거에는 인벤토리에서 게임 시작 버튼을 눌러 던전에 입장하는 임시 흐름이 있었다.

최신 기획에서는 광산 입구 상호작용을 통한 던전 선택창으로 대체되었다.

기존 임시 UI의 실제 삭제 여부는 프로젝트에서 확인한다.

### 10.3 레이아웃

| 위치 | 구성 |
|---|---|
| 상단 | 던전 입장 타이틀 |
| 좌측 | 층 선택 목록 |
| 우측 상단 | 선택한 층 이름 및 난이도 |
| 중앙 | 대표 맵 이미지 및 필요 레벨 |
| 난이도 영역 | 4개 난이도 |
| 보상 영역 | 획득 가능한 클리어 보상 |
| 하단 | 입장 버튼 |
| 별도 조작 | 닫기 버튼 |

### 10.4 층 선택

선택한 층은 강조 상태를 유지한다.

다른 층을 선택하면 관련 정보를 갱신한다.

### 10.5 난이도 선택

난이도는 총 4개이다.

선택한 난이도도 강조 상태를 유지한다.

난이도 변경 시 다음 정보를 갱신한다.

- 난이도 표시
- 입장 레벨
- 관련 이미지 또는 표시 정보
- 보상 정보

난이도별 정확한 이름과 수치는 현재 데이터 확인이 필요하다.

### 10.6 클리어 보상 미리보기

보상 미리보기의 구성 요소:

- 아이콘 또는 이미지
- 획득 확률
- 희귀도 테두리

보상은 좌측에서 우측으로 나열하는 방향이다.

낮은 확률의 아이템을 어느 방향에 배치할지는 최종 구현 확인이 필요하다.

일반·엘리트 몬스터 처치 보상을 향후 별도의 도감에서 확인하는 구상이 있으나, 현재 도감은 구현 완료로 확인되지 않았다.

### 10.7 입장 가능 조건

선택한 던전의 필요 레벨을 충족하면 입장할 수 있다.

이전 던전 클리어 여부는 입장 조건으로 사용하지 않는다.

### 10.8 레벨 부족 안내

필요 레벨을 충족하지 못하면 입장 불가 상태를 회색 등의 방식으로 표현한다.

입장을 시도하면 레벨이 부족하다는 플로팅 안내 메시지를 표시한다.

시각적으로 입장 불가 상태를 표현하는 것과 실제 입력 이벤트를 구분한다.

### 10.9 닫기

닫기 버튼 또는 ESC로 창을 닫을 수 있다.

던전 선택창에서 I를 누르면 창을 닫고 인벤토리를 연다.

인벤토리를 닫아도 던전 선택창을 다시 열지 않는다.

### 10.10 시간 처리

던전 선택창이 열려 있어도 게임 시간은 흐른다.

## 11. 던전 결과창

### 11.1 목적

던전 결과창은 해당 런의 클리어 또는 실패 결과와 획득한 보상, 전투 기록을 확인하는 화면이다.

기존 결과창 구현 완료 보고가 존재한다.

### 11.2 결과 유형

**클리어**

보스를 처치하면 발생한다.

**실패**

부활 2회를 모두 사용한 뒤 최종 사망하면 발생한다.

### 11.3 보상 지급과 UI 분리

**확정 규칙**

클리어 보상은 결과창 최초 표시 과정에서 지급하고 저장한다.

결과창을 닫거나 다시 열어도 보상을 다시 지급하지 않는다.

결과창은 이미 획득한 보상을 보여주는 UI이다.

### 11.4 클리어와 실패의 조작 차이

| 상태 | 플레이어 이동 |
|---|---|
| 클리어 | 가능 |
| 실패 | 불가능 |

클리어 결과창이 열린 상태에서도 플레이어는 이동할 수 있다.

창을 닫고 주변을 돌아볼 수 있다.

실패 결과창은 닫더라도 사망 상태가 유지되며 이동할 수 없다.

이동 외 공격·스킬 사용 가능 범위는 현재 구현 확인이 필요하다.

### 11.5 공통 레이아웃

클리어와 실패는 같은 2패널 구조를 사용한다.

- 화면 전체 반투명 암전
- 상단 중앙 결과 타이틀
- 좌측 획득 보상 패널
- 우측 전투 기록 및 이동 버튼 패널

### 11.6 암전

기존 결과창 명세의 암전 색상:

`rgba(8, 10, 15, 0.80)`

### 11.7 결과 타이틀 배치

상단 타이틀에는 별도의 배경 패널을 두지 않는다.

텍스트와 좌우 장식선을 표시한다.

### 11.8 싱글플레이 구성

현재 게임은 싱글플레이를 기준으로 한다.

다음 요소를 결과창에 추가하지 않는다.

- 파티원 표시
- MVP
- 매치메이킹 UI

## 12. 결과창 등장 연출

기존 인수인계에 명시된 결과창 등장 연출은 다음과 같다.

### 12.1 1단계 — 0.0~0.4초

- 남은 적 공격 및 예고 정리
- 암전 페이드인
- 결과 상태 확정
- 보상 지급 및 저장 처리

이는 기존 결과 연출 명세의 단계이며, 실제 내부 이벤트 순서를 이 표만으로 확정하지 않는다.

### 12.2 2단계 — 0.4~1.0초

- 결과 타이틀이 화면 중앙에 등장
- 타이틀이 상단으로 이동
- 획득 보상창이 화면 중앙에 단독 등장

### 12.3 3단계 — 1.0~1.6초

- 아이템 슬롯 순차 등장
- 골드 카운트업
- 경험치 카운트업

### 12.4 4단계 — 1.6~2.1초

- 보상창이 화면 왼쪽으로 이동
- 오른쪽 전투 기록창 공개

### 12.5 카운트업 주의사항

카운트업은 표시 연출이다.

숫자 연출에 따라 실제 돈이나 경험치를 다시 지급하지 않는다.

- 부활 체력 복원을 회복량에 포함하는지
- 퍼즈 시간을 진행 시간에 포함하는지
- 로딩 시간을 진행 시간에 포함하는지

결과창 UI에서 임의로 별도 계산 규칙을 만들지 않는다.

전투 기록은 관련 전투·던전 시스템에서 관리하는 데이터를 표시한다.

## 17. 결과창 닫기·재열기·이동

### 17.1 결과창 닫기

결과창을 닫을 수 있다.

결과창을 닫았다는 이유로 새 던전 런이 시작되지 않는다.

### 17.2 결과창 다시 열기

닫힌 상태에서 화면 우측 하단에 결과창 다시 열기 버튼을 표시한다.

버튼을 선택하면 같은 런의 결과를 다시 표시한다.

보상은 다시 지급하지 않는다.

### 17.3 다시 시작

결과창의 다시 시작 버튼은 같은 층과 난이도로 새 런을 시작한다.

기존 초기화 규칙:

- 첫 번째 방부터 시작
- 체력 초기화
- 물약 3개
- 부활 가능 횟수 2회
- 영구 성장 및 획득 보상 유지

### 17.4 로비로 이동

현재 던전 진행을 종료하고 메인 로비로 이동한다.

획득하고 저장한 보상은 유지한다.

### 17.5 결과창 데이터 유지

결과창을 닫거나 다시 열어도 같은 런의 보상과 전투 기록을 유지한다.

장착 표시와 스킬 입력 표시가 혼동되지 않아야 한다.

**UI ↔ 몬스터**

HP바와 공격 예고가 현재 체력과 공격 판정을 올바르게 표시해야 한다.

## 24. 문서 관리

본 문서는 UI 구성, HUD 표시, 화면 전환, 입력과 시간 처리, 결과창 시각 명세를 관리한다.

게임의 실제 보상 지급, 캐릭터 성장, 몬스터 공격, 장비 및 저장 데이터의 원천 규칙은 각 관련 Systems 문서에서 관리한다.

UI 변경 시 다음을 검토한다.

1. 기존 UI 규칙과의 충돌
2. 게임 시간 처리 영향
3. 입력키 및 UI 전환 충돌
4. 보상 지급과 저장 처리 영향
5. 플레이어 조작 허용 상태 영향
6. 관련 Systems 문서 수정 필요 여부
7. 사용자 최종 승인 여부
8. CHANGELOG 기록 필요 여부

사용자 승인 없이 기존 확정 UI 규칙을 변경하거나 미확정 기능을 추가하지 않는다.
