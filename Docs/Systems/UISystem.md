## 1. 시스템 개요

### 1.1 목적

UI 시스템은 플레이어가 게임의 상태와 진행 정보를 확인하고, 던전 입장, 인벤토리 관리, 장비·스킬 확인, 전투 결과 확인 등의 기능을 이용할 수 있도록 한다.

기존 UI의 표시 방식과 입력 규칙을 유지하면서 각 게임 시스템에서 관리하는 데이터를 정확하게 표현하는 것을 목표로 한다.

### 1.2 UI 구성

| UI | 주요 역할 |
|---|---|
| 플레이어 HUD | 체력, 생명, 물약, 성장 상태 등 표시 |
| 일반 몬스터 HP바 | 몬스터 체력 표시 |
| 보스 HP바 | 보스 체력 및 지연 피해 표시 |
| 공격 예고 | 위험 범위 및 공격 발동 시점 안내 |
| 획득 알림 | 아이템·재료 획득 정보 |
| 인벤토리 | 아이템 분류, 검색, 정렬, 장착 정보 |
| 던전 입장창 | 층·난이도 선택, 입장 조건 및 보상 확인 |
| 던전 결과창 | 획득 보상, 전투 기록, 재시작 및 로비 복귀 |
| 퍼즈 메뉴 | 일반적인 일시정지와 메뉴 기능 |
| 곡괭이 제작창 | 제작할 곡괭이 및 필요 자원 확인 |

곡괭이 제작창은 기획 단계이며, 현재 모든 UI가 구현 완료되었다는 의미는 아니다.

## 2. UI 공통 규칙

### 2.1 기준 해상도

UI의 기준 해상도는 **1920 × 1080**이다.

실제 UI의 크기, 배치 및 스케일 설정은 기존 Unity 프로젝트 값을 확인한다.

### 2.2 UI 디자인 방향

UI는 정보를 쉽게 구분할 수 있도록 구성하며, 현재 개발된 UI와 시각적 일관성을 유지한다.

기존 Figma 레퍼런스는 주로 다음 요소를 참고하는 용도이다.

- 버튼 위치
- 정보 배치
- 패널 크기
- 선택 상태
- 화면 구성

레퍼런스의 모든 색상과 문구를 그대로 복제하지 않는다.

### 2.3 UI 크기

인벤토리와 던전 선택창은 기존에 화면을 지나치게 많이 차지하여 크기를 줄인 이력이 있다.

사용자는 수정된 크기가 적절하다고 보고했다.

따라서 새로운 UI 작업에서 기존 패널의 크기를 임의로 확대하거나 초기 레퍼런스 크기로 되돌리지 않는다.

### 2.4 UI 표시 데이터

UI는 관련 시스템의 실제 상태를 표시해야 한다.

예시:

- 체력 HUD: 플레이어 체력
- 생명 HUD: 남은 생명
- 인벤토리: 보유 아이템
- 던전 선택창: 입장 조건 및 보상
- 결과창: 해당 런에서 획득한 보상과 전투 기록

UI를 다시 표시한다는 이유로 보상을 지급하거나 영구 데이터를 변경하지 않는다.

### 2.5 OREPLUME 메인 타이틀 — 기본 방향 승인/Unity완료 미확인

표시명OREPLUME(오어플룸),개발 프로젝트명광산던전을 구분한다. 게임 시작 시 별도 타이틀을 표시하며 탑뷰 플레이와 다른 일러스트형 광산 입구·탐험 분위기/광부슬라임·곡괭이를 유지한다.1920×1080 기준 왼쪽상단로고·왼쪽중단게임시작/설정/게임종료·오른쪽광산입구/슬라임,레일/광차·암벽/목재·랜턴2개의 어둡고 따뜻한 화면을 기본 구성으로 한다.

게임 시작은 기존 영구데이터를 보존해 기존 로비로 진입하고 최초실행만 기존 정상 초기화 경로를 쓴다. 새게임/이어하기 선택창은 임의 추가하지 않는다. 설정은 기존UI재사용 우선,게임종료도 기존 종료/확인UI재사용 우선이며 없으면 현재구현/추가결정필요사항을 보고한다. 새 종료확인 정책을 확정하지 않는다. 실제 시작씬/초기화·연결방식은 Codex확인 대상이다.

아트제작/시안선택과Unity완료를 분리한다. 현재Title 관련씬/스크립트·아트파일이 있고 미커밋 작업이 진행 중이지만 완료/Play 보고는 확보하지 못했다. 파일존재/수정상태를 타이틀연결완료로 추정하지 않는다. 상세 아트는 [ArtDirection](ArtDirection.md) §8.8,데이터보존은 [SaveSystem](SaveSystem.md) §12.6이다. 로컬폴더/저장경로/클래스·저장소명은 바꾸지 않는다.

## 3. UI 입력 및 시간 처리

### 3.1 확인된 입력

| 입력 | 기능 |
|---|---|
| T | 월드 상호작용 |
| I | 인벤토리 열기 및 닫기 |
| ESC | 열린 UI 닫기 또는 퍼즈 메뉴 |

공격, 회피, 물약 및 스킬의 최종 입력 배치는 Unity 프로젝트 확인이 필요하다.

### 3.2 게임 시간 처리

**확정 규칙**

- 인벤토리를 열어도 게임 시간이 멈추지 않는다.
- 던전 선택창을 열어도 게임 시간이 멈추지 않는다.
- 일반적인 일시정지는 ESC 퍼즈 메뉴에서 처리한다.

UI를 열 때마다 공통적으로 게임의 `timeScale`을 0으로 변경하는 구조를 적용하지 않는다.

### 3.3 ESC 입력

ESC는 열린 UI를 닫거나 퍼즈 메뉴를 이용하는 입력으로 사용한다.

다음 동작의 정확한 입력 우선순위는 기존 구현을 확인한다.

- 여러 UI가 열린 경우
- 결과창이 열린 경우
- 퍼즈 메뉴가 열린 경우
- UI 전환 도중 ESC를 누르는 경우

확정되지 않은 UI 입력 우선순위를 새로 지정하지 않는다. UI-06의 장착 대기 정리는 기존 ESC 닫기/퍼즈 우선순위를 유지하며 실제 인벤토리가 I/ESC로 닫힐 때 함께 수행한다(§9.13).

### 3.4 인벤토리와 던전 선택창 전환

던전 선택창이 열린 상태에서 I를 누르면 다음 순서로 동작한다.

1. 던전 선택창을 닫는다.
2. 인벤토리를 연다.
3. 이후 인벤토리를 닫더라도 던전 선택창을 다시 열지 않는다.
4. 일반 게임 화면으로 돌아간다.

인벤토리를 닫았다는 이유로 이전 던전 선택창을 자동으로 다시 표시하지 않는다.

### 3.5 UI 중복 및 재열림

확정된 UI 전환 규칙을 유지한다.

다른 UI에도 불필요한 자동 재열림을 추가하지 않는다.

여러 UI의 동시 표시 허용 범위는 실제 구현 확인이 필요하다.

### 3.6 Tab 실시간 현재 방 지도 — 2026-10-27 사용자 최종 승인

**기존 승인 유지 / 2026-10-28 구현·아트/배경수정 핵심Play 보고 존재.** 최신 범위는 §3.8을 따르며 모든흐름 회귀 완료를 뜻하지 않는다. Tab 홀드 중 현재 방 지도를 표시하고 해제하면 즉시 숨긴다. 1920×1080 기준 화면 중앙560×400·배경 불투명도80%이며 방 종횡비를 유지한다. 전체 던전 연결도/다음 방 미리보기는 범위 밖이다. 실제 지형·플레이어/생존 몬스터·출구 상태 및 좌표 변환은 [MapSystem](MapSystem.md) §16.6을 따른다.

비정지 오버레이로 배경/이미지/아이콘은 마우스 Raycast를 가로채지 않는다. 정상 상태에서는 이동·360도 조준/3단 콤보·클릭/홀드/예약·E/R·회피·Q·몬스터/보스 전투·쿨타임이 계속된다. 표시/숨김만으로 현재 공격 취소·콤보/스킬/패시브/물약 초기화를 만들지 않는다. 기존 조작 제한을 우회하지 않으며 인벤토리 전투 입력 차단/비정지·UI-01~08·ESC 퍼즈/닫기 우선순위를 유지한다.

| 상태 | 지도 규칙 |
|---|---|
| 인벤토리·ESC 퍼즈·던전 입장/선택·클리어/실패 결과창·기타 조작/표시를 제한하는 주요UI | 표시 금지, 열리면 즉시 숨김 |
| 방 이동 시작 | 즉시 숨김, 이전 방 표시 정리 |
| 사망·부활 처리 | 즉시 숨김/표시 금지 |
| 보스 최초 등장·변신 | 연출 시작 즉시 숨김, 종료/스킵까지 표시 금지 |
| 클리어 결과창 닫힘 + 기존 이동 허용 | 현재 보스 방 지도 허용, 공격/스킬/물약 허용 범위 확대 없음 |
| 실패 확정 | 결과창을 닫아도 사망 상태이므로 표시 금지 |

**추가 최종 승인4개:** ①다른 주요UI 종료 ②방 이동·사망/부활 완료 ③보스 연출 종료/스킵 후에도 기존 Tab 홀드로 자동 복귀하지 않는다. 정상 상태로 돌아온 뒤 Tab을 완전히 놓고 새로 눌러야 한다. 차단 중 입력으로 재표시 제한을 우회하지 않는다. ④클리어 결과창을 닫고 기존 이동이 허용되면 새 Tab 입력으로 지도를 허용한다. 결과창 재열기 시 즉시 숨기며 보상 재지급·재시작·새 런은 발생시키지 않는다.

기존 HUD/패널 배치·월드 카메라 위치/크기/추적/흔들림을 변경하지 않는다. 28일기본지도10맵/보스룸 검사와Map01/Map10/보스룸아트·입력/재입력·동적위치의 핵심Play 보고가 있다(§3.8). 공격예고/밀집가독성·전체흐름·다해상도/장시간 성능은 여전히 미검증이다. 색상·아이콘·글꼴·범례·갱신 주기 수치는 미확정이다.

## 4. 플레이어 HUD

### 4.1 목적

플레이어 HUD는 전투 중 확인해야 하는 플레이어 상태를 표시한다.

### 4.2 체력

플레이어의 현재 체력과 최대 체력 관련 정보를 표시하는 영역이다.

현재HP/최대HP·HP바는 §4.7의 승인된 좌상단 상태 HUD에 표시한다. 기존 색상/스타일을 존중하고 승인되지 않은 세부 색상을 임의 확정하지 않는다.

### 4.3 생명 HUD

**확정 규칙**

- 최초 생명을 포함한 총 3개의 생명
- 부활 가능 횟수는 2회
- 부적 또는 유사한 아이콘 3개 사용
- 소모된 아이콘은 어둡게 표시

| 상황 | 활성 생명 아이콘 |
|---|---:|
| 던전 시작 | 3개 |
| 첫 번째 사망 후 | 2개 |
| 두 번째 사망 후 | 1개 |
| 세 번째 사망 후 | 0개 |

세 번째 사망 시 던전 실패가 발생한다.

### 4.4 물약 표시

물약은 플레이어의 회복 수단이다.

다시 시작하면 물약 3개로 초기화한다.

Q 물약은 §4.7~4.8의 좌하단72×72 아이콘형 슬롯을 사용한다. 독립적인 물약 쿨타임은 없으며 기존 회복·수량·사용 조건은 유지한다.

과거 제안 중 물약 HUD를 화면 중앙 하단으로 변경하는 안은 사용자가 적용하지 않도록 요청했다.

따라서 해당 배치를 자동 반영하지 않는다.

### 4.5 레벨 및 경험치

기존 레벨·경험치 HUD는 구현 완료 보고가 있다.

플레이어의 레벨 및 경험치 상태를 표시한다.

레벨·EXP바는 §4.7의300×142 좌상단 상태 HUD에 유지한다. 실제 데이터 갱신은 기존 성장 경로를 사용한다.

### 4.6 스킬 표시

스킬 4종의 구현 완료 보고가 존재한다.

E/R 스킬은 §4.7~4.8의 우하단72×72 슬롯2개로 표시한다. 실제 장착 스킬에 맞는 기존 임시I·II·III·IV 표식을 갱신하며 정식 아이콘PNG는 별도 아트 작업이다. 기존 시전·장착·쿨타임 수치를 변경하지 않는다.

### 4.7 전투 HUD 모서리 배치 — 2026-10-28 최종 승인

1920×1080 기준 **승인 디자인값**이다. 기존 HUD 오브젝트를 가능한 재사용하며 다른 화면비의 확대/축소·안전영역·정확한 표시 검증 완료를 뜻하지 않는다.

| HUD | 위치 | 크기 | Anchor |
|---|---|---|---|
| 플레이어 상태 | 좌상단 | 300×142 | (0,1) |
| Q 물약 | 좌하단 | 72×72 | (0,0) |
| E 스킬 | 우하단 | 72×72 | (1,0) |
| R 스킬 | 우하단 | 72×72 | (1,0) |

화면 모서리 여백24px, E/R 사이8px이다. 하단 중앙에는Q/E/R을 두지 않는다. 상태 HUD의 레벨·현재/최대HP·HP바·EXP바·생명 아이콘3개와 소모 상태·부활2회는 유지한다. **전투 HUD의 골드 표시와 `남은 생명` 설명 텍스트만 제거**한다. 골드 획득/저장·인벤토리 확인·제작/초기화 비용·결과창 골드는 유지한다.

HUD는 마우스 Raycast를 가로채지 않으며 기존 조준/콤보·이동/회피·E/R·Q·사망/부활·방 전환·행동 제한·보상/저장을 변경하지 않는다. 중앙Tab 지도 영역을 침범하지 않고 비정지·우선순위·재입력 규칙을 보존한다. 보스 HP바는 상단 중앙과 기존 피해 표시를 유지하고 좌상단 상태 HUD와 겹치지 않아야 한다.

우하단 E/R과 기존 결과 다시 보기 버튼의 동시 표시/충돌 조건은 §17.2를 따른다. 충돌 시 숨김/이동을 임의 확정하지 않는다.

### 4.8 Q/E/R 아이콘형 표시와 쿨타임 — 최종 승인

넓은 이름/텍스트 패널 대신72×72 슬롯 중앙에 물약/스킬 아이콘, 좌상단에 단축키Q/E/R, Q 우하단에 남은 물약 수량을 표시한다. 물약·스킬 이름은 전투 HUD에서 표시하지 않는다. 단축키/물약 수량은 오버레이에 가려지지 않아야 한다.

E/R은 사용 직후 아이콘 전체를 어둡게 하고 시간 경과에 따라 어두운 영역의 아래쪽 경계가 위에서 아래로 내려가 아이콘이 위쪽부터 드러난다. 쿨타임 종료 시 오버레이를 제거한다. 중앙 숫자는 실제 남은 시간을 기준으로 다음처럼 표시하며 밝은 글자+어두운 외곽선/그림자로 읽기 쉽게 한다.

| 실제 남은 시간 r | 표시 규칙 |
|---|---|
| r≥10초 | 올림한 정수 |
| 0<r<10초 | ceil(r×10)/10, 소수점1자리 |
| r≤0초 / 사용 가능 | 숫자 숨김 |

표시는 시간을 변경하지 않는다. 종료 전 조기0.0이 나오지 않도록 한다. 실제9.999초가 올림으로10.0으로 보일 수 있는 경계도 실제 남은 시간 구간을 기준으로 처리한다.

**Q 예외:** 독립적인 재사용 쿨타임이 없으므로 새 타이머/오버레이를 만들지 않는다. 기존 사용동작·회복/수량·체력패시브 회복증가를 유지하고0개도 `0`으로 표시하며 빈 물약 사용을 거부한다. 사용 중/행동 금지를 독립 쿨타임으로 표시하지 않는다.

**스킬 아트 예외:** 현재4종 정식 아이콘PNG는 별도 작업이며 기존I·II·III·IV 표식을 유지한다. 장착 스킬이 바뀌면 해당 표식을 갱신하고 임의 PNG/새 스킬 아이콘을 지정하지 않는다. 기존 E/R 장착·시전·쿨타임·저장을 유지한다. 디자인 승인과 아래 기존 시범 구현 보고/최종 아트 품질을 구분한다.

## 5. 일반 몬스터 HP바

### 5.1 표시 위치

일반 몬스터 HP바는 몬스터 캐릭터 아래쪽에 배치하는 방향이다.

몬스터가 이동하면 HP바도 함께 이동한다.

### 5.2 체력 표시

몬스터의 현재 체력 상태를 반영한다.

기존 피격 및 사망 처리와 연동한다.

### 5.3 엘리트 몬스터

기존 HP바 기획에는 일반 몬스터와 엘리트 몬스터가 함께 언급되었다.

다만 엘리트 몬스터의 실제 존재 여부, 별도 HP바 형태 및 차별화 규칙은 확인이 필요하다.

### 5.4 구현 확인 사항

- HP바의 최종 크기
- 표시 및 숨김 조건
- 체력 감소 애니메이션
- 몬스터 사망 시 표시 종료
- 몬스터와 HP바 위치 정렬
- 현재 구현 여부

## 6. 보스 HP바

### 6.1 표시 위치

보스 HP바는 **플레이어 HUD 상단 중앙**에 배치한다.

### 6.2 체력 감소

플레이어가 보스에게 피해를 입히면 현재 체력 표시가 즉시 감소한다.

### 6.3 지연 피해 표시

기존 확정된 표현 방식은 다음과 같다.

1. 보스가 피해를 받는다.
2. 현재 체력 표시가 즉시 감소한다.
3. 감소 전 체력 구간은 밝은 주황색 계열로 남는다.
4. 일정 시간 공격받지 않으면 주황색 구간이 현재 체력까지 감소한다.

### 6.4 연속 공격

연속으로 보스에게 피해를 입힐 때 누적된 피해량을 인지할 수 있어야 한다.

### 6.5 미확정 수치

- 지연 체력 표시 대기 시간
- 잔상 감소 속도
- 정확한 색상값
- HP바 크기
- 보스 사망 시 HP바 종료 시점

### 6.6 적용하지 않는 변경

보스 HP바를 사망 연출 후가 아니라 사망 즉시 숨기도록 변경하는 과거 제안은 적용하지 않는다.

현재 보스 구현과 연출을 확인하여 유지한다.

### 7.2 일반 몬스터

### 7.4 예고와 실제 공격

석탄과 자철석의 개별 예고·실제 범위 차이는 기존 확정 명세를 유지한다.

### 7.5 전투 종료 및 취소

플레이어 사망, 방 전환 또는 공격 중단 시 남아 있는 예고 장판을 정리해야 한다.

## 9. 인벤토리 UI

### 9.1 목적

플레이어가 보유한 아이템을 확인하고 분류·검색하며, 장비 및 스킬 정보를 관리하는 화면이다.

### 9.2 구현 현황

인벤토리는 구현 완료 보고가 있다.

기존에 화면을 너무 많이 차지하던 크기를 축소했으며, 사용자는 수정된 크기가 적절하다고 보고했다.

실제 패널 크기는 Unity 프로젝트에서 확인한다.

### 9.3 보관 대상

기존 인벤토리 기획에서 확인되는 보관 대상:

- 곡괭이
- 스킬
- 제작 재료
- 향후 장비 확장 가능 항목

### 9.4 분류 탭

기존 기본 분류:

1. 전체
2. 무기
3. 상의
4. 하의
5. 악세서리
6. 재료

분류 탭은 아이콘으로 표시한다. UI-08에서는 현재 임시 문자 아이콘과 탭 크기·위치·정렬을 유지하고, 확장형 Hover 설명을 작은 독립 분류명 툴팁으로 대체한다. 정식 아이콘 제작/교체는 이번 범위가 아니다. 상세는 §9.14를 따른다.

선택한 분류에 해당하는 아이템만 목록에 표시한다.

스킬의 최종 분류 탭 또는 별도 화면 방식은 실제 구현을 확인한다.

### 9.5 아이템 검색

아이템 이름을 검색할 수 있다.

검색어에 맞는 아이템을 목록에 표시한다. 우측 상단의 검색 결과 개수 텍스트는 UI-07에 따라 제거하되 실제 검색 결과 목록은 유지한다. `전체 보유 N개`는 검색·분류·정렬과 독립적인 전체 보유 종류 수다(§9.14).

검색 결과와 현재 분류 탭의 관계는 기존 구현 확인이 필요하다.

### 9.6 아이템 정렬

기존에 예시로 제시한 정렬 요소:

- 희귀도
- 타입
- 마법력
- 물리 능력치

최종 정렬 목록 및 정렬 방향은 확인이 필요하다.

위 항목을 모두 실제 구현 완료된 기능으로 판단하지 않는다.

### 9.7 아이템 슬롯

기존 인벤토리 슬롯 구성:

| 위치 | 표시 정보 |
|---|---|
| 중앙 | 아이템 아이콘 |
| 테두리 | 희귀도 색상 |
| 우측 상단 | 수량 |
| 좌측 상단 | 장착 여부 |

장착 중인 아이템은 E 아이콘 등의 방식으로 표시하는 요청이 있었다.

E 표시는 스킬 입력과 혼동되지 않도록 검토한다. 지속 선택이 필요 없는 일반 아이템은 Hover 종료 시 청록 강조를 해제하되 희귀도/실제 장착 표시는 유지한다. 내부 선택 데이터와 시각 테두리는 구분하며 상세 정보 등 의존 기능은 구현 전에 확인한다(UI-04, §9.13).

### 9.8 희귀도 표시

기존 결과창에 명시된 희귀도 색상 기준은 다음과 같다.

| 희귀도 | 색상 |
|---|---|
| 일반 | 회색 |
| 고급 | 초록 |
| 희귀 | 파랑 |
| 영웅 | 보라 |
| 전설 | 금색 |

인벤토리에서도 희귀도에 따른 슬롯 테두리 표현을 사용한다.

현재 인벤토리에 적용된 정확한 색상값은 확인이 필요하다.

### 9.9 아이템 툴팁

모든 아이템은 마우스 호버 시 설명창을 표시하는 방향이다.

아이템 종류에 따라 관련 정보를 표시한다.

- 이름
- 분류
- 희귀도
- 물리·마법 타입
- 관련 능력치
- 스킬 쿨타임
- 스킬 설명
- 피해량
- 장착 안내

아이템과 무관한 항목은 표시하지 않는다.

### 9.10.1 스탯 투자와 패시브 카드

미사용 스탯 포인트가 있으면 스탯 탭에 알림 점을 표시한다. 체력·물리·마법 카드에서 현재 투자량·각100P 상한과 20P/50P/100P 패시브 상세/해금 상태를 확인한다. 패시브는 자동 해금이며 별도 포인트 소모 버튼을 추가하지 않는다. 3카드는 아코디언으로 한 번에 하나만 펼치며 펼친 카드에 투자 보너스와20P/50P/100P 상세를 표시한다. 9패시브 모두 잠긴 조건·효과를 포함하는 Hover 상세 툴팁을 제공한다. 현재 툴팁 위치를 유지하며 우측 아이템 목록을 일부 가리는 것은 허용한다.

×1/×5/×10 선택 후 [+] 클릭 즉시 투자하고 저장한다. `실제 투자량=min(선택 배수, 보유 포인트, 100-해당 스탯 투자량)`을 적용하고 능력치·해금 표시를 즉시 갱신한다. 일반 투자를 매번 확인창 대기 방식으로 바꾸지 않는다. 쓰기 성공 후 투자량/능력치를 반영하고 실패 시 포인트·HP·기존 파일을 유지하며 오류/재시도 안내를 제공한다는 구현 보고가 있다.

성장·스탯 UI의 상시 상태/정상 성공 메시지는 UI-01에 따라 표시하지 않는다. 수치 갱신으로 성공을 전달하며 실제 투자·저장·이벤트 통지와 부족/실패/제한 안내는 유지한다(§9.13).

### 9.10.2 스탯 초기화와 열람 제한

메인 로비에서 **스탯 초기화 · 500G** 버튼을 사용한다. 500G는 레벨/투자량과 무관한 초기 밸런스 테스트값이다. 투자0P·골드 부족·던전에서는 실행할 수 없다. 세 투자 전부를 기존 미사용P에 반환하고 투자0/패시브 잠김·능력치·골드·알림 점을 갱신한다. 레벨·EXP·다른 영구 정보는 보존하며 개발용 전체 저장 초기화와 구분한다.

1. 첫 클릭: 같은 스탯 탭 영역을 비용500G·반환P 확인 문구와 **취소 / 초기화 확인** 버튼으로 전환한다. 골드와 포인트는 아직 변경하지 않는다. 별도 팝업을 띄우지 않는다.
2. 최종 확인: 보유 골드·투자량·로비 등 최신 실행 조건을 다시 검사하고 저장을 요청한다. 성공한 경우에만 골드 차감과 반환을 함께 반영한다. 쓰기 실패는 원래 데이터와 확인 상태를 유지하며 오류·재시도/취소를 제공한다. 중복 시작/확인으로 재과금하지 않는다.

취소·탭 전환·인벤토리 닫기는 확인 상태를 해제한다. 현재 구현은 확인 중 투자를 막고 영구 데이터가 달라졌으면 먼저 확인 내용을 갱신한다. 공격·물약·회피·예약/잔류 스킬 중에는 거부한다. 세부 저장 경계는 [SaveSystem](SaveSystem.md) §6.6을 따른다.

던전에서는 인벤토리와 장비·스킬·스탯·패시브 정보를 열람할 수 있지만 장비/스킬 교체·투자·초기화는 불가하다. 입장 시 성장 구성 고정, 인벤토리 시간 계속 진행 및 기존 전투 입력 차단을 유지한다. 최대HP 변경 시 현재HP 비율을 유지하는 규칙은 PlayerSystem을 따른다. 기존 물약/부활·스킬 장착/저장 동작을 임의로 바꾸지 않는다.

### 9.10.3 버튼 상태와 Hover 피드백

Default / Hover / Pressed / Selected / Disabled를 구분한다. 초기화 기본 버튼은 중립 테두리이며 Hover에서 강조하고 확인 단계에서 금색으로 구분한다. 골드 부족 시 실제 부족액을 안내한다(380G 보유 시 “골드가 120G 부족합니다.”).

### 9.14 인벤토리 UI-07~UI-08 — 사용자 최종 승인, 2026-10-25 반영

**상태:** UI-07~08 및 충돌 방지 조건3개 사용자 최종 승인 완료. 신규 개선안의 Unity 구현은 미확인/별도 작업 대상이며 관련 회귀 검증은 미진행이다. 과거 검색·분류·정렬·장착 기능의 구현 보고와 구분한다. 이번은 문서 갱신이며 Unity 파일 수정이나 Play 테스트 요청/실행을 하지 않는다.

#### UI-07. 전체 보유 아이템 종류 수만 표시

우측 상단의 `검색 결과 9개 / 전체 보유 9개`를 `전체 보유 9개`로 간소화한다. 검색 결과 개수 텍스트만 제거하고 **`전체 보유 N개`**를 유지한다.

N은 실제 인벤토리 전체에 존재하는 서로 다른 아이템 종류 수다. 검색어·분류 탭·정렬을 바꿔도 N은 변하지 않으며 실제 보유 종류가 추가/제거될 때 갱신한다. 동일 종류의 개별 보유 수량은 기존대로 표시한다. 철광석30개와 돌12개면 `전체 보유 2개`, 검색에 철광석만 나와도 `전체 보유 2개`다. 기존 검색·필터·정렬·아이템 목록 기능은 바꾸지 않는다.

**충돌 방지①:** 현재 표시된 결과가 아닌 **기존 인벤토리 전체 데이터**를 집계한다. 동일 종류 판별과 보유 집계는 기존 구현 규칙을 재사용하며 새 아이템ID 체계·저장 필드를 만들지 않는다. 수량 합계/필터 결과 수와 종류 수를 혼동하지 않는다.

#### UI-08. 분류 탭의 독립 Hover 툴팁

Hover 시 탭 옆으로 늘어나는 기존 분류 설명을 제거하고 작은 독립 툴팁으로 해당 분류 이름을 표시한다. Hover 종료 시 숨긴다. 기존 탭 크기·위치·정렬, 선택 강조와 Hover 피드백, 전체/무기/상의/하의/악세서리/재료 등의 필터 기능과 임시 문자 아이콘을 유지한다. 정식 분류 아이콘 제작/교체는 포함하지 않는다. 툴팁 추가로 탭 선택이나 필터링을 바꾸지 않는다.

**충돌 방지② — UI-06:** 단순 Hover/툴팁 표시를 다른 UI 탭 전환으로 처리하지 않으며 임시 장착 대기를 취소하지 않는다. 실제 다른 분류로 전환하면 기존 UI-06에 따라 임시 선택 강조·E/R 펄스·장착 대기 참조를 정리한다. **실제 E/R 장착 스킬은 유지하고 장착 저장/해제 요청은 발생시키지 않는다.** 상세 연동은 [EquipmentSkillSystem](EquipmentSkillSystem.md) §4.4.2를 따른다.

**충돌 방지③ — 배치·입력 보호:** 툴팁이 나타나도 탭 크기/위치는 변하지 않는다. 다른 주요UI를 불필요하게 가리지 않고 인벤토리 패널과 화면 경계를 벗어나 잘리지 않게 배치한다. 마우스 입력을 가로채 탭 Hover/클릭을 방해하지 않는다. 표시/숨김으로 검색 결과나 분류 상태를 바꾸지 않으며 선택 강조/Hover 피드백을 유지한다. 정확한 위치·여백·표시 지연은 기존 UI 구조를 확인해 결정하고 새 최종 디자인 수치를 임의 확정하지 않는다.

#### 기존 기능 보존 및 구현 전 확인

UI-01~06 전체 규칙, 기준1920×1080/패널1440×810, 좌측 정보/스탯2탭·우측 배치·아이템 상세/툴팁·희귀도/실제 장착/개별 수량·Hover/Pressed/Selected, 스킬 선택/E·R 장착, 스탯 투자/초기화/저장·비정지·전투 입력 차단·기존 저장 스키마를 유지한다. 아이템 데이터·장착 로직·전투 규칙 변경이 아니다.

구현 전에는 기존 종류 판별/전체 데이터 집계 경로·종류 추가/제거 갱신, Hover와 실제 분류 전환 이벤트 분리, 툴팁 경계/입력 비간섭·배치/지연을 확인한다. 미승인 ID·집계 저장 필드·아이콘·UX 기능을 추가하지 않는다.

## 10. 던전 입장창

### 10.1 진입 방법

광산 입구가 존재하는 메인 씬에서 이용한다.

플레이어는 광산 입구에 접근하여 T 키로 상호작용한다.

### 10.2 기존 임시 방식 폐기

과거에는 인벤토리에서 게임 시작 버튼을 눌러 던전에 입장하는 임시 흐름이 있었다.

최신 기획에서는 광산 입구 상호작용을 통한 던전 선택창으로 대체되었다.

기존 임시 UI의 실제 삭제 여부는 프로젝트에서 확인한다.

### 10.3 레이아웃

| 위치 | 구성 |
|---|---|
| 상단 | 던전 입장 타이틀 |
| 좌측 | 층 선택 목록 |
| 우측 상단 | 선택한 층 이름 및 난이도 |
| 중앙 | 대표 맵 이미지 및 필요 레벨 |
| 난이도 영역 | 4개 난이도 |
| 보상 영역 | 획득 가능한 클리어 보상 |
| 하단 | 입장 버튼 |
| 별도 조작 | 닫기 버튼 |

### 10.4 층 선택

선택한 층은 강조 상태를 유지한다.

다른 층을 선택하면 관련 정보를 갱신한다.

### 10.5 난이도 선택

난이도는 총 4개이다.

선택한 난이도도 강조 상태를 유지한다.

난이도 변경 시 다음 정보를 갱신한다.

- 난이도 표시
- 입장 레벨
- 관련 이미지 또는 표시 정보
- 보상 정보

난이도별 정확한 이름과 수치는 현재 데이터 확인이 필요하다.

### 10.6 클리어 보상 미리보기

보상 미리보기의 구성 요소:

- 아이콘 또는 이미지
- 획득 확률
- 희귀도 테두리

보상은 좌측에서 우측으로 나열하는 방향이다.

낮은 확률의 아이템을 어느 방향에 배치할지는 최종 구현 확인이 필요하다.

일반·엘리트 몬스터 처치 보상을 향후 별도의 도감에서 확인하는 구상이 있으나, 현재 도감은 구현 완료로 확인되지 않았다.

### 10.7 입장 가능 조건

선택한 던전의 필요 레벨을 충족하면 입장할 수 있다.

이전 던전 클리어 여부는 입장 조건으로 사용하지 않는다.

### 10.8 레벨 부족 안내

필요 레벨을 충족하지 못하면 입장 불가 상태를 회색 등의 방식으로 표현한다.

입장을 시도하면 레벨이 부족하다는 플로팅 안내 메시지를 표시한다.

시각적으로 입장 불가 상태를 표현하는 것과 실제 입력 이벤트를 구분한다.

### 10.9 닫기

닫기 버튼 또는 ESC로 창을 닫을 수 있다.

던전 선택창에서 I를 누르면 창을 닫고 인벤토리를 연다.

인벤토리를 닫아도 던전 선택창을 다시 열지 않는다.

### 10.10 시간 처리

던전 선택창이 열려 있어도 게임 시간은 흐른다.

## 11. 던전 결과창

### 11.1 목적

던전 결과창은 해당 런의 클리어 또는 실패 결과와 획득한 보상, 전투 기록을 확인하는 화면이다.

기존 결과창 구현 완료 보고가 존재한다.

### 11.2 결과 유형

**클리어**

보스를 처치하면 발생한다.

**실패**

부활 2회를 모두 사용한 뒤 최종 사망하면 발생한다.

### 11.3 보상 지급과 UI 분리

**확정 규칙**

보스 사망 즉시 기존 클리어·보상·저장을 처리한다. 결과창 시각 시작만 실제 사망 효과 완료까지 기다리며 최초 화면 표시를 지급/저장 조건으로 삼지 않는다(§11.9).

결과창을 닫거나 다시 열어도 보상을 다시 지급하지 않는다.

결과창은 이미 획득한 보상을 보여주는 UI이다.

### 11.4 클리어와 실패의 조작 차이

| 상태 | 플레이어 이동 |
|---|---|
| 클리어 | 가능 |
| 실패 | 불가능 |

클리어 결과창이 열린 상태에서도 플레이어는 이동할 수 있다.

창을 닫고 주변을 돌아볼 수 있다.

실패 결과창은 닫더라도 사망 상태가 유지되며 이동할 수 없다.

이동 외 공격·스킬 사용 가능 범위는 현재 구현 확인이 필요하다.

### 11.5 공통 레이아웃

클리어와 실패는 같은 2패널 구조를 사용한다.

- 화면 전체 반투명 암전
- 상단 중앙 결과 타이틀
- 좌측 획득 보상 패널
- 우측 전투 기록 및 이동 버튼 패널

### 11.6 암전

기존 결과창 명세의 암전 색상:

`rgba(8, 10, 15, 0.80)`

### 11.7 결과 타이틀 배치

상단 타이틀에는 별도의 배경 패널을 두지 않는다.

텍스트와 좌우 장식선을 표시한다.

### 11.8 싱글플레이 구성

현재 게임은 싱글플레이를 기준으로 한다.

다음 요소를 결과창에 추가하지 않는다.

- 파티원 표시
- MVP
- 매치메이킹 UI

## 12. 결과창 등장 연출

기존 인수인계에 명시된 결과창 등장 연출은 다음과 같다.

### 12.1 1단계 — 0.0~0.4초

- 남은 적 공격 및 예고 정리
- 암전 페이드인
- 결과 상태 확정
- 보상 지급 및 저장 처리

이는 기존 결과 연출 명세의 단계이며, 실제 내부 이벤트 순서를 이 표만으로 확정하지 않는다.

### 12.2 2단계 — 0.4~1.0초

- 결과 타이틀이 화면 중앙에 등장
- 타이틀이 상단으로 이동
- 획득 보상창이 화면 중앙에 단독 등장

### 12.3 3단계 — 1.0~1.6초

- 아이템 슬롯 순차 등장
- 골드 카운트업
- 경험치 카운트업

### 12.4 4단계 — 1.6~2.1초

- 보상창이 화면 왼쪽으로 이동
- 오른쪽 전투 기록창 공개

### 12.5 카운트업 주의사항

카운트업은 표시 연출이다.

숫자 연출에 따라 실제 돈이나 경험치를 다시 지급하지 않는다.

## 17. 결과창 닫기·재열기·이동

### 17.1 결과창 닫기

### 17.2 결과창 다시 열기

닫힌 상태에서 화면 우측 하단에 결과창 다시 열기 버튼을 표시한다.

버튼을 선택하면 같은 런의 결과를 다시 표시한다.

보상은 다시 지급하지 않는다.

**E/R HUD 충돌 확인 조건:** §4.7의 우하단 슬롯과 같은 화면 영역이므로 클리어 상태에서 E/R의 실제 표시 여부와 버튼 동시 표시 시 겹침을 확인한다. 충돌이 없으면 현행 배치를 유지한다. 충돌이 있으면 기존 버튼/HUD를 임의로 숨기거나 이동하지 말고 최소 수정안을 사용자에게 보고한다. 기존 닫기/재열기·동일런/중복 보상 방지·클리어 후 행동 제한은 보존하며 새 결과창 UX 정책을 확정하지 않는다. 이번 실제 화면 확인은 미실행이다.

### 17.3 다시 시작

결과창의 다시 시작 버튼은 같은 층과 난이도로 새 런을 시작한다.

기존 초기화 규칙:

- 첫 번째 방부터 시작
- 체력 초기화
- 물약 3개
- 부활 가능 횟수 2회
- 영구 성장 및 획득 보상 유지

### 17.4 로비로 이동

현재 던전 진행을 종료하고 메인 로비로 이동한다.

획득하고 저장한 보상은 유지한다.

### 17.5 결과창 데이터 유지

결과창을 닫거나 다시 열어도 같은 런의 보상과 전투 기록을 유지한다.

### 20.1 주요 충돌 가능성

**UI ↔ 게임 시간**

결과창 재열기가 보상 중복 지급으로 연결되지 않아야 한다.

**UI ↔ 플레이어 상태**

클리어 및 실패 결과창에 따른 이동 가능 여부가 기존 규칙을 따라야 한다.

**UI ↔ 장비**

장착 표시와 스킬 입력 표시가 혼동되지 않아야 한다.

**UI ↔ 몬스터**

HP바와 공격 예고가 현재 체력과 공격 판정을 올바르게 표시해야 한다.

**기록된 Unity MCP 테스트:** 인벤토리 57개, 광산 입구 38개, 후속 일반 UI 비정지 14개 통과 보고를 시간순으로 구분한다. 비정지 14개에는 월드시간/오디오 유지·입력 차단·I 전환·ESC·클릭 누출·쿨타임/적 진행·외부 timeScale 0.5 보존이 포함된다. 1920×1080 패널 실측과 1366×768 화면 경계 확인 기록이 있다. 결과 입력 주입 9개는 W 이동/Space·E·Q 차단, 결과 닫기→퍼즈→재개, I 중복 UI 차단, 재열기 버튼을 포함한다. 저장 최종 입력 8개는 설정/확인창 ESC의 퍼즈 복귀·기본 퍼즈 재개 등을 보고한다.

**기획 대조 / 검토 대상:** 초기 ‘인벤토리 정지’ 기록은 후속 비정지 수정으로 해소된 과거 차이다. 후속 저장 기록의 설정/확인창 ESC는 퍼즈로 복귀하므로 더 이른 ‘하위 페이지도 닫고 재개’ 기록과 구분한다. Q/E/R 재배치 보고만으로 물약 HUD가 금지된 중앙 하단으로 이동했다고 단정할 수 없다. 실제 물약 위치를 확인하기 전 §4.4의 배치 제한은 변경하지 않는다. 보스 기존 0.7초 연출과 결과 2.1초 연출의 연결·HP바 숨김 시점, 가장자리 툴팁/정확히 8개 보상/다중 레벨업 중간 프레임·극단 화면비는 후속 확인 대상이다.

## 23. 기획 상태 정리

### 23.1 확정된 기존 규칙

- UI 기준 해상도 1920 × 1080
- 인벤토리 및 던전 입장창의 수정된 크기 유지
- T 월드 상호작용
- I 인벤토리 열기·닫기
- ESC 열린 UI 닫기 또는 퍼즈 메뉴
- 인벤토리와 던전 입장창에서 게임 시간 유지
- 던전 선택창에서 I 입력 시 인벤토리로 전환
- 인벤토리를 닫아도 던전 선택창 자동 재열림 없음
- 생명 아이콘 3개와 부활 2회 표시
- 일반 몬스터 HP바의 하단 배치 방향
- 보스 HP바 상단 중앙 배치
- 보스 HP바의 지연 피해 표시
- 우측 중앙 획득 알림 방향
- 인벤토리 기본 분류·검색·툴팁 구성
- 기존 우측 아이템 유지·좌측 캐릭터 정보/스탯 2탭·공통 FINAL ATTRIBUTES
- 미사용P 알림·×1/×5/×10 즉시 투자/저장·패시브 상세·메인 전용 비용 확인 초기화
- 광산 입구 상호작용을 통한 던전 선택
- 난이도 선택 4종
- 클리어·실패 결과창 2패널 구성
- 기존 결과창 색상·문구·연출 시간 명세
- 클리어 시 이동 가능, 실패 시 이동 불가
- 결과창 닫기 및 다시 열기
- 결과창 재열기에 따른 중복 지급 없음

- 인벤토리·던전 선택창 열기 시 무조건 시간 정지
