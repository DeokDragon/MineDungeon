## 1. 프로젝트 개요

### 1.1 게임 소개

광산던전은 광산을 배경으로 광물 계열 몬스터와 전투하며 던전을 공략하는 2D 탑뷰 싱글플레이 액션 게임이다.

플레이어는 곡괭이를 주요 무기로 사용하며, 던전의 각 전투 방을 돌파하고 마지막 보스를 처치하는 것을 목표로 한다.

몬스터를 처치하면서 돈, 경험치, 제작 재료를 획득하고, 이를 활용해 캐릭터를 성장시키고 새로운 곡괭이를 제작한다.

성장한 캐릭터로 더 높은 난이도의 던전에 도전하는 구조를 기본으로 한다.

### 1.2 주요 특징

- 곡괭이를 중심으로 한 액션 전투
- 광물의 특성을 반영한 몬스터
- 일반 방을 돌파하여 보스에게 도달하는 던전 진행
- 층과 난이도 선택 시스템
- 몬스터 처치에 따른 돈·경험치·재료 획득
- 곡괭이 제작과 스킬 장착을 통한 성장
- 클리어와 실패 결과에 따른 보상 및 전투 기록
- 저장 데이터를 통한 영구 성장 유지

### 1.3 개발 방향

- 싱글플레이를 우선 개발한다.
- Unity 2D 탑뷰 시점을 사용한다.
- 전투, 성장, 던전 반복 플레이를 핵심 구조로 한다.
- 주요 무기는 곡괭이이다.
- 아트는 도트 느낌을 검토하고 있으나 최종 규격은 미확정이다.

## 2. 핵심 게임 플레이

### 2.1 핵심 플레이 루프

1. 메인 씬에서 캐릭터를 준비한다.
2. 광산 입구에서 던전 및 난이도를 선택한다.
3. 던전에 입장하여 일반 방의 몬스터와 전투한다.
4. 일반 방의 몬스터를 모두 처치하여 출구를 개방한다.
5. 다음 방으로 이동한다.
6. 보스 방에 도달하여 보스와 전투한다.
7. 던전 클리어 또는 실패 결과를 확인한다.
8. 획득한 돈·재료·경험치로 캐릭터를 성장시킨다.
9. 곡괭이를 제작하고 획득한 스킬을 장착한다.
10. 던전에 다시 도전한다.

### 2.2 전투 진행 구조

일반 방에는 몬스터가 배치되어 있다.

플레이어는 몬스터의 공격을 회피하고 곡괭이 및 스킬을 사용하여 적을 처치한다.

일반 방에서 처치해야 하는 모든 몬스터가 사망하면 출구가 개방된다. 보스 방은 출구 없이 보스 처치로 클리어한다.

플레이어는 출구를 이용하여 다음 방으로 진행할 수 있다.

일반 방은 신규 제작한 맵 7종을 랜덤 후보로 사용한다. 기존 테스트 맵은 후보에서 제외하며 A는 맵 5로 편입한다. 후보 종류 수와 진행 방 수는 구분하고 상세 기준은 §12를 따른다.

**확인 필요:** 정확한 방 수, 방 등장 순서, 맵 중복 방지 규칙.

## 3. 던전 시스템

### 3.1 던전 구성

던전은 층과 난이도로 구분한다.

던전 선택창에는 4가지 난이도가 존재한다.

난이도 선택에 따라 입장 필요 레벨, 보상 정보 및 관련 표시 정보가 갱신된다.

현재 확정되지 않은 항목은 다음과 같다.

- 전체 층 수
- 난이도별 정확한 명칭
- 난이도별 입장 필요 레벨
- 층·난이도별 최종 HP/공격 배율·종류별 추가 보정 값 (계산 규칙은 §6에서 확정)
- 방 구성 및 몬스터 등장 수
- 난이도별 클리어 보상

### 3.2 던전 입장 조건

**최신 확정 규칙**

정규 던전은 기존 콘텐츠 구현 여부·필요 레벨 검사를 유지하며, 층/난이도 밸런스와 런의 각 후보 맵 독립 배치가 미설정/무효이면 입장을 차단한다. 레벨 조건만으로 데이터 검사를 생략하지 않는다.

이전 던전 또는 이전 층을 클리어했는지는 입장 조건으로 사용하지 않는다. Editor 전용 선택 맵 테스트만 레벨·콘텐츠 구현 조건을 우회할 수 있으며 밸런스/독립 배치의 유효성은 우회하지 않는다. 개발 예외가 정규 입장 규칙을 바꾸는 것은 아니다.

### 3.3 방 진행 규칙

- 방 생성 시 몬스터를 배치한다.
- 대상 몬스터가 남아 있으면 출구는 잠긴 상태이다.
- 일반 방의 모든 대상 몬스터를 처치하면 출구가 열린다. 설정 완료된0마리 배치는 유효한 빈 방이며 미설정과 구분한다. BossRoom24x22는 출구 없이 보스 처치로 클리어한다.
- 정규 진행은 일반 방 3개 → 보스 방 → 결과 정산을 유지한다.
- 플레이어가 출구를 이용하면 다음 방으로 이동한다.
- 진행 도중 현재 런의 상태를 유지한다.

### 3.4 방 이동 시 유지 데이터

한 번의 던전 플레이 중 방을 이동해도 다음 정보는 유지한다.

- 현재 체력
- 남은 물약
- 남은 부활 횟수
- 획득한 돈
- 획득한 경험치
- 획득한 재료 및 아이템
- 전투 기록

방 이동만으로 현재 체력이나 부활 횟수를 초기화하지 않는다.

### 3.5 던전 완료 조건

**클리어:** 보스 처치

**실패:** 부활 기회를 모두 사용한 뒤 최종 사망

클리어 및 실패 시 결과창으로 연결한다.

## 4. 플레이어 시스템

### 4.1 기본 조작 및 행동

플레이어는 다음 기능을 중심으로 전투한다.

- 이동
- 곡괭이 기본 공격
- 회피
- 장착 스킬 사용
- 물약 사용
- 월드 상호작용

기존 문서에서 확인되는 UI 단축키는 다음과 같다.

| 입력 | 기능 |
|---|---|
| T | 월드 상호작용 |
| I | 인벤토리 열기·닫기 |
| ESC | 열린 UI 닫기 또는 퍼즈 메뉴 |

공격, 회피, 스킬, 물약의 최종 키 배치는 Unity 프로젝트 확인이 필요하다.

### 4.2 체력과 사망

플레이어는 체력을 보유한다.

적의 공격을 받으면 체력이 감소하고, 체력이 모두 소진되면 사망한다.

### 4.3 부활

**최신 확정 규칙**

플레이어에게는 최초 생명을 포함한 총 3개의 생명이 주어진다.

부활 가능 횟수는 2회이다.

| 상황 | 남은 생명 | 결과 |
|---|---:|---|
| 던전 시작 | 3 | 정상 플레이 |
| 첫 번째 사망 | 2 | 부활 |
| 두 번째 사망 | 1 | 부활 |
| 세 번째 사망 | 0 | 던전 실패 |

부활 위치는 현재 방의 입구이다.

처음 입장했던 던전의 첫 번째 방으로 되돌아가지 않는다.

### 4.4 물약

- 다시 시작하면 물약 수량을 3개로 초기화한다.
- 물약은 플레이어의 체력 회복에 사용한다.
- 회복량, 쿨타임 및 세부 사용 조건은 현재 구현을 확인한다.

## 5. 전투 시스템

### 5.1 기본 전투 구조

곡괭이를 주요 공격 무기로 사용한다.

플레이어는 기본 공격과 장착 스킬을 이용하여 몬스터를 처치한다.

공격 및 피격 판정은 대상의 체력 시스템과 연동한다.

### 5.2 공격 예고

일부 몬스터 및 보스 공격에는 위험 범위와 공격 발동까지의 예고 시간을 표시한다.

예고가 완료되는 시점과 실제 공격 판정 시점을 일치시키는 것을 원칙으로 한다.

개별 공격의 예고 범위와 실제 공격 범위는 각 몬스터 또는 보스의 상세 명세를 따른다.

### 5.3 타격감과 피격감

시각 효과를 우선하여 다음 감각을 강화하는 방향이다.

- 공격이 적에게 적중했다는 감각
- 적이 피해를 받았다는 감각
- 적을 처치했을 때의 감각
- 무거운 공격이 충돌했을 때의 충격감

검토 대상은 피격 플래시, 타격 이펙트, 피해량 표시, 적 피격 반응, 사망 연출, 화면 흔들림이다.

모든 효과의 실제 적용 여부는 확인이 필요하다.

화면 흔들림은 무거운 공격을 중심으로 적용하며, 연속적인 충격 효과가 과도하게 중복되지 않도록 한다.

### 5.4 신규 공격 피해 공식 — 승인 기획

최종 물리/마법 공격 스탯은 각각 기본+투자 보너스+장비 보너스다.

- 곡괭이 기본 공격 = 곡괭이 기본 피해×(1+최종 물리 공격 스탯/100)
- 물리 스킬 = 스킬 기본 피해×(1+최종 물리 공격 스탯/100)
- 마법 스킬 = 스킬 기본 피해×(1+최종 마법 공격 스탯/100)

대지 분쇄·착암 돌격은 물리, 청록 광선·불안정 광석 발파는 마법이다. 기존 혼합 계수 기획을 단일 유형 공식으로 대체하고 기본 계산 뒤 패시브 강화 배율/추가 피해를 처리한다. 소수점은 최종 계산 후 한 번 반올림하며 정확히.5는 큰 정수로 올린다.

신규 스킬 기본 피해량은 미확정이고 과거 임시 피해/혼합 계수를 옮기지 않는다. 명시된 패시브 효과 외 기존 시전·판정·기본 범위·쿨타임·행동 제한은 유지한다. 방어력 감소 공식·미명시 패시브 경계의 최종 정책은 별도 검토하며 현재 피해/패시브 구현 보고는 §14와 CombatSystem §18에서 구분한다. 상세는 CombatSystem §6.5를 따른다.

## 6. 몬스터 및 보스

### 6.1 일반 몬스터

현재 일반 몬스터는 5개 계열로 구성되어 있다.

| 몬스터 | 전투 특징 |
|---|---|
| 돌 몬스터 | 플레이어 위치를 목표로 하는 도약 공격 |
| 철 몬스터 | 방향을 고정하고 직선 돌진 |
| 수정 몬스터 | 수정 파편을 발사하는 원거리 공격 |
| 석탄 몬스터 | 근거리 원형 열기 폭발 |
| 자철석 몬스터 | 피해와 이동 속도 감소 효과를 주는 자기장 공격 |

각 몬스터의 초기 HP, 이동 속도, 공격 범위, 피해량, 공격 예고, 후딜레이 및 쿨타임은 기존 인수인계 문서의 1층 난이도 1 기준 명세를 유지한다.

상세 수치는 `Systems/MonsterSystem.md`에 기록한다.

### 6.2 일반 몬스터 공통 규칙

- 몬스터는 플레이어를 대상으로 전투한다.
- 각 몬스터는 고유 공격 패턴을 사용한다.
- 몬스터 사망은 방 전멸 판정에 반영된다.
- 방 교체나 플레이어 사망 시 남은 공격 판정과 투사체를 정리한다.
- 내부 벽과 충돌하거나 이동할 때 기존 전투 규칙을 유지한다.

### 6.2.1 층·난이도 능력치 조정

일반 5종의 기존 기본 능력치는 유지하고 층 HP/공격 배율·난이도 HP/공격 배율·종류별 HP/공격 추가 보정을 각각 독립 관리한다.

- 최종 HP = 반올림(기본 HP × 층 HP 배율 × 난이도 HP 배율 + 종류별 HP 추가 보정)
- 최종 공격력 = 반올림(기본 공격력 × 층 공격력 배율 × 난이도 공격력 배율 + 종류별 공격력 추가 보정)

모든 배율·보정 뒤 마지막 한 번 반올림하며 정확히 .5는 더 큰 정수로 올린다. 층/난이도 변경으로 이동 속도·공격 쿨타임·인식 반경·고유 공격 패턴을 자동 변경하지 않는다. 개체별 보정은 기록상 예약 필드만 있고 0이 아닌 값은 거부하므로 지원 기능으로 표현하지 않는다. 최종 배율/보정 값과 개체별 보정 활성화·우선순위는 미확정이다.

### 6.2.2 일반 몬스터 어그로

5종 모두 새 개체는 미인식이며 최초에는 반경 안+벽에 시야가 차단되지 않을 때 인식한다. 이후 반경 밖/벽 뒤로 이동해도 인식을 자동 해제하지 않는다. 미인식 상태에서 유효한 피해를 받으면 거리/시야와 관계없이 인식하고 다른 몬스터로 전파하지 않는다. 사망 개체 재활성화나 사망 중 공격 지속을 뜻하지 않는다. 반경 6은 임시 구현값이며 최종 밸런스가 아니다. 기존 보스 AI에 자동 적용하지 않는다. 상세 계산·검증·CSV는 [MonsterSystem](Systems/MonsterSystem.md)을 따른다.

### 6.3 돌골렘 보스

현재 보스는 돌골렘이다.

기존에 개발한 보스의 공격 패턴은 총 5종을 기준으로 한다.

인수인계 문서에 기록된 패턴 계열:

1. 도약 내려찍기
2. 주변 강타
3. 바위 돌진
4. 부채꼴 돌 파편

### 6.3.1 돌골렘 2페이즈 개편 — 2026-10-25 최종 승인

**승인된 신규 기획 / Unity 구현·검증 미완료.** HP50% 초과는 기본5종,50% 이하에서 전환 예약 후 현재 공격 종료·변신 완료/스킵을 거쳐 강화 단일5종과 기본형2개 연계2종을 사용한다. 선택70:30은 초기 테스트 비율이다. 강화형은 추가 원형 충격파·원형 전체2차 강타·기존 동작 유지 돌진·재조준/별도 예고2차 파편·반복 낙석이다. 연계A는 기본 도약→강타, B는 기본 돌진→파편이며 낙석/강화형 연계는 제외한다.

낙석B안은 실제 이동 바닥/플레이어 주변 가중치·회차당7~8개 동시 낙하·겹침/플레이어·보스 발밑 허용·안전 위치 보장 없음·회차별 독립 추첨·지속 피해 없음이다. 같은 회차의 플레이어 피해는 최대1회, 다른 회차는 기존 피격 무적을 따른다.2페이즈1/2/3회 확률20/45/35%도 초기 테스트값이다.

불가능한 연계는 현재 가능한 단일 공격 재선택, 각 패턴은 실제 예고 시작 시 개별 쿨타임을 소모한다. 돌진 벽 충돌은 둘째 파편 취소/기존 후딜, 중첩 실행 금지다. 등장/변신 중 행동·신규 피해/공격을 차단하고 양측 모든 전투 쿨타임을 정지했다가 남은 시간부터 재개한다. 연출/카메라/스킵은 진행하며 인벤토리 비정지/ESC 규칙은 유지한다.

정상 종료/수동·향후 자동 스킵의 최종 상태는 같고 한 번만 처리한다. 부활2회·현재 입구(12,2)와 보스HP/페이즈/위치 유지·완료 연출 재생 금지를 따른다. 전환 예약 중 사망은 공격 정리/기존 부활 뒤 예약 변신으로 연결하며 취소 연계는 재개하지 않는다. HP0/기존 동일 프레임 클리어 우선·중복 보상 방지를 유지한다. BossRoom24x22/1층 쉬움·일반3방→보스→정산은 바꾸지 않는다.

최종HP·피해·범위·속도·쿨타임과 추가 공격 수치·가중치·연출/스킵UI·자동 설정 저장·ESC 세부는 미확정이다. 기존 테스트 수치를 최종값으로 승격하지 않는다. 상세 기준은 [BossSystem](Systems/BossSystem.md) §4.8~4.16을 따른다.

## 7. 성장·스탯·패시브 시스템 — 2026-10-23 최신화

**2026-10-23 최신 사용자 승인 반영.** 승인 기획과 [WORK_STATUS.md](WORK_STATUS.md)의 Codex 구현·검증 보고를 구분한다. 이번 작업은 문서 갱신과 관련 코드의 읽기 전용 확인이며 Unity 컴파일·Play·빌드 검증은 재실행하지 않았다. 아래 과거 구현 기록은 당시 이력으로 보존한다.

### 7.1 레벨과 포인트

Lv.1 미사용3P 시작·레벨업당3P·최대Lv.50이며 총150P(초기3+49×3)다. Lv.50 이후에는 레벨이 상승하지 않는다. 기존 스탯/9패시브·이전 규칙, 처치EXP 즉시 지급·실패 시 유지·방/던전 클리어EXP 보너스 없음은 유지한다.

**성장 시스템 1차 초기 테스트값(최종 밸런스 아님):** Lv.1~49의 다음 레벨 필요EXP는 `100 + 50 × (현재 레벨 - 1)`이다. 전체49구간의 Lv.1→50 총 필요량은63,700EXP이며 상세 표는 [ProgressionSystem](Systems/ProgressionSystem.md) §3.3.1을 따른다. 과거Lv.5 표는 임시 구현 이력이다. WORK_STATUS 성장1차 이후에 표 적용·검증 보고가 있으며 이번 문서 작업에서 Unity 테스트를 재실행하지 않았다.

1층 권장 성장 구간은Lv.1~12, 악몽 완료 무렵Lv.10~12 도달을 목표로 하며 **Lv.12 이상 성장도 제한하지 않는다.** 쉬움Lv.1/보통Lv.3/어려움Lv.5/악몽Lv.8 입장 제안·약12판 목표는 별도의 초기 검토안이다. 2층 이후 및 전체 경험치표의 최종 튜닝, Lv.50 이후 추가EXP 처리 방식은 미확정이다. 기존 캐릭터 레벨·현재 레벨 진행EXP와 영구정보를 이 표로 역산/초기화하지 않는다.

### 7.2 투자 스탯과 초기화

투자 스탯은 체력·물리·마법, 각100P 상한이다. 체력1P당 최대HP+3, 물리/마법1P당 해당 공격 스탯+0.4다. 방어력은 투자 대상에서 제외하고 일부 상의·하의에서 획득한다. 최대HP 변경 시 현재HP 비율을 유지한다.

메인에서 ×1/×5/×10 선택 후 [+] 즉시 투자/저장하며 실제량은 min(선택 배수, 보유P, 100-현재 투자P)다. 메인 로비 인벤토리 스탯 탭에서 고정500G(초기 테스트값)로 세 투자 전부를 기존 미사용P에 반환하고 투자0/패시브 잠김으로 갱신한다. 레벨·EXP·다른 영구 정보는 보존하며 투자0P·골드 부족·던전에서는 거부한다. 같은 영역의 인라인2단계 확인을 사용하고 파일 저장 성공 후 골드/성장을 함께 확정한다. 실패는 원래 데이터 유지, 취소·탭 전환·닫기는 확인 해제다. 일반 스킬 쿨타임·물약·부활은 보존하고 잔류 스킬 중 실행은 거부한다.

던전 입장 시 성장 구성을 고정하고 던전 내부에서는 장비·스킬·스탯·패시브 열람만 허용한다. 장비/스킬 교체·투자/초기화는 불가하며 인벤토리를 열어도 시간은 흐른다. 기존EXP/레벨·미사용P 보존을 폐기하지 않고 투자 구성 고정과 런 중 자동 레벨/미사용P 증가를 구분한다. 세부 동작은 ProgressionSystem §4.2를 따른다.

## 8. 장비·스킬·제작

### 8.1 곡괭이

곡괭이는 플레이어의 주요 무기이다.

던전에서 획득한 재료와 돈을 사용하여 새로운 곡괭이를 제작하는 구조를 사용한다.

### 8.2 곡괭이 제작

제작 시스템은 광산 입구가 존재하는 메인 씬에서 이용하는 방향이다.

기본 제작창 구성:

- 제작 가능한 곡괭이 목록
- 선택한 곡괭이 정보
- 필요한 제작 재료
- 보유 재료 수량
- 제작에 필요한 돈
- 제작 버튼
- 제작 결과 안내

개별 곡괭이 종류, 능력치, 제작 비용 및 상세 UI는 추후 확정이 필요하다.

제작 시스템의 구현 완료는 아직 보고되지 않았다.

### 8.3 스킬

스킬은 던전 클리어 보상으로 획득한다.

획득한 스킬을 장착하고 전투에서 사용한다.

일반 몬스터 처치 시 스킬을 직접 드롭하지 않는다.

인챈트로 곡괭이에 스킬을 부여하는 방식이 현재 주된 스킬 획득 구조는 아니다.

기존 스킬 4종의 구현 완료 보고가 존재한다.

개별 스킬의 이름, 효과, 수치, 쿨타임 및 장착 방식은 실제 프로젝트 데이터 확인 후 상세 문서에 정리한다.

### 8.4 장비 확장

인벤토리 기획에는 무기 이외에 상의, 하의, 악세서리 장비 슬롯 구상이 포함되어 있다.

해당 장비의 실제 종류와 획득·장착·성장 시스템은 확정 또는 구현 완료로 단정하지 않는다.

## 9. 경제 및 보상 시스템

### 9.1 몬스터 처치 보상

> 아래7맵 예상EXP/완주187~216·평균약199.71은 과거7종/당시 배치 계산 자료다. 현재10종에 적용하거나 신규 예상값을 임의 계산하지 않는다.

몬스터를 처치하면 돈과 경험치를 즉시 획득한다.

몬스터 종류에 따라 지급하는 돈과 경험치가 존재한다.

이미 지급한 처치 보상은 던전 결과창에서 다시 지급하지 않는다.

**경험치 확정 정책:** 같은 층·난이도·종류의 몬스터는 맵과 관계없이 동일EXP를 지급하고, 맵 총량은 실제 종류·수량에 따라 달라진다. 처치 즉시 지급·방/던전 클리어EXP 보너스 없음·실패 시 이미 받은EXP 유지를 따른다. 기존 맵 선택·독립 배치는 변경하지 않는다.

**1층 쉬움 미적용 초기안:** 돌4/철5/수정5/석탄4/자철석6/돌골렘45 EXP. Map_01~07 예상값은 순서대로47/57/52/48/57/52/48, 일반3방+보스 완주 최소187·최대216·평균약199.71EXP다. 이는 사용자 제공 현재 배치·현행 선택 기준의 계산값이며 실제 적용/테스트 완료가 아니다. 공유 보상 에셋·돈·재료는 변경하지 않는다. 상세는 [RewardSystem](Systems/RewardSystem.md) §2.5~2.6을 따른다.

### 9.2 일반 몬스터 재료 드롭

일반 몬스터는 자신의 계열에 해당하는 재료를 드롭한다.

- 드롭 성공 확률: 50%
- 성공 시 획득 수량: 1~2개

수량을 균등한 확률로 추첨하는 경우 다음 결과가 적용된다.

| 결과 | 확률 |
|---|---:|
| 획득 없음 | 50% |
| 재료 1개 | 25% |
| 재료 2개 | 25% |

이 확률을 보스나 엘리트 몬스터에게 임의로 확대 적용하지 않는다.

### 9.3 던전 클리어 보상

던전 클리어 시 클리어 전용 보상을 획득한다.

클리어 보상은 결과 처리 과정에서 지급·저장한다.

별도의 던전 클리어 돈 보너스와 경험치 보너스는 지급하지 않는다.

### 9.4 던전 실패 보상

던전 실패 시에도 이미 획득한 다음 보상은 100% 유지한다.

- 돈
- 경험치
- 재료
- 획득한 아이템

아직 획득하지 않은 보스 보상 및 클리어 전용 보상은 지급하지 않는다.

### 9.5 보상 지급 중복 방지

몬스터 처치 보상과 클리어 보상을 구분한다.

결과창을 닫거나 다시 열어도 보상이 중복 지급되지 않아야 한다.

클리어 보상은 결과창 최초 표시 시점에 확정·저장한다.

### 10.2 인벤토리

기획된 기본 분류 탭:

- 전체
- 무기
- 상의
- 하의
- 악세서리
- 재료

스킬의 실제 분류 화면 구성 및 정렬 조건은 추가 확인이 필요하다.

### 10.2.1 캐릭터 정보/스탯 탭과 FINAL ATTRIBUTES

기존 우측 아이템 영역·레퍼런스 색상/배치/스타일을 유지하고 좌측 캐릭터 정보/스탯 2탭 및 양 탭 공통 하단 FINAL ATTRIBUTES를 고정한다. 항목은 물리 공격력·마법 공격력·최대 체력·방어력·공격 간격·이동 속도이며 실제DEF와 감소율을 구분한다.

미사용P 알림 점, ×1/×5/×10 부분 투자·[+] 즉시 저장/능력치·패시브 갱신을 제공한다.3스탯 카드는 한 번에 하나만 펼치는 아코디언이며9패시브 Hover에서 잠긴 조건/효과도 확인한다. 현재 툴팁 위치와 우측 목록 일부 가림을 허용한다.500G 초기화는 별도 팝업 대신 인라인2단계다. 클릭 UI의 기본/호버/눌림/선택/비활성을 구분하고 부족 골드 등 사유를 안내한다. 구현/Pointer 검증 보고와 실제 OS 입력 미검증은 [UISystem](Systems/UISystem.md) §9.10/21을 따른다.

### 10.2.2 인벤토리 UX UI-01~UI-06 — 2026-10-24 승인

성장·스탯의 상시/정상 성공 안내, 캐릭터 영역의 `현재 플레이어`, 스킬 장착 고정 안내를 제거하되 수치 갱신·중요 실패/제한 안내와 실제 저장/기능은 유지한다. 일반 아이템의 불필요한 지속 청록 선택 강조를 해제하고 Hover/Pressed·희귀도/실제 장착 표시는 보존한다.

장착 가능한 스킬 선택 시 임시 선택 강조와 E/R 테두리 펄스(약0.8초 초기 시각 테스트값)를 표시한다. 장착 완료 또는 다른 행동/닫기로 대기를 끝내며 취소는 실제 E/R 장착·저장 데이터에 영향을 주지 않는다. 바깥 클릭의 월드 전달 차단·기존 ESC 우선순위·인벤토리 비정지는 유지한다. **승인 완료, Unity 적용·회귀 검증 미진행**이다. 상세는 [UISystem](Systems/UISystem.md) §9.13과 [EquipmentSkillSystem](Systems/EquipmentSkillSystem.md) §4.4.1을 따른다.

### 10.3 던전 입장창

광산 입구에 접근하여 T 키로 상호작용하면 던전 선택창을 연다.

플레이어는 층과 난이도를 선택하고, 입장 필요 레벨과 보상 정보를 확인할 수 있다.

입장 필요 레벨이 부족하면 해당 사실을 안내한다.

### 10.4 UI와 게임 시간

- 인벤토리를 열어도 게임 시간이 정지하지 않는다.
- 던전 입장창을 열어도 게임 시간이 정지하지 않는다.
- 일반적인 일시정지는 ESC 퍼즈 메뉴에서 처리한다.

던전 입장창이 열려 있을 때 I 키를 누르면 입장창을 닫고 인벤토리를 연다.

인벤토리를 닫았을 때 이전 던전 입장창을 자동으로 다시 열지 않는다.

### 10.5 던전 결과창

보스 처치 또는 최종 사망 시 결과창을 표시한다.

클리어 및 실패 결과창은 공통적인 2패널 구조를 사용한다.

- 좌측: 획득한 보상
- 우측: 전투 기록 및 이동 버튼

공통 전투 기록:

- 클리어 시간 또는 진행 시간
- 넣은 데미지
- 받은 피해량
- 회복량
- 처치한 몬스터 수
- 사용한 부활 횟수

클리어 상태에서는 결과창을 열거나 닫은 상태에서 플레이어 이동이 가능하다.

실패 상태에서는 플레이어가 사망했으므로 이동할 수 없다.

닫힌 결과창은 우측 하단 버튼으로 다시 열 수 있다.

다시 시작 버튼은 동일한 층과 난이도로 새로운 런을 시작한다.

로비로 이동 버튼은 현재 던전 진행을 종료하고 메인 로비로 돌아간다.

## 11. 저장 및 불러오기

### 11.1 저장 목적

던전 반복 플레이와 게임 종료 이후에도 영구 성장 및 획득 보상을 유지한다.

### 11.2 저장 대상

저장이 유지되어야 하는 주요 항목:

- 돈
- 경험치와 레벨
- 획득 재료
- 획득 아이템
- 획득한 스킬
- 장착한 스킬
- 제작한 곡괭이
- 장비 데이터
- 성장 데이터
- 사용 및 미사용 스탯 포인트

실제 저장 코드에서 현재 지원하는 범위는 확인이 필요하다.

### 11.3 보상 저장

클리어 보상은 최초 결과 진입 시 지급 및 저장한다.

결과창 닫기, 로비 복귀, 게임 종료 등에 의해 이미 획득한 보상이 사라지지 않아야 한다.

같은 결과를 여러 번 확인해도 보상이 중복 지급되지 않아야 한다.

### 11.4 개발용 초기화

테스트를 위한 저장 데이터 초기화 기능이 요청된 이력이 있다.

구현 여부와 최종 조작 방법은 확인이 필요하다.

### 11.5 신규 성장 저장과 이전

스탯별 투자·미사용P와 이전 완료 상태를 현행v3로 관리한다는 구현 보고가 있다. §7.4/[SaveSystem](Systems/SaveSystem.md) §6의 최초1회 보정·원본/백업 별도 보호·영구 데이터 보존을 유지한다.500G 초기화는 기존v3 후보 저장 한 번에 골드 차감/포인트 반환을 담고 성공 뒤 메모리를 확정한다. 골드 스탯 초기화와 Editor 전체 진행 초기화는 구분한다.

## 13. 아트 및 시각적 방향

### 13.1 기본 방향

2D 탑뷰 시점에 적합한 그래픽을 사용한다.

도트 아트 느낌을 검토하고 있지만 최종 제작 규격은 정해지지 않았다.

### 13.1.1 돌 몬스터 B-1R 현재 사용 기준

2026-10-23 사용자 승인으로 돌 몬스터의 B-1R 현재 사용 기준을 채택한다. 애니메이션·전투VFX·시각 방향 전환/피격 표현을 기존 전투AI에 연동하되 기존 전투 수치·공격 판정·EXP/재화 지급·몬스터 전멸/방 진행은 유지한다. 사망 연출로 보상/출구 처리를 지연하지 않으며 현재 성장·스탯·패시브 규칙도 변경하지 않는다.

이는 돌 몬스터 전용 기준이다. 돌 전용 기준을다른 대상에 자동 확대하지 않는다. 철·수정·석탄의 별도 채택 기준은 §13.1.2, 자철석은 §13.1.3에서별도채택하며 플레이어·보스·맵·UI 및 전체게임 공통 아트 규격은 미확정으로 구분한다. 당분간 전체 재제작 없이 플레이테스트에서 확인된 문제에 한해 개별 개선을 검토할 수 있다.

상세 외형/애니메이션/VFX 기준은 [ArtDirection](Systems/ArtDirection.md) §4.3, AI/방향/피격·사망 연동은 [MonsterSystem](Systems/MonsterSystem.md) §4.7~4.8을 따른다. 구현·검증은 WORK_STATUS의 기존 보고와 구분하며 이번 문서 작업에서 Unity 테스트를 새로 수행한 것은 아니다.

### 13.1.2 철·수정·석탄 현재 아트 기준과 적용 보고

2026-10-23 사용자 채택 자료를 기준으로 철I-3R(각진 금속판·전방 중량감/돌진), 수정C-2R Core Focus Fine-Tuned(큰 어깨 수정·청록 가슴 코어/원거리 발사), 석탄C-1R Furnace Cracked Body(검은 몸체·붉은 화로/비자폭 반복 폭발)를 현재 사용 기준으로 기록한다. 애니메이션/VFX는 기존 AI 상태와 시간에 연동하며 기존 전투 수치·판정·보상·방 진행을 바꾸지 않는다. 수정의 투사체 원점과 석탄의 폭발 중심은 기존 공격 시작 시 저장한 Rigidbody2D 위치를 따른다.

**Codex 검증 보고:** 3차 어그로 75개, 4차 계산/배치·일반 전체 진행, 5차-A CSV/Undo·안전 검증, 5차-B 선택 테스트/격리·별도 정규 전체 진행, 로비 벽 수정 이동 비교, 6·7차 격리 그룹/프로필 복사·기록/CSV·API Play와 일반 다음 방 회귀를 구분한다. 6·7차에서 전체3방→보스→정산을 새로 재주행하지 않았다는 제한을 유지한다. 최신 보고는 컴파일/Console 오류0과 기존 폰트 글리프 경고5개를 별도로 기록한다. 이를 이번 작업의 검사 결과로 주장하지 않는다.

**사용자 기능 확인:** 이번 요청에서 선택 테스트 투명벽 수정 후 및 6·7차 기능도 정상 작동한다고 확인했다. **미검증:** 모든 실제 마우스/키보드·드래그/단축키/확인창·Excel 직접 조작, 장시간/대량 성능, 전 맵 수동 전체 전투와 모든 스킬/회피/물약/부활 조합, 배포 빌드·강제 저장/프로세스 장애. 기능 확인과 자동/API 검증을 합쳐 완전 검증 완료로 표현하지 않는다.

## 15. 공식 문서 관리 기준

### 15.1 문서 역할

> **2026-10-21 실제 파일 기준 보충:** 구현·테스트 원자료는 [WORK_STATUS.md](WORK_STATUS.md), 이번 갱신의 시스템별 대조 결과는 각 Systems 구현 현황, 전체 요약은 §14에서 관리한다. 아래 `DEVELOPMENT_STATUS.md`는 기존 문서의 관리 구상이며 현재 Docs에 존재하지 않는다. 이를 새로 만들거나 WORK_STATUS를 이동·덮어쓰지 않았다.

- `GDD.md`: 게임 전체의 확정 기획 기준
- `Systems/`: 시스템별 상세 기획 및 수치

- `DEVELOPMENT_STATUS.md`: 구현 진행 및 검증 상태
- `Tasks/`: Codex 구현 지시서

### 15.2 기획 변경 규칙

기획 변경 시 다음 절차를 따른다.

1. 파트별 상세 기획 작성
2. 기존 기획과의 충돌 확인
3. 관련 시스템 영향 분석
4. 사용자 최종 승인
5. 공식 문서 수정안 작성
6. 실제 문서 반영
7. 변경 기록 갱신
8. 필요한 경우 구현 작업 지시

### 15.3 기획 우선순위

**이번 사용자 지시에 따른 적용 순서:** 최신 사용자 명시적 확정 → 승인된 최신 GDD/Systems → CHANGELOG 확정 변경 → WORK_STATUS 구현·테스트 기록 → 기존 인수인계 → 과거 미확정 아이디어. WORK_STATUS는 구현 근거이며 승인된 기획을 변경할 권한이 아니다.

기존 우선순위 기록은 다음과 같이 보존한다.

1. 사용자가 가장 최근에 명시적으로 확정한 결정
2. 최신 공식 GDD 및 Systems 문서
3. CHANGELOG에 기록된 확정 변경
4. 인수인계 문서
5. 과거 미확정 제안

### 15.4 구현 상태 관리

기획 확정과 실제 구현 완료는 별도로 관리한다.

사용자의 구현 완료 보고만으로 코드 검증이 끝났다고 판단하지 않는다.

Codex의 작업 완료 보고 또한 실제 Unity 프로젝트 검증 결과와 구분한다.
