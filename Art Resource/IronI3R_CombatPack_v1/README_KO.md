# I-3R 전투 애니메이션·이펙트 v1

철 몬스터 전투 애니메이션 6종과 이펙트 5종의 게임용 투명 PNG입니다. 캐릭터는 기존 IronMonster_I-3R_Base_64x64.png와 설치된 Idle v1을 기준으로 픽셀을 재사용했습니다. I-3R을 새로 디자인하거나 돌 몬스터 형태를 복사하지 않았습니다. 기존 Idle/Move, 돌 몬스터 리소스, Unity 코드/프리팹, 공식 기획 문서를 변경하지 않았고 Git 커밋·푸시를 하지 않았습니다.

Animations와 VFX 폴더가 게임용 PNG입니다. 모두 실제 RGBA/투명 배경, 가로 한 줄이며 프레임 중앙 Pivot (0.5,0.5)을 기준으로 정렬했습니다. 캐릭터는 64×64, PPU64용입니다. 이펙트도 PPU64를 시범 제안하지만 해상도/표시 크기는 공식 규격이 아니며 실제 씬에서 조정 검토해야 합니다. PNG 자체에 Unity Pivot/PPU 설정이나 재생시간이 포함되지는 않습니다. .meta 파일을 새로 쓰지 않았습니다.

캐릭터 PNG에는 배경/바닥/그림자/텍스트/테두리/흐림/반투명 외곽선이 없습니다. VFX의 먼지와 소멸에는 계단식 픽셀 실루엣의 반투명 알파를 사용하며 블러는 사용하지 않았습니다. 벽이나 공격 범위 마스크는 그리지 않았습니다.

## 동작 구성

- ChargeWindup: Idle 기본 픽셀로 시작합니다. 발 접지를 유지하며 허벅지/무릎을 굽히고, 어깨를 앞으로 내밀고 팔꿈치를 접어 방어 자세를 만듭니다. 몸통은 단계적으로 최대 5px 낮아지며 눈을 가리지 않습니다.
- Charge: 상체는 일정한 낮은 높이와 전방 숙임을 유지하고 큰 어깨와 방어 팔을 고정한 채 짧게 다리로 밀어붙입니다. 일반 Move의 기본 상체/늘어진 팔과 구별됩니다. 실제 월드 이동이나 속도선은 캐릭터 시트에 넣지 않았습니다. 방향 반전은 추후 Unity flipX가 처리할 수 있으며 별도 좌/우 시트는 만들지 않았습니다.
- WallImpact: Charge F1과 동일한 자세에서 시작합니다. F2는 기본보다 7px 낮아진 몸통, 깊은 무릎/팔꿈치 접힘, 전방 어깨의 뒤로 밀림을 함께 사용합니다. F3에서 상체와 팔이 짧게 반동하고 F4는 낮게 균형을 잃은 자세입니다. 파괴/사망/벽 그림/스파크는 본체에 넣지 않았습니다.
- Recovery: WallImpact F4와 완전히 같은 낮은 자세에서 시작하고 첫 두 프레임은 몸통 높이를 유지합니다. 이후 3px→1px→기본 높이로 올라옵니다. 마지막 프레임은 현재 설치된 Idle 첫 프레임과 완전히 같습니다. 일반 돌진 종료 후에도 사용할 수 있으며 WallImpact를 반드시 먼저 재생할 필요가 없습니다.
- Hit: 원래 자세→1px 상체/어깨 충격→원래 자세로 복귀하는 짧은 반응입니다. 피격 플래시나 전신 스케일 변형을 중복하지 않습니다. 공격 취소/이동 제한/경직 기능이나 이벤트는 전혀 포함되지 않습니다. 실제 공격 도중 적용 여부는 기존 상태 우선순위에 따라 별도 통합에서 결정해야 합니다.
- Death: 원본의 큰 어깨 철판, 중심 금속판, 팔/다리 연결부를 나누어 벌어짐→붕괴→잔해→투명 종료로 구성했습니다. F7은 의도적으로 완전 투명입니다. 큰 어깨 판은 본체 Death에서 처리하고 VFX는 작은 조각 위주여서 분리 사용이 가능합니다. 과도한 폭발/불꽃/새 철판 디자인은 없습니다.

금속판·어깨는 원본 크기를 유지하고, 팔꿈치/무릎 관절을 국부적으로 굽혔습니다. 머리와 눈은 정수 픽셀 이동만 하며 별도 얼굴을 생성하지 않았습니다. 허리 접힘과 관절의 보이지 않는 연결은 원본 인접 색으로 최소 보완한 2D 시범 리깅입니다. 보이지 않던 철판 측면이나 실제 3D 회전면을 새로 그린 최종 수작업 아트는 아닙니다.

## 이펙트 사용

- ChargeDust: 64×64, 5f, 단발 0.20초 제안. 돌진 시작 발밑의 작은 먼지이며 본체를 포함하지 않습니다.
- ChargeTrail: 96×48, 6f, 반복 주기 0.42초 제안. 중심에서 화면 왼쪽으로 흘러가는 먼지입니다. 기본 진행 방향은 오른쪽을 가정하며 나중에 실제 공격 방향으로 정렬/반전해야 합니다. 기존 본체 잔상은 포함하지 않았습니다. 반복 또는 연속 생성 모두 가능한 별도 자료입니다.
- WallImpact: 96×96, 6f, 단발 0.30초 제안. 제한된 먼지와 금속 파편이며 벽/본체는 없습니다.
- HitSparks: 32×32, 4f, 단발 0.18초 제안. 작은 밝은 금속색/노란 불꽃이며 화면 전체 플래시는 없습니다.
- DeathFragments: 96×96, 7f, 단발 0.45초 제안. 작은 판 조각과 제한적인 먼지입니다. 본체의 큰 어깨/중심 판을 그대로 중복하지 않습니다.

일회성 이펙트 마지막 프레임은 완전 투명입니다. 실제 피해 반경/충돌 크기/보상 이벤트는 이펙트 이미지와 무관하며 바꾸지 않았습니다.

## 기존 구현과의 관계

읽기 전용으로 IronMonsterAI, IronMonsterSpriteAnimation, NormalMonsterAI를 확인했습니다.

- 기존 Warn/StoneGolemTelegraph가 돌진 예고선을 담당하므로 새 예고 텍스처를 만들지 않았습니다.
- 기존 BodyGlow가 약 0.08초 간격으로 본체 잔상을 만듭니다. 새 ChargeTrail은 먼지만 포함하므로 본체 잔상의 중복 제작이 아닙니다. 실제 합성에서 양쪽 밀도를 확인해야 합니다.
- 기존 Impact는 Pulse와 본체 스프라이트를 작게 복제한 Fragments를 생성합니다. 새 WallImpact PNG는 금속 파편/먼지의 대체 시각 자료입니다. 나중에 기존 Fragments/Pulse와 새 시트를 무조건 중첩하면 과해질 수 있으므로 표현을 선택해야 합니다. 이번 작업에서는 기존 효과를 끄거나 교체하지 않았습니다.
- 현재 IronMonsterSpriteAnimation은 Idle/Move만 사용하고 공격 중 첫 기본 프레임을 표시하는 구조입니다. 새 전투 PNG는 자동 연결되지 않습니다. 애니메이션 상태/재생 연결은 이번 작업 범위 밖입니다.
- 일반 후딜 0.8초, 벽 충돌 후딜 1.5초의 기존 AI 시간 소유권을 유지해야 합니다. Recovery 시트 하나를 각 상태 시간에 정규화해서 쓰는 자료이며 PNG가 시간을 강제하지 않습니다. WallImpact를 별도 후딜로 더하거나 사망/보상/방 클리어를 시각 종료까지 지연시키면 안 됩니다.
- Windup GIF의 0.75초는 읽은 소스 기본값을 참고한 시범 시간입니다. Prefab 직렬화 값/실제 런타임 오버라이드까지 확인하지 않았으므로 게임 시간을 수정하는 근거로 사용하지 않습니다. Charge는 AI가 실제 이동/충돌로 종료할 때까지 반복하는 자료입니다.

## 미리보기

Previews에 모든 리소스의 GIF와 무손실 RGBA WebP가 있습니다. GIF는 게임에서 단발인 리소스도 검토 편의를 위해 반복합니다. 반투명 먼지는 GIF에서 미세한 점 패턴으로 알파를 근사하므로 원본 PNG/무손실 WebP가 더 정확합니다. 캐릭터의 불투명 프레임은 GIF 디코딩 픽셀과 실제 PNG 확대가 같은지 검사했습니다.

Recovery 기본 GIF는 0.8초이며 추가 Recovery_wall_1500ms 미리보기는 같은 5프레임을 1.5초로 재생합니다. 이는 미리보기일 뿐 PNG에 내장된 시간이나 공격 수치가 아닙니다.

Review/Animations_contact.png와 VFX_contact.png는 정적 검토용 프레임 모음입니다. 텍스트/테두리 없는 게임용 원본은 Animations/VFX 폴더입니다.

## 검증 결과

- 요청된 PNG 11개를 모두 생성했고 실제 크기/RGBA/알파/셀 분할과 저장 픽셀 일치를 재검사했습니다.
- 모든 프레임 바깥 네 변이 투명하며 캐릭터/효과의 경계 잘림은 검출되지 않았습니다.
- 분리/붕괴 이전의 얼굴/노란 눈 원본 픽셀 일치, Windup 발 접지, 낮은 준비 자세, Move와 다른 방어 자세, 벽 충돌 압축 및 낮은 Recovery 앞 두 자세를 프레임 비교로 확인했습니다.
- Windup F1=Idle F1, Charge F1=WallImpact F1, WallImpact F4=Recovery F1, Recovery F5=현재 Idle F1의 전체 RGBA 픽셀 일치를 확인했습니다.
- Charge의 몸통/눈은 4프레임 동안 고정되고 다리만 추진 자세로 바뀝니다. 반복 전환과 Trail의 프레임 차이 수치를 validation.json에 기록했습니다. 이 수치만으로 자연스러움을 판정하지는 않았습니다.
- GIF 12개는 실제 프레임 수와 시간으로 다시 디코딩했고, WebP 12개의 보이는 RGBA 픽셀/알파는 PNG 확대 프레임과 정확히 같음을 확인했습니다. 완전 투명 종료 프레임도 보존했습니다.
- 원본/기존 Idle·Move/돌 몬스터 그래픽/참조한 코드의 SHA-256 미변경 확인. 프로젝트를 편집하지 않았으므로 컴파일/플레이 테스트를 실행하지 않았습니다.

## 완료하지 않은 검증과 품질 한계

- 브라우저 보안 정책으로 로컬 file:// GIF 재생이 차단된 상태여서 실제 시간 흐름의 재생을 직접 관찰하지 못했습니다. 우회하지 않았으며, 실제 GIF 동작 감상 검증을 완료했다고 보고하지 않습니다.
- Unity Import, 실제 배경/카메라/이동 속도/flipX/기존 잔상·피격 효과와의 합성은 검증하지 않았습니다. 금속의 무게감, 루프 자연스러움, Death 철판 분리의 최종 자연스러움은 게임 내 검토가 필요합니다.
- Death의 철판은 단일 정지 원본을 분절해 2D에서 회전/이동한 근사이며, 숨은 면과 바닥에 누운 판의 3D 투영을 정밀하게 다시 그린 리소스는 아닙니다. 그 점은 남은 시각 품질 한계입니다.
- 파일 생성 실패는 없습니다. 정적 프레임/규격 검사에서 확인된 잘림·알파 오류는 없지만, 실시간 연출 품질 검증까지 모두 끝났다는 의미는 아닙니다.
