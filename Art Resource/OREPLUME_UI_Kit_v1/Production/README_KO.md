# OREPLUME UI Kit v1 — Hybrid A Production

## 결과와 사용 범위

**실제 게임용 PNG19개**를 `PNG/`에 저장했다. 텍스트·수치·아이콘·게이지를 포함한 검토 화면은 `Previews/`로 분리했다. 기존 Hybrid A의 재질·프레임·색상을 재사용했으며 새 스타일이나 이미지 생성은 도입하지 않았다.

Unity에 Import하거나 코드·씬·프리팹을 수정하지 않았다. 기존 UI를 재구현한 것이 아니며 실제 적용/Play 검증은 후속 작업이다.

상태 이름은 `Normal`, `Hover`, `Pressed`, `Selected`, `Disabled`다. 클리어/실패별 프레임 파일을 중복 제작하지 않았다. 큰 패널의 표면664×349와 소형 표면64×64는 용도가 다르다. 소형은 기존 A HUD의 낮은 대비 재질을 사용해 통계 행마다 큰 균열이 반복되는 문제를 피했다. 두 배경은 반복용 타일이 아니며 **Simple Image로 내부 영역에 늘려 사용**하는 구조다.

전체 경로·규격·Border·알파값·적용 대상은 `Specs/AssetManifest.csv`와 `.json`에 있다. PNG 폴더 기준 경로는 위 표와 같다.

## Import 및 Image 권장값

- Sprite(2D/UI), Single, Point, Compression None, Mipmap Off, sRGB On, Mesh FullRect.
- UI Sprite PPU100을 초기 적용값으로 제안한다. 기존 Canvas Reference Pixels Per Unit과의 관계를 적용 담당자가 확인한다. 게임 월드 PPU를 변경하는 지시가 아니다.
- 프레임/버튼/HUD/슬롯은 `Image.Type=Sliced`, 두 배경만 `Simple`.
- Frame의 중앙은 투명하다. `fillCenter=false`를 쓸 수 있다. 목재/암석 버튼과 배경 포함 HUD·슬롯은 `fillCenter=true`를 유지한다.
- 모든 Image.color는 흰색·알파1에서 시작한다. 버튼 상태는 동일 크기의 Sprite를 교체하며 크기나 TMP 위치를 바꾸지 않는다.
- 최소 수학적 Slice 크기는 Large/Medium56×56, Inset/Buttons16×16, HUD16×16, Slots12×12, Boss16×8이지만 **기존 실제 UI 크기를 줄이는 권장이 아니다**. HUD300×142·슬롯72×72·보스864×62는 그대로 사용한다.
- 플랫폼 자동 다운스케일로1440px 프레임이 줄지 않도록 Max Size2048 이상을 검토한다. 텍스처가 다른 해상도로 리샘플되면 Border 픽셀도 어긋날 수 있다.
- 이번에는 `.meta`나 GUID를 생성/교체하지 않았다. 기존 아트 덮어쓰기를 전제로 하지 않는다.

## 패널 배경과 프레임의 정렬

두 요소는 같은 영역을 두 번 덮지 않도록 조합한다.

1. 기존 패널 Rect의 크기와 중심을 유지한다.
2. Large/Medium 프레임은 Rect 전체에 표시한다.
3. 큰 Slate Background는 프레임의 **좌28/하28/우28/상28px 안쪽**만 채운다. 예:1440×810에서 내부1384×754.
4. Inset Frame도 같은 원칙으로8px 안쪽만 소형 Background로 채운다.
5. 그 위에 기존 TMP·아이콘·통계·스크롤·버튼을 그대로 표시한다.

프레임의 어두운 띠에는 이미80% 알파가 있고 구리 부분은 불투명이다. 내부 바탕을 프레임 전체 아래에 겹쳐 깔면 띠와 바탕이 중복 합성될 수 있으므로 내부 사각에만 맞춘다. 모서리 투명 부분도 채우지 않는다. 이는 아트 합성 명세이며 이번 작업에서 UI 오브젝트를 추가한 것이 아니다. 실제 연결은 기존 구조를 확인한 후 적용 담당자가 결정한다.

### 결과창 주의

1440×810은 결과창의 기존 논리 배치 영역이다. 승인된 Hybrid A처럼 **제목 주변은 열려 있고 좌우 패널 두 개**가 있어야 한다. 결과창 전체에 새 큰 외곽 프레임을 추가하지 않는다.

LargeFrame을 기존 보상/기록660×570 Rect에9-Slice로 재사용한다. 결과 내용 내부 좌표는 보상(40,220,660,570), 기록(740,220,660,570)를 유지한다. 제목/보상/통계/버튼은 기존 분리 구조이므로 내부 등장 연출과 CanvasGroup 제어도 그대로 유지해야 한다. 새 레이아웃·연출 시간·보상/정산/저장 조건을 만들지 않는다.

## 알파80% 중복 방지

- 공통 배경2종의 PNG 알파는 **204/255=80%**다.
- 프레임의 암석부·HUD/슬롯의 내부 바탕도204를 사용하고 구리선/주요 테두리는255를 유지한다.
- 투명 외부와 프레임 중앙은0이다. 공통 바탕2종은 사각 내부를 채우는 재질이므로 캔버스 전체가204인 것이 의도된 형식이다.
- 따라서 Image.color.alpha는 **1**을 사용한다. 여기에0.8을 다시 곱하면64%로 변해 승인 시안보다 옅어진다.
- 기존 상위 CanvasGroup이 연출용 알파를 조절하는 것과 상시 배경 불투명도는 구분한다. 연출 제어 자체를 제거하지 않는다.
- Tab 지도의 기존80% 배경/클리핑 아트는 이번 대상이 아니며 교체하지 않는다.

## HUD·슬롯·보스HP 표시 영역

상태HUD는300×142, 좌상단(24,24) 기준이다. Q는좌하단, E/R은우하단이며1920×1080 좌상단 좌표로 Q(24,984), E(1744,984), R(1824,984)다.24px 화면 여백과 E/R8px 간격을 유지한다.

- 상태HUD PNG에는 레벨·HP·EXP·헬멧·생명·문구가 없다. 기존 별도 UI를 올린다.
- 슬롯의 내부 아이콘 Rect는(6,6,60,60)이다. Ready와 Normal의 이 영역 픽셀은 완전히 동일하고 가장자리 구리선만 다르다. Ready 표시 여부는 기존 사용가능 상태를 읽는 후속 시각 연결 대상이며 새 기능/쿨타임 조건을 뜻하지 않는다.
- Q/E/R, 물약 수량, 스킬 표식, 쿨타임 오버레이·수치는 Sprite에 포함하지 않았다. 기존 순서대로 프레임/아이콘→쿨타임 오버레이→숫자/단축키/수량을 표시한다.
- BossFrame은864×62이고 현재/지연 HP가 차지하는 **x2~861, y42~60**의 알파가0임을 검사했다. 이름과 트랙도 포함하지 않았다. 기존 이름/HP/지연피해 UI를 위에 유지하고 프레임을 그 뒤에 표시한다.
- 보스명 뒤 바탕이 필요하면 기존 Image 또는 공통 Slate를 이름 영역 안에만 사용한다. 게이지 내부를 새 배경으로 덮지 않는다.

## 버튼 적용 원칙

목재는 주요 행동 버튼에만 사용한다. 층·난이도·닫기·작은 선택 버튼은 암석 상태 세트를 쓴다. 타이틀 버튼 원본을 늘려 복사하지 않았고, Hybrid A의 빈 버튼 원형에서5개 상태를 분리했다.

Normal은 낮은 대비 목재/구리선, Hover는 상단선과 밝기, Pressed는 어두운 내부와 반전 음영, Selected는 기존 청록 선택선, Disabled는 저채도·저명도다. 레이블의 크림/청록/회색 처리는 TMP에 남겨 둔다. Sprite에는 레이블이 없다.

버튼5상태는 모두 같은 Border/크기/Pivot이다. 목재는 결과287×68, 퍼즈471×72 등의 크기로9-Slice 시험했고 원본 모서리가 보존됐다. 빈 원형이 추가됐다는 이유로 실제 버튼 수나 기능을 늘리지 않는다. 결과 다시 보기와 E/R의 동시 표시 문제는 기존 위치 그대로 남겨 후속 별도 판단 대상으로 둔다.

## 실제 검증 / 미검증

- 게임용19PNG를 다시 열어 크기·RGBA·실제 알파를 검사했다. 투명 픽셀RGB를0으로 정리했다.
- 목재/암석 각5상태가 모두 서로 다른 픽셀인지 확인했다.
- Large/Medium/Inset 및 모든 버튼 상태에서 실제 사용 크기의9-Slice 좌상·우하 모서리 픽셀 동일성을 검사했다. 결과는 `Specs/Validation.json`에 있다.
- 슬롯 Ready의60×60 내부 픽셀 보존, 보스 게이지 창 완전 투명, 클리어/실패 아트 동일성을 검사했다.
- 전체 목록·퍼즈·결과·보스HP 정적 합성을 직접 검토했다.
- 기존 시안·참조아트·관련문서·씬·프리팹·코드152파일의 작업 전후 해시가 동일하다.
- **미검증:** 실제 Unity Import/9-Slice 렌더러, TMP 줄바꿈·마스크·Sorting, 실제 마우스 전환, 다해상도·런타임 픽셀 정렬, 연출·전투·저장 회귀와 Play. 파일 검사/오프라인 합성을 Play 통과로 보고하지 않는다.
- 이전 조사에서 발견된 퍼즈620×600 제작 규격과 런타임1440×810 조회값 불일치는 수정하지 않았다. 후속 적용 담당자가 확인해야 한다.
