# MineExit v2 — 높은 갱도형 출구

v1.1의 낮은 가로형 출구를 **새로운128×128 비율로 재구성**했다. 목재·철판·못·어두운 암석 팔레트는 유지하되 높은 수직 지지대, 넓은 상부 들보, 불규칙한 암석 아치, 뒤로 이어지는 갱도 버팀목과 바닥 깊이를 새로 그렸다. v1.1 전체 이미지를 세로로 확대한 결과가 아니다.

현재 출구·게임 코드·Map01~10 프리팹·지형/충돌은 변경하지 않았다. 이번 폴더는 별도 시험 아트이며 자동 적용되지 않는다.

모든 셀128×128, RGBA 실제 투명 배경, PPU64, 중앙 Pivot(64,64)/(0.5,0.5), 가로1줄. 본체 알파는0/255이며 반짝임·발광은 의도된 부분 알파를 사용한다. 갱도 내부는 어두운 불투명 표면이다. 본체 자체 캔버스 표시 크기는2×2유닛이다.

## 비율 개선과 기존 디자인 유지

- v1.1 불투명 외곽은118×52px, 높이/너비 약0.44. v2는121×105px, 약0.87로 전체가 거의 정방형인 높은 입구가 되었다. 픽셀 배율/PPU를 바꾸지 않고 형상·문짝·목재 결을 다시 구성했다.
- 기존 문 내부 영역은51×30px, 새 내부는51×65px다. 현재 플레이어 원본의 불투명 몸체는48×56px여서, 정적 같은 PPU 합성에서는 기존보다 머리 위 여유가 생긴다. 이는 외형상 가독성 비교이며 실제 Collider 통과 검사가 아니다.
- 최종 외곽 bbox는 전 프레임 x4≤x<125, y12≤y<117로 같다. 상단 암석 아치·세로 기둥·문틀은 고정되고 문짝만 이동한다.
- 같은 새 문짝 두 장을 좌우로0/3/8/15/22/26px 이동해 열었다. 프레임마다 나무 무늬/철판을 다시 생성하지 않았다. 문짝 영역은x39≤x<90, y46≤y<111.
- 기존 v1.1 횃불 받침과 불꽃 픽셀을 네이티브 크기로 재사용했다. 위치만 새 기둥으로 옮겼고 긴 횃불·새로운 장식을 추가하지 않았다. 새 중심은 대략좌(31.5,63.5)/우(96.5,63.5). 잠김은 꺼짐, 개방 중 점등, 열림은 기존 미세한4프레임 불꽃 변화다.

## RoomExit2×1 판정과 시각2×2 정렬

**기존 RoomExit 중심·Root Scale·Collider·Trigger는 유지한다.** 이미 적용된 v1.1처럼 시각 자식만 사용한다. 읽기 확인한 현재 Map01의 RoomExit Root Scale은(2,1,1), 시각 자식 MineExitVisual_v1_1의 Scale은(0.5,1,1), 위치는(0,0,0)이다.

v2 시각 자식의 초기 제안값:

| 항목 | 제안값 |
|---|---|
| Root의 위치/배율/Collider |기존 유지, 수정하지 않음|
| 시각 자식 Local Scale |(0.5,1,1), 기존 가로2배 보정 유지|
| 시각 자식 Local Position |**(0,0.40625,0)**|
| 시각 Pivot |(0.5,0.5), 이미지 픽셀(64,64)|
| VFX 자식 |시각 자식 아래 Local Position(0,0,0), Scale(1,1,1), 같은Pivot/PPU|

위로0.40625유닛은26px다. 초기에 하단 반캔버스를 기준으로0.5유닛을 검토했으나, 두 파일의 투명 패딩을 측정해 **실제 불투명 하단 접지선을 맞추는26px**로 보정했다.

- v1.1 하단(배타 bbox)=59, 중앙32 → Root 아래27px.
- v2 하단(배타 bbox)=117, 중앙64 → 중앙 아래53px.
- 시각을위로26px 올리면53−26=27px이 되어 기존 실제 하단과 정확히 일치한다.

좌상단 이미지 좌표에서 Root 중심은v2의(64,90)에 해당한다. 기존2×1유닛 Collider의 시각 대응 영역은x0~128/y58~122다. 새 문틀 윗부분은 그 위로 솟고, 하단 출입·바닥 부분은 기존 판정과 겹친다. **이 사각형을 새 Collider로 만들거나 문 내부 개구부 크기로 Collider를 줄이지 않는다.**

개구부 안쪽은 x39~89/y46~110이며 중심축은기존과0.5px 차이다. 문틀 아래/상단이 판정과 같은 크기일 필요는 없다. 실제 통과·캐릭터 가림·상단 암벽과 겹침은 현장 적용에서 확인한다. 위값은 읽기 확인한 현재 부모Y배율1을 전제로 하므로 추가 부모 배율이 있으면 월드값으로 재검토한다.

이미지→Unity 로컬 변환은((px−64)/64,(64−py)/64), 그 뒤 시각 자식 배율과위쪽 오프셋을 적용한다. Root의 Scale2배를 중복 적용하지 않는다. 중앙Pivot 대신 하단Pivot으로 임의 변경하면 이 정렬식이 달라지므로 둘을 동시에 적용하지 않는다.

## 재생 시간과 게임 규칙

- 개방·점등6프레임:60/70/80/100/110/100ms=0.52초. F1=잠김PNG, F6=열림PNG. 최종 열림은0.42초부터 표시된다.
- 횃불4프레임:180/160/200/160ms=0.70초. F1=열림PNG, 기존 v1.1 불꽃 모양/색/리듬 재사용.
- 반짝임6프레임:40/60/70/80/80/70ms=0.40초. 개방완료+0.52초에1회, 마지막 프레임은 투명.
- 갱도 발광8프레임:각350ms=2.80초. 개방 완료 이후 열린 동안 반복. 횃불과 독립 타임라인이다.
- 이미 열린 출구를 활성화하면 열림/횃불/발광만 표시하고 개방·반짝임을 반복하지 않는 기존 원칙을 유지한다.

**몬스터 전멸 순간 기존 출구 통과 가능 규칙은 그대로다.** 개방0.52초나 반짝임0.40초가 끝날 때까지 Collider/Trigger·방 이동을 기다리게 하지 않는다. 출구 개방·이동 판정/지형/전투는 아트 애니메이션이 소유하지 않는다.

## VFX 재정렬

기존 피드백 팩을 통째로2배 확대하지 않았다.

- 반짝임: 기존1~3px 입자 모양·색·알파·좌우/위쪽 경로는 그대로,128×128 새 개구부 안에 맞춰 **Y+42px만 이동**했다. 입자 크기와0.40초는 같다.
- 발광: 기존 시트의 실제 작은 빛 패치만 추출해새 내부 하단(x43~85,y68~105)에 맞췄다. 패치의가로43px는 유지하고 높이25→38px로 내부 공간에 맞게 정리했다. 문틀/불꽃은 포함하지 않는다. 최대 알파48 이하·기존8단계 밝기·2.80초를 유지한다.
- VFX도128×128/PPU64/중앙Pivot으로 본체 시각Transform에 겹친다. 별도 월드Y오프셋을 다시 더하면 조명 위치가 어긋난다.
- Sorting은현재 출구시각Order S 기준 발광S+1/반짝임S+2를 시험값으로 유지하되 플레이어·전투효과보다 아래에 둔다. 실제 프로젝트 Sorting을 우선한다.

## Unity 가져오기

- 정지 PNG2개:Sprite Single. 시트4개:Multiple, Grid Cell128×128, Rect n=(128×n,0,128,128), n은0부터.
- PPU64, 중앙Pivot, Point, Compression None, Mip Maps Off, Alpha is Transparency On, Max Size1024 이상.
- 기존 적갈색/초록색 Tint를 새 시각PNG/VFX에 중복 적용하지 않는다. 중립흰색으로 표시하고 실제 상태·레이어·Trigger 처리는 유지한다. v1.1 통합에서 이미 분리된 시각 구조라면 그 구조를 기준으로 재확인한다.
- 현재 MineExitSpriteAnimation의0.52/0.70/0.40/2.80초와 프레임 수를 유지했으므로 시간 배열을 바꿀 이유가 없다. 실제 시트참조·새 셀 Slice·위치·가림 연결은 후속 Codex가 담당한다.
- 새 상단 아치는 기존보다 약53px(0.828125유닛) 더 위로 올라간다. 문 위쪽의암벽·장식·화면상단과 겹침을 확인하되 새 공간을 확보하려고 지형/충돌을 변경하지 않는다. 시각레이어의 겹침과 렌더링 순서를 우선 검토한다.

- Environment_GameRatio_1024x576.png:16:9,세로9유닛을64px/유닛으로 표현한 비교용 환경 합성. Main 씬에기록된 Orthographic Size4.5를 기준으로 한 카메라 크기 시험이다.
- Environment_GameRatio_1920x1080_Example.png:같은 시야를1080p로 표시한 예시. 현재 실행 화면 해상도/PixelPerfect 결과가 확인됐다는 의미는 아니다.
- Environment_v1_1_SameRoot_1024x576.png:같은 Root위치·카메라 범위의 기존출구 비교.
- Doorway_Player_Headroom_3x.png:접근 중플레이어와새 출구 확대. Player_At_Threshold_3x.png:플레이어를문턱에 놓아 크기를 비교한 정적 합성. 실제 이동/충돌 검증은 아니다.
- Alignment_Collider2x1_Visual2x2.png:기존 판정영역(초록)과새 시각영역(황토),유지된Root 중심십자선. 검토 전용이며 게임용 PNG에 선이 없다.
- v1_1_vs_v2_SamePPU_6x.png:실제 불투명 하단을같은 기준선에 맞춘 비율 비교. 이미지 자체의PPU/캐릭터배율은 바꾸지 않았다.
- Opening/TorchLoop/Sparkle_Only/Glow_Only Native 및4x GIF, Full_Sequence GIF, Environment_FullSequence_GameRatio.gif를 제공한다. 전체GIF의잠김600ms는검토 대기다. 게임에서 문을 반복잠그라는 의미가 아니다.

## 실제 검증과 미검증 사항

확인한 항목:

- 게임용 PNG 6개의 크기, RGBA, 128×128 셀과 프레임 수, 투명 알파를 검사했다.
- 본체 외곽과 고정 문틀은 모든 프레임에서 유지되며 잘림이 없다. 개방 첫 프레임은 잠김, 마지막은 열림, 횃불 첫 프레임은 열림 PNG와 일치한다.
- 반짝임과 발광은 새 개구부 안에 들어가고 횃불·문틀을 침범하지 않는다. 기존 VFX 전체를 확대하지 않았다.
- 현재 Root를 유지한 채 시각 오프셋으로 v1.1과 실제 불투명 하단 접지선을 맞추는 좌표식을 검증했다.
- 같은 PPU의 원배율·확대 정지 합성에서 높은 기둥과 암석 아치가 읽히고, 플레이어 머리 위 여유가 생겼다. 눌린 형태가 개선됐다는 판단은 이 정적 비교를 근거로 한다.
- GIF의 모든 프레임을 디코딩해 표시 시간과 예상 화면을 비교했다. PNG 원본은 GIF의 256색 제한과 구분한다.
- 기존 v1.1과 피드백 VFX, 관련 코드·맵 프리팹·Main 씬의 작업 전후 해시를 비교했다. 결과는 Specs/Validation_and_Alignment.json에 있다.

미검증 사항:

- 실시간 GIF 재생을 직접 관찰하지 못했다. 연속 동작의 자연스러움은 정적 검사·디코딩과 구분해 미검증으로 보고한다.
- Unity Play와 현재 실행 카메라, 실제 Map01 배치의 상단 암벽 가림, 실제 통과 판정, 무기를 포함한 플레이어 가림은 후속 Codex 확인 대상이다. 정적 슬라임이 개구부보다 작다는 비교는 물리 통과 검사가 아니다.
- 시각 Offset 0.40625는 현재 루트 배율을 기준으로 한 적용 시험값이다. 아트 위치만 조정하며 판정과 맵을 바꾸지 않는다.

## 제작 출처

이미지 생성 스킬의 내장 image_gen으로 v1.1과 기존 목재·암벽을 참고해 높은 구조를 새로 제작했다. Source/TallMineExit_Generated_Atlas.png는 생성 보관본이며 게임용 아틀라스가 아니다. 최종 파일은 고정 문틀과 동일한 문짝 픽셀을 재사용해 구성했다. 기존 횃불과 VFX는 위에서 설명한 범위만 옮기거나 새 공간에 맞췄다. 생성 조건은 Source/Generation_Brief.md에 기록했다.
