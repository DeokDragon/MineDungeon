# 돌골렘 최초 등장·P2 변신 아트 v1

현재 Assets의 채택 P1/P2 Idle·Move 및 제작/적용된 공격10종의 외형 기준으로 만든 시각 전용 리소스다. 미채택16프레임·0.40초 보행 포즈는 사용하지 않았다. 기존 소스 암석판과 편집용 관절 리그를 재사용했으며, 캐릭터를 새로 생성하거나 전체 이미지 확대/축소/월드 이동으로 연출을 대체하지 않았다.

모든 PNG는 가로1줄/RGBA/실제 투명 배경/알파0·255다. **본체 PPU128, 중앙 Pivot(80,80)/(0.5,0.5), 기존 Body Scale1.8 유지.** 파편은 본체160셀 밖까지 이동하므로192셀에 분리했다. 파편 Pivot은(96,96)으로 본체 중심에 정렬한다. 추가 광역 발광·충격파·공격·피해는 없다.

마지막 프레임은시험2.5초 종료 시까지 유지한다. P1/P2를 한 번에 교체하거나 반투명 전체 페이드로 변신을 대신하지 않았다. 원본 P2의 균열 위치에서부터 어두운 균열→발광→부위별 판 교체가 진행되고, 상체/팔/어깨/머리 순서로 P2가 완성된다. 원본 P2 균열·눈·외곽 형태를 추가 재디자인하지 않는다. 중간 발광은 기존 P2 색으로 향하는 단계적 색 변화이며 최종에는 기존 P2 픽셀이 정확히 표시된다.

## 본체 중심과 발 접지

본체 프레임의 Root Motion/월드 이동은 없다. 최초 등장 때 상체가3~5px 낮아지고 팔·관절이 움직이지만 두 발의 기준 위치는 유지한다. 변신 때 몸체 중심·다리 레이어를 이동시키지 않고 선택된 어깨·팔 암석만 최대1px 반응시킨다. 두 원본의 근거리 발 최하단Y141, 원거리 발Y132라는 깊이 차이를 유지한다. 전체 불투명 bbox의 아래 경계는 낮아진 주먹 때문에 발 기준보다 아래에 올 수 있으므로 단순 bbox 바닥을 접지 위치로 간주하지 않는다.

변신 도중 외곽 bbox는 P1에서 P2의 더 벌어진 어깨/암석 실루엣으로 바뀐다. 이는 승인된 두 원본 사이의 구조 변화이며 전체 캐릭터 확대/축소가 아니다. 두 원본에서 공통인 발바닥 픽셀 좌표가 모든 본체 프레임에서 불투명하게 유지되는지 별도로 검사했다. 최종 발의 색·모양은 각각의 원본 그대로다.

## 별도 파편 VFX

192×192/8프레임/PPU128/중앙(96,96). **변신 F6 시작0.86초**에 재생한다. VFX F1~8의 시간은180/190/190/190/190/180/180/180ms로, 변신 F6~13과 동기화된다.

4개의 아주 작은 원본 암석 조각이 바깥·아래로 떨어진다. VFX F7에서 일부 픽셀이 사라지고, F8(변신F13 시작2.16초)부터 전체 투명이다. 마지막 투명 프레임을 포함한 클립은2.34초까지며 그때 정리할 수 있다. 본체가 소멸하거나 사망하는 연출이 아니고 바닥에 지속 잔해/장애물/피해를 생성하지 않는다.

VFX는 본체와 같은 위치, 같은 유효 PPU·배율로 표시한다. 예를 들어 Body 아래 시각 자식 Local Position(0,0,0)/Scale(1,1,1)을 쓰면 기존 Body Scale1.8이 한 번 적용된다. 다른 루트에 둘 때는 현재 부모 배율을 확인해 중복 적용하지 않는다. 160셀과192셀을 좌상단으로 맞추지 않고 중앙 Pivot으로 맞춘다. 수동 합성은 본체를192셀의(16,16)에 배치한 것과 같다. 현재 flipX를 쓸 경우 파편도 동일 기준을 적용한다.

## 정상 완료·스킵·기존 AI와의 관계

- 등장 정상 완료/스킵: **P1 Idle F1**, 이번 Intro F10과 같은 RGBA를 즉시 표시한다.
- 변신 정상 완료/스킵: **P2 Idle F1**, 이번 Transform F14와 같은 RGBA를 즉시 표시하고 모든 파편을 지운다. 중간 프레임이나 파편 재생 종료를 기다리지 않는다.
- 기존 `PresentationStarted(ai, transformation)`의 bool로 두 시각 클립을 구분하고, 기존 `PresentationEnded`/스킵 경로와 연결하는 것은 별도 Codex 구현 범위다. 현재 소스는 연출 드라이버가 종료를 전달하는 구조이며 `EndPresentation`이 실제 Phase2 전환 등을 소유한다. PNG 프레임 도달을 이유로 아트 쪽에서 Phase/HP/피해/쿨타임을 임의 변경하면 안 된다.
- 실제 완료 시각·EndPresentation 호출 순서·AI 전투 제한 해제는 통합 담당자가 확인한다. 이번2.0/2.5초는 제작용 시험값이며 최종 확정이나 전투 시간 변경 명령이 아니다.
- 현재 Sprite 표시 코드가 Presentation 중 Idle을 선택하므로 이 PNG만 넣어서는 자동 재생되지 않는다. 연출 표시 우선권을 기존 공격/Idle 표시와 조율하는 후속 코드 연결이 필요하다.
- 사망/플레이어 사망/연출 중단은 기존 AI가 우선이다. 사망 연출 위에 강제로 Idle을 덮지 않으며, 파편만 즉시 정리한다. 카메라 이동·줌·스킵 UI·공격·피해·전투 쿨타임 기능은 추가하지 않았다.

## 가져오기

1. 본체 시트는Sprite Multiple, Grid160×160, 좌→우. Rect n=(160×n,0,160,160), n은0부터. PPU128/Pivot(0.5,0.5).
2. 파편 시트는Grid192×192, Rect n=(192×n,0,192,192), PPU128/Pivot(0.5,0.5).
3. Point / Compression None / Mip Maps Off / Alpha is Transparency On. **변신 시트 폭2240px이므로 Max Size4096 이상**으로 가져와 자동 축소를 막는다.
4. Body Scale1.8 유지. 이미지 원점은좌상단/+x오른쪽/+y아래. 본체 Unity 로컬=((x−80)/128,(80−y)/128), 파편은80대신96을 쓰고 기존 배율을 뒤에 한 번 적용한다.
5. 가변 프레임 시간을 사용한다. 단순10FPS/14FPS로 재생하면 제안 구간이 달라진다. 최종 시간이 바뀌면 타임라인을 정규화해서 표시할 수 있으나 AI/쿨타임 변경으로 보정하지 않는다.

## 실제 확인한 사항 / 미검증

확인:

- 본체10/14프레임과 별도 파편8프레임의 크기·RGBA·알파0·255·정확한 셀 분할.
- 본체/파편 셀 경계의 불투명 픽셀 잘림 없음. 본체 실루엣은 매 프레임 하나로 연결됨.
- 등장 마지막=P1 Idle F1, 변신 첫=P1 Idle F1, 변신 마지막=P2 Idle F1을 RGBA 전체 배열로 비교해 정확히 일치.
- 기존 공격10종의 첫 프레임도 해당 P1/P2 Idle과 정확히 일치하므로 연출 종료 후 기본 시작 포즈 기준이 연결됨. 실행 도중 공격 포즈로의 전환은 통합 동작 검증 대상이다.
- 원배율/확대 정지 비교에서 눈 점등·상체 일으킴·균열 단계·부위별 P2 전환이 구분됨. 원본 암석 비율·팔레트 구조를 사용하고 최종 외형을 보존함.
- 발 접지 공통 좌표 검사, GIF 디코딩·시간 검사. 기존 원본/Idle·Move/공격10종/관련 코드·보스 프리팹·공식 문서 해시 보존 검사.

미검증:

- 실시간 GIF 반복을 직접 관찰하지 못했다. 연속 재생의 자연스러움/무게감/암석 교체 경계는 정적 포즈 검사와 구분해 미검증으로 보고한다.
- 현재 Unity 카메라 실제 게임 크기, Unity Play, 연출 이벤트 동기화·정상 완료·스킵·사망 중단·전투 제한 유지·공격 복귀는 별도 Codex 검증 범위다. 이번 Native 미리보기는160px 원본 픽셀 크기이며 실제 카메라 표시 크기를 보증하지 않는다.
- 변신 중 부위 교체 시 암석 경계의 이음새가 실제 재생에서 충분히 자연스러운지 추가 검토가 필요하다. 전체 크로스페이드/무작위 픽셀 용해 대신 부위별 전환을 택했으며, 자연스러움이 최종 승인됐다는 의미는 아니다.

프레임별 좌표·시간·검사 결과는 Specs/Unity_Presentation_Spec.json과 Validation_and_Timing.json에 기록했다. 이번 작업은 새 아트 폴더만 생성했고 Unity 구현/공식 문서/Git 커밋·푸시는 수행하지 않았다.
