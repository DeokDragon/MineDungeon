# 돌 골렘 P1 이동 접지 시험 v1

## 결론과 현재 채택 상태

**기존 v4.1을 유지합니다.** 새 시트는 P1 수평 정속 이동용 시험 후보이며 자동 교체하지 않았습니다. 수평 접지의 수치 개선은 확인했지만,0.40초 주기의 무게감과 전반적인 자연스러움을 실제 재생/Unity Play로 확인하지 못했습니다. 상하·대각선까지 같은 접지가 유지되는 시트도 아닙니다. 따라서 기존보다 전반적으로 명확하게 개선됐다는 채택 판정은 보류합니다. P2는 제작하거나 변경하지 않았습니다.

## 1. 시험 규격

- `Sprites/StoneGolemBoss_P1_Move_16f_160x160_T040_Trial_v1.png`
- 160×160셀16개, 가로1줄, 전체 **2560×160 RGBA PNG**.
- 실제 외부 투명, 알파0/255, 선명한 최근접 픽셀. 게임용 시트에 바닥·가이드·텍스트·그림자 없음.
- 원본128px 캐릭터 픽셀 배율 유지. 동일16px 패딩, 중앙 Pivot (0.5,0.5) 유지.
- 시험 PPU128, 보스 본체 배율1.8, 이동 속도 **1.4유닛/초**.
- 보행 주기 **0.40초는 시험 후보**.16프레임, 각25ms/40fps에 해당. 최종 공식 주기 아님.
- 지지발은50% 구간을 지지하고 반대50%에서 회수. 좌우 반주기 차이0.20초.

**프레임 수 선택 이유:**0.40초/현재 배율에서6프레임은1장 유지 중 약6.64px만큼 루트가 이동합니다.12프레임은3.32px,16프레임은2.49px,20프레임은1.99px입니다.16은 접지 양자화와 제작/검수 부담의 절충 시험입니다.20보다 소폭 거칠지만 중복 방향 시트를 늘리지 않았습니다. 기존 픽셀 리그를 사용해16장을 새 골렘으로 각각 생성하지 않았습니다.

16장은 폭2560이므로, 후속 Unity 시험 시 기존 리소스처럼 Max Size2048로 줄이지 않도록 **4096 이상의 임포트 허용 크기**가 필요합니다. 이번에 임포트 설정은 바꾸지 않았습니다.12장/1920폭은2048 안에 들어가는 대안이지만 접지 유지 중 루트 이동량이 약0.83px 더 큽니다.

## 2. 기준 파일과 읽기 전용 확인

기존 비교 시트는 `Assets/Art/Bosses/StoneGolem/StoneGolemBoss_P1_Move_6f_160x160_v4_1.png` 실제960×160 PNG입니다. 원형은 `D:/던전 게임/아트 리소스/몬스터 정지 이미지/Code_Generated1_Image.png`이며 현재 P1 Idle F1의16px 패딩 안쪽과 동일합니다.

현재 `BossRoom24x22.prefab`에서 P1 v4.1의6장 참조, 본체 로컬 배율1.8, 이동 재생5.5555553fps, 프레임 가중치0.17/0.21/0.16/0.17/0.21/0.16을 읽었습니다. 한 주기는1.08초입니다. AI 이동 속도1.4도 읽었습니다. 기존 `Library/StoneGolemMoveV41/play.txt`에는 약1.4유닛/초에서 지지발이0.54초 동안 약0.756유닛 이동한 기록이 있습니다. 이 기존 기록을 이번에 새로 Play한 결과처럼 보고하지 않습니다.

배율1.8은 현재 프리팹과 기존 검증 자료를 기준으로 사용했습니다. 실행 중 다른 부모 배율/피격 변형까지 새로 실측한 것은 아니므로, 후속 통합에서 실제 lossyScale이 다르면 경로를 다시 계산해야 합니다.

## 3. 실제 이동량을 반영한 발 경로

원본 픽셀1개가 나타내는 세계 길이 =1.8/128=0.0140625유닛입니다.

- 루트의 원본 픽셀 속도: **1.4×128/1.8=99.5556px/초**.
- 반주기0.20초의 지지 구간: **19.9111px** 뒤로 이동해야 루트 이동이 상쇄됩니다.
- 한 주기 루트 이동:0.56유닛/39.8222px. 한 발의 지지 구간은0.28유닛입니다.

지지 구간의 몸체 기준 발 X는 `앞쪽 접지점−99.5556×경과시간`입니다. 루트의 `+99.5556×시간`과 합하면 이상적인 세계 접점은 고정됩니다. 발은 로컬 좌표에 고정하지 않았습니다.

회수 구간은 뒤쪽에서 앞쪽으로 이동합니다. 정규화 회수 진행률u에 대해 `f(u)=−4u³+6u²−u`의 경로를 사용해 이륙/착지 때의 접선 속도를 지지 구간과 연결했습니다. 양 끝의 약1px 이내 작은 초과 이동은 급격한 방향 전환을 피하기 위한 것입니다. 들어 올리는 높이는 가까운 발9px/먼 발8px, `sin²(πu)`이며 양 끝의 상승·하강 속도는0입니다. 발목의 작은 피치로 바닥에서 떨어지는 실루엣을 보조했습니다.

허벅지·정강이는2관절 IK로 각각 회전하고 기존 길이를 늘이지 않았습니다. 무릎·발목의 노출된 연결부에만 원래 암석 팔레트의 관절 뒤면을 사용했습니다. 기존 리그에서 몸통으로 잘못 분리되어 있던 작은 팔꿈치/발목44픽셀은 원래 픽셀 그대로 이웃 팔다리에 재배정해, 발 이동 후 뒤에 남는 작은 암석 조각을 제거했습니다. 최종16프레임은 모두 하나의 연결된 몸체입니다.

지지발 전체 신발은 원본 픽셀의 정수 이동으로 유지됩니다. 실제 최종 합성물의 밑창 마지막2행이 신발 레이어와 같은 좌표/RGBA인지 검사했습니다. 지지발은 단순 표시 점만 고정하고 신발을 변형한 것이 아닙니다.

## 4. 몸체와 무게감

- 착지 때 가슴은1~2px 눌리고, 골반은 무릎을 굽힌 보행 자세에 맞춰 약4px 낮게 유지됩니다.
- 가슴/머리는 작은 하중 이동을 따라가며 얼굴·호박색 눈은 원본 형태와 RGB를 유지합니다.
- 어깨는 약0.024초, 팔/주먹은 약0.040초 늦게 반응하는 위상으로 구성했습니다. 큰 팔 휘두르기는 하지 않았습니다.
- 허리·다리의 국소 변화이며 캐릭터 전체를 상하로 이동시키지 않았습니다. 원본 어깨/주먹/몸체를 재디자인하지 않았습니다.
- 프레임 사이 최대 발목 위치 변화는 약5.09px입니다. 기존 v4.1과 같은 다리 포즈가 아니며, 지지/회수 궤적을 다시 구성했습니다.

0.40초는 양발 한 주기이므로 초당5번 발 디딤이 발생합니다. 기존1.08초의 약1.85번보다 빠릅니다. 접지가 개선돼도 이 빈도가 거대 골렘의 무게감을 약하게 만들 수 있습니다. 이것이0.40초를 최종 확정하지 않는 이유입니다. 주기를 더 느리게 시험하려면 이동 속도를 그대로 둔 채 **발 경로 길이도 주기에 맞춰 다시 계산**해야 합니다. 이 시트를 재생 속도만 늦추면 접지가 다시 어긋납니다.

## 7. 방향·전환·Unity 통합 제한

**이번은 우측 수평 이동의 발 경로 시험입니다.** 좌측은 같은 시트를 반전하는 진단을 제공했습니다. 상하/대각선은 발이 그 이동 벡터의 반대 방향으로 움직여야 하므로 단일 고정 X경로로는 모두 고정할 수 없습니다. 예를 들어 위아래 이동에 이 X경로를 그대로 쓰면 미끄러짐이 더 커질 수 있습니다. 방향별 경로나 실제 이동량 기반 발 보정은 별도 검토이며 이번에 구현하지 않았습니다.

기존 Idle의 중심·원본 배율·발 깊이 기준은 유지했지만, 이번은 정속 보행의 정상 반복 시험입니다. Idle→첫 보행,방향 변경,가속/정지,공격 전환에서의 접지는 검증하지 않았습니다.

후속 통합 시 기존16장 참조와0.40초에 맞는 시각 재생 설정이 별도로 필요합니다. 현행6장/5.555fps 설정에16장만 넣으면 주기가 달라집니다. 시험 기준은40fps/16장 또는 동등한0.40초 재생입니다. 실제 이동 속도1.4나 전투 기능을 바꾸라는 뜻이 아닙니다. 현재 속도 연동 재생식은 읽었지만 설정을 적용하지 않았습니다. 방향과 최종 주기가 정해진 뒤 Codex가 확인할 항목입니다.

## 9. 보존과 파일

`Sprites/`는 시험 PNG, `Previews/`는 비교 GIF, `Review/`는 포즈·발 경로·검증 데이터입니다. `Preview_Index.html`에서 비교 파일을 열 수 있습니다. 기존 P1/P2/Idle/원본/Unity Assets/코드/프리팹/씬의 읽은 파일 해시를 확인했고 변경하지 않았습니다. 공식 문서·이동 속도·전투 기능을 수정하지 않았으며 Git 커밋/푸시도 하지 않았습니다. 새 파일은 이 Art Resource 시험 폴더에만 추가했습니다.
