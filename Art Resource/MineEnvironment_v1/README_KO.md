## 제작·가져오기 규격

이번 세트의 제안 PPU는 **64**이며 공식 확정 규격이 아닙니다.

- 반복 바닥/일반 암벽 표면: 64×64px = 1×1유닛.
- 경계 기본 모듈: 32×32px = 0.5×0.5유닛.
- 좁은 벽 표면: 16×64px = 0.25×1유닛.
- 소형 장식 16~32px, 중형 32~64px. 보스룸 광맥·바닥 데칼은 최대 128px.
- 모든 게임용 파일 RGBA. 반복 표면은 불투명, 독립 소품은 투명 배경입니다.
- 소품의 Alpha는 0/255. 바닥 데칼 Alpha 0/100, 접점 음영 Alpha 0/110은 의도된 낮은 대비입니다. 흐린 가장자리나 가짜 체크 배경이 아닙니다.
- Point Filter, 압축 없음, Mipmap 끔을 시범 기준으로 권장합니다. 플랫폼별 자동 축소가 적용되지 않도록 원본 해상도를 확인합니다.
- 개별 PNG는 Single Sprite, Pivot은 모두 **중앙 (0.5, 0.5)** 기준입니다. PNG 자체에는 PPU·Pivot·Sorting Layer가 저장되지 않습니다. 이번 납품에는 `.meta`가 없습니다.
- 캐릭터의 이동 방향에 따른 가림을 자동 설정하지 않았습니다. 상자 등을 벽 장식으로 쓰는 현재 범위에서는 캐릭터 아래 표시를 우선 제안합니다.

표시 순서는 기존 프로젝트 레이어를 확인한 뒤 대응시킵니다. 아래 이름은 **제안 이름**이며 실제 생성·설정하지 않았습니다. 숫자는 동일한 기존 환경 정렬 그룹 안에서의 상대 예시입니다. 캐릭터·기존 공격 예고보다 아래에 둡니다.

| 제안 그룹 | 상대 순서 | 대상 |
|---|---:|---|
| EnvironmentFloor | -50 | 반복 바닥 |
| EnvironmentDecal | -45 | 균열·마모·채굴 흔적·보스 바닥 흔적 |
| EnvironmentShadow | -40 | 벽 밑 접점 음영 |

| EnvironmentBorder | -20~-19 | 접점·코너·캡 |

| EnvironmentProps | -10 | 작은 소품·목재·잔해 |

## 반복 바닥 사용

`Floor_RockGray_64x64`를 주 바닥으로 사용하고, ExposedEarth/CoolStone/WornStone을 부분적으로 섞습니다. WornStone은 긁힘이 있으므로 드물게 사용합니다. 동일한 64px 무늬를 무한 반복하면 무늬 자체의 반복은 보일 수 있습니다. 변형 혼합과 별도 마모 데칼을 활용하되 일정 간격으로 같은 소품을 놓지 않습니다.

바닥 네 종류는 서로 맞닿는 네 변의 RGB가 같도록 내보냈습니다. 모든 종류 쌍 16개에 대해 양 축 경계 픽셀 차이 0을 확인했습니다. 이는 색상 경계 검증이며 실제 Unity 카메라·압축·픽셀 정렬의 결과를 보증하지 않습니다.

암벽 표면 4종은 각각 같은 종류끼리 양 축 반복하도록 제작했습니다. **서로 다른 암벽 표면 종류의 경계 호환은 보증하지 않습니다.** 다른 표면이 만나는 곳은 광맥·독립 암석·균열로 연결하거나 기존 벽 덩어리별로 종류를 나눕니다.

## 불규칙 암벽과 좁은 조각의 조합

기존 Floor/Rock/RockFace/BoxCollider2D와 경로 영역은 그대로 두고, 별도 시각 레이어에서 조합하는 것을 전제로 합니다.

1. 기존 바닥 범위에 반복 바닥을 표시합니다. 전체 방을 하나의 큰 배경 PNG로 바꾸지 않습니다.
2. 기존 Rock의 시각 범위 안을 Wall 표면으로 채웁니다. 표면은 반복/잘라 쓰고, 큰 사각형에 한 장을 과도하게 늘여 픽셀을 길쭉하게 만들지 않습니다.
3. 바닥과 만나는 직선 구간에 `RockRim_South/East/North/West`를 해당 방향으로 이어 놓습니다. 이름은 벽에서 바닥을 바라보는 방향입니다. 반복 축은 Manifest에 기록했습니다.
4. 바깥으로 꺾이는 곳은 `CornerOuter`, 안으로 들어가는 곳은 `CornerInner`를 겹쳐 연결합니다. 코너 방향은 기본 SE 이미지의 회전 변형입니다. 자동 연결 규칙이나 고정 좌표가 아닙니다.
5. 짧은 끝은 `RockEndCap`으로 덮고, 필요한 곳에 `WallFoot_Shadow`를 먼저 배치해 암벽과 바닥을 분리합니다. 접점과 코너의 내부 픽셀까지 자동으로 일치하는 오토타일 세트는 아니므로 겹침과 끝 캡으로 이음새를 정리합니다.
6. 0.25유닛 폭에는 `Wall_NarrowStrip_16x64`를 사용합니다. 높이 방향 반복, 끝에서 잘라 쓰기가 가능합니다. `RockSpine_Narrow_16x64`는 불규칙 실루엣 장식이며 연속 표면 대체재가 아닙니다.
7. 경계 모듈의 0.5유닛 폭이 실제 벽보다 넓으면 통째로 덮지 않습니다. 벽 시각 영역 안에서 잘라 쓰거나 16px 스트립·독립 음영으로 처리합니다. 1×1 타일 격자에 맞추려고 충돌을 수정하면 안 됩니다.
8. 벽 광맥·목재·큰 잔해는 기존 충돌 영역 안쪽을 우선합니다. 경계 픽셀의 작은 시각 돌출까지 실제 통행 폭·몬스터 몸체와 비교해 별도 적용 작업에서 확인해야 합니다.

`Previews/BorderAssembly_Examples.png`는 이 조합 방법의 확대 예시이며 실맵이나 충돌 배치도가 아닙니다.

## 미리보기 해석과 검증

16×9 미리보기는 **1024×576px, 64 PPU의 가상 화면 구성**입니다. 방 전체 지도·실제 프리팹·Unity 적용 결과가 아닙니다. 플레이어 약 0.8유닛, 일반 몬스터 약 1유닛, 보스 약 2.25유닛에 대응하는 프레임 크기로 원본을 비교 합성했습니다. PNG의 투명 여백을 포함한 크기이므로 가시 실루엣 크기는 더 작습니다. 기존 캐릭터 원본은 수정하지 않았습니다.

실행한 파일 검증은 `Specs/Validation.json`에 기록했습니다.

- 게임용 50개 모두 RGBA, 규격과 파일 목록 일치.
- 독립 소품/데칼의 바깥 테두리는 모두 투명. 반복 표면과 반복 경계의 연결 축은 의도적으로 가장자리 픽셀이 존재합니다.
- 바닥 4종 16개 조합, 상하좌우 가장자리 RGB 차이 0.
- 암벽 표면 4종 각각 자체 반복 가장자리 RGB 차이 0.
- 16px 좁은 표면과 방향별 직선 경계·접점 음영의 반복 축 RGBA 차이 0.
- 종류별 바닥 5×5 및 혼합 미리보기, 일반/보스 가상 화면, 원배율 비교, 전체 모음 시트를 직접 열어 검토했습니다.
- 흙/청회색 변형의 격자 인상을 줄이도록 색 차이를 낮추고, 잘못된 작은 잡점 때문에 좁은 장식이 축소되는 문제를 수정했습니다. 픽셀 확대는 Nearest, 팔레트 축소는 디더링 없이 처리했습니다.
- 바닥의 낮은 대비와 캐릭터의 높은 대비, 벽/바닥의 구분, 목재/광맥/잔해의 식별성을 미리보기에서 확인했습니다. 보스 바닥 흔적은 밝은 원형 문양이 아닙니다.
- 납품 전 Unity 콘솔 오류 조회 결과 0건. 이번 작업은 Assets 밖의 아트 제작으로, 새 게임 코드의 컴파일 테스트를 실행한 것은 아닙니다.

**미실행:** Unity Import/실제 맵 적용, 실제 카메라 이동과 공격 예고의 중첩, 통행·전투 테스트, 배포 빌드. 이번 작업에서 Unity 코드·씬·프리팹·기존 객체·공식 기획 문서를 수정하지 않았으며 Git 커밋·푸시도 하지 않았습니다.

## 제작 이력과 재현 자료

아트 원본은 내장 `image_gen`으로 실제 적용 리소스를 스타일 참조하여 생성했습니다. `Specs/GenerationPrompts.json`에 사용 프롬프트 3개를 보관했습니다. 별도의 API/CLI 이미지 생성 경로는 사용하지 않았습니다.

개별 PNG는 생성 아틀라스에서 분할하고 규격에 맞게 픽셀 리샘플링, 참조 팔레트 정리, 반복 표면 가장자리 보정, 투명 여백 정리를 거쳐 내보냈습니다. 단순 도형을 그려 생성 아트를 대체한 세트가 아닙니다. 재현용 `Specs/export_assets.py`는 Pillow 13으로 실행했으며 게임 런타임에는 필요하지 않습니다. 생성 원본 자체를 사용하려면 개별 PNG의 완성 규격·가장자리 보정이 적용되지 않았다는 점을 구분합니다.

전체 묶음: `Art Resource/MineEnvironment_v1.zip`. ZIP에는 게임용 PNG·미리보기·규격·생성 원본·README를 포함하고 기존 캐릭터 원본 파일과 이미지 처리 라이브러리는 포함하지 않습니다.
