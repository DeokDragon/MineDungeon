# 돌골렘 보스 P1 기본 공격 아트 v1

현재 채택된 P1 Idle/Move v4.1 및 원본 암석판 구조를 기준으로 만든 본체 전용 리소스다. 미채택 16프레임·0.40초 보행의 포즈는 사용하지 않았다. Unity 적용/Play 검증은 수행하지 않았다.

## 게임용 파일과 구간

번호는 1부터 시작하며 양 끝을 포함한다. PNG는 가로 한 줄, 셀 160×160, RGBA, 알파 0/255다. 총 50프레임.

## 포즈와 프레임별 역할

원본 픽셀의 암석판을 분리한 기존 편집용 리그를 사용했다. 팔꿈치·무릎을 관절 기준으로 움직이고, 관절 뒤의 암부만 원본 팔레트로 연결했다. 전체 캐릭터 확대/축소나 평행 이동으로 동작을 대체하지 않았다. 얼굴과 호박색 눈 픽셀은 모든 포즈에서 동일한 형태·색상으로 유지한다. 발광/VFX/투사체/지면/그림자는 포함하지 않는다.

- 도약: F1 기본, F2 힘 모음, F3 깊은 웅크림, F4 이륙, F5 다리 모음, F6 착지 준비, F7 접촉, F8 최대 압축, F9 충격 흡수, F10 일어서기, F11 Idle. 공중 자세의 발 접기는 관절 변화이며 본체의 도약 높이를 시트에 추가하지 않았다.
- 강타: F1 기본, F2 팔 올리기, F3 들어 올린 팔, F4 최대 준비, F5 내려치기 시작, F6 지면 접촉, F7 압축, F8 힘 풀기, F9 복원, F10 Idle. 거대한 주먹의 비대칭과 시점상 접촉 깊이 차이를 유지한다.
- 돌진: F1 기본, F2 어깨 준비, F3 낮은 방어, F4–7 낮은 실행 자세와 제한된 발/팔 반응, F8 제동, F9 균형, F10 복원, F11 Idle. F5/F7은 서로 다른 발이 반응한다. 원본 전체 전진은 없고 실제 이동은 AI 담당이다.
- 파편: F1 기본, F2 뒤로 당김, F3 준비 완료, F4 전방 방출, F5 반동, F6 팔 안정, F7 복원, F8 Idle. 실제 돌 파편 이미지는 본체에 그리지 않았다.
- 낙석: F1 기본, F2 팔 올림, F3 소환 준비, F4 소환, F5 힘 유지, F6 완료 대기, F7 팔 낮춤, F8 안정화, F9 복원, F10 Idle.

## 시간 및 AI 이벤트 연결 — 전투 시간을 바꾸지 않는다

시간은 기존 전투 구간 안의 표시 배분 제안이다. 애니메이션 종료를 기다리느라 피해/물리/후딜을 지연시키면 안 된다. 숫자는 `Unity_FrameTiming_Spec.json`에도 기록했다.

| 공격 | 준비 프레임별 ms | 실행 | 피해/발동 동시 표시 | 기존 후딜 안의 프레임별 ms |
|---|---|---|---|---|
| 도약 | F1–3: 250/300/450 = 1.0초 | F4–6: 160/220/220 = 0.6초 | 실제 착지 ResolveAttack 순간 F7 | F7–11: 80/120/170/160/170 = 0.7초 |
| 강타 | F1–5: 250/300/350/200/100 = 1.2초 | 별도 시간을 추가하지 않음 | 예고 종료 ResolveAttack 순간 F6 | F6–10: 70/130/190/210/200 = 0.8초 |
| 돌진 | F1–3: 250/350/400 = 1.0초 | F4–7 각각100ms 반복, 최대0.9초/충돌 단축 | FinishCharge 순간 F8 | F8–11: 90/160/200/250 = 0.7초, 벽 충돌은 같은 비율로1.2초 |
| 파편 | F1–3: 250/300/350 = 0.9초 | 별도 시간을 추가하지 않음 | FireShards 순간 F4 | F4–8: 70/90/150/140/150 = 0.6초 |
| 낙석 | F1–3: 250/300/350 = 0.9초 | F4–6: 150/200/200 = 0.55초 | 낙하 시작은 F4, 피해는 기존 낙석 시스템 담당 | F7–10: 160/180/180/180 = 0.7초 |

### 고정 시계만으로 처리하면 안 되는 구간

- 도약: `TickJump`의 실제 착지 확인 후 `ResolveAttack`에 맞춰 F7로 전환한다. 단순히0.6초가 되었다고 접촉 프레임/피해를 강제하지 않는다. 지연 시 F6 유지, 경로 취소 시 기존 취소 처리를 따른다. `body.localPosition`/JumpVisual의 최대1.8유닛 상승은 기존 기능을 그대로 사용하며 스프라이트 오프셋으로 더하지 않는다.
- 돌진: `Charge` 진입 때 F4부터 실행하고 `FinishCharge`가 발생하면 반복 중간에도 즉시 F8로 전환한다. 정상 종료0.7초, 벽 충돌1.2초는 복귀 구간만 정규화해 맞춘다. 비교 GIF는 최대0.9초 실행의 정상 종료 예시다. 벽 충돌 후 회복의 실제 자연스러움은 미검증이다.
- 파편: `FireShards` 호출과 F4 표시가 동기화되어야 한다. 후딜0.6초 뒤 잔여 투사체가 남으면 마지막 Idle 유지. 투사체 정리가 끝날 때까지 방출 포즈를 반복하지 않는다.
- 낙석: `Rockfall` 상태는 준비와 낙하를 함께 포함한다. 예고 종료0.9초에 F4로 전환하되, F6 이후는 마지막 낙석이 정리되어 `TickRockfalls`가 Recovery로 넘어갈 때까지 유지한다. 본체 프레임에서 낙석 위치나 피해를 생성하지 않는다.
- 강타/파편의 접촉·방출은 각각 후딜 첫 프레임에 포함되어 있다. 실행 시간을 별도로 더하면 기존 전투가 느려지므로 추가하지 않는다.

## Unity 가져오기 명세 — 이번 작업에서는 적용하지 않음

- Texture Type Sprite / Multiple, Slice Grid by Cell Size160×160, Rect n번째=(160×n, 0, 160, 160), n은0부터 시작.
- PPU128, 중앙 Pivot 정규화(0.5,0.5), 셀 픽셀 기준(80,80). 기존 Body Scale1.8은 유지하며 PNG 픽셀에 적용하지 않는다.
- 좌표 기록은 이미지 좌상단 원점, 오른쪽+x/아래+y다. Unity 로컬 변환은 x=(px−80)/128, y=(80−py)/128. 기존 Body Transform의 배율은 그 뒤 한 번 적용한다.
- Filter Mode Point, Compression None, Mip Maps Off, Alpha is Transparency On. 최대 시트 폭1760px이므로 Max Size2048 이상을 사용해 자동 축소를 막는다.
- 기존 flipX/방향 처리 유지. 새 방향별 시트나 물리 Root Motion은 없다.
- 현재 공격 중 Idle 고정 표시를 바꾸는 실제 코드 연결은 후속 통합 작업이며 이번에 수정하지 않았다. 이 파일만 복사한다고 재생되는 상태가 아니다.
- 준비/실행/복귀는 전체 시트를 일정 FPS로 끝까지 재생하는 대신 위 이벤트·시간 구간으로 나눠 사용한다. 취소/사망/전환은 기존 AI 상태가 우선이다.

## P2 재사용 범위

이번에 만든 것은 P1 픽셀이다. P2 외형에 그대로 표시하면 P1 디자인으로 바뀌므로 P2 완성 리소스라고 간주하지 않는다. 구간/이벤트 명세와 관절 포즈 구조를 P2 리소스 제작 때 재사용할 수 있다. P2 전용 PNG는 제작하지 않았다.

- 도약: 기본 착지 구간 뒤 별도 충격파 예고/발동 상태를 연결한다. 추가타 전용 그림과 타이밍을 P1 후딜에 임의 삽입하지 않는다.
- 강타: 첫 접촉 뒤 기존 두 번째 예고 상태에서 준비 구간으로 돌아가 두 번째 접촉 이벤트를 받는다. 마지막 복귀는 연속타 종료 뒤 수행한다.
- 돌진: 같은 실행 반복/종료 이벤트 구조를 사용할 수 있다.
- 파편: 첫 발사 뒤 재조준/두 번째 예고가 시작되면 준비 구간으로 연결하고 다음 FireShards 때 방출한다. 첫 투사체가 남아 있다고 방출을 자동 반복하지 않는다.
- 낙석: 각 회차의 준비→유지 구간을 기존 회차/간격에 따라 반복하고 마지막 낙석 종료 뒤 복귀한다.
- 연계 A는 기본 도약→기본 강타, B는 기본 돌진→기본 파편이다. 기존 연결 상태/대기시간을 우선하고 강화 추가타로 대체하지 않는다. 단축된 준비 시간이 있다면 준비 구간을 해당 AI 시간에 정규화하며 전투 시간을 늘리지 않는다.

## 미리보기와 검증

`Previews/*_Native160.gif`:160×160 원배율, `*_3x.gif`:3배 확대, `*_Idle_Transition.gif`:Idle→공격→Idle(2배). 모든 GIF는 최종 PNG 셀을 읽어 같은 포즈/프레임 순서로 만들었고, 파일 디코딩 후 프레임 수·지속 시간·팔레트 변환된 화면이 예상과 같은지 검사했다. GIF의256색 제한으로 색 양자화는 존재하며 게임용 PNG에는 적용하지 않았다.

도약 GIF에는 기존 JumpVisual의 월드 상승이나 실제 수평 이동을 합성하지 않았다. 따라서 공중 자세는 보이지만 게임 속 궤적/높이/공간 타격감의 검증 자료는 아니다. 돌진 GIF도 제자리 본체 자세 검토용이다. GIF 반복 사이에는 마지막/첫 Idle이 연결되며, 실제 공격을 연속 자동 실행하라는 의미가 아니다.

확인한 사항:

- 다섯 PNG의 크기/셀 수/가로 배열/RGBA/알파0·255와 투명 외부 배경.
- 프레임 시작·끝 Idle과 원본 RGBA 일치, 원본 팔레트만 사용, 얼굴/눈의 소스 픽셀 형태 유지.
- 변환 전 원본 불투명 픽셀의 좌표를 계산한 경계 검사와 최종 셀 경계 검사에서 잘림 없음.
- 신규 자세마다 불투명 실루엣이 하나로 이어짐. 최초 발견된 관절 분리 조각은 부위 소속을 보정했다.
- 원배율 및 확대 정지 프레임에서 도약의 다리 접기/착지 압축, 강타의 팔 상승/하강, 돌진의 낮은 방어, 파편의 당김/반동, 낙석의 양팔 유지가 구분됨.
- 원본/Idle·Move/P2 아트 및 관련 Unity 파일과 기존 보행 시험 ZIP의 변경 여부를 SHA256으로 검사했다. 최종 포장 직전 동시 작업으로 변경된 파일은 아래 별도 기록을 따른다.

미검증/남은 확인:

- 실시간 GIF 반복을 직접 관찰하지 못했다. GIF 디코딩과 정적 포즈 확인은 수행했으나 동작의 자연스러움·무게감을 최종 승인하지 않는다.
- Unity Play, 실제 카메라 원배율, AI 이벤트와 표시 프레임의 실제 동기화, JumpVisual 합성, 벽 충돌 시 조기 종료, 좌우 반전 및 P2 연계는 미검증/후속 통합 대상이다.
- 새로 드러난 팔꿈치 암부와 극단 자세의 암석판 겹침은 실제 재생에서 추가 시각 검토가 필요하다. 원본 그대로의 얼굴/판 질감을 우선했으며 전체 외형 재생성을 하지 않았다.
