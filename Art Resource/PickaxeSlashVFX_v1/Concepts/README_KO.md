## 디자인

### 1타 / 시계방향

얇은 은백색 중심과 청록·회청 잔광의 초승달이다. 형성은 오른쪽 위, 피해 순간은 오른쪽 전방의 긴 곡선, 소멸은 오른쪽 아래의 끊어진 선으로 구성했다. 화면 기준 위→앞→아래의 방향이 읽히도록 했다.

### 2타 / 반시계방향

같은 팔레트로1타보다 두껍고 밝은 곡선이다. 아래쪽 형성→전방 곡선→위쪽 잔광의 순서다.1타를 그대로 좌우 반전하지 않았으며, 서로 반대 방향의 잔광과 팁 형태를 만들었다. 피해 키프레임의 불투명/반투명 유효 픽셀수는1타2684개,2타3435개로 두께 차이를 두었다.

### 3타 / 전방 파쇄

짧은 중앙 내지르기 광과 갈라진 V형 파쇄선을 사용했다. 큰 원이나 외부로 퍼지는 충격파는 없다. 소멸 키는 같은 전방 영역 안에서 선이 부서지고 어두워지는 형태다. 실제로 날아가는 독립 투사체로 쓰는 리소스가 아니다.

90° 양쪽 방향을 파쇄선으로 암시하지만 원형 경계 전체를 연속 표시하지 않는다. 이 선택이 실제 적중 범위를 충분히 전달하는지, 화살형 투사체처럼 오인되지 않는지는 사용자 디자인 검토와 후속 Unity 확인이 필요하다.

세 검기의 내부는 대부분 투명하다. 단색 부채꼴 필드나 고정 범위 표식을 내보내지 않았다. 밝은 은백색/청록 파편은 잔광 픽셀이며 기존 회갈색 적중 먼지·돌 파편과 다르게 설계했다. 마법진·긴 광선·새 충격파를 추가하지 않았다.

위 파일은 `Keyframes/`에 있다. 모두 중앙 Pivot(0.5,0.5), 기준 방향+X, PPU64 후보다. 각 공격의 세 키는 같은 원점과 같은 캔버스를 사용한다. 가시 영역 중심을 매번 Pivot으로 옮기지 않았다. 형성은 짧고 소멸은 다시 축소되는 에너지 포즈이므로 가시 영역 크기는 의도적으로 다르다.

반경은 캔버스 끝이 아니라 **발광 픽셀이 도달하는 유효 영역**이다. 피해 키 실측 외곽 반경은1타87.82px,2타87.79px,3타111.55px다. 설계 반경의 끝2px와 각도 끝2°는 단계 알파로 정리해 뚝 잘리는 외곽을 피했다. 실제 피해 키의 각도 폭은 약119.65°/119.65°/88.89°다. 각도 끝의 완전 투명 픽셀까지 그림이 있는 것으로 보고하지 않는다.

팔레트: #F2FBF8 / #CDE7E3 / #9EC7C6 / #6E9DA0 / #40656C. 밝은 중심은 선명한 픽셀군, 가장자리는 낮은 단계 알파로 소멸한다. 부드러운 사각 블룸은 사용하지 않았다. RGB/알파 정리와 Point 변환 후 외부 투명 픽셀의 RGB는0이다.

## 월드 크기와 Scale 후보

스프라이트 유효 반경을 Rpx, PPU를64라고 하면 **표시 월드Scale = 실제 공격 사거리×64/Rpx**다.

|공격|기본 사거리|월드Scale 후보|물리20P 사거리|+15% 월드Scale 후보|
|---|---:|---:|---:|---:|
|1/2|1.5|1.090909|1.725|1.254545|
|3|1.7|0.971429|1.955|1.117143|

이는 실제 부모 Scale이 적용된 뒤의 **최종 월드 배율**이다. 플레이어0.8을 무조건 한 번 더 곱하지 않는다.0.8 부모 아래에 그대로 붙이면 범위가 줄어든다. 부모의 실제 lossyScale을 보정하거나 월드 배율을 독립 관리할지는 적용 담당자가 결정한다. 예를 들어 균일0.8 부모 아래의 기본 localScale은1/2타1.363636,3타1.214286이지만 실제 계층을 확인하지 않고 확정하지 않는다.

20P는 각도를 바꾸지 않고 최종 반경만1.15배로 늘린다. 기본 셀 여백은1/2타8px,3타16px다. **그림 자체를15% 확대해 같은192/256 셀에 다시 굽는 방식은 잘린다.** 후속 Unity에서 Sprite 전체의 월드Scale을 확대하면 캔버스도 함께 커지므로 잘림 없이 대응할 수 있다.20P 비교 그림은 충분한 별도 도식 캔버스에서 만들었다.

## 원점·회전·후속 애니메이션

- 위치 원점: WeaponPivot의 월드 위치. 피벗의 상시 회전과 곡괭이 머리 위치는 구분한다.
- 검기의 기준회전: 공격 시작 시 고정된 조준 방향. 시안은+X이고45° 예시는 이를 한 번 회전했다.
- 실제 WeaponPivot은 공격 중 회전한다. 이 회전 아래에 검기를 무보정으로 붙이고 키프레임 자체의 스윙까지 재생하면 이중 회전할 수 있으므로 주의한다. 기존 조준/공격 방향 고정 규칙을 변경하는 지시가 아니다.
- 현재 직접 판정은50%에1회다.1/2타0.125초,3타0.16초를 주요 키에 맞춘다. 검기 곡선이 넓게 보인다고 추가 피해 시점이나 Collider가 생기는 것이 아니다.
- 이번 세 키의 시간은 형성약20%,피해50%,소멸약85%의 설계 기준이다. 연속 움직임을 재생/검증한 것은 아니다.

승인 후6프레임 후보는 [40,40,45,40,40,45]ms로 총250ms, F4 시작125ms에 피해 키를 배치할 수 있다.8프레임은 각40ms로 총320ms, F5 시작160ms를 후보로 삼을 수 있다. 이 시간은 **기존 실행 시간 안의 아트 배분 시험값**이며 공격 속도·피해 시점을 바꾸는 확정값이 아니다. 프레임 자연스러움은 전체 제작 후 별도 검토해야 한다.

## 실제 Game 합성과 정밀 도식의 차이

Game 합성은 원본 캡처 위에 검기만 추가했다. 기존 몸체·곡괭이·잔상·HUD는 지우거나 재생성하지 않았다. 캡처의 WeaponPivot 화면위치(960,540)와120px/유닛을 **추정 정렬값**으로 사용했다. 해당 캡처의 카메라/프레임 진행률을 이번에 실시간으로 조회하지 않아, 이 이미지가 정확히50% 프레임의 거리 검증이라고 주장하지 않는다. 각 전체 Game 파일과 비교 제목을 예상 시안으로 구분했다.

정밀 비교는 별도 월드 단위 격자에서 P=(0,0) 원점과 실제 반경1.5/1.5/1.7, 각도120/120/90를 수식으로 배치했다. 격자1u, 원점, 얇은 금색 경계는 도식에만 존재한다. 실제 씬의 절대 월드좌표를 조회한 결과가 아니라 WeaponPivot을 원점으로 한 정확한 상대 월드좌표 도식이다.

기존 머리 잔상은 짧은 실제 금속 머리 궤적을 담당하고, 검기는 더 바깥의 직접 공격 범위 가독성을 담당한다. 따라서 머리 끝과 검기 경계 사이 빈 공간을 긴 광선으로 강제로 잇지 않았다. 이 간격의 자연스러움은 실제 모션과 함께 후속 확인한다.

## 기존 효과/기능 유지

- 기존 머리 잔상·직접 적중 먼지·3타 돌 파편 보존. 허공 합성에서 새 먼지를 임의로 추가하지 않았다.
- 물리50P의2u/90° 독립 충격파는 별도 로직/효과로 유지한다. 이번 검기는 그것을 대체하지 않는다.
- 사거리·각도·공격 시간·피해량·이벤트·패시브·Collider 변경 없음.
- 기존 플레이어·곡괭이·소켓·공격 아트·VFX·공식문서·Unity 코드/씬/프리팹 수정 없음. Git 커밋/푸시 없음.

## 생성 원형 안내

내장 image_gen으로 공격별3키 원형을 각각 생성하고, 같은 원점/후보 반경에 정렬·팔레트/알파/각도 외곽을 정리했다. 사용한 전체 프롬프트는 `Sources/GenerationPrompts.md`다. Sources의3칸 원형은 제작 참고자료이며 최종 Unity 애니메이션 시트가 아니다. 최종 검토 대상은 Keyframes의 개별9PNG다. CLI/API 별도 이미지 생성은 사용하지 않았다.
