# MineBoundary_Transition_v1 — Map01 세로 경계 A/B 시험

## 수정한 분석

작은 돌 테두리의 반복을 핵심 원인으로 본 이전 분석을 수정한다. 이번 문제는 **평평한 바닥의 재질/명암과 큰 암벽의 부피감이 하나의 직선에서 끊어지는 것**이다. 작은 돌 테두리는 유지한다. 기존 그림자·잔돌은 보조 재료로 유효하지만, 벽의 뿌리에서 바닥으로 이어지는 불규칙한 면을 구성하는 전용 전이 아트가 부족하다고 판단했다.

기존 MineEnvironment_v1의 회갈색·올리브 암석, 청회색 음영, 회색 바닥을 참조했다. 새 아트의 RGB는 기존 Wall_RockMass와 Floor_RockGray에서 추출한 32색으로 제한했다. 생성 도구로 원형을 제작한 후 투명 영역 정리, 원배율 픽셀 정리, 기존 팔레트 대응 및 단계 알파 처리를 했다. 원본 PNG는 재내보내기하지 않았다.

## 실제 참조와 구간

- 기존 50개 환경 PNG, MineEnvironment_v1 README, MineBoundary_v1 분석·사용 목록을 확인했다.
- 실제 Game 캡처: `Art Resource/MineBoundary_v1/Sources/Map01_ActualCapture_2026-10-26.png` (1920×1080). 이번 신규 캡처가 아니다.
- 동일 비교 구간: 캡처 좌상단 기준 **(0,350)~(220,590)**, 왼쪽 중앙 공동의 세로 경계 220×240px. 동일한 원본 위에 A/B만 합성했다.
- 별도로 말씀하신 세로 경계 확대 첨부는 이번 입력에서 파일을 식별할 수 없어 확인하지 못했다. Sources의 확대 이미지는 위 실제 캡처에서 만든 참고 확대다.
- 현재 Unity 상태나 최신 Game 화면을 새로 확인하지 않았다. 화면 좌표를 현재 프리팹 월드 좌표로 확정하지 않았다.

## 두 시안

|안|구성|연결감 평가|남은 문제|
|---|---|---|---|
|A|벽 밑의 낮은 대비 접지 음영, 불규칙한 암석 가루·침식 흔적|직선에서 갑자기 끝나던 바닥을 벽 발치까지 이어 보이게 하는 기본 후보|기존 경계선 자체는 남는다. 긴 반복에서는 새 퇴적물 띠처럼 보일 수 있다|
|B|A 위에 벽에 붙은 낮은 암석 돌출부 추가|바닥 쪽 실루엣 변화가 더 분명하고 큰 암벽과의 재질 연결이 강하다|큰 돌출부가 충돌 가능한 새 바위로 읽힐 위험. 전 구간 연속 배치는 권장하지 않는다|

**권장: A부터 한 구간 검토, B는 일부 지점에만 선택 사용.** 둘 다 단순 잔돌 장식 대신 면/접지 연결을 시험했지만, 이번 합성만으로 하나의 자연지형처럼 완전히 해결됐다고 판정하지 않는다. 특히 B의 바닥 침범 인상이 실제 이동 가독성을 해치지 않는지는 Unity에서 별도 확인해야 한다.

## 게임용 PNG 2개

|파일|실제 크기|역할|
|---|---|---|
|Textures/Transition_A_ContactDust_48x128.png|48×128 RGBA|A 전이 띠|
|Textures/Transition_B_RockToe_48x128.png|48×128 RGBA|B 돌출부, A와 함께 사용|

두 파일은 벽이 왼쪽/바닥이 오른쪽인 한 방향 시험 리소스다. 다른 코너·전 방향 세트를 제작한 것이 아니다. 캔버스는 0.75×2유닛(PPU64), 실제 유색 폭은 최대28px다. 불필요한 전체 배경, 벽·바닥 사각 텍스처는 포함하지 않았다. 프레임/애니메이션 시트가 아닌 정적 전이 Sprite다.

- PPU64, Point, Compression None, Mipmap Off 제안. `.meta`를 생성하지 않았다.
- RGB는 기존 팔레트, 투명 외부 알파0. A 최대 알파144, B 최대216. 반투명은 먼지/음영을 합성하기 위한 의도된 단계값이며 흐린 외곽선 처리는 하지 않았다.
- 캔버스 4방향에 투명 여백이 있다. 좌측 결합부를 벽 밑에 겹치고 기존 작은 돌 테두리를 위에 표시한다.
- PNG 좌상단 기준 권장 결합점: A `(4,64)`, B `(8,64)`. 중심 Pivot 사용 시 각각 중심에서 `(-20,0)px`, `(-16,0)px` 지점이 결합점이다. 이는 실제 맵 배치를 보고 보정할 시험값이다.
- 현재 기존 정렬(-50대 바닥, -40 그림자, -30 벽, -20 Rim)을 참고하면 A는 바닥 위/벽 아래, B는 벽 위/Rim 아래가 출발점이다. 새 Sorting Layer나 Material/Light를 만들 필요가 없다. 배우와 공격 예고보다 아래에 둔다.
- B가 작은 돌을 덮어 대체하지 않도록 기존 Rim을 위에 표시하거나 Rim 마스크로 제외한다. 비교 합성은 원본 crop의 x=0~51열을 완전 보존했다. 기존 돌 테두리 및 벽 쪽의 해당 픽셀은 A/B 모두 동일하다.

## 합성 배치와 반복 예시

캡처 기준 1원본픽셀≈1.875화면픽셀을 시험 대응했다(64PPU, 해당 캡처 카메라 기준 추정). 48×128 Sprite를 90×240 화면픽셀로 Point 합성했다. A 좌상단은 캡처 `(44,350)`, B는 `(36,350)`이며 x<52 화면영역은 기존 Rim 보존을 위해 제외했다. 이 좌표는 화면 합성용이며 월드좌표가 아니다.

반복 예시는 원본 구간을 세로로 이어 붙인 시험 바탕 위에 112원본px 간격/16px 중첩과 세로 반전을 시험했다. 바탕 캡처 자체의 반복 이음은 실제 Map01 형상이 아니다. 무조건 Tile Repeat할 자산으로 확정하지 않았다. 낮은 대비의 끝단을 겹쳐도 돌출 리듬과 퇴적물 띠가 반복되므로, B는 일부 모듈 생략/분산 사용을 권장한다. 기존 경계 자체의 위치, 바닥 색, 작은 돌 띠는 바꾸지 않았다.

## 실제 검증 / 미검증

- 두 PNG를 다시 열어 48×128, RGBA, 알파0 외부 배경, 단계 알파, 외곽 투명 여백 확인.
- 동일 원본 구간·동일 크기·동일 정렬로 A/B 합성을 직접 정적 검토했다.
- 작은 돌 테두리를 포함한 crop x0~51열 픽셀 동일성 검사 통과.
- 기존 환경 원본/Unity Import 폴더 및 Map01 프리팹의 작업 전후 해시 동일성 확인. 수량은 Specs/Validation.json에 기록했다.
- **미검증:** Unity 실시간 표시, 최신 Map01 화면, 캐릭터/VFX가 겹친 상태, 이동 경계 오인 정도, 실제 Sorting/마스크 적용, 다른 방향/코너 연결.
- Unity 코드·씬·프리팹·Collider·이동영역은 수정하지 않았다. 전체 맵 적용, 공식문서 변경, Git 커밋/푸시 없음.

완료 범위는 세로 경계 한 구간의 **A/B 아트 시험과 동일 캡처 합성 비교**다. 최종 자연스러움 승인이나 Unity 적용 완료로 보고하지 않는다.
