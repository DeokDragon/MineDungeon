# MineExit_v1 — 일반 방 공통 광산 출구

Map01~Map10 공통 아트1종이다. 기존 MineEnvironment_v1/실제 Assets 환경의 탁한 갈색 목재, 어두운 철제 보강판, 회갈색·올리브 암벽을 참조했다. 두 문짝이 좌우로 문틀 안쪽에 들어가며, 열린 상태에는 어두운 갱도와 뒤쪽 버팀목이 보인다. 작은 황토빛 등은 문틀에 고정되어 은은하게 유지된다. 별도 네온/마법/광역 발광은 없다.

## 게임용 PNG

| 파일(Sprites/) | 크기 | 용도 |
|---|---|---|
| MineExit_Locked_128x64_v1.png |128×64|잠김/전투 중|
| MineExit_Open_128x64_v1.png |128×64|열림/통과 가능|
| MineExit_Opening_6f_128x64_v1.png |768×64|128×64 셀6개, 가로1줄|

세 파일 모두 RGBA, 외부 실제 투명, Alpha0/255, 선명한 네이티브 픽셀 경계다. 갱도 안쪽은 **불투명한 어두운 내부**이며 뒤쪽 바닥이 비치는 투명 구멍이 아니다. 게임용 파일에 라벨/체크무늬/프레임 테두리는 없다. PNG 자체에 PPU/Pivot 설정은 저장되지 않는다.

## 규격과 정렬

- PPU64, 중앙 Pivot normalized(0.5,0.5), 픽셀(64,32). 캔버스 표시 크기2×1유닛을 전제로 한다.
- 플레이어가 아래쪽에서 위쪽 출구로 접근하는 정면에 가까운3/4 환경 시점이다. 방향별/맵별 중복 디자인은 없다. 보스룸 적용 대상이 아니다.
- 불투명 외곽 bbox는 모든 프레임에서 x5~122/y7~58(좌상단 원점)로 동일하다. 그 밖은 투명이고 128×64 밖으로 돌출되지 않는다.
- 문짝 이동 영역은 x39≤x<90, y23≤y<53, 문틀·암벽·못·등·바닥 접점은 그 밖에서 픽셀 단위로 고정이다. 해당 영역 중심은(64.5,38)로 캔버스 중앙축과0.5px 차이다. 문짝은 바깥으로 튀어나오지 않고 그 영역 안에서 잘려 문틀 뒤로 들어가는 방식이다.
- 열린 시각적 통로는 문틀 안쪽에 위치한다. 표시 캔버스/기존Collider는2×1이며 실제 어두운 개구부는 그보다 좁다. 이 장식 개구부의 크기를 근거로 Collider를 줄이지 않는다. 통과 시 캐릭터 가림/여유 폭은 Unity 적용 단계에서 확인한다.

## 개방 애니메이션 제안

6프레임, **클립0.52초** 시험값이다. 최종 확정 시간이 아니다.

| 프레임 | 각 문짝 이동량 | 표시 ms | 시작 시각 |
|---|---:|---:|---:|
|F1|0px|60|0.00초|
|F2|좌우 각3px|70|0.06초|
|F3|각8px|80|0.13초|
|F4|각15px|100|0.21초|
|F5|각22px|110|0.31초|
|F6|각26px/완전 개방|100|0.42초|

F1은 잠김 PNG와 RGBA 픽셀이 정확히 같다. F6은 열린 PNG와 정확히 같다. 한 번 재생한 뒤 F6/열림 이미지를 유지한다. 완전 열린 이미지는0.42초부터 표시되고, 마지막100ms까지 포함한 제안 클립 길이가0.52초다. 루프 재생/문이 다시 닫히는 기능은 제안하지 않는다. 검토 GIF의 반복은 확인 편의를 위한 것으로 게임 동작 규칙이 아니다.

**게임의 개방 시점은 기존 몬스터 전멸 이벤트 그대로다.** 애니메이션은 시각 전용이며0.52초 종료를 기다려 Trigger/통과를 켜면 안 된다. 이미 문에 닿아 있는 플레이어는 기존 규칙대로 즉시 통과할 수 있으므로 시각 연출이 생략·중단되는 것도 허용한다. 새로운 개방 대기 상태, 통과 차단, 장애물은 추가하지 않는다.

## Unity 적용 시 별도 Codex 확인 사항

이 작업에서는 Unity 코드/프리팹/Collider/Trigger를 변경하지 않았다. 아래는 가져오기 명세이며 적용은 후속 작업이다.

1. Single 스프라이트2개, Opening은Multiple. Grid by Cell Size128×64, 왼쪽부터 F1~F6. Rect n=(128×n,0,128,64), n은0부터.
2. PPU64, Pivot center, Point, Compression None, Mip Maps Off, Alpha is Transparency On. Sheet Max Size1024 이상으로 자동 축소를 막는다.
3. 읽기 확인 결과 Map01~10의 RoomExit Root Scale은(2,1,1), BoxCollider2D 로컬 Size는(1,1)이다. 따라서 현재 월드 판정은2×1이다. **Root Scale을1로 바꾸면 Collider까지 변하므로 하지 않는다.**
4. 새 PNG를 PPU64로 기존 루트 렌더러에 바로 넣으면 루트의 가로2배가 중복되어4×1 표시가 될 수 있다. 기존 루트/Collider를 그대로 보존하고 별도 시각 자식의 Local Scale(0.5,1,1), Local Position(0,0,0)을 사용하는 방식이 후보다. 루트(2,1)×자식(0.5,1)×아트(2,1)=월드2×1. 실제 부모 배율과 렌더링 구조는 통합 담당자가 확인한다. SpriteRenderer 크기/별도 시각 Transform을 조정하는 다른 방법도 가능하나 판정 크기는 보존한다.
5. 기존 RoomExit.cs는 루트 SpriteRenderer에 잠김 빨강/열림 초록을 곱한다. 새 목재 이미지를 그 렌더러에 그대로 연결하면 색이 물든다. 통합 때 시각 PNG는 중립 흰색 tint로 표시하고 기존 IsOpen/Collider.isTrigger/레이어/통과 처리는 유지해야 한다. 이 아트 팩에서 해당 코드를 수정하지 않았다.
6. 현재 Root 위치를 유지하고 중앙축으로 정렬한다. 문틀 암벽이 주변 벽에 묻히거나 열린 내부 위에 벽이 겹치지 않도록 시각 정렬/Sorting을 별도 확인한다. 이미지로 뒷벽을 덮는다고 물리 벽이 제거되는 것은 아니다. 이미 존재하는 출구 통로 구조를 유지하며 새 장애물/판정을 만들지 않는다.
7. 문·통로는 배경 수준으로 두고 플레이어를 가리지 않는 순서를 우선 검토한다. 문틀 앞뒤의 실제 통과 가림과 카메라 원배율은 Play 확인 대상이다. 이 패키지는 추가 Collider나 램프 Light2D를 요구하지 않는다.

## 실제 검사 결과와 한계

- PNG3개 실제 크기/RGBA/알파0·255/셀6개 확인.
- 모든 프레임 bbox 동일, 외곽 잘림 없음, 내부 통로 불투명 확인.
- 문틀/암벽/고정 못/등/접점 영역은 전 프레임 RGBA 정확히 동일.
- F1=잠김, F6=열림 픽셀 일치. 동일 문짝 원본을 좌우로 이동시켜 프레임마다 목재 무늬와 철판이 새로 바뀌지 않게 구성했다.
- 원배율/6배 정지 프레임과 기존 환경 합성 이미지를 검토했다. 문을 막은 상태와 어두운 열린 갱도가 구분되며 색상은 기존 환경보다 과도하게 밝지 않다.
- GIF를 다시 디코딩해 전 프레임 수/표시 시간/예상 화면 일치를 검사했다. PNG는 공유64색 팔레트로 정리했고 반투명 외곽선이 없다.
- 참조 환경 원본과 Map01~10 프리팹, RoomExit.cs 등 보호 대상은 작업 전후SHA256을 비교했다. 변동 내역은 Specs/MineExit_Spec.json에 기록한다.
- 실시간 GIF 재생을 직접 관찰하지 못했다. 연속 움직임의 자연스러움은 정지 포즈/디코딩 검증과 구분하여 **미검증**이다.
- 실제 Unity Play, 카메라에서의 시인성, 현재 맵에서의 암벽 접합/통과 가림, 개방 이벤트와 표시 동기화는 별도 통합 검증 대상이다. 문 개구부와 월드Collider의 실제 시각적 여유 폭도 후속 확인이 필요하다.

## 제작 출처

이미지 생성 스킬의 내장 image_gen 도구로 기존 목재/암벽/바닥을 참조해 출구 표면과 내부를 제작했다. 생성본은 Source/MineExit_Generated_Atlas.png에 보존했다. 최종 게임용은 원본 고해상도 비교 시트가 아니라 128×64 네이티브 파일이다. 생성 표면을 고정 문틀과 두 문짝 레이어로 정리하여 동일 픽셀 재사용으로 개방 동작을 구성했다. Source/Generation_Brief.md에 생성 요청 조건을 기록했다. Source 폴더는 Unity 가져오기 대상이 아니다.
