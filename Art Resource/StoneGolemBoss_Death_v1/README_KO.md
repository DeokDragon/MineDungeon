# 돌골렘 보스 사망 애니메이션 v1

현재 적용된 P1·P2 원본과 Idle/공격/등장·변신의 암석판 구조를 재사용한 본체 붕괴 아트다. 기존 리소스를 덮어쓰지 않았으며 이번 작업은 새 아트 폴더만 생성했다. Unity 코드·프리팹·HP·피해·사망·보상·클리어·결과창은 변경하지 않았다.

P1의 회갈색 암석/작은 호박색 눈, P2의 벌어진 암석과 강화 균열을 각각 유지한다. P2 발광 강도는1/.80/.60/.40/.28/.15/.07/.02/0/0/0/0으로 낮아진다. 눈은1/.65/.30/.10/0 이후 꺼진다. 몸체가 무너지는 동안 남은 균열 위치는 해당 원본 암석판을 따라 움직이며 새 균열/충격파를 추가하지 않는다.

## 중심과 접지

캐릭터 Root/캔버스/Pivot을 프레임마다 옮기지 않는다. 처음3프레임은 기존 발바닥 위치를 유지한 채 관절과 상체가 내려앉고, 그 뒤부터 발·다리도 의도적으로 분리돼 붕괴한다. 사망 후에도 모든 발 픽셀을 같은 위치에 고정하는 동작은 아니다.

잔해의 깊이는 기존 근거리 발Y141/원거리 발Y132를 참고해 낮은 바닥 범위에 배치했다. 대다수 큰 잔해가Y134~141 부근에 닿고 셀 밖으로 잘리지 않는다. 상체·어깨가 아래로 내려가는 것은 붕괴 동작이며 본체 전체 월드 이동이 아니다. 별도 재생 오브젝트의 Transform은 고정해 사용한다.

## Unity 가져오기와 독립 재생

1. Sprite Multiple, Grid Cell160×160, 좌→우12개, Rect n=(160×n,0,160,160), n은0부터. PPU128/중앙Pivot.
2. Point / Compression None / Mip Maps Off / Alpha is Transparency On / Max Size2048 이상. 두 PNG 폭1920이므로 자동 축소를 막는다. 마지막 부분 알파를0/255로 강제하지 않는다.
3. 기존 Body Scale1.8이 적용된 시각 구조를 기준으로 한다. 독립 시각 오브젝트에는 사망 순간의 실제 시각 월드 위치·회전·유효 배율·flipX·Sorting을 복사하고 한 번만 재생한다. 부모 배율과1.8을 중복 곱하지 않는다. Sprite 원점은 좌상단이며 Unity 로컬=((px−80)/128,(80−py)/128)이다.
4. 사망 시점의 Phase로 P1/P2 중 하나를 고른다. 이후 페이즈 전환 예약이나 살아 있는 AI 상태를 따라 버전을 다시 바꾸지 않는다.
5. 마지막 F12는 완전 투명이다.1.60초 종료 또는 화면 정리 조건에서 시각 오브젝트만 제거할 수 있다. 피해·보상·클리어가 이 시각 종료를 기다리면 안 된다.
6. 정지 Idle/등장·변신의 종료 포즈와 F1이 정확히 같아 기본 연결 기준은 일치한다. 공격 실행 중 임의 포즈에서 죽을 때는 해당 포즈와 정면 Idle인 F1이 다를 수 있다. 짧은 사망 스냅샷 또는 상황별 진입 처리의 필요성은 통합 담당자가 확인해야 한다. 이번 두 시트만으로 모든 공격 중 사망 전환의 자연스러움을 보장하지 않는다.

읽기 확인한 EnemyHealth는 사망 처리를 진행한 뒤 본체 GameObject를 파괴하고, StoneGolemBossAI는 사망 시 비활성화된다. 따라서 죽은 AI에 붙인 Animator가 계속 재생될 것이라 가정하지 않는다. 기존 사망 시각 경로와 마찬가지로 **확정 사망 순간 시각 정보/페이즈를 먼저 보관하고 별도 오브젝트에서 재생**하는 방식이 후보이며, 실제 코드 연결은 후속 Codex 범위다. 공격·도약 중 기존 시각 피벗이 복원되기 전의 위치를 어떻게 보관할지도 통합 단계에서 확인한다. 이번 작업에서 기존 파괴/물리/판정 순서를 변경하지 않았다.

## 기존 파편 효과와 중복 주의

추가 사망 VFX 파일은 제작하지 않았다. 본체의 큰 암석판 붕괴와 잔해만 포함하고 먼지 구름/작은 파편 폭발/충격파를 추가하지 않아 기존 효과와의 과밀 위험을 줄였다.

읽기 확인한 StoneCombatBurst 기본값은 보스 사망에0.7초,12개 조각과3개 먼지, 짧은0.05초 Breaking body 잔상을 사용한다. 프리팹 오버라이드와 실제 합성은 별도 확인 대상이다. 새 붕괴와 기존 짧은 잔상을 동시에 중복 표시하면 첫 순간 실루엣이 겹칠 수 있다. 이 팩의 미리보기에는 해당 실행 시 파티클/먼지/카메라 흔들림을 합성하지 않았으므로, 함께 사용할 때의 과밀도·가림은 미검증이다. 후속 담당자가 기존 효과 재사용/본체 잔상 표시 중복만 검토하되 사망/클리어/보상 시점은 그대로 유지해야 한다.

## 검증 결과와 한계

확인:

- PNG2개1920×160/RGBA/정확한12셀/160×160와 끝 프레임 전체 RGBA0 확인.
- 첫 프레임이 현재 해당 페이즈 Idle F1과 픽셀 단위로 정확히 일치.
- 원본 암석판 구역의 회전 전 좌표 계산 및 최종 셀 경계 검사에서 잘림 없음. Root/Pivot은 고정.
- 원배율/확대 정지 포즈에서 지지 상실·어깨/팔 분리·몸통/머리 침하·낮은 잔해·소멸을 구분할 수 있음. P2의 밝은 노란 중심색까지 포함해 발광을 단계적으로 감쇠하도록 검토했다.
- GIF 저장 후 전체 프레임 수·시간·예상 합성 화면 디코딩 검사. 게임용 PNG는GIF256색 제한과 구분한다.
- 기존 원본/Idle·Move/공격10종/등장·변신 및 관련 코드·보스 프리팹의 작업 전후SHA256 비교. 실제 기록은Specs/Validation_and_Timing.json.

미검증:

- 실시간 GIF 재생을 직접 관찰하지 못했다. 연속 재생의 자연스러움/무게감은 정지 포즈·파일 디코딩과 구분해 미검증으로 기록한다.
- Unity Play, 실제 실행 카메라 크기, 공격·도약 중 사망 진입, 기존 파편/먼지/잔상과의 중복, 결과창과의 가림, 독립 재생 오브젝트의 정리는 후속 통합 검증 범위다.
-1.6초와12프레임은 초기 시험값이다. 사망 확정/보상/클리어/결과창을 이 길이에 맞춰 지연시키는 기능은 포함하지 않는다.

기존 편집 가능한 픽셀 암석판 리그와 원본 P1/P2 픽셀을 사용했으며 전체 외형을 새로 생성하지 않았다. 구역별 원본 마스크 범위·회전·목표 좌표·프레임별 투명도와 시간은Specs에 기록했다. 실제 적용을 위한 코드·프리팹·공식 문서 수정과Git 커밋/푸시는 수행하지 않았다.
