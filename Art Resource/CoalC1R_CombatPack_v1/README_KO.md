# C-1R 전투 애니메이션 / VFX 시범 패키지 v1

석탄 몬스터 C-1R의 전투 애니메이션 5종과 VFX 5종입니다. 일반 공격은 열기를 방출한 뒤 살아남는 반복 공격이며, 붕괴/화로 파손은 Death에만 넣었습니다. 원본, Idle/Move, 돌/철/수정 몬스터 그래픽과 Unity 코드/씬/프리팹/전투 수치/공식 문서를 수정하지 않았습니다. Git 커밋·푸시를 하지 않았습니다.

기준 C-1R.jpg는 실제로 PNG 시그니처를 가진 RGBA 파일이었습니다. 알파 0/255의 기존 투명 배경을 사용했고 검은 몸체를 삭제하는 배경 제거는 하지 않았습니다. 원본의 둥글고 낮은 몸체와 176색(투명 포함)을 재사용했습니다. 살아 있는 전투 프레임의 불투명 색은 모두 원본 팔레트에 포함됩니다.

바닥/그림자/배경/텍스트/프레임선/블러를 넣지 않았습니다. 캐릭터 본체에 큰 외부 불꽃이나 피해 영역을 그리지 않았습니다. VFX의 잔광/소멸은 계단식 픽셀 실루엣과 반투명 알파로 표현하며 부드러운 블러를 사용하지 않았습니다.

## 살아 있는 공격과 사망의 구분

- HeatWindup: 기본 Idle 픽셀로 시작해 화로 내부와 원래 붉은 균열만 단계적으로 밝힙니다. 발·눈·화로 중심·철창 위치를 고정하고 팔꿈치를 안으로 접습니다. 무릎/골반만 1px 긴장 자세를 추가했습니다. 몸통 전체 이동이나 크기 조절로 준비 동작을 만들지 않았습니다.
- Explosion: F1은 준비 마지막과 동일합니다. F2/F3에서 팔을 바깥으로 벌리고 무릎/골반에 힘이 걸리도록 하여 짧은 팽창 인상을 줍니다. 몸통/얼굴/철창을 확대하거나 산산조각 내지 않았습니다. 불투명 화로·균열 형태와 발 접지는 유지되고 F4는 냉각으로 이어지는 온전한 생존 자세입니다. HP 감소/자폭/추가 피해/Collider가 포함되지 않습니다.
- CoolingRecovery: F1은 Explosion F4와 동일합니다. 화로와 균열 밝기를 줄이고 팔/무릎을 기본으로 돌립니다. F5는 현재 설치된 Idle F1과 전체 픽셀이 같습니다. 다음 반복 공격이 가능한 기본 자세로 복귀합니다.
- Hit: 기본 열 상태의 짧은 팔/몸체 충격 반응입니다. 화로/철창/눈/발과 기본 불씨는 유지하며 폭발/코어 파괴/공격 취소 표현을 넣지 않았습니다. 기존 피격 플래시/변형/변위를 이미지에 중복하지 않았습니다.
- Death: 불씨 불안정→균열 파손→일부 석탄 분리→화로 구조 파손/몸체 붕괴→큰 석탄 조각 낙하→작은 잿더미→희미한 잔재로 사라집니다. 이 파손은 일반 Explosion에 없습니다. F7은 완전 공백이 아니라 알파 18~24의 작은 재/불씨 잔재이며 별도 시각 오브젝트가 종료될 때 정리할 수 있습니다. 이를 보상/출구 개방의 대기 조건으로 삼으면 안 됩니다.

본체 불씨를 회색/하얀색으로 덮지 않고 원본 주황·붉은 팔레트 내에서 더 뜨거운 색으로 교체했습니다. 눈은 새로 밝히지 않았습니다. 철창과 테두리는 완전히 같은 픽셀로 고정되며 붉은 균열은 위치/모양을 유지한 채 색만 변합니다. 팔이 가까워지는 장면에서도 이 고정 영역이 가려지지 않도록 레이어를 정리했습니다. 사망 F4 이후에만 화로 구조가 파손됩니다.

## 시간과 연결

- HeatWindup: 100/120/140/150/160/180ms = 0.85초.
- Explosion: 60/60/60/60ms = 0.24초.
- CoolingRecovery: 180/190/200/210/180ms = 0.96초.
- Explosion+Cooling 합계는 정확히 1.2초입니다. 별도 후딜을 더하지 않습니다.
- Hit 0.15초, Death 0.45초는 검토용 제안입니다. 기존 피해/사망/보상/출구 타이밍을 수정하지 않았습니다.

전체 RGBA 픽셀 일치 확인:
1. 설치된 Idle F1 = HeatWindup F1.
2. HeatWindup F6 = Explosion F1.
3. Explosion F4 = CoolingRecovery F1.
4. CoolingRecovery F5 = 설치된 Idle F1.

Hit는 기본 열 상태의 자료입니다. 충전/폭발 중 full-body Hit 시트로 단순 교체하면 준비 중 밝기와 어긋날 수 있으므로, 공격 포즈 우선순위 및 기존 피격 피드백과의 합성은 실제 연동 때 확인해야 합니다. 이번 그래픽만으로 공격 중 모든 Hit 전환이 자연스럽다고 보장하지 않습니다.

## VFX 분리

모두 단발 시각 효과이며 실제 공격 판정을 담지 않습니다. 개별 프레임 Pivot은 중앙입니다.

- FurnaceCharge: 64×64 / 6f / 0.85초. 화로/원래 균열의 에너지 픽셀과 좁은 주변광만 포함합니다. 전체 몸체를 다시 그리지 않았고 철창은 광원 마스크에서 제외했습니다. 캐릭터와 같은 64px 중심을 맞추면 원본 화로/균열 위치에 정렬됩니다. BodyGlow를 유지할지 이 효과로 대체할지는 나중에 결정해야 합니다.
- HeatExplosion: 96×96 / 6f / 0.24초. 사방으로 확산되는 짧은 원형 주황 열기 파동입니다. 본체·자폭 파편·방향성 광선·새 공격 예고는 없습니다. 마지막 프레임은 투명입니다.
- CoalEmbers: 64×64 / 5f / 0.24초. 소량의 불씨와 작은 검은 석탄 조각입니다. 큰 불꽃/연기는 없고 HeatExplosion의 보조 자료입니다.
- CoalHitFragments: 32×32 / 4f / 0.18초. 작은 석탄 조각과 소수의 불씨입니다. 기존 공통 피격 파편을 대체할 수 있는 독립 자료이며 자동 연결하지 않았습니다.
- CoalDeathBurst: 96×96 / 7f / 0.45초. 작은 검은 석탄 조각 중심으로 흩어지며 불씨는 적습니다. 일반 HeatExplosion과 달리 원형 파동이나 커지는 불꽃 링이 없습니다. 본체의 큰 화로/석탄 덩어리를 그대로 복제하지 않았습니다.

HeatExplosion/CoalEmbers/CoalDeathBurst는 실제 저장된 물리 공격/사망 중심에 정렬하는 자료입니다. FurnaceCharge는 본체 프레임에 맞추는 자료입니다. 시각 화로의 위치를 이유로 물리 공격 중심을 옮기면 안 됩니다.

## HeatExplosion 유효 픽셀 범위 / 반경 2.0 참고

96×96 셀의 Pivot은 (48,48)입니다. 모든 가시 프레임의 알파>0 합집합은 x=5..90, y=5..90, 경계 표기로 [5,5,91,91)입니다. 유효 축 방향 범위는 86×86px이며 최대 가시 픽셀 중심 반경은 약 43.4108px입니다. 전체 96px 캔버스에는 투명 여백이 있습니다.

PPU64·배율1에서 유효 반경은 약 0.67829유닛입니다. 이 픽셀 중심 반경을 기존 실제 피해 반경 2.0에 맞추는 시범 배율은 약 2.94857(약 2.95)입니다:

scale = 2.0 × 64 / 43.4108

이때 투명 여백을 포함한 전체 캔버스 크기는 약 4.42286유닛이고 가시 반경은 약 2.0입니다. 캔버스 전체 지름을 4.0유닛으로 맞추는 것과 다릅니다. 픽셀 모서리·계단식 원형·부모 배율 때문에 실제 게임에서 오차가 있으므로 씬 합성 검토가 필요합니다. 이 계산은 이미지의 시각 배율 제안이며 Collider/damageRadius/경고 반경을 바꾸는 값이 아닙니다. 다른 보조 VFX의 크기도 공격 판정을 의미하지 않습니다.

## 기존 구현 보존

CoalMonsterAI.cs를 읽기 전용으로 확인했습니다. 기존 Warn, BodyGlow, HitArea(origin,damageRadius), Impact, Recover 순서가 있으며 damageRadius 기본값은 2.0, warningRadius 기본값은 2.2입니다. 경고와 피해 반경을 혼동해 새 PNG로 변경하지 않았습니다.

사용자가 제공한 기존 흐름인 준비 0.85초 / 저장 Rigidbody2D 위치에서 피해 1회 / 공격 반경 2.0 / 후딜 1.2초 / 예고 시작 기준 간격 3.5초를 그래픽 참고로 사용했습니다. 실제 직렬화 시간값을 쓰거나 변경하지 않았습니다.

기존 코드에서는 피해 후 플레이어가 사망하면 Impact 전 yield break로 일부 후속 효과가 생략될 수 있습니다. 새 VFX는 이 시각 자료일 뿐 피해가 적용되기 위한 조건이 아니며, 생략을 막기 위한 전투 코드 변경도 하지 않았습니다.

기존 원형 공격 예고와 카메라 흔들림·피격 피드백은 재사용 대상입니다. BodyGlow와 기존 Impact의 펄스/파편에 새 FurnaceCharge/HeatExplosion/CoalEmbers를 모두 겹치면 과해질 수 있어 추후 교체/선택이 필요합니다. 이번에는 효과 교체나 자동 연결을 하지 않았습니다. 새 지속 피해/화상/자폭 기능도 없습니다.

## 검증 결과

- 요청된 PNG 10개 전부 실제 크기/RGBA/투명도/셀 수/저장 픽셀 분할을 확인했습니다.
- 모든 프레임 바깥 네 변은 투명하고 잘림이 없습니다.
- 사망 전 몸체·발·화로 중심, 철창 및 눈의 원본 픽셀, 균열 위치/알파를 검사했습니다.
- 준비 단계의 화로 평균 밝기는 순차 증가하고 냉각 단계는 순차 감소합니다. 상세 수치는 validation.json에 있습니다.
- 일반 Explosion의 4프레임 모두 화로·철창·얼굴·팔다리가 유지되고 원본 연결 실루엣을 유지함을 검사했습니다. Death의 파손/잔재와 정적 프레임상 구분했습니다.
- 연결 지정 프레임은 전체 픽셀 일치합니다. PNG가 생존/피해/보상 이벤트를 소유하지는 않습니다.
- GIF를 재디코딩해 프레임 수와 시간을 확인했습니다. 불투명 본체 프레임은 GIF 픽셀이 PNG 확대와 같고 WebP의 보이는 색/알파는 모든 PNG 확대와 정확히 같습니다.
- 원본·기존 Idle/Move·다른 몬스터 그래픽·읽은 프로젝트 코드의 해시가 변경되지 않았습니다.

## 미검증 / 남은 시각 검토

로컬 file:// 브라우저 재생이 이전에 보안 정책으로 차단된 상태여서, 실제 시간 흐름의 GIF 화면을 직접 관찰하지 못했습니다. 우회하지 않았으며 GIF 파일 생성/디코딩을 실시간 시각 검토 완료로 보고하지 않습니다.

Unity Import/실제 배경/카메라/부모 배율/공격 중심·반경 합성/공격 중 Hit 우선순위와 빛 유지/기존 효과 중복/반복 재생 자연스러움은 미검증입니다. 검은 파편의 실제 배경에서의 대비도 확인해야 합니다.

원본 정지 이미지를 분절해 팔꿈치·무릎과 석탄 파편을 2D로 재구성한 시범 자료입니다. 숨은 관절/화로 내부 파단면을 새로 정밀하게 그린 최종 수작업 아트는 아닙니다. Death의 자연스러움은 실제 재생으로 최종 확인이 필요합니다.

현재 요청 파일 생성 실패는 없습니다. 정적 규격·정렬·철창 구조·잘림 검사를 통과했지만, 실시간 시각 품질까지 전부 검증한 것은 아닙니다. 별도 게임 테스트나 컴파일은 실행하지 않았습니다. 모든 그래픽은 프로젝트 밖에 저장했고 코드/씬/프리팹/GDD/Systems/Git은 변경하지 않았습니다.
