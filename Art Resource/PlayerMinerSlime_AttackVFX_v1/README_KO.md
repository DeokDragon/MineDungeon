# 광산던전 플레이어 곡괭이 공격 VFX v1

## 제공 범위

금속 머리 잔상 PNG3종, 적중 먼지 시트3종,3타 광물 파편 시트1종입니다. 기존 몸체/무기/소켓/공격 애니메이션을 바꾸지 않았습니다. 잔상은 기존 금속 머리 픽셀을 재사용했고, 먼지·파편 원형은 이미지 제작 도구로 별도 생성한 뒤 작은 원배율 픽셀과 제한된 회갈색 팔레트로 정리했습니다. 마법 발광·검기·충격파·손잡이 잔상은 제작하지 않았습니다.

게임용 PNG는 `PNG/`, GIF·확대 검수는 `Previews/`, 제작용 원형은 `Reference/`입니다. 생성 도구와 사용 프롬프트는 `Generation_Prompts.txt`에 기록했습니다.

잔상3종은 같은 머리 모양에 공격별 알파 상한을 적용한 독립 스탬프입니다. 방향 차이는 기존 무기의 실제 과거 위치/회전으로 표현합니다. 불필요한8방향 잔상 시트를 중복 제작하지 않았습니다.

## 3. 머리 위치·Pivot·픽셀 밀도

문서 좌표는 왼쪽 위 원점, X 오른쪽/Y 아래쪽인 픽셀 경계 좌표입니다.

|리소스|기준 좌표|Unity 정규화 Pivot 제안|
|---|---|---|
|기존 무기56×48|손잡이 결합점 G=(14,24)|(0.25,0.5),기존값 유지|
|무기 머리 중심|원본 무기 내 H=(43,24)|손잡이 G와 구분|
|머리 잔상24×40|H=(12,20)|(0.5,0.5)|
|먼지32×32|적중 원점 (16,16)|(0.5,0.5)|
|파편40×32|적중 원점 (20,16)|(0.5,0.5)|

무기 G→H의 오프셋은 로컬 +X방향29px입니다. 무기의 원본 중심 (28,24)을 머리 원점으로 쓰지 않습니다. 일반 변환은 무기 이미지 좌표 (x,y)를 **((x−pivotX)/PPU,(height−y−pivotY)/PPU)** 로 바꾼 후 실제 무기 Transform에 적용합니다. 현재 무기에서 H 로컬 위치는 (29/64,0)입니다. SpriteRenderer.flipX/flipY가 있다면 Transform과 별도로 이미지 반전을 반영해야 합니다.

권장 시작값은 VFX도 PPU64이며 실제 세계 픽셀 폭을 무기와 같게 맞춥니다. 기존 참조의 본체/무기 Scale0.8에서는1px=0.0125유닛입니다. **월드 공간 VFX의 최종 Scale은 이 픽셀 폭과 PPU로 맞추며**, 부모 Scale0.8에 다시0.8을 중복 적용하지 않습니다. 실제 프리팹의 lossyScale/PPU는 후속 통합에서 재확인해야 합니다. 게임 전체 PPU나 공격 범위를 확정하는 제안이 아닙니다.

미리보기는320×320 투명 작업셀에 원래64px 몸체를 (128,128)에 배치했습니다. 적중 대상까지 포함할 여백이며 캐릭터를 키운 것이 아닙니다. `1x` GIF 안의 본체는 원래64px 픽셀 배율입니다.

## 4. 잔상 재생 방식

1. 기존 공격 시각 동작에서 **무기 머리의 세계 위치·회전·크기·앞뒤 정보**를 약20ms 간격으로 캡처합니다.
2. 과거 머리 스냅샷에 해당 공격의 독립 머리 PNG를 배치합니다. 캐릭터나 현재 무기 Transform의 자식으로 따라다니게 하지 않습니다. 이동 중에도 과거 위치가 남아야 합니다.
3. 각 스냅샷의 수명과 알파를 줄인 후 제거합니다.1타는 시계,2타는 반시계의 기존 궤적을 그대로 기록합니다.
4.3타는 상승하는 전진 구간에만 스냅샷을 만듭니다. 수명은0.15초 상한이며, 현재 머리에서 공격축 기준8px보다 먼 과거 흔적은 제외해 짧은 방향성 잔상으로 유지합니다. 이는 VFX 길이 제한이며 **무기 전진량을 줄이는 처리가 아닙니다**.

미리보기의 방출 구간은1·2타 진행률12~88%,3타10~50%입니다. 이 구간은 VFX용 시험값이며 기존 공격 시작 각도·실행 시간·피해 시점을 변경하지 않았습니다. 개별 스냅샷의 수명과 전체 방출 구간은 구분해야 합니다. 수명0.10초가 공격 전체를0.10초로 재생한다는 뜻은 아닙니다.

### 겹친 잔상의 알파 상한

PNG의 알파 상한만 맞춰 여러 장을 겹치면 합성 알파가35/45/50%를 넘을 수 있습니다. 미리보기는 모든 살아 있는 스냅샷에 대해 아래와 같이 분배했습니다.

- `w_i=(1−age_i/life)^2`
- `a_i=1−(1−cap)^(w_i/max(1,sum(w)))`
- PNG에 cap이 이미 들어 있으므로 Sprite 색상 알파 배율은 `a_i/cap`입니다. cap을 두 번 곱하지 않습니다.

앞/뒤 그룹을 나누기 전에 같은 스냅샷 목록으로 분배합니다. 기본 알파 합성을 사용하고 Additive/발광 재질로 바꾸지 않습니다. 이 계산과 픽셀 반올림을 포함한 미리보기 알파가 공격별 상한을 넘지 않는지 검사했습니다. **현재 Unity에 이 분배 코드가 적용되어 있다는 뜻은 아닙니다.** 이번에 Unity 코드나 재질을 추가하지 않았습니다.

공격 취소/종료 뒤 새 잔상 방출은 멈추고, 이미 생성된 스냅샷은 자신의 짧은 수명 안에서 소멸시키는 구조를 제안합니다. 새 피해나 추가 경직을 발생시키지 않습니다.

## 5. 적중 먼지·파편 발생 조건

먼지와 파편은 **실제 적중이 확인된 시각 이벤트에만** 연결합니다. 공격 애니메이션 진행률50%라는 이유만으로 발생시키지 않습니다. 기존 피해·범위 판정은 그대로 두고, 이미 확인된 결과에 붙일 그래픽입니다.

- 허공 공격: 머리 잔상만. 먼지/파편 없음.
-1·2타 적중: 해당 먼지 시트1회.
-3타 적중: 먼지 시트와 별도 파편 시트를 같은 실제 접촉점에서1회씩 사용할 수 있음.
- 생성한 적중 효과는 그 세계 위치에 고정합니다. 적이 이동/사망하거나 플레이어가 이동해도 플레이어 무기에 계속 붙이지 않습니다.
- 기준점은 후속 통합에서 받은 실제 접촉점/대상 가장자리 등의 표시 좌표입니다. 무기 머리가 반드시 피해 판정 원점이 된다는 의미가 아닙니다.
- 다수 대상 동시 적중 때의 버스트 중복·표시량은 후속 Play에서 확인해야 합니다. 이번에 피해나 적중 이벤트 체계를 새로 만들지 않았습니다.

`BeforeAfter`, `Hit`, `8Directions_Hit`, `Combo_HitDemo` GIF는 **명시적인 적중 테스트 신호를 별도로 넣은 예시**입니다. 비교를 위해 기존 돌 몬스터를 같은 위치에 표시하고 진행률50%의 시각 머리 지점을 예시 접촉점으로 사용했습니다. Unity 충돌/피해를 실행한 검증이 아닙니다. 같은 진행률의 `Air_TrailOnly` GIF에는 적중 신호를 주지 않았고 먼지·파편이 없습니다.

## 6. 앞뒤 가림·반전·이동

기존 무기의 앞뒤 정렬을 참고해 위쪽 머리 잔상은 본체 뒤, 아래쪽은 본체 앞에 두었습니다. 과거 스냅샷은 각자의 위치·각도 정보를 유지합니다. 앞쪽 잔상도 실제 금속 머리보다 아래에 놓아 현재 무기를 가리지 않습니다. 먼지/파편은 접촉점의 깊이를 기준으로 대상과 몸체를 가리지 않도록 정렬해야 합니다.

좌우 조준에서 같은 PNG를 회전/위치 변환해 사용하며, 본체 flipX만으로 시계·반시계 방향을 반대로 바꾸지 않습니다. 본체/소켓/곡괭이를 통째로 VFX 한 프레임에 굽지 않았습니다.3타는 회전 궤적 없이 기존0.4유닛 전진 수식을 그대로 따라갑니다. Scale0.8/PPU64 조건에서 최대32px, 관측0.399유닛은31.92px입니다.

이동 시험은 과거 머리/적중점의 세계 위치를 고정한 채 카메라가 몸체를 따라가는 상황으로 합성했습니다. 이동량 (40,−12)px/초는 확인용 시나리오이며 실제 이동 속도를 바꾼 값이 아닙니다.

## 8. 검증 결과와 미검증 사항

### 확인

- 게임용 PNG7개 실제 크기·셀 수·RGBA·외부 투명도. 입자 최종 프레임 완전 투명.
- 금속 머리의 원본 회색/검은 외곽선·하이라이트 픽셀 재사용. 갈색 손잡이 전체는 잔상에 없음.
- 잔상 상한을 넘지 않는 합성,3타의 짧은 축 방향 이력, 마법진/충격파/지속 장판 없음.
- 허공2,400표본(3공격×8방향×2반전×2이동 조건×25시점), 정지 적중1,200표본(3×8×2×25), 총 **3,600표본**에서 미리보기 경계 잘림0개. 잔상의 얼굴/헬멧 영역 침범0px, 적중 입자의 얼굴/헬멧 침범0px,3타 잔상과 젤리 확장부 겹침0px. 이동 중 적중 GIF는 별도 예시이며 모든 이동/적중 조합을 수치 검증한 것은 아닙니다.
- 허공 시험의 먼지/파편 발생0회. 이는 미리보기의 명시적 이벤트 분리 검사입니다.
