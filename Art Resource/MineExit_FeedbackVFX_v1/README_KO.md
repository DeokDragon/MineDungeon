# MineExit Feedback VFX v1

현재 MineExit_v1_1 출구 위에 겹쳐 쓰는 독립 VFX2종이다. 기존 문 개방6프레임/0.52초, 횃불4프레임/0.70초를 그대로 사용한다. VFX에는 문틀·문·횃불을 중복해서 그리지 않았다. 기존 원본·Unity 코드·프리팹·판정은 수정하지 않았다.

## 게임용 파일

| 파일(VFX/) | 실제 크기 | 셀/프레임 | 시험 시간 |
|---|---|---|---|
| MineExit_OpeningSparkle_6f_128x64_v1.png |768×64|128×64×6|0.40초,1회|
| MineExit_TunnelGlow_8f_128x64_v1.png |1024×64|128×64×8|2.80초,반복|

둘 다 RGBA/실제 투명 배경/Point용 네이티브 픽셀이다. 셀128×64, PPU64, 중앙 Pivot 픽셀(64,32)/정규화(0.5,0.5), 캔버스 표시 범위2×1유닛. 입자 사라짐과 은은한 발광을 위해 **부분 알파가 의도적으로 있다.** 알파를0/255로 강제하면 강도가 망가지므로 임계값으로 자르지 않는다.

## A. 개방 완료 반짝임

7개의 매우 작은 금빛 입자(1~3px)를 개구부 중앙 안쪽에서 시작해 좌우·위쪽으로 조금 퍼뜨린 뒤 사라지게 했다. 가장 밝은 시점에도 실제 입자 픽셀은17개로, 문틀/횃불을 가릴 큰 섬광이나 폭발은 없다. F6은 완전 투명으로 종료를 명확히 했다.

| 프레임 | 역할 | ms | 시작 시각(반짝임 기준) |
|---|---|---:|---:|
|F1|중앙에 작은 입자 발생|40|0.00초|
|F2|짧은 금빛 점등|60|0.04초|
|F3|좌우·위쪽 확산|70|0.10초|
|F4|조금 더 퍼지며 약화|80|0.17초|
|F5|작은 잔광만 남음|80|0.25초|
|F6|완전 투명|70|0.33초|

몬스터 전멸/출구 실제 개방이 아니라 **그에 따른 시각 개방 애니메이션 완료 시점**에 한 번 재생한다. 현재 시험값으로는 실제 개방 이벤트+0.52초가 시작 시각이다. 0.40초 종료 뒤 숨기거나 투명 F6을 유지한다. 자동 반복하지 않는다.

## B. 열린 갱도 발광

갱도 안쪽 하단을 중심으로 작은 황금·주황색 빛이 천천히 강해졌다 약해진다. 빛은 픽셀 단위의 제한된 면과 단계적 알파로 표현했다. 최대 알파는48/255(약18.8%)이며 갱도 안쪽 암석과 버팀목이 비치도록 낮게 잡았다. 문틀·등불·바닥 전체를 덮는 큰 광원은 없다. 기존 횃불을 대체하지 않고 그보다 느린 주기로 움직인다.

8프레임 각각350ms, 총2.8초. 상대 강도는0.60/0.70/0.85/0.96/1.00/0.96/0.85/0.70이다. 실제 최대 알파는29/34/41/46/48/46/41/34다. F8→F1도 작은 차이로 이어지며, 매번 밝은 섬광으로 재시작하지 않는다.

발광은 개방 완료부터 켜고 열린 동안 반복한다. 문이 이미 열린 상태로 활성화/재입장한 경우에는 발광만 표시하고 반짝임을 새로 만들지 않는 구성을 권장한다. 잠김으로 돌아가거나 해당 출구가 사라지면 즉시 두 VFX를 정리한다. 실제 개방/방 전환 판정은 이 리소스와 무관하다.

## 기존 타이밍과 동기화

| 실제 개방 이벤트 기준 | 시각 구성 |
|---|---|
|0.00초|기존처럼 즉시 통과 가능. 기존 개방/점등6프레임 재생|
|0.00~0.52초|기존 문/점등만 표시; 이 VFX2종은 아직 표시하지 않음|
|0.52초|반짝임1회와 은은한 발광 시작. 기존 횃불 루프도 현재 방식대로 시작|
|0.52~0.92초|반짝임+발광+기존 횃불 표시|
|0.92초 이후|반짝임 종료. 발광2.8초와 횃불0.70초를 독립 반복|

2.8초는 횃불4주기에 해당하지만 두 시트의 프레임을1:1로 연결하지 않는다. 각자의 타임라인을 사용한다. 실제 문 통과를 개방 완료나 반짝임 종료까지 기다리는 기능은 절대 추가하지 않는다. 이미 출구에 닿은 플레이어가 즉시 다음 방으로 이동해 효과를 보지 못하는 경우에도 기존 이동 규칙을 우선한다.

읽기 확인한 MineExitSpriteAnimation.cs는 .52초 개방 이후 .70초 횃불을 표시하고 OnEnable에서 이미 열린 문은 개방 애니메이션을 다시 시작하지 않는다. 신규 VFX와의 실제 이벤트 연결은 후속 Codex 작업이며 이번에는 구현하지 않았다. 반복 LateUpdate에서 완료 시간을 지났다는 이유로 반짝임을 매번 새로 시작하지 않도록, 완료 경계를 한 번 감지하는 방식이 필요하다. 게임 기능을 새로 설계하라는 의미가 아니다.

## Unity 가져오기·Pivot·Sorting 제안

1. Sprite Multiple, Grid by Cell Size128×64, 가로 왼쪽부터 순서대로. Rect n=(128×n,0,128,64), n은0부터. PPU64/Pivot(0.5,0.5).
2. Point / Compression None / Mip Maps Off / Alpha is Transparency On. Max Size1024 이상으로 원본을 축소하지 않는다. 일반 Sprite Alpha Blend, 색상흰색/알파1을 시험 기준으로 한다. 낮은 알파를 이미 이미지에 반영했으므로 별도 Additive/네온 셰이더·Light2D·Bloom을 추가할 필요가 없다.
3. **위치와 배율:** 현재 올바르게 적용된 출구 시각 Transform의 중심을 그대로 사용한다. VFX 로컬 위치(0,0,0), 동일 유효 배율을 적용한다. 현재 출구 루트의 Scale(2,1,1)에 새2×1 스프라이트를 그대로 놓으면4×1로 늘어날 수 있다. 이미 보정된 출구 시각 자식 아래 VFX를 두고 Local Scale(1,1,1)로 상속하는 방법 등이 후보이며, 통합 시 현재 구조를 확인한다. Collider 크기를 맞추려고 출구 루트 Scale/Trigger를 바꾸지 않는다.
4. **Sorting 권장:** 기존 출구 아트의 Sorting Layer를 L, Order를 S라고 할 때 갱도 발광은L/S+1, 반짝임은L/S+2를 초기 시험값으로 제안한다. 둘 다 플레이어·전투 효과보다 아래에 두며 실제 프로젝트의 Sorting 규칙을 우선한다. 효과 픽셀을 개구부 안으로 제한했으므로 문틀 위에서 보일 픽셀은 없다. 별도 글로벌 레이어 생성은 요구하지 않는다.
5. 기존 적갈색/초록 tint를 신규 VFX에 물려주지 않는다. 흰색 tint로 원본 황금색을 유지하고, RoomExit.cs의 기존 개방/통과/레이어 처리와 분리한다. 색 변경이나 배율 조정을 이유로 판정을 변경하지 않는다.
6. 좌표는 이미지 좌상단(+x오른쪽,+y아래), 본체와 동일한 중심이다. Unity 로컬 위치 환산은((px−64)/64,(32−py)/64). 임의 오프셋/별도 바닥 위치로 다시 정렬하지 않는다.

## 실제 검증과 한계

확인:

- 두 PNG의 크기/RGBA/셀 수/프레임 분할/투명 알파 확인. 부분 알파는 의도된 VFX 강도다.
- 모든 효과 픽셀이128×64 캔버스와 갱도 안쪽 영역(x40~88,y23~52) 안에 들어옴. 반짝임 실제 bbox는x50~81/y26~40 범위, 발광은x43~85/y27~51 범위다. 잘림 없음.
- 문틀·횃불 영역에 VFX 픽셀이 없음을 검사. 원배율 및 확대 정지 합성에서 입구·버팀목과 램프가 구분된다.
- 반짝임 마지막 프레임 완전 투명, 발광 최대 알파48 이하, 반복의 대칭 밝기 단계 확인.
- 모든 GIF 저장 후 전 프레임 디코딩하여 프레임 수/표시 시간/예상 합성 화면을 비교했다. GIF는256색 제한이 있으나 게임용 RGBA PNG의 알파/색은 유지한다.
- 기존 MineExit_v1_1 전체 파일 및 관련 Unity 코드/맵 프리팹의 작업 전후SHA256 비교. 결과는 Specs/Validation_and_Timing.json.

미검증:

- 실시간 애니메이션 재생을 직접 관찰하지 못했다. 자연스러운 입자 이동·맥동 인상은 정지 프레임/디코딩 검사와 구분해 미검증이다.
- Unity Play, 실제 카메라 원배율, 실제 Sorting·부모 배율·tint·개방 완료 이벤트와의 연동은 범위 밖이며 후속 Codex가 확인한다. 이 아트만 복사하면 자동 재생되는 것은 아니다.
- 아주 밝거나 다른 색의 갱도 배경에서는 발광 가독성을 추가 검토할 수 있다. 이 팩은 현재 v1.1의 어두운 내부를 기준으로 맞췄으며 화면 전체 조명/새 광원/게임플레이 기능을 추가하지 않았다.

## 제작 출처

이미지 생성 스킬의 내장 image_gen으로 금빛 입자와 투명 내부 발광 원본을 각각 만들었다. Source/Generated_GoldGlints.png와 Generated_TunnelGlow.png는 생성 보관본이며 게임용이 아니다. 생성된 작은 입자 픽셀을 분리해 개별 경로로 애니메이션을 구성하고, 내부 발광은 네이티브 픽셀 범위와 낮은 알파로 정리했다. Source/Generation_Brief.md에 프롬프트 조건을 기록했다. 게임용은 VFX/의 두 PNG만 사용한다.
