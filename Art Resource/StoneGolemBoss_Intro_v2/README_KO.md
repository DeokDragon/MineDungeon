# 돌골렘 보스 최초 등장 v2 — 아트 시험본

현재 적용된 P1 원본 암석 픽셀과 관절 편집 리그로 새 등장 포즈를 구성했다. v1의 10프레임을 늘이거나 반복하지 않았다. P1의 얼굴·어깨·명암을 유지하면서 무릎/골반 압축, 머리 들기, 어깨와 팔꿈치 관절, 주먹의 지연을 조합했다. P2 외곽판/금빛 균열은 가져오지 않았다. 기존 P1 몸통의 어두운 이음새 일부만 잠깐 따뜻하게 밝힌 뒤 원래 색으로 복원한다.

## 게임용 리소스

`Sprites/StoneGolemBoss_P1_Intro_18f_160x160_v2.png`: **2880×160px / 18셀 / 셀160×160 / RGBA / 알파0·255**. 각 셀은 `Frames/Intro_F01.png`~`Intro_F18.png`에도 동일하게 저장했다. 18개 셀은 모두 서로 다른 픽셀 이미지다.

PPU128, 중앙 Pivot(80,80)=(0.5,0.5), 기존 Body Scale1.8. Point / Compression None / Sprite Multiple / Grid160×160을 시험한다. 프레임 정렬과 원본 픽셀 배율을 유지하며, 애니메이션에 Transform 이동/확대/회전을 굽지 않는다. 내부 암석판 관절의 회전은 최근접 픽셀로만 재배치했다. 첫 프레임은 의도적으로 웅크린 자세라 Idle과 다르며, 마지막 F18은 현재 Unity P1 Idle F1과 RGBA 픽셀 단위로 동일하다.

## 전체 약5초 시험 배분

- 카메라 접근 0.80초: F1 휴면 자세 유지. 본체18프레임의 시간에는 포함하지 않는다.
- 본체 등장 3.60초: 카메라가 보스를 확보한 뒤 F1부터 한 번 재생한다.
- 카메라 복귀 0.60초: F18/P1 Idle F1을 유지한다.
- 합계5.00초. 모든 수치는 시험 제안이며 현재 코드의2초 타이머를 수정하지 않았다. 후속 통합에서 연출 종료/전투 잠금/쿨타임 규칙을 보존하면서 상태 종료 시각과 카메라를 함께 확인해야 한다.

카메라가 도착하기 전에 주요 기상·위협 프레임을 소모하지 않는다. 본체3.6초를 고정 FPS로 균등 분배하면 아래 리듬과 달라진다. JSON의 프레임별 시간 사용을 권장한다. 실제 카메라 경로·줌·흔들림·스킵 UI는 제작하지 않았다.

## 분리 VFX — 기존 파일 재사용

전용 VFX를 새로 그리지 않았다. `ReusedVFX/`의 두 PNG는 기존 원본과 바이트 단위로 같다. .meta/GUID는 복사하지 않았다. 이미 Import된 동일 자산을 재사용할 수 있으면 중복 Import를 피한다.

|VFX|원본/셀/프레임|시작|시험 재생·강도|
|---|---|---:|---|
|기상 먼지|B-1R_VFX_JumpDust.png /64×64 /5 /시트320×64|1.12초|각100ms, 총0.50초, 알파28%|
|어깨 돌조각|StoneGolemBoss_Transform_Chips_8f_192x192_v1.png /192×192 /8 /시트1536×192|1.38초|각140ms, 총1.12초, 알파60%|
|위협 하중 먼지|같은 JumpDust 재사용|2.54초|각100ms, 총0.50초, 알파48%|

돌조각은 P1 원석 색상의 기존 분리 아트이며 P2 본체가 아니다. 이름에 Transform이 있으나 이 PNG만 시각용으로 재사용한다. 기존 변신 시스템/공격 컴포넌트를 실행하지 않는다. 원형 공격 충격파는 사용하지 않았다. 먼지·조각은 실제 대미지나 공격 예고와 무관하다.

192셀 조각 Pivot(96,96), PPU128, 본체와 중심 일치, Body 아래 localScale1. 먼지 Pivot(32,32), 본체셀의(80,134)를 중심으로 배치한다. 본체 로컬 단위는(0,-54/128)=(0,-0.421875), BodyScale1.8 적용 시 월드 오프셋Y=-0.759375다. 기존 먼지 Import는PPU64이므로 Body 하위 localScale0.5를 써야 본체 원본 픽셀 밀도와 일치한다. 새 별도 Import를PPU128로 한다면 localScale1이 동등하다. 두 배율을 동시에 적용하지 않는다.

Sorting은 기존 본체와 같은 Layer에서 먼지=본체Order-1, 돌조각=Order+1을 시험한다. 새 광원/머티리얼은 필요 없다. 조각은2.50초, 먼지는3.04초에 끝나 전투 준비 전에 잔여 효과가 없다. 중단/즉시 전환 시 두 VFX를 정리하고 현재 P1 Idle F1을 표시한다. 실제 게임의 연출 완료·전투 제한은 기존 AI가 담당한다.

## 실제 검증과 한계

- 실제 파일을 다시 열어2880×160/RGBA/18셀/투명 알파0·255를 검사했다. 프레임별PNG와 시트의 모든 픽셀이 같다.
- F18은 현재 `Assets/Art/Bosses/StoneGolem/StoneGolemBoss_P1_Idle_4f_160x160_v1.png` 첫 셀과 정확히 같다.
- 양발 바닥의 원본109픽셀을18프레임 모두 동일 좌표·동일 색으로 보존했다. 전체 이미지 최하단은 주먹 자세에 따라 몇 픽셀 달라질 수 있으므로 최하단만으로 발 접지를 판단하지 않았다.
- 모든 본체 프레임의 가장자리에 투명 여백이 있고, 개별 암석판 변환 좌표도 셀 안에 있는지 검사했다. 실루엣 확대·축소 없이 머리·팔·무릎의 자세가 변한다.
- 원배율/확대 접촉 시트와 환경 합성을 정적으로 검토했다. 휴면에서 기상, 팔을 들어 위협하는 자세 차이는 확인했다. 눈·얼굴의 원본 형태를 유지했다.
- GIF의 실제 저장 프레임 수·표시 시간·디코딩 픽셀을 검사했다. **실시간으로 움직이는 GIF의 자연스러움을 직접 관찰한 검증은 하지 못했다.** 따라서 무게감·프레임 간 이음·VFX의 동적 자연스러움은 최종 확인이 필요하다.
- Unity Import/Play, 실제 카메라 접근·복귀, 실제 보스룸에서의 가림, 상태 종료/전투 재개는 미검증이다. 실제 Play 검증은 이번 범위에서 제외했다.
- 기존 보스 아트·관련 코드/프리팹·공식 문서216개 파일의 작업 전후SHA256이 같다. 기존meta/GUID, 공격/변신/사망/Idle/Move는 수정하지 않았다. Git 커밋·푸시는 하지 않았다.

세부 수치는 `Specs/Unity_Intro_v2_Spec.json`, 파일·GIF·보존 검사는 `Specs/Validation_and_Timing.json`에 기록했다. 본체동작의 정적 차이를 넘어 실제 위압감이 충분한지는 후속 재생 검수에서 판단한다.
