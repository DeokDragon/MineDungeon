# 광산던전 — 통합 기획 및 개발 인수인계

작성일: 2026-10-20
목적: 다른 ChatGPT 대화, Gemini, Codex에서 기존 기획과 개발 진행 상황을 이어가기 위한 문서

---

## 1. 이 문서를 읽는 방법

이 문서는 지금까지의 대화에서 확인되는 기획과 사용자가 보고한 구현 상황을 정리한 것이다.

실제 Unity 프로젝트 소스를 검사한 결과가 아니므로 다음을 구분한다.

- 확정 기획: 사용자가 직접 결정하거나 변경한 내용
- 구현 완료 보고: 사용자가 구현했다고 알려준 내용
- 구현 요청: Codex에 작업을 요청했거나 구현 대상으로 논의한 내용
- 미확정: 정확한 수치, 동작, 구현 여부를 현재 대화만으로 확인할 수 없는 내용

현재 프로젝트의 코드, 프리팹, 씬을 확인하기 전에는 구현 여부를 단정하지 않는다.

이전 문서와 충돌할 경우 사용자의 최신 결정이 우선한다.
확인되지 않은 이름, 수치, 파일 경로를 임의로 만들어 확정 기획처럼 사용하지 않는다.

## 2. 프로젝트 개요

### 2.1 기본 정보

- 가칭: 광산던전
- 개발 엔진: Unity
- 사용자 Unity 버전: 6000.3.12f1 LTS
- 현재 개발 방향: 싱글플레이 우선
- 전투 방향: 작은 방들을 진행하며 몬스터를 처치하는 액션 던전 게임
- 주요 무기: 곡괭이
- 주요 적: 돌, 철, 수정, 석탄, 자철석 계열 몬스터
- 보스: 돌골렘
- 화면 기준 해상도: 1920 × 1080
- 아트 방향: 도트 느낌을 검토 중이며 최종 규격은 미확정

멀티플레이 가능성을 논의했으나 현재는 싱글플레이부터 제작하기로 결정했다.

### 2.2 참고하는 게임 구조

사용자는 로블록스의 헌티 좀비 계열 게임과 던전퀘스트처럼 다음 구조를 원한다.

1. 비교적 작은 전투 방을 불러온다.
2. 방에는 몬스터들이 배치되어 있다.
3. 해당 방의 몬스터를 모두 처치한다.
4. 출구가 열린다.
5. 다음 방을 랜덤으로 불러온다.
6. 보스 방에 도달하여 보스를 처치한다.
7. 결과창을 통해 전투 기록과 획득 보상을 확인한다.

현재 방 개수, 한 런의 정확한 방 구성, 중복 맵 방지 규칙은 프로젝트 설정을 확인해야 한다.

### 2.3 협업 방식

- 사용자: 최종 기획 결정, Unity 플레이 확인, Figma 레퍼런스 제작
- ChatGPT: 기획 정리, 시스템 검토, Codex 전달용 작업 지시 작성
- Gemini: 보조 기획, 기획 검토, UI 및 맵 시각 레퍼런스 제작
- Figma AI: UI 배치 참고용 레퍼런스
- Codex + Unity MCP: 코드 및 Unity 씬·프리팹·컴포넌트 작업

사용자는 사소한 구현 선택마다 질문을 반복하기보다 기존 기획에 따라 작업을 계속 진행하기를 원한다.

단, 실제로 보지 못한 이미지나 확인하지 않은 코드 내용을 추측해서 설명하면 안 된다.

## 4. 핵심 던전 진행 규칙

### 4.1 방 진행

- 방 단위로 전투한다.
- 방 생성 시 몬스터가 배치된다.
- 모든 대상 몬스터를 처치해야 출구가 열린다.
- 출구를 통해 다음 방으로 진행한다.
- 일반 방은 준비된 맵 후보에서 랜덤으로 불러오는 방향이다.
- 보스 방까지 진행하는 연결은 사용자가 확인했다.

### 4.2 런 내부 상태 유지

한 던전 플레이 동안 다음 상태는 방을 이동해도 유지되어야 한다.

- 현재 체력
- 남은 물약
- 남은 부활 횟수
- 획득한 돈과 경험치
- 획득한 아이템
- 해당 런의 전투 기록

방을 바꿨다는 이유로 체력이나 부활 횟수가 초기화되면 안 된다.

### 4.3 던전 입장 조건

최신 확정 기획:

- 필요한 레벨만 충족하면 입장할 수 있다.
- 이전 던전 클리어 여부를 입장 조건으로 사용하지 않는다.

이전 던전 클리어를 요구하는 해금 규칙을 임의로 추가하면 안 된다.

### 4.4 난이도

- 던전 선택창에 난이도 4종이 존재한다.
- 난이도 선택에 따라 제목, 입장 레벨, 이미지 또는 표시 정보, 보상 정보가 갱신된다.
- 정확한 난이도 이름, 입장 레벨, 배율은 현재 데이터 확인이 필요하다.

## 5. 플레이어 생명·부활·물약

### 5.1 최종 생명 규칙

초기 논의의 부활 3회는 폐기되었다.

최신 확정 규칙:

- 최초 생명 포함 총 3번의 생명
- 부활 가능 횟수는 2회
- 첫 번째 사망: 생명 표시 3 → 2, 부활
- 두 번째 사망: 2 → 1, 부활
- 세 번째 사망: 1 → 0, 던전 실패

### 5.2 부활 위치

- 현재 방의 입구에서 부활한다.
- 던전 전체의 첫 방 입구로 돌아가는 방식이 아니다.
- 보스 위치를 강제로 옮기는 추가 규칙은 확정하지 않았다.

### 5.3 생명 HUD

- 부적 또는 유사한 아이콘 3개로 표시한다.
- 소모된 아이콘은 어둡게 표시한다.
- 결과창의 부활 기록은 최대 2회를 기준으로 표시한다.

### 5.4 물약

- 다시 시작 시 물약 3개로 초기화한다.
- 회복량, 사용 쿨타임, 회복 방식은 현재 코드 확인이 필요하다.
- 체력이 최대일 때의 사용 처리도 기존 구현을 확인한다.

## 6. 시간 정지와 UI 입력 규칙

### 6.1 확정된 시간 규칙

- 던전 입장창을 열어도 게임 시간이 정지하지 않는다.
- 인벤토리를 열어도 게임 시간이 정지하지 않는다.
- 일반적인 일시정지는 ESC 퍼즈 메뉴에서 처리한다.

UI를 연다는 이유만으로 공통적으로 timeScale을 0으로 만드는 구조는 피해야 한다.

### 6.2 확인된 단축키

- T: 월드 상호작용
- I: 인벤토리 열기 및 닫기
- ESC: 열린 UI 닫기 또는 퍼즈 메뉴

공격, 회피, 물약, 스킬의 정확한 현재 키 배치는 프로젝트를 확인한다.

### 6.3 UI 전환

던전 선택창에서 I를 누르면:

1. 던전 선택창을 닫는다.
2. 인벤토리를 연다.
3. 이후 인벤토리를 닫아도 던전 선택창을 다시 열지 않는다.
4. 일반 게임 화면으로 돌아간다.

다른 UI에도 불필요한 자동 재열림을 추가하지 않는다.

### 6.4 UI 크기

- 기준 해상도는 1920 × 1080이다.
- 인벤토리와 던전 선택창이 화면을 너무 꽉 채워 크기를 줄였다.
- 사용자는 수정된 크기가 적절하다고 보고했다.
- 실제 적용된 패널 크기는 현재 프로젝트 값을 유지한다.

## 7. 성장 및 장비 획득 구조

### 7.1 경험치와 레벨

- 몬스터 처치 시 경험치를 바로 획득한다.
- 경험치가 쌓이면 레벨이 오른다.
- 레벨이 오를 때마다 스탯 포인트 1개를 얻는다.
- 포인트를 투자하여 성장하는 구조를 원한다.

미확정 또는 확인 필요:

- 레벨별 필요 경험치
- 최대 레벨
- 투자 가능한 스탯 종류
- 스탯 1포인트당 증가량
- 스탯 투자 UI의 구현 여부

### 7.2 돈

- 몬스터 처치 시 즉시 획득한다.
- 몬스터마다 지급하는 돈이 존재한다.
- 곡괭이 제작에 돈을 사용한다.

### 7.3 곡괭이

- 던전에서 얻은 재료와 돈으로 제작한다.
- 인챈트로 스킬을 붙이는 방식이 주된 스킬 획득 구조가 아니다.
- 무기 중심은 곡괭이이다.

### 7.4 스킬

- 던전 클리어 보상으로 얻는다.
- 획득한 스킬을 장착하여 사용한다.
- 일반 몬스터가 스킬을 드롭하지 않는다.
- 스킬 4종은 구현 완료 보고가 있다.

중요:
현재 대화에 스킬 4종의 전체 최종 명세가 남아 있지 않다.
이름, 속성, 계수, 사거리, 쿨타임은 실제 스킬 데이터와 코드를 확인해야 한다.
임의의 스킬 이름이나 수치를 새로 만들어 기존 확정 기획처럼 사용하지 않는다.

## 8. 몬스터 처치 보상

### 8.1 공통 원칙

- 돈과 경험치는 처치 시 즉시 획득한다.
- 몬스터마다 돈과 경험치 지급량이 존재한다.
- 재료 획득도 인벤토리와 획득 알림에 반영한다.
- 결과창은 이미 획득한 보상을 다시 지급하는 창이 아니다.

### 8.2 던전 클리어 돈·경험치

확정 기획:

- 별도의 던전 클리어 경험치 보너스는 없다.
- 별도의 던전 클리어 돈 보너스는 없다.

결과창 문서에 “클리어 보너스”라는 표현이 있어도 돈과 경험치를 새로 추가하지 않는다.
클리어 전용 아이템 보상과 몬스터 처치 재화를 구분한다.

### 8.3 일반 몬스터 재료 드롭

사용자는 각 몬스터의 재료를 다음 공통 방식으로 드롭하도록 요청했고 완료했다고 보고했다.

- 드롭 확률: 50%
- 드롭 성공 시 수량: 1~2개

수량을 균등하게 추첨하면 다음 분포가 된다.

| 결과 | 확률 |
|---|---:|
| 획득 없음 | 50% |
| 1개 획득 | 25% |
| 2개 획득 | 25% |

몬스터별 실제 아이템 이름과 ID는 현재 프로젝트 데이터를 확인한다.

대상 계열:

- 돌 몬스터 재료
- 철 몬스터 재료
- 수정 몬스터 재료
- 석탄 몬스터 재료
- 자철석 몬스터 재료

보스나 엘리트 보상을 동일한 확률로 임의 변경하지 않는다.

### 8.4 획득 HUD 알림

- 화면 우측 중앙 부근에 표시한다.
- 세로로 나열한다.
- 최신 획득이 위쪽이다.
- 이전 획득은 아래로 내려간다.
- 구성: 아이콘 + 아이템 이름 + 수량
- 몬스터 재료 획득도 표시 대상이다.
- 아이템을 바닥에 떨어뜨렸다가 줍는 과정 없이 직접 획득하는 방향이다.

### 8.5 보상 미리보기와 도감

- 던전 입장창에는 클리어 보상 목록을 보여주는 방향이다.
- 일반·엘리트 몬스터 처치 보상은 향후 도감 같은 별도 화면에서 확인하는 구상을 했다.
- 도감은 구현 완료로 확인되지 않았다.

### 9.3 돌 몬스터 — StoneMonsterAI

역할:

6. 후딜레이 후 다시 행동한다.

보스 도약 내려찍기의 기초 버전이다.

### 9.4 철 몬스터 — IronMonsterAI

역할:
직선 돌진 및 벽 충돌 시 긴 빈틈을 제공하는 몬스터

행동:
1. 공격 거리까지 접근한다.
2. 플레이어 방향을 확인하고 고정한다.
3. 폭 1.2, 길이 6.0의 직선 예고를 표시한다.
4. 고정 방향으로 돌진한다.
5. 종료 원인에 따라 후딜레이를 적용한다.

돌진 종료 조건:
- Wall 충돌
- Player 충돌 후 1회 피해
- 최대 거리 도달

후딜레이:
- 벽 충돌: 1.5초
- 플레이어 충돌 또는 최대 거리 도달: 0.8초

동료 몬스터에 막히거나 경로가 틀어지지 않아야 한다.
이를 구현하기 위해 다른 전투 전체에 영향을 주는 전역 충돌 설정을 무분별하게 바꾸지 않는다.

### 9.5 수정 몬스터 — CrystalMonsterAI

역할:
원거리 직선 저격형

행동:
1. 공격 거리까지 접근한다.
2. 예고 시작 순간 플레이어 방향을 고정한다.
3. 길이 7.5의 직선 발사선을 0.75초 표시한다.
4. 수정 파편 1개를 발사한다.
5. 발사 후 0.7초 후딜레이를 갖는다.

투사체 소멸 조건:
- 플레이어 명중
- 벽 충돌
- 최대 이동거리 도달

거리 유지:
- 쿨타임 대기 중 플레이어가 거리 2.2 이내에 있으면 후퇴한다.
- 후퇴 속도는 1.8이다.
- 벽을 뚫으며 후퇴하면 안 된다.
- 예고 이후 플레이어를 계속 추적하는 유도탄으로 바꾸면 안 된다.

### 9.6 석탄 몬스터 — CoalMonsterAI

역할:
근접 원형 열기 폭발형

행동:
1. 빠르게 접근한다.
2. 근접 거리에서 정지한다.
3. 몸체가 달아오르며 원형 예고를 표시한다.
4. 주변에 단발 폭발 피해를 준다.
5. 열기가 식는 후딜레이를 갖는다.

주의:
- 자폭하여 죽는 몬스터가 아니다.
- 공격 후에도 생존한다.
- 반복해서 열기를 분출한다.
- 표시 반경 2.2와 실제 반경 2.0은 명세에 지정된 의도적 차이다.

### 9.7 자철석 몬스터 — MagnetMonsterAI

역할:
플레이어 이동을 방해하는 중거리 지원형

행동:
1. 거리 5.5 이내까지 접근한다.
2. 예고 시점의 플레이어 위치에 자기장 예고를 고정한다.
3. 발동 시 피해 8을 준다.
4. 이동 속도를 30% 감소시킨다.
5. 감속은 1.5초 유지한다.

주의:
- 장판이 지속 피해를 반복하는지에 대한 별도 명세는 없다.
- 명세에 없는 지속 피해를 임의로 추가하지 않는다.
- 감속 종료 시 기본 속도를 특정 숫자로 강제 대입하지 말고 현재 능력치에 맞게 복구한다.
- 감속 중첩 규칙은 구현 시 명확히 정리한다.

## 10. 돌골렘 보스

### 10.1 명칭

- “돌 보스”는 돌골렘을 의미한다.

### 10.2 패턴

총 5종으로 확장하여 구현을 진행했다.

기존 대화에서 다룬 패턴 계열:
- 도약 내려찍기
- 주변 강타
- 바위 돌진
- 부채꼴 돌 파편
- 메테오 또는 낙석

정확한 현재 패턴명, 체력, 공격 범위, 피해량, 쿨타임, 경직 시간은 보스 코드와 데이터 확인이 필요하다.

일반 몬스터 수치를 보스 수치로 대신 사용하지 않는다.

### 10.3 공격 예고

- 위험 범위가 보인다.
- 공격 발동까지 남은 시간을 채워지는 형태로 보여준다.
- 메테오만 적용되어 보였기 때문에 나머지 스킬에도 비슷한 예고 시간 표현을 요청했다.
- 실제 공격 시점과 예고 완료 시점이 일치해야 한다.

### 10.4 화면 흔들림

- 무거운 공격에만 적용한다.
- 발사와 낙하 타격이 거의 동시에 발생할 때 양쪽에 과도한 흔들림을 중복 적용하지 않는다.
- 단순 발사보다 착지·충돌·폭발 같은 실제 충격을 우선한다.
- 최종 적용 패턴과 강도는 현재 구현을 확인한다.

## 11. HP바와 전투 피드백

### 11.1 일반·엘리트 몬스터 HP바

- 몬스터 캐릭터 아래쪽에 배치하는 방향이다.
- 몬스터 움직임을 따라간다.
- 기존 피격 및 사망 처리와 연결한다.

### 11.2 보스 HP바

- 플레이어 HUD 상단 중앙에 표시한다.
- 현재 체력은 즉시 줄어든다.
- 감소 전 체력 구간을 밝은 주황색 계열로 남긴다.
- 일정 시간 공격받지 않으면 주황색 구간이 현재 체력까지 줄어든다.
- 연속 공격 중에는 누적 피해량을 인지할 수 있어야 한다.

정확한 대기 시간, 감소 속도, 색상값은 현재 코드 확인이 필요하다.

### 11.3 타격감·피격감 방향

사용자가 원하는 것은 핵앤슬래시 계열의 다음 감각이다.

- 공격이 적에게 닿았다는 느낌
- 적이 피해를 받았다는 느낌
- 적을 처치했다는 느낌
- 무거운 공격의 충격

현재는 시각 효과를 먼저 구현하고 사운드는 나중에 추가하는 방향이다.

검토 및 연동 대상:
- 피격 플래시
- 타격 이펙트
- 피해량 표시
- 적 피격 반응
- 사망 연출
- 무거운 공격의 화면 흔들림

이 목록 전체가 최종 구현되었다고 단정하지 말고 프로젝트를 확인한다.

### 11.4 사용자가 무시하라고 한 변경안

Gemini 정리 중 다음 변경은 사용자가 일단 무시하라고 했다.

- 보스 HP바를 사망 연출 후가 아니라 사망 즉시 숨기기
- 모든 공격 실제 범위를 예고보다 작게 만들기
- 곡괭이 외에 해머·탐사봉 추가
- 물약 HUD를 중앙 하단으로 변경
- 부활 시 근처 보스 위치 강제 조정

따라서 이 변경을 자동 반영하지 않는다.

단, 이후 일반 몬스터 명세에서 명시한 석탄·자철석의 표시/실제 반경 차이는 별도의 최신 구체적 설정이다.

## 13. 메인 씬과 던전 입장창

### 13.1 월드 진입 방식

- 던전 입구가 있는 메인 씬을 사용한다.
- 광산 입구 근처에서 T로 상호작용한다.
- 던전 선택창을 연다.
- 던전과 난이도를 선택하여 입장한다.

이 기능을 만든 뒤 기존 임시 방식은 제거하기로 했다.

제거 대상:
- 인벤토리를 열어서 게임 시작 버튼을 누르는 임시 흐름
- 기존 임시 인벤토리 열기 및 던전 시작 창

실제 삭제 여부는 프로젝트 확인이 필요하다.

### 13.2 UI 구성

- 상단: 던전 입장 타이틀
- 좌측: 층 선택 목록
- 우측 상단: 선택한 층 이름 및 난이도
- 중앙: 대표 맵 이미지 및 입장 필요 레벨
- 난이도 선택: 4개
- 보상 영역: 획득 가능한 클리어 보상
- 하단: 입장 버튼
- 닫기 버튼

### 13.3 선택 피드백

- 선택한 층은 강조 상태를 유지한다.
- 선택한 난이도도 강조 상태를 유지한다.
- 선택 변경 시 관련 정보가 함께 갱신된다.

### 13.4 보상 표시

- 아이콘 또는 이미지
- 획득 확률
- 희귀도 테두리
- 좌측에서 우측으로 나열

낮은 확률을 왼쪽에 둘지 오른쪽에 둘지는 최초 요청에서 고민 사항이었다.
최종 정렬 규칙은 구현을 확인한다.

### 13.5 입장 불가

- 필요 레벨을 표시한다.
- 입장 불가 상태를 회색 등으로 표현한다.
- 클릭 시 레벨이 충족되지 않았다는 플로팅 메시지를 보여준다.

완전히 클릭 불가능한 버튼으로 만들면 안내 메시지를 띄울 수 없으므로 시각적 비활성 표현과 실제 입력 처리를 구분한다.

### 13.6 닫기 및 전환

- 닫기 버튼으로 닫는다.
- ESC로 닫을 수 있다.
- I를 누르면 던전 선택창을 닫고 인벤토리를 연다.
- 인벤토리를 닫아도 던전 선택창을 다시 열지 않는다.
- 창이 열려 있어도 게임 시간은 흐른다.

## 14. 던전 결과창 — 최신 확정 기획

구현 완료 보고가 있다.

### 14.1 기존 상자 방식 폐기

이전 기획:
보스 처치 → 던전 중앙 상자 생성 → T 상호작용 → 보상 획득

최신 기획:
보스 처치 → 클리어 보상 지급 및 저장 → 결과창 연출

따라서 보스 처치 후 보상 상자를 생성하는 기믹은 폐기되었다.

### 14.2 결과 진입 조건

클리어:
- 보스 처치

실패:
- 부활 2회를 모두 사용한 뒤 최종 사망

### 14.3 보상 지급 시점

핵심:
결과창을 처음 띄울 때 클리어 보상을 지급하고 저장한다.

다음 행동으로 보상이 사라지면 안 된다.

- 결과창 닫기
- 결과창 다시 열기
- 결과창에서 로비로 이동
- 퍼즈 메뉴에서 로비로 이동
- 게임 종료

몬스터 처치 보상은 이미 즉시 획득한 상태이므로 결과창에서 다시 지급하면 안 된다.

보상 지급과 저장은 결과창의 표시·숨김과 분리한다.
결과창을 다시 열어도 중복 보상이 발생하면 안 된다.

### 14.4 실패 보상 유지

실패해도 사망 전 획득한 다음 보상은 100% 유지한다.

- 돈
- 경험치
- 재료
- 이미 획득한 아이템

아직 획득하지 않은 보스·클리어 전용 보상은 지급하지 않는다.

엘리트가 존재한다면 이미 지급한 엘리트 처치 보상을 “일반 몬스터만 유지”라는 문구 때문에 회수하면 안 된다.

### 14.5 클리어와 실패의 이동 차이

클리어:
- 결과창이 떠 있는 상태에서도 플레이어 이동 가능
- 창을 닫고 주변을 돌아볼 수 있음

실패:
- 플레이어가 사망한 상태이므로 이동 불가
- 창을 닫더라도 이동 가능 상태로 복구하면 안 됨

기존 문서의 “결과 진입 시 플레이어 조작 전체 잠금”보다 이 최신 규칙이 우선한다.

이동 외 공격·스킬 사용 허용 범위는 실제 구현을 확인한다.

### 14.6 닫기와 다시 열기

- 결과창을 닫을 수 있다.
- 닫힌 상태에서 우측 하단에 결과창을 다시 여는 버튼을 표시한다.
- 다시 열면 같은 런의 결과를 보여준다.
- 보상 지급을 반복하지 않는다.
- 결과창을 닫았다고 새 런이 시작되면 안 된다.

### 14.7 공통 레이아웃

클리어와 실패는 동일한 2패널 UI를 공유한다.

- 화면 전체 반투명 암전
- 상단 중앙: 결과 타이틀
- 좌측: 획득 보상
- 우측: 전투 기록 및 이동 버튼

암전 색:
rgba(8, 10, 15, 0.80)

상단 타이틀에는 별도 배경 패널을 두지 않는다.
텍스트와 좌우 장식선만 표시한다.

싱글플레이 전용:
- 파티원 표시 없음
- MVP 없음
- 매치메이킹 UI 없음

### 14.8 등장 연출

1단계: 0.0~0.4초
- 남은 적 공격 및 예고 정리
- 암전 페이드인
- 결과 상태 확정
- 보상 지급 및 저장 처리

2단계: 0.4~1.0초
- 결과 타이틀이 중앙에 나타난 후 위로 이동
- 획득 보상창이 화면 중앙에 단독 등장

3단계: 1.0~1.6초
- 아이템 슬롯 순차 등장
- 골드와 경험치 카운트업

4단계: 1.6~2.1초
- 보상창이 왼쪽으로 이동
- 오른쪽 전투 기록창 공개

카운트업은 표시 연출이며 실제 재화를 반복 지급하는 로직이 아니다.

### 14.9 타이틀

클리어:
- 상단 영문: CHAMBER CONQUERED
- 메인: 던전 클리어

실패:
- 상단 영문: THE MINE CLAIMS ANOTHER
- 메인: 던전 실패
- 보조 영문: DUNGEON FAILED

- 하단: 층 이름, 난이도, 획득 보상 유지 안내

### 14.10 획득 아이템 영역

- 희귀도 테두리
- 우측 하단 획득 수량 배지
- 마우스 호버 툴팁

희귀도 색상:

- 희귀: 파랑
- 영웅: 보라

클리어:

- 클리어 전용 아이템 보상

실패:
- 실패 전까지 획득한 보상

현재 없는 장비 드롭 등을 UI 예시만 보고 새로 추가하지 않는다.

## 15. 저장 및 불러오기

사용자는 저장 및 불러오기 작업을 완료했다고 보고했다.
Unity Play를 멈췄다가 다시 실행해도 경험치와 돈 등이 유지되는 것을 확인했다.

### 15.1 반드시 유지되어야 하는 데이터

- 돈
- 경험치와 레벨
- 획득 재료
- 획득 아이템
- 획득 및 장착 스킬
- 제작한 곡괭이
- 장비 및 성장 데이터
- 미사용·사용 스탯 포인트

실제 저장 대상과 파일 경로는 프로젝트에서 확인한다.

### 15.2 결과 보상 저장

- 결과창 표시 시점에 보상 확정 및 저장
- 결과창의 로비 버튼에만 저장을 의존하지 않음
- 퍼즈 메뉴 복귀로도 보상이 유지됨
- 게임 종료 후 재실행해도 지급한 보상 유지
- 보상 지급 중복 방지

### 15.3 개발용 저장 초기화

사용자가 요청한 기능:
테스트를 위해 저장 기록을 지울 수 있는 단축키 또는 기능

구현 여부 및 정확한 단축키는 확인되지 않았다.

추가 구현 시 필요한 기준:
- 개발용 기능임을 명확히 표시
- 실수로 초기화하지 않도록 확인 절차 제공
- 저장 파일뿐 아니라 현재 메모리 상태도 함께 정리
- 자동 저장이 삭제 전 데이터를 곧바로 다시 쓰지 않도록 처리
- 초기화 범위를 명확히 표시
- 다른 프로그램의 데이터나 무관한 설정을 삭제하지 않음

- 몬스터별 재료 드롭을 먼저 구현했다.

- 던전 전투 도중 제작하는 구조가 아니다.

### 16.3 기본 구조

- 제작 가능한 곡괭이 목록
- 선택한 곡괭이 정보
- 필요한 재료
- 현재 보유 재료 수량
- 필요한 돈
- 제작 버튼
- 제작 결과 안내

### 16.4 확정된 경제 관계

몬스터 처치
→ 돈과 재료 획득
→ 메인 씬에서 곡괭이 제작
→ 장착
→ 던전 재도전

### 16.5 아직 확정되지 않은 내용

- 제작 곡괭이 이름과 종류
- 물리·마법 능력치
- 희귀도
- 재료별 요구 수량
- 제작 비용
- 제작 상호작용 오브젝트 외형
- 제작창 최종 레이아웃
- 제작 성공 연출
- 자동 장착 여부
- 같은 곡괭이 중복 제작 처리

확정되지 않은 강화·분해·판매·랜덤 옵션 시스템을 제작 기능에 자동 추가하지 않는다.

## 17. 맵 기획 — 기존 9종

### 17.1 설계도 표기

- 초록색 네모: 플레이어 입장 위치
- 빨간색 네모: 몬스터 전멸 후 사용할 출구
- 주황색 원: 몬스터 배치 영역
- 벽 표시: 플레이어와 몬스터의 이동을 막는 벽
- 연보라색: 이동 가능한 바닥 영역

주황색 원은 몬스터 1마리의 정확한 위치를 뜻하지 않는다.
여러 몬스터를 배치하는 영역이다.

입구·출구·몬스터 원의 색상을 실제 게임 아트에 그대로 구현하라는 의미가 아니다.

### 17.2 기존 맵별 특징

| 맵 | 기존 설계 특징 |
|---|---|
| 1 | 직사각형, 좌우로 번갈아 뻗는 가로 벽, 좌측 하단 입구, 우측 상단 출구, 몬스터 영역 2개 |
| 2 | 세로형, 중앙 상단 장애물, 하단 중앙 입구, 상단 출구 후보 2개 중 하나 랜덤 선택, 몬스터 영역 4개 |
| 3 | 세로형, 작은 장애물과 긴 가로 벽, 우측 하단 입구, 상단 중앙 출구, 몬스터 영역 3개 |
| 4 | 꺾인 외곽과 우측 아래 확장 구역, 좌측 아래 입구, 우측 아래 출구, 몬스터 영역 3개 |
| 5 | 맵 1의 변형, 번갈아 배치한 가로 벽, 좌측 아래 입구, 우측 위 측면 출구, 몬스터 영역 3개 |
| 6 | 세로 중심 통로에 좌측·우측 확장 구역, 하단 입구, 상단 출구, 몬스터 영역 4개 |
| 7 | 하단 중앙 벽으로 좌우가 나뉨, 좌측 아래 입구, 상단 출구, 몬스터 영역 4개 |
| 8 | 맵 7 계열의 반대 배치, 우측 아래 입구, 상단 출구, 몬스터 영역 4개 |
| 9 | 오른쪽 아래에서 시작해 왼쪽 위로 진행하는 꺾인 구조, 좌측 위 출구, 몬스터 영역 3개 |

이 표는 확인 가능한 기존 설계도 기준이다.
Gemini가 수정한 최신 이미지와 달라질 수 있다.

### 17.3 맵 2 출구

- 상단의 두 출구 후보 중 하나만 선택한다.
- 방이 생성될 때 한 번 결정한다.
- 선택되지 않은 위치를 실제 사용 가능한 출구로 남기지 않는다.
- 방 전멸 전에는 선택한 출구도 사용할 수 없다.

### 17.4 내부 벽과 연결선

- 내부 벽은 캐릭터 이동을 막는다.
- 카메라는 내부 벽 위를 지나가거나 벽을 화면에 담을 수 있다.
- 인접한 두 바닥 구역을 표시하는 도형 경계가 곧 벽이라는 의미는 아니다.
- 맵 6 같은 확장 구역 연결부를 실수로 벽으로 막으면 안 된다.

### 17.5 무너진 벽 표시

맵 4와 맵 9에 “무너진 벽” 표시가 있다.

이 표시만으로 다음 기능을 확정할 수는 없다.

- 파괴 가능한 벽
- 숨겨진 방
- 외부 탈출 경로
- 추가 상호작용

별도 기획 없이 파괴 시스템을 추가하지 않는다.

### 17.6 맵 크기

이전에 테스트 바닥을 25, 20으로 설정한 적이 있다.
이는 모든 신규 맵의 최종 크기 확정이 아니다.

현재 신규 맵별 최종 월드 크기는 미확정이다.

최종 크기는 다음을 함께 보고 정한다.

- 실제 플레이어 크기와 이동 속도
- 카메라가 보여주는 범위
- 몬스터 공격 사거리
- 회피 공간
- 통로 폭
- 몬스터 수
- 방 클리어 시간

이미지 픽셀 크기를 Unity 월드 크기로 그대로 사용하지 않는다.

## 18. 맵 제작 최신 변경 방향 — 가장 중요한 현재 작업

### 18.1 기존 시도

처음에는 다음 방향을 검토했다.

- 비직사각형 이동 영역을 그대로 제작
- 내부 벽은 카메라 통과 허용
- 맵 외곽 밖으로 카메라가 나가지 않도록 제한

이후 Codex가 진행 중인 맵 제작에 문제가 많다고 사용자가 판단했다.

### 18.2 사용자 최신 제안

사용자가 Gemini에서 개선한 방향:

“전체 맵을 직사각형 안에 넣고, 실제 이동하지 않는 빈 공간을 암석이나 암벽으로 채운다.”

핵심 구분:

1. 전체 맵 캔버스
   - 직사각형

2. 실제 이동 영역
   - 기존처럼 꺾이거나 갈라진 여러 모양 가능

3. 이동 불가 공간
   - 암석·암벽으로 채움

4. 카메라
   - 전체 직사각형을 기준으로 제한
   - 암석과 내부 벽은 화면에 보일 수 있음

즉, 이동 경로까지 직사각형으로 바꾸자는 뜻은 아니다.

### 18.3 맵 4 수정

사용자는 개선안의 맵 4가 추가 수정이 필요해 보인다고 했다.

원하는 방향:
- 맵 6처럼 남는 공간을 암벽 등으로 채운다.
- 전체 외형을 직사각형으로 정리한다.
- 실제 이동 경로는 유지한다.

정확한 최신 형태는 이미지를 확인해야 한다.

### 18.4 신규 맵 A

- 사용자가 최신 개선안에 신규 맵 A를 추가했다.
- 해당 맵의 실제 이미지 내용은 이 대화에서 확인하지 못했다.
- 기존 맵을 대체하는지, 추가 후보인지도 최종 확인이 필요하다.
- 구조를 추측하여 구현하면 안 된다.

### 18.5 이미지 확인 문제

기존 9종 및 연보라색 설계도는 대화에서 확인할 수 있었다.

그러나 Gemini가 개선한 최신 이미지 2장은 다음 오류로 확인하지 못했다.

“No such file or directory”
또는 이미지 파일을 읽을 실행 환경 문제

사용자는 여러 차례 다시 업로드했으나 해결되지 않았다.

최신 이미지 파일명 예:
- Gemini_Generated_Image_y5gwzgy5gwzgy5gw.png
- Gemini_Generated_Image_y5gwzgy5gwzgy5gw111.png

이후 같은 자료를 image(5), image(6), image(7), image(8) 등으로 재업로드한 것으로 보인다.

다음 대화에서는 최신 이미지 2장을 다시 받아 실제로 보이는지 확인하는 것이 우선이다.

### 18.6 Git 되돌리기

사용자는 Fork의 Discard Changes로 문제가 있는 맵 작업을 되돌리는 방향을 이야기했다.

실제로 되돌리기를 완료했는지는 확인되지 않았다.

진행 시:
- 실행 중인 Codex 작업을 먼저 멈춘다.
- 변경 파일을 확인한다.
- 정상적으로 완성한 다른 기능까지 함께 버리지 않는다.
- 맵 변경과 관련 없는 수정은 보존한다.
- .meta 및 프리팹 참조 손상 여부를 확인한다.

## 19. 신규 맵 구현 시 유지할 시스템

### 19.1 전투와 방 진행

- 기존 EnemyHealth 사망 이벤트 유지
- 실제 몬스터 전멸 시 출구 개방
- 모든 종류 몬스터에 플레이어 타겟 연결
- 방 교체 시 남은 공격 정리
- 입구 부활 유지
- 보상 중복 지급 방지

### 19.2 몬스터 배치

- 주황색 영역 내부에 여러 몬스터 배치 가능
- 벽 안에 생성하지 않음
- 서로 완전히 겹쳐 생성하지 않음
- 입구를 막지 않음
- 출구를 막지 않음
- 플레이어가 도달할 수 없는 구역에 생성하지 않음

기존 몬스터 수를 각 배치 영역에 그대로 복제해 방 전체 적 수가 의도치 않게 폭증하지 않도록 한다.

### 19.3 AI와 복잡한 벽

기존 직선 추적만으로는 새 맵의 내부 벽에 걸릴 수 있다.

확인할 내용:
- 벽을 우회하여 플레이어에게 접근하는가
- 입구에서 모든 적에게 도달할 수 있는가
- 남은 적이 벽 뒤에 갇혀 방을 완료하지 못하는가
- 수정 몬스터가 벽을 무시하고 공격하는가
- 돌 몬스터가 벽을 넘어 착지하는가
- 철 몬스터의 돌진이 벽 충돌로 정상 종료되는가

일반 이동의 우회 처리와 공격 패턴의 이동 규칙을 구분한다.
철 몬스터의 직선 돌진을 자동으로 벽을 돌아가는 공격으로 바꾸면 안 된다.

### 19.4 카메라

최신 직사각형 전체 맵 방향 기준:

- 전체 직사각형을 카메라 표시 영역으로 사용
- 실제 화면의 폭과 높이를 고려
- 카메라 중심점만 제한하고 화면 가장자리가 맵 밖으로 나가는 문제 방지
- 흔들림 중 외부 빈 공간 노출 여부 확인
- 내부 벽과 암석은 카메라 제한 장애물이 아님
- 방 교체 시 새 방의 제한 영역 갱신
- 입구 이동 및 부활 시 이전 방 카메라 설정이 남지 않음

### 19.5 권장 작업 순서

다음은 구현을 안정적으로 진행하기 위한 제안이며 완료된 작업이 아니다.

1. 현재 프로젝트와 되돌리기 상태 확인
2. 최신 이미지 2장 확인
3. 전체 직사각형 + 암벽 채우기 규칙 확정
4. 대표 맵 한 개만 우선 제작
5. 카메라·벽 충돌·AI·출구·부활 검증
6. 맵 4 및 나머지 후보로 확대
7. 신규 맵 A 반영
8. 랜덤 방 선택에 연결

모든 맵을 한 번에 만든 뒤 문제를 찾기보다 공통 구조를 먼저 검증한다.
